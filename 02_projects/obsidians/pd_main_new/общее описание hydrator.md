### 🔍 Основные задачи гидратора

#### 1. **Hydration** (`hydrate`)
Принимает:
- объект `CallRegistryMissedModel`
- массив данных (например, строку из результата SQL-запроса)

→ Заполняет **приватные свойства объекта** значениями из массива, **преобразуя типы**:
- строки → `int`, `DateTimeImmutable`, `string`

#### 2. **Extraction** (`extract`)
Принимает:
- объект `CallRegistryMissedModel`

→ Возвращает массив с данными, **готовыми для вставки/обновления в БД**:
- `DateTimeImmutable` → строка вида `'2025-04-05 14:30:00'`
- `int`, `string` → как есть (но с приведением типов при необходимости)

### 🗺️ Как это работает: карта полей (`$map`)

```php
private array $map = [
    'id' => ['id', 'int'],
    'calledAt' => ['called_at', 'DateTime'],
    // ...
];
```

Каждая запись:
- **Ключ** — имя **свойства в PHP-объекте** (`$object->calledAt`).
- **Значение** — массив:
  - `[0]` — имя **колонки в БД** (`called_at`)
  - `[1]` — **тип данных** (`int`, `string`, `DateTime`)

Эта карта позволяет:
- При **гидратации**: взять значение из `$data['calledAt']` → преобразовать через `createDateTime()` → записать в `$object->calledAt`.
- При **экстракции**: взять `$object->calledAt` → преобразовать через `extractDateTime()` → положить в `$dbData['called_at']`.

> Обратите внимание: в `$data` ключи — это **имена свойств модели** (`calledAt`), а не колонок БД (`called_at`). Это важно — значит, где-то выше (в репозитории) уже произошло переименование колонок БД в имена свойств.

### 🔄 Методы преобразования типов

Гидратор использует **пары методов** для каждого типа:

| Тип       | Гидратация (`create*`)        | Экстракция (`extract*`)            |
|----------|-------------------------------|------------------------------------|
| `int`    | `createInt(?string): ?int`    | `extractInt(?int): ?int`           |
| `string` | `createString(?string): ?string` | `extractString(?string): ?string` |
| `DateTime` | `createDateTime(?string): ?DateTimeImmutable` | `extractDateTime(?DateTimeInterface): ?string` |

Пример:
```php
// Из БД: '2025-04-05 10:00:00' → в объект: DateTimeImmutable
$this->createDateTime('2025-04-05 10:00:00');

// Из объекта: DateTimeImmutable → в БД: '2025-04-05 10:00:00'
$this->extractDateTime($dateTime);
```

- Любое изменение в модели (добавление поля) → потребует обновления гидратора.

Генератор:
1. Читает модель (через атрибуты `#[Column]` или анализ свойств).
2. Определяет типы полей.
3. Генерирует `$map` и соответствующие `create*/extract*` вызовы.

### 💡 Зачем всё это нужно?

Без гидратора пришлось бы:
- Вручную писать сеттеры для каждого поля.
- Или делать свойства `public` (что нарушает инкапсуляцию).
- Или использовать медленные магические методы (`__set`, `__get`).

Гидратор даёт:
- **Чистую модель** с приватными свойствами и контролируемым доступом.
- **Безопасное преобразование типов**.
- **Отделение логики отображения от логики бизнеса**.
- **Производительность** за счёт кэширования Reflection.
