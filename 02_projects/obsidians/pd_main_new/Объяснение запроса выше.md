Запрос **не берёт больше одной строки на пользователя** — он возвращает **ровно 10 строк из таблицы `users`**, пронумерованных по полю `id`.

Разберём ваш запрос по шагам:

```sql
WITH t AS (
    SELECT *,
           ROW_NUMBER() OVER (ORDER BY id) AS rn
    FROM users
)
SELECT * FROM t WHERE rn <= 10;
```

### Что происходит:
1. **`ROW_NUMBER() OVER (ORDER BY id)`** присваивает **уникальный номер** каждой строке из таблицы `users`, отсортированной по `id` по возрастанию.
   - Первая строка (с наименьшим `id`) получает `rn = 1`
   - Вторая — `rn = 2`
   - ...
   - Десятая — `rn = 10`

2. Внешний `SELECT` выбирает только те строки, где `rn <= 10` — то есть **первые 10 записей** из `users` по порядку `id`.

### Почему может *казаться*, что строк больше, чем ожидалось?
- Если в таблице `users` **действительно есть не менее 10 записей**, запрос вернёт **10 строк** — и это нормально.
- Если вы ожидали **одну строку**, возможно, вы перепутали этот запрос с чем-то вроде `SELECT * FROM users WHERE id = ?`.
- Также может смущать `SELECT *` — он возвращает **все столбцы**, но **всё ещё только по одной строке на запись**.

### Важно:
- **`ROW_NUMBER()` всегда даёт уникальные номера** — даже если `id` повторяется (хотя в случае `id` как первичного ключа дубликатов быть не должно).
- Этот запрос **не дублирует строки** и **не соединяется с другими таблицами**, так что каждая строка результата — это одна реальная строка из `users`.

### Вывод:
> Запрос возвращает **не больше одной строки на запись** из `users`. Он просто выбирает первые **10 записей**, упорядоченных по `id`. Если в таблице 1000 пользователей — вы получите 10 из них. Если пользователей 5 — получите 5. Никаких "лишних" строк нет.d
