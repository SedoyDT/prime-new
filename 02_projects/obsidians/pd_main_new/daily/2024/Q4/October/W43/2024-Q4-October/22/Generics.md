Большая часть программной инженерии заключается в создании компонентов с хорошо определёнными и последовательными API, которые также могут быть переиспользуемыми. Компоненты, которые способны работать с данными как настоящего, так и будущего, обеспечат максимальную гибкость при построении крупных программных систем.

В языках, таких как C# и Java, одним из главных инструментов для создания повторно используемых компонентов являются дженерики, то есть возможность создавать компонент, который может работать с различными типами данных, а не только с одним. Это позволяет пользователям использовать эти компоненты и применять к ним свои собственные типы данных.

### Пример с функцией идентичности
Начнем с самого простого примера дженериков: функции идентичности. Функция идентичности — это функция, которая возвращает тот же самый аргумент, который был ей передан. Это можно сравнить с командой "echo".

Без дженериков нам пришлось бы задать конкретный тип для функции идентичности:

```typescript
function identity(arg: number): number {
  return arg;
}
```

Или мы могли бы описать функцию идентичности с использованием типа `any`:

```typescript
function identity(arg: any): any {
  return arg;
}
```

Хотя использование `any` делает функцию обобщенной, так как она принимает любые типы аргументов, при этом теряется информация о типе данных, переданном в функцию. Если мы передали число, у нас больше не будет информации о том, какой тип данных возвращается.

Вместо этого нам нужно способ захватить тип аргумента таким образом, чтобы можно было использовать его для указания возвращаемого значения. Здесь мы воспользуемся переменной типа — специальной переменной, которая работает с типами, а не с конкретными значениями.

```typescript
function identity<Type>(arg: Type): Type {
  return arg;
}
```

Теперь мы добавили переменную типа `Type` в функцию идентичности. Эта переменная позволяет нам захватить тип, который пользователь передаёт (например, `number`), чтобы мы могли использовать эту информацию позже. Здесь мы снова используем `Type` в качестве возвращаемого типа. Теперь видно, что один и тот же тип используется и для аргумента, и для возвращаемого значения. Это позволяет нам «передавать» информацию о типе через функцию.

Мы говорим, что эта версия функции идентичности является обобщенной, так как она работает с различными типами. В отличие от использования `any`, она также сохраняет точность (т.е. не теряет информацию) так же, как и первая версия функции, которая работала только с числами.

Как только мы написали обобщенную функцию идентичности, мы можем вызывать её двумя способами. Первый способ — передать все аргументы, включая аргумент типа:

```typescript
let output = identity<string>("myString");
```

Здесь мы явно указываем, что `Type` должен быть строкой, используя символы `< >` для передачи типа.

Второй способ, и он, пожалуй, более распространённый — это позволить компилятору автоматически вывести значение для переменной типа, исходя из переданного аргумента:

```typescript
let output = identity("myString");
```

Обратите внимание, что нам не нужно было явно передавать тип внутри угловых скобок — компилятор сам определил тип на основе значения `"myString"` и установил `Type` как `string`. Вывод типов может помочь сократить код и сделать его более читабельным. Однако иногда вам нужно будет явно указывать типы, если компилятор не может правильно их вывести.

### Работа с переменными типов
Когда вы начинаете использовать дженерики, компилятор будет следить за тем, чтобы вы корректно использовали обобщённые типы в теле функции. Это означает, что вам нужно учитывать, что параметры с обобщёнными типами могут представлять любой тип данных.

Возьмём нашу функцию идентичности:

```typescript
function identity<Type>(arg: Type): Type {
  return arg;
}
```

Что если мы захотим выводить длину аргумента `arg` в консоль при каждом вызове функции? Мы можем быть склонны написать так:

```typescript
function loggingIdentity<Type>(arg: Type): Type {
  console.log(arg.length);
  return arg;
}
```

Однако компилятор выдаст ошибку, так как у типа `Type` может не быть свойства `length`. Мы не можем гарантировать, что переданный аргумент имеет это свойство, поскольку это может быть, например, число.

Вместо этого, давайте уточним, что функция должна работать с массивами типа `Type`, где свойство `length` точно существует. Мы можем описать это так:

```typescript
function loggingIdentity<Type>(arg: Type[]): Type[] {
  console.log(arg.length);
  return arg;
}
```

Теперь мы точно знаем, что у массива есть свойство `length`, поэтому ошибки больше не будет.

### Обобщённые типы
Мы уже создавали обобщённые функции, которые работают с различными типами данных. Теперь давайте рассмотрим, как можно определить обобщённые интерфейсы и классы.

Тип обобщённых функций определяется так же, как и типы обычных функций, только сначала перечисляются параметры типов:

```typescript
function identity<Type>(arg: Type): Type {
  return arg;
}
 
let myIdentity: <Type>(arg: Type) => Type = identity;
```

Мы также можем написать это так:

```typescript
let myIdentity: <Input>(arg: Input) => Input = identity;
```

### Обобщённые классы
Обобщённые классы имеют такой же синтаксис, как и интерфейсы. Параметры типов указываются в угловых скобках сразу после имени класса:

```typescript
class GenericNumber<NumType> {
  zeroValue: NumType;
  add: (x: NumType, y: NumType) => NumType;
}
 
let myGenericNumber = new GenericNumber<number>();
myGenericNumber.zeroValue = 0;
myGenericNumber.add = function (x, y) {
  return x + y;
};
```

Обратите внимание, что мы не ограничиваем использование только числами. Мы можем создать экземпляр класса с любым типом, например, строкой:

```typescript
let stringNumeric = new GenericNumber<string>();
stringNumeric.zeroValue = "";
stringNumeric.add = function (x, y) {
  return x + y;
};
```

### Ограничения обобщённых типов
Иногда мы хотим ограничить множество типов, с которыми может работать обобщённая функция. Например, в функции `loggingIdentity` нам нужно было обратиться к свойству `length`, но не все типы имеют это свойство.

Мы можем установить ограничение, указав, что тип должен иметь определённые свойства. Для этого мы создадим интерфейс:

```typescript
interface Lengthwise {
  length: number;
}
 
function loggingIdentity<Type extends Lengthwise>(arg: Type): Type {
  console.log(arg.length);
  return arg;
}
```

Теперь функция будет работать только с типами, которые имеют свойство `length`. Например:

```typescript
loggingIdentity({ length: 10, value: 3 });
```

Этот пример и другие концепции демонстрируют гибкость дженериков для создания многоразовых компонентов, которые могут работать с разными типами данных, оставаясь при этом безопасными и предсказуемыми в поведении.
