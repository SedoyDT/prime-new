Как работает декоратор для парметра ?::

Конечно! Ниже ты увидишь **весь исходный код с подробными комментариями**, а после — **объяснение логики работы и как всё связано между собой**.

## ✅ Полный код с подробными комментариями

```ts
// Подключаем reflect-metadata — библиотеку, которая позволяет работать с метаданными в декораторах
require('reflect-metadata');

// Создаём уникальный ключ (Symbol), чтобы хранить в метаданных информацию о параметрах,
// которые должны быть проверены на тип "string"
const metadataKey = Symbol('validations');

/**
 * Декоратор для параметров метода.
 * Используется как @isString — помечает параметр, который должен быть строкой.
 *
 * @param target — целевой объект (prototype класса)
 * @param key — имя метода, к которому применяется декоратор
 * @param index — индекс параметра в списке аргументов метода
 */
function isString(target: any, key: string, index: number) {
    // Получаем текущий список индексов параметров, помеченных как @isString для этого метода
    const existingIndexes = Reflect.getOwnMetadata(metadataKey, target, key) || [];

    // Обновляем метаданные, добавляя туда новый индекс параметра
    Reflect.defineMetadata(
        metadataKey,                        // Ключ, по которому храним данные
        [...existingIndexes, index],        // Добавляем текущий индекс к уже существующим
        target,                             // Целевой объект (prototype)
        key                                 // Метод, к которому применён декоратор
    );
}

/**
 * Декоратор метода.
 * Проверяет типы аргументов, помеченных через @isString, перед выполнением метода.
 *
 * @param target — целевой объект (prototype класса)
 * @param key — имя метода, к которому применён декоратор
 * @param descriptor — дескриптор свойства метода
 */
function validate(target: any, key: string, descriptor: PropertyDescriptor) {
    // Сохраняем оригинальную реализацию метода
    const originalMethod = descriptor.value;

    // Переопределяем метод на обёртку, которая будет выполнять валидацию
    descriptor.value = function (...args: any[]) {
        // Получаем список индексов параметров, которые должны быть строками
        const indexes = Reflect.getOwnMetadata(metadataKey, target, key) || [];

        // Проходимся по каждому такому индексу и проверяем тип аргумента
        for (let i of indexes) {
            if (typeof args[i] !== 'string') {
                throw new Error(`Аргумент под индексом ${i} должен быть строкой`);
            }
        }

        // Если все проверки пройдены — вызываем оригинальный метод
        return originalMethod.apply(this, args);
    };

    // Возвращаем изменённый дескриптор метода
    return descriptor;
}

/**
 * Пример использования:
 * Класс UserService содержит метод createUser(), который принимает параметры.
 * Один из них помечен как @isString — значит, он должен быть строкой.
 */
class UserService {
    /**
     * Метод createUser() создаёт пользователя.
     * Первый параметр name помечен как @isString — значит, он должен быть строкой.
     */
    @validate
    createUser(@isString name: string, age: number) {
        console.log(`Создаём пользователя: ${name}, возраст: ${age}`);
    }
}

// Создаём экземпляр класса
const service = new UserService();

// Вызываем метод с корректными данными — должно сработать нормально
service.createUser("Bob", 25); // OK

// Вызываем метод с некорректным типом первого аргумента — должно выбросить ошибку
// service.createUser(123, 25); // ❌ Ошибка: Аргумент под индексом 0 должен быть строкой
```

## 🧠 Как это работает?

### 1. **`@isString` — декоратор параметра**
- Он вызывается автоматически при определении класса.
- Записывает индекс параметра (например, `0` для `name`) в метаданные метода.
- Это позволяет нам знать, какие параметры нужно проверять на тип `string`.

### 2. **`@validate` — декоратор метода**
- Оборачивает оригинальный метод в функцию, которая:
  - Читает из метаданных индексы параметров, которые должны быть строками
  - Проверяет их типы
  - Если всё верно — вызывает оригинал

### 3. **Использование**
- При вызове метода `createUser()` с `@isString` над первым параметром:
  - Система проверяет, что первый аргумент — строка
  - Если да — выполняет логику
  - Если нет — выбрасывает ошибку

## 📦 Технологии и подходы:

| Элемент | Роль |
|--------|------|
| `Reflect.defineMetadata` / `getOwnMetadata` | Хранение информации о том, какие параметры требуют проверки |
| `@isString` | Декоратор параметра — помечает нужные аргументы |
| `@validate` | Декоратор метода — оборачивает метод и добавляет валидацию |
| `PropertyDescriptor` | Позволяет изменять поведение метода |
| `Symbol` | Уникальный ключ для хранения метаданных, чтобы не было конфликтов |

---

## ✅ Преимущества такого решения

- Гибкая система валидации
- Не дублируется логика проверок
- Можно легко расширить (например, добавить `@isNumber`, `@isEmail` и т.д.)
- Чистая бизнес-логика в методах

---

## ❗ Возможные улучшения

- Поддержка других типов (`@isNumber`, `@isBoolean`)
- Поддержка сложных валидаций (например, через схемы или регулярные выражения)
- Логирование, трассировка, мониторинг
- Комбинирование нескольких валидаторов на одном параметре
