Что такое хранимые процедуры в mysql?::


Хранимые процедуры (stored procedures) в MySQL — это наборы SQL-команд, которые сохраняются в базе данных и могут быть вызваны для выполнения различных операций. Они представляют собой одно из средств для централизованного управления бизнес-логикой и обеспечивают возможность выполнения сложных задач, которые требуют нескольких шагов обработки.

### Основные характеристики хранимых процедур

1. **Автономность:** Хранимые процедуры сохраняются в базе данных и могут быть вызваны независимо от клиентских приложений. Это позволяет централизованно управлять логикой работы с данными.

2. **Параметры:** Хранимые процедуры могут принимать параметры для более гибкого использования. Параметры могут быть входными, выходными или входными/выходными.

3. **Множественные команды:** В отличие от SQL-запросов, которые выполняются как одна команда, хранимые процедуры могут содержать несколько SQL-команд и логических операторов, таких как циклы и условия.

4. **Возвращаемые значения:** Хранимые процедуры не возвращают значения напрямую, как это делают хранимые функции, но могут возвращать статус выполнения или изменять данные в базе.

### Примеры создания и использования хранимых процедур

#### 1. Создание хранимой процедуры

Для создания хранимой процедуры используется команда `CREATE PROCEDURE`. Например, создадим процедуру, которая добавляет нового пользователя в таблицу `users`:

```

DELIMITER //

CREATE PROCEDURE AddUser(
    IN userName VARCHAR(50),
    IN userEmail VARCHAR(100)
)
BEGIN
    INSERT INTO users (name, email)
    VALUES (userName, userEmail);
END //

DELIMITER ;

```

В этом примере:
- `DELIMITER //` изменяет разделитель команд для упрощения создания процедуры (по умолчанию разделитель — `;`).
- `CREATE PROCEDURE AddUser` создаёт процедуру с именем `AddUser`, которая принимает два входных параметра `userName` и `userEmail`.
- Внутри процедуры выполняется SQL-команда `INSERT`, добавляющая новую запись в таблицу `users`.
- `DELIMITER ;` возвращает разделитель команд к стандартному `;`.

#### 2. Вызов хранимой процедуры

После создания процедуры её можно вызвать для выполнения:

```

CALL AddUser('Alice', 'alice@example.com');

```

Этот вызов добавит нового пользователя с именем 'Alice' и электронной почтой 'alice@example.com' в таблицу `users`.

#### 3. Процедура с параметрами по умолчанию

Процедуры могут иметь параметры с значениями по умолчанию:

```

DELIMITER //

CREATE PROCEDURE GreetUser(
    IN userName VARCHAR(50) DEFAULT 'Guest'
)
BEGIN
    SELECT CONCAT('Hello, ', userName, '!');
END //

DELIMITER ;

```

Использование процедуры:

```

CALL GreetUser();           -- Результат: 'Hello, Guest!'
CALL GreetUser('Bob');      -- Результат: 'Hello, Bob!'

```

#### 4. Процедура с выходным параметром

Процедуры могут также возвращать значения через выходные параметры:

```

DELIMITER //

CREATE PROCEDURE GetUserCount(
    OUT totalCount INT
)
BEGIN
    SELECT COUNT(*) INTO totalCount FROM users;
END //

DELIMITER ;

```

Вызов процедуры и получение результата:

```

CALL GetUserCount(@count);
SELECT @count;   -- Получаем количество пользователей

```

### Преимущества хранимых процедур

1. **Централизованное управление:** Позволяют централизованно управлять бизнес-логикой и SQL-кодом, упрощая обновление и поддержку.

2. **Упрощение кода:** Могут упростить клиентский код, сократив количество SQL-запросов и логики, размещённой в приложении.

3. **Повышение производительности:** Процедуры могут выполнять сложные задачи более эффективно, поскольку они компилируются и хранятся в базе данных.

4. **Безопасность:** Могут помочь улучшить безопасность, ограничивая доступ к данным и выполняя проверку данных в одном месте.

### Ограничения хранимых процедур

1. **Производительность:** При неэффективном использовании или сложных вычислениях хранимые процедуры могут замедлить работу базы данных.

2. **Отладка:** Отладка хранимых процедур может быть сложной задачей, поскольку они выполняются на сервере базы данных.
