# Покажи пример адаптера на php
<!-- basicblock-start  deck='P_patterns' -->
Покажи пример адаптера на php::


Конечно, вот пример реализации шаблона **Адаптер** на PHP.

### Задача:
Допустим, у нас есть система, которая работает с интерфейсом для **квадратных отверстий** (`SquareHole`), и мы хотим вставить в неё **круглые колышки** (`RoundPeg`). Однако интерфейсы у них разные. Чтобы это сделать, мы создадим адаптер, который позволит использовать круглый колышек в квадратном отверстии.

### 1. **Интерфейс для квадратных отверстий и класс для работы с ними:**

```
<?php
class SquareHole {
    private $width;

    public function __construct($width) {
        $this->width = $width;
    }

    public function getWidth(): float {
        return $this->width;
    }

    public function fits(SquarePeg $peg): bool {
        return $this->getWidth() >= $peg->getWidth();
    }
}
```

### 2. **Класс для квадратных колышков:**

```
<?php
class SquarePeg {
    private $width;

    public function __construct($width) {
        $this->width = $width;
    }

    public function getWidth(): float {
        return $this->width;
    }
}
```

### 3. **Класс для круглых колышков:**

```
<?php
class RoundPeg {
    private $radius;

    public function __construct($radius) {
        $this->radius = $radius;
    }

    public function getRadius(): float {
        return $this->radius;
    }
}
```

### 4. **Адаптер, который позволит использовать `RoundPeg` в `SquareHole`:**

```
<?php
class RoundPegAdapter extends SquarePeg {
    private $roundPeg;

    public function __construct(RoundPeg $roundPeg) {
        $this->roundPeg = $roundPeg;
        // Рассчитываем эквивалентную ширину для квадратного отверстия, исходя из радиуса круга
        parent::__construct($this->roundPegToSquareWidth());
    }

    private function roundPegToSquareWidth(): float {
        // Диагональ квадрата вписывается в круг: ширина квадрата равна диаметру круга
        return $this->roundPeg->getRadius() * sqrt(2);
    }
}
```

### 5. **Пример использования:**

```
<?php
// Квадратное отверстие
$squareHole = new SquareHole(5);

// Квадратный колышек подходит
$squarePeg = new SquarePeg(5);
echo $squareHole->fits($squarePeg) ? "Квадратный колышек подходит!\n" : "Квадратный колышек не подходит!\n";

// Круглый колышек не подходит напрямую
$roundPeg = new RoundPeg(5);
$adapter = new RoundPegAdapter($roundPeg); // Адаптируем круглый колышек

echo $squareHole->fits($adapter) ? "Круглый колышек через адаптер подходит!\n" : "Круглый колышек не подходит!\n";
```

### Описание:
1. **Класс `SquareHole`** — это "клиент", который работает только с квадратными колышками через интерфейс `SquarePeg`.
2. **Класс `RoundPeg`** — это класс, который нужно адаптировать.
3. **Класс `RoundPegAdapter`** — это адаптер, который наследуется от `SquarePeg` и делает так, чтобы круглый колышек можно было использовать как квадратный. Он рассчитывает эквивалентную ширину квадрата на основе радиуса круга.

### Вывод в консоль:
```
Квадратный колышек подходит!
Круглый колышек через адаптер подходит!
```

### Объяснение:
- Адаптер `RoundPegAdapter` преобразует интерфейс круглого колышка в интерфейс квадратного отверстия. Он рассчитывает ширину квадрата, которая может содержать круг с данным радиусом, чтобы сделать круглые колышки совместимыми с квадратными отверстиями.

# Расскажи про шаблон проектирования адаптер?
<!-- basicblock-start  deck='P_patterns' -->
Расскажи про шаблон проектирования адаптер?::


Шаблон проектирования **Адаптер** (Adapter) относится к структурным паттернам и используется для того, чтобы два несовместимых интерфейса могли работать вместе. Он как бы "адаптирует" один интерфейс к другому, делая их совместимыми без изменения исходного кода самих классов.

### Основная задача
Адаптер нужен, когда необходимо использовать существующий класс, но его интерфейс не соответствует нужному. Вместо изменения самого класса (что может быть неудобно или невозможно, например, при работе с внешними библиотеками), мы создаем адаптер, который "переводит" интерфейс одного класса в ожидаемый интерфейс другого.

### Суть шаблона

- **Клиент** — это код, который использует какой-то интерфейс для работы.
- **Адаптируемый класс** (или сервис) — это существующий класс, который предоставляет полезные функции, но его интерфейс несовместим с клиентом.
- **Адаптер** — это класс, который оборачивает адаптируемый класс, чтобы сделать его совместимым с интерфейсом, который ожидает клиент.

### Пример

Предположим, у нас есть система, которая ожидает, что объект поддерживает интерфейс для работы с прямоугольниками, но у нас есть существующий класс для работы с кругами. Адаптер позволит использовать этот класс для работы с прямоугольниками.

#### Пример на TypeScript:

1. **Класс кругов**:
```
class Circle {
    constructor(public radius: number) {}

    getArea(): number {
        return Math.PI * Math.pow(this.radius, 2);
    }
}
```

2. **Интерфейс для работы с прямоугольниками**:
```
interface IRectangle {
    getWidth(): number;
    getHeight(): number;
}
```

3. **Адаптер для класса Circle**:
```
class CircleToRectangleAdapter implements IRectangle {
    private circle: Circle;

    constructor(circle: Circle) {
        this.circle = circle;
    }

    // Преобразуем круг в "эквивалентный" прямоугольник
    getWidth(): number {
        return this.circle.radius * 2;
    }

    getHeight(): number {
        return this.circle.radius * 2;
    }
}
```

4. **Клиентский код, работающий с прямоугольниками**:
```
function calculateRectangleArea(rectangle: IRectangle): number {
    return rectangle.getWidth() * rectangle.getHeight();
}

const circle = new Circle(5);
const adapter = new CircleToRectangleAdapter(circle);

console.log(`Площадь "прямоугольника", созданного на основе круга: ${calculateRectangleArea(adapter)}`);
```

Здесь `CircleToRectangleAdapter` адаптирует класс `Circle` под интерфейс `IRectangle`. В результате клиентский код может использовать круг как прямоугольник, что решает проблему несовместимости.

### Применение адаптера
- Когда вы хотите использовать существующий класс, но его интерфейс не соответствует вашим требованиям.
- Когда работаете с внешними библиотеками или сторонними API, и вам нужно подстроить их поведение под ваш код.
- Когда необходимо интегрировать новый функционал в уже существующую систему без изменения старых классов.

### Преимущества:
1. Упрощает интеграцию различных систем с несовместимыми интерфейсами.
2. Следует принципу единственной ответственности, так как не изменяет существующий код, а добавляет дополнительную "оболочку".

### Недостатки:
- В случае чрезмерного использования адаптеров может увеличиться сложность кода, что усложнит его поддержку и понимание.
  
Шаблон Адаптер помогает избежать сложностей, связанных с изменением существующего кода, и делает систему гибкой при изменении интерфейсов.
