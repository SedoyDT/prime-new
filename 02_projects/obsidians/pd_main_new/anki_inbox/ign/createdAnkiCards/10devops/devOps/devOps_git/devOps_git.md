# git reset --soft HEAD^ что делает эта команда?
<!-- basicblock-start oid="ObslpOFFVT3kRGEBnbgr9c4a"  deck='devOps_git' -->
git reset --soft HEAD^ что делает эта команда?::


Команда `git reset --soft HEAD^` в Git выполняет следующие действия:

1. **Перемещение HEAD**: Она сдвигает указатель HEAD на один коммит назад от текущего положения.

2. **Сохранение изменений**: Опция `--soft` указывает Git сохранить изменения из последнего коммита в рабочей директории и индексе. После выполнения этой команды все изменения, внесенные в последний коммит, остаются в индексе, как будто вы только что добавили их снова с помощью `git add`.

Таким образом, команда `git reset --soft HEAD^` используется для того, чтобы "отменить" последний коммит, оставив изменения из этого коммита в рабочей директории и индексе. Это полезно, например, если вы хотите внести изменения в последний коммит или добавить что-то в коммит, который вы только что сделали.

# Расскажи про создание пользователя в Linux
<!-- basicblock-start oid="ObspOXcuKsUuGvoFFvLzdE9d"  deck='devOps_git' -->
Расскажи про создание пользователя в Linux::


Создание пользователя в Linux — это процесс, который можно выполнить с помощью командной строки. В основном, для этого используется команда `useradd`, но также могут применяться `adduser` (в некоторых дистрибутивах) и другие инструменты для управления пользователями.

### 1. Команда `useradd`

Команда `useradd` используется для создания нового пользователя в системе. Она является более низкоуровневой и гибкой, чем `adduser`. Основной синтаксис выглядит так:

```

sudo useradd [опции] имя_пользователя

```

#### Пример создания пользователя:
```

sudo useradd john

```
Эта команда создаст пользователя с именем `john`, но не создаст домашнюю директорию и не установит пароль.

#### Полезные опции команды `useradd`:
- `-m`: Создает домашнюю директорию для пользователя.
- `-d /home/john`: Указывает домашнюю директорию (по умолчанию `/home/имя_пользователя`).
- `-s /bin/bash`: Указывает оболочку пользователя (например, `/bin/bash`).
- `-c "John Doe"`: Добавляет описание пользователя (например, полное имя).
- `-G group1,group2`: Добавляет пользователя в дополнительные группы.
- `-u 1001`: Указывает конкретный UID для пользователя.

#### Пример с опциями:
```

sudo useradd -m -d /home/john -s /bin/bash -c "John Doe" john

```
Эта команда создаст пользователя `john` с домашней директорией `/home/john`, оболочкой Bash и с описанием "John Doe".

### 2. Установка пароля

После создания пользователя нужно задать ему пароль. Это делается с помощью команды `passwd`:

```

sudo passwd john

```

После этого система запросит ввод и подтверждение пароля.

### 3. Команда `adduser`

В некоторых дистрибутивах Linux (например, в Ubuntu) существует команда `adduser`, которая является более дружелюбной оболочкой для `useradd`. Она автоматически выполняет большинство необходимых шагов и предлагает ввести данные (например, пароль) в процессе.

Пример создания пользователя с помощью `adduser`:

```

sudo adduser john

```

Эта команда:
1. Создаст пользователя `john`.
2. Создаст домашнюю директорию `/home/john`.
3. Запросит пароль для нового пользователя.
4. Настроит различные параметры пользователя, такие как полное имя и прочее.

### 4. Управление группами

При создании пользователя система автоматически создает группу с таким же именем, что и у пользователя. Однако вы можете добавить пользователя в дополнительные группы, например:

```

sudo usermod -aG sudo john

```

Эта команда добавляет пользователя `john` в группу `sudo`, что дает ему права суперпользователя.

### 5. Удаление пользователя

Чтобы удалить пользователя, используется команда `userdel`:

```

sudo userdel john

```

Если нужно также удалить домашнюю директорию пользователя:

```

sudo userdel -r john

```

### 6. Проверка созданного пользователя

Вы можете проверить, что пользователь успешно создан, с помощью команды `id`:

```

id john

```

Она покажет информацию о пользователе, такой как UID, GID и группы, к которым он принадлежит.

### Итог

Создание пользователя в Linux — это базовая задача, которую можно выполнять через командную строку с помощью команд `useradd` или `adduser`. Вы можете настроить параметры пользователя, такие как домашняя директория, группы, оболочка и пароль. После создания пользователь получает возможность входить в систему и выполнять операции в соответствии с его правами и принадлежностью к группам.

# 📌 **<u>В чём основное преимущество systemd?</u>** 
<!-- basicblock-start oid="ObsjpHLPTGKIRTR6fem3p8IF"  deck='devOps_git' -->
📌 **<u>В чём основное преимущество systemd?</u>** ::


💬 [Спрашивают в 13% собеседований](https://easyoffer.ru/rating/python_developer)

Основное преимущество systemd по сравнению с традиционными системами инициализации, такими как SysV init и Upstart, заключается в его расширенных функциональных возможностях и улучшенной производительности. Вот несколько ключевых аспектов, которые делают systemd более предпочтительным:

1️⃣** Параллельный запуск сервисов**

**Что это:** 
systemd позволяет запускать службы параллельно, в то время как SysV init запускает их последовательно.

**Почему это важно:** 
Параллельный запуск значительно ускоряет время загрузки системы, что особенно важно для серверов и рабочих станций с большим количеством сервисов.

2️⃣** Упрощённое управление зависимостями**

**Что это:** 
systemd автоматически определяет и управляет зависимостями между службами, используя унифицированный формат конфигурации.

**Почему это важно:** 
Это снижает вероятность ошибок конфигурации и облегчает управление службами, так как все зависимости четко определены и отслеживаются.

3️⃣** Мониторинг и управление сервисами**

**Что это:** 
systemd предоставляет встроенные механизмы для мониторинга состояния служб, их перезапуска при сбоях и сбора логов.

**Почему это важно:** 
Это повышает надежность системы, так как службы автоматически перезапускаются в случае сбоев, а администратор может легко отслеживать их состояние и получать диагностическую информацию.

4️⃣** Удобные конфигурационные файлы**

**Что это:** 
systemd использует простые и читаемые файлы конфигурации в формате INI для определения служб и их параметров.

**Почему это важно:** 
Эти файлы легко редактировать и понимать, что упрощает настройку и управление службами для администраторов.

5️⃣ **Поддержка современных функций**

**Что это:** 
systemd поддерживает множество современных функций, таких как cgroups для управления ресурсами, таймеры для замены cron-джобов и сокет-активацию для запуска служб по запросу.

**Почему это важно:** 
Эти функции позволяют более гибко и эффективно управлять ресурсами системы, автоматизировать задачи и улучшать общую производительность.

🤔** Примеры использования**

🤔 **Пример файла сервиса systemd:**
```
[Unit]
Description=My Example Service

[Service]
ExecStart=/usr/bin/myservice
Restart=always

[Install]
WantedBy=multi-user.target
```

Этот файл конфигурации определяет сервис, который будет запускаться после сети и автоматически перезапускаться в случае сбоя.

4️⃣ **systemd** использует удобные конфигурационные файлы.

# Команда `git stash` временно сохраняет изменения в рабочей директории и индексе (stage) в "тайник" (stash), чтобы вы могли вернуться к чистому состоянию ветки. Это особенно полезно, если вам нужно переключиться на другую ветку или выполнить `git pull`, но у вас есть несохранённые изменения.
<!-- basicblock-start oid="Obs1KlCaFyNk7mMbaQeVZ3ti"  deck='devOps_git' -->
Команда `git stash` временно сохраняет изменения в рабочей директории и индексе (stage) в "тайник" (stash), чтобы вы могли вернуться к чистому состоянию ветки. Это особенно полезно, если вам нужно переключиться на другую ветку или выполнить `git pull`, но у вас есть несохранённые изменения.::


### Основные команды `git stash`:

1. **Сохранение изменений в stash**:
   ```
   git stash
   
```
   Эта команда сохранит все незафиксированные изменения (включая изменения в индексе) и вернёт рабочую директорию к последнему зафиксированному состоянию.

2. **Сохранение с сообщением**:
   Если вы хотите добавить описание к сохранённым изменениям:
   ```
   git stash save "Your message here"
   
```

3. **Просмотр списка stash**:
   Чтобы увидеть все сохранённые состояния:
   ```
   git stash list
   
```
   Вы увидите список всех stash с их индексами и сообщениями (если они были добавлены).

4. **Применение изменений из stash**:
   Чтобы восстановить последнее сохранённое состояние:
   ```
   git stash apply
   
```
   Эта команда применяет изменения, но не удаляет их из stash. Если вы хотите применить конкретный stash, укажите его индекс:
   ```
   git stash apply stash@{1}
   
```

5. **Применение и удаление из stash**:
   Чтобы применить изменения и удалить их из stash:
   ```
   git stash pop
   
```
   Это эквивалентно выполнению `git stash apply` с последующим `git stash drop`.

6. **Удаление stash**:
   Если вы хотите удалить конкретный stash:
   ```
   git stash drop stash@{0}
   
```
   Для удаления всех stash:
   ```
   git stash clear
   
```

7. **Сохранение с учётом неотслеживаемых файлов**:
   По умолчанию `git stash` не сохраняет неотслеживаемые файлы. Если вы хотите включить их в stash:
   ```
   git stash -u
   
```
   Или:
   ```
   git stash --include-untracked
   
```

### Пример использования:
Допустим, у вас есть незавершённая работа, но вам нужно срочно переключиться на другую ветку:
```
git stash           # Сохранение изменений
git checkout другой-branch  # Переключение на другую ветку
# ... выполняете нужные действия в другой ветке ...
git checkout исходный-branch  # Возвращение на исходную ветку
git stash pop       # Восстановление изменений
```

`git stash` — это мощный инструмент, позволяющий вам временно сохранить свои изменения и вернуться к ним позже, не теряя никакой работы.

# Этот Git-сообщение говорит о том, что у вас есть расхождения между локальной и удалённой ветками, и Git не знает, как их объединить. Вам нужно указать предпочтительную стратегию слияния. Вот что означают различные параметры и как их использовать:
<!-- basicblock-start oid="ObsMCklhVW2btKTnXjlS3VaY"  deck='devOps_git' -->
Этот Git-сообщение говорит о том, что у вас есть расхождения между локальной и удалённой ветками, и Git не знает, как их объединить. Вам нужно указать предпочтительную стратегию слияния. Вот что означают различные параметры и как их использовать:::


### 1. **Использование слияния (merge)**:
   Если вы хотите объединить изменения из удалённой ветки в локальную с помощью merge-коммита (по умолчанию):
   ```
   git config pull.rebase false
   
```
   Либо, если хотите применить это глобально для всех репозиториев:
   ```
   git config --global pull.rebase false
   
```
   После этого можно выполнить `git pull`, и изменения будут слиты с помощью merge.

### 2. **Использование перемещения (rebase)**:
   Если вы хотите выполнить rebase (переместить ваши локальные коммиты поверх удалённых):
   ```
   git config pull.rebase true
   
```
   Либо глобально:
   ```
   git config --global pull.rebase true
   
```
   Затем выполните `git pull`, и ваши коммиты будут перемещены поверх изменений из удалённой ветки.

### 3. **Только fast-forward слияние**:
   Если вы хотите, чтобы `git pull` делал слияние только если возможно fast-forward (то есть, если нет конфликтов и локальные изменения линейно следуют за удалёнными):
   ```
   git config pull.ff only
   
```
   Либо глобально:
   ```
   git config --global pull.ff only
   
```
   В этом случае, если fast-forward невозможно, Git выдаст ошибку.

### **Альтернативный вариант: Указание опции прямо при выполнении `git pull`**:
   Если вы не хотите менять конфигурацию, можете указать стратегию слияния непосредственно при выполнении команды:
   - Для слияния: `git pull --no-rebase`
   - Для rebase: `git pull --rebase`
   - Для fast-forward only: `git pull --ff-only`

После указания предпочтительной стратегии слияния, Git будет знать, как поступать в ситуациях с расхождениями в будущем.
