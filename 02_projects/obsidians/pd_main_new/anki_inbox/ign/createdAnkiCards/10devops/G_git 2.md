# Как правильно делать git patch чтобы не было проблемы whitespace?
<!-- basicblock-start oid="ObsCHeHOeSoD28UqhU5FzxMi"  deck='G_git' -->
Как правильно делать git patch чтобы не было проблемы whitespace?::


Чтобы избежать проблем с пробелами (whitespace) при создании и применении патчей в Git, рекомендуется следовать ряду правил и использовать встроенные опции Git. Вот как это можно сделать:

### 1. **Удаление лишних пробелов перед созданием патча**
Перед созданием патча убедитесь, что в коде нет лишних пробелов, особенно в конце строк или пустых строках. Git предоставляет команду, которая позволяет найти такие пробелы:

```
git diff --check
```

Эта команда покажет вам все места в изменениях, где есть проблемы с пробелами, такие как "trailing whitespace" (пробелы в конце строк).

### 2. **Использование флага `--whitespace=fix`**
Git позволяет автоматически исправлять пробелы при создании и применении патчей с помощью флага `--whitespace=fix`.

#### Пример при создании патча:
Чтобы избежать проблем с пробелами при создании патча, можно сначала их исправить:

```
git diff --whitespace=fix > my-fix.patch
```

Этот флаг автоматически удаляет лишние пробелы из диффов.

#### Пример при применении патча:
Чтобы автоматически исправить пробелы при применении патча, можно использовать флаг `--whitespace=fix`:

```
git apply --whitespace=fix my-fix.patch
```

Этот флаг исправит проблемы с пробелами в процессе применения патча.

### 3. **Настройка Git для автоматического удаления пробелов**
Можно настроить Git на автоматическое удаление пробелов в конце строк во время коммитов с помощью опции `core.whitespace`.

```
git config --global apply.whitespace fix
```

Это автоматически будет исправлять пробелы при создании и применении патчей в вашем репозитории.

### 4. **Использование хуков pre-commit**
Чтобы автоматически удалять пробелы перед коммитом, можно использовать хук Git `pre-commit`. Для этого создайте файл `.git/hooks/pre-commit` и добавьте в него следующий код:

```
#!/bin/sh
git diff-index --check --cached HEAD --
```

Сделайте этот файл исполняемым:

```
chmod +x .git/hooks/pre-commit
```

Теперь при каждом коммите Git будет проверять на наличие лишних пробелов и предотвращать коммит, если они есть.

### 5. **Ручное исправление пробелов перед коммитом**
Вы также можете использовать встроенные команды текстовых редакторов для автоматического удаления пробелов. Например, в редакторах, таких как VSCode или PHPStorm, есть опция удаления пробелов в конце строк при сохранении файлов.

### Заключение
- Проверяйте свои изменения с помощью команды `git diff --check`.
- Используйте флаг `--whitespace=fix` при создании и применении патчей.
- Настройте Git на автоматическое удаление пробелов через конфигурацию или хуки.

Это позволит вам избежать проблем с пробелами при создании и применении патчей.

# поиск файлов и стории git ?
<!-- basicblock-start oid="Obs1oX7Kt2hSXzEpgGtLjxXe"  deck='G_git' -->
поиск файлов и стории git ?::


В Git существует множество команд и инструментов для поиска файлов, изменения их истории и анализа изменений в репозитории. Давайте рассмотрим основные команды и подходы для этих задач.

### 1. Поиск файлов в репозитории Git

Если вам нужно найти файл в репозитории Git или проверить, какие файлы присутствуют в определённом коммите или ветке, вы можете использовать следующие команды:

- **Поиск файла по имени:**

  Вы можете использовать команду `git ls-files` в сочетании с `grep`, чтобы найти файл по его имени в текущей ветке:

  ```
  git ls-files | grep "filename"
  
```

  Например, чтобы найти файл с именем `index.html`:

  ```
  git ls-files | grep "index.html"
  
```

- **Поиск файла в истории (по всем коммитам):**

  Если вам нужно найти коммит, в котором файл был добавлен, изменен или удален, используйте команду `git log`:

  ```
  git log --all --pretty=format:'%h %s' --name-only | grep "filename"
  
```

  Это покажет все коммиты, связанные с файлом.

- **Поиск файла в конкретной ветке:**

  Если вы хотите найти файл в определённой ветке, вы можете указать ветку перед файлом:

  ```
  git ls-tree -r branch_name --name-only | grep "filename"
  
```

  Например:

  ```
  git ls-tree -r main --name-only | grep "index.html"
  
```

### 2. История изменений файлов

Чтобы изучить историю изменений определённого файла, используйте следующие команды:

- **Просмотр истории изменений файла:**

  Используйте команду `git log`, чтобы просмотреть историю коммитов, связанных с определённым файлом:

  ```
  git log --follow -- filename
  
```

  Флаг `--follow` нужен для отслеживания изменений файла даже если он был переименован.

  Например:

  ```
  git log --follow -- index.html
  
```

- **Просмотр изменений в конкретном файле:**

  Чтобы увидеть, как файл изменился в каждом коммите, используйте команду `git log` с флагом `-p`:

  ```
  git log -p -- filename
  
```

  Это покажет диффы (различия) между версиями файла в каждом коммите.

- **Показать конкретный коммит:**

  Чтобы посмотреть изменения файла в конкретном коммите, используйте `git show`:

  ```
  git show commit_hash -- filename
  
```

  Например:

  ```
  git show 9fceb02 -- index.html
  
```

  Это покажет изменения, внесённые в файл `index.html` в коммите `9fceb02`.

### 3. Восстановление и удаление файлов

- **Восстановление удалённого файла:**

  Если файл был удалён и вы хотите его восстановить, используйте команду `git checkout`:

  ```
  git checkout commit_hash -- filename
  
```

  Например:

  ```
  git checkout HEAD~1 -- index.html
  
```

  Это восстановит версию файла `index.html` из предыдущего коммита.

- **Удаление файла из истории:**

  Если вам нужно удалить файл из истории репозитория (например, если он содержит конфиденциальную информацию), используйте команду `git filter-repo` (раньше это была `git filter-branch`, но её использование не рекомендуется из-за сложности и риска порчи репозитория).

  Установите `git-filter-repo` и используйте его:

  ```
  git filter-repo --path filename --invert-paths
  
```

  Это удалит файл `filename` из всех коммитов в истории.

### 4. Поиск по содержимому файлов

Если вам нужно найти файлы по содержимому, можно использовать следующие команды:

- **Поиск текста по всей истории:**

  Чтобы найти строки в истории коммитов, используйте `git grep`:

  ```
  git grep "search_term"
  
```

  Например, чтобы найти все упоминания слова "TODO":

  ```
  git grep "TODO"
  
```

- **Поиск по истории коммитов:**

  Если нужно найти текст в истории коммитов, используйте `git log`:

  ```
  git log -S "search_term"
  
```

  Это покажет все коммиты, в которых текст "search_term" был добавлен или удалён.

### Заключение

Git предоставляет мощные инструменты для поиска файлов, анализа изменений и работы с историей. Эти команды позволяют эффективно управлять и исследовать репозиторий, находя нужные файлы и анализируя их изменения на разных этапах разработки.
