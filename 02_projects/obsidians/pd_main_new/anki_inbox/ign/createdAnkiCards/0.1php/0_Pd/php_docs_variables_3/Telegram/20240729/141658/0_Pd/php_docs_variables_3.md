Что можно сказать про правила создания переменных?::


ледующий список правил даёт обзор прав именования, которые проект PHP оставляет себе при выборе новых идентификаторов. Полным руководством является официальный "» Стандарт написания кода":

    PHP владеет глобальным пространством имён, но старается находить хорошие описательные имена и избегать любых очевидных коллизий.

    Имена функций используют подчёркивания между словами, а имена классов используют как camelCase, так и PascalCase.

    PHP добавляет префикс к глобальным именам, принадлежащим модулю с именем этого модуля. В прошлом было множество исключений из этого правила, например:

        curl_close()

        mysql_query()

        PREG_SPLIT_DELIM_CAPTURE

        new DOMDocument()

        strpos() (пример исключения, допущенного в прошлом)

        new SplFileObject()

    Тем не менее, итераторы и исключения просто получают постфиксы "Iterator" и "Exception". Примеры:

        ArrayIterator

        LogicException

    PHP резервирует все идентификаторы, начинающиеся с * как магические. Рекомендуется не создавать идентификаторы, начинающиеся с* , кроме как с целью использовать документированную магическую функциональность. Примеры:

        __get()

        __autoload()
