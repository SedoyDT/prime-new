# **Какой синтаксис у заголовков ?**
<!-- basicblock-start oid="Obsy7oHv2GTpva4EeL14D5Sq"  deck='1_PD_php' -->
**Какой синтаксис у заголовков ?**::

*Спросят с вероятностью 7%*

<u>Заголовки</u> в языках и разметки часто используются для указания ключевой информации, на которую стоит обратить внимание, и они различаются в зависимости от конкретного контекста и языка. Ниже приведены примеры синтаксиса заголовков в различных контекстах:

**Заголовки в HTML**

Поддерживает шесть уровней заголовков, от `<h1>` до `<h6>`, где `<h1>` представляет самый важный заголовок, а `<h6>` — наименее важный.
```
<h1>Заголовок уровня 1</h1>
<h2>Заголовок уровня 2</h2>
<h3>Заголовок уровня 3</h3>
<h4>Заголовок уровня 4</h4>
<h5>Заголовок уровня 5</h5>
<h6>Заголовок уровня 6</h6>
```

**Заголовки в Markdown**

Это язык разметки, который упрощает форматирование текста, особенно для написания документации. Заголовки создаются с помощью символа `#` перед текстом заголовка. Количество символов `#` определяет уровень заголовка.
```
# Заголовок уровня 1
## Заголовок уровня 2
### Заголовок уровня 3
#### Заголовок уровня 4
##### Заголовок уровня 5
###### Заголовок уровня 6
```

**Заголовки в LaTeX**

Это система подготовки документов, широко используемая для научных и технических документов. В LaTeX заголовки создаются с помощью команд `\section`, `\subsection`, `\subsubsection` и так далее.
```
\section{Заголовок уровня 1}
\subsection{Заголовок уровня 2}
\subsubsection{Заголовок уровня 3}
\paragraph{Заголовок уровня 4}
\subparagraph{Заголовок уровня 5}
```

**Заголовки в Языке разметки Wiki**

Многие вики-движки (например, MediaWiki) используют свои синтаксисы для создания заголовков. В MediaWiki заголовки создаются с помощью равно (`=`) вокруг текста заголовка.
```
= Заголовок уровня 1 =
== Заголовок уровня 2 ==
=== Заголовок уровня 3 ===
==== Заголовок уровня 4 ====
===== Заголовок уровня 5 =====
====== Заголовок уровня 6 ======
```

**Заголовки в языках** 

Часто не используются так же, как в разметке, но комментарии могут выполнять схожую роль для организации и документирования кода. Примеры синтаксиса для комментариев-заголовков:

**Python**
```
# Заголовок уровня 1
## Заголовок уровня 2
### Заголовок уровня 3
```

**JavaScript**
```
// Заголовок уровня 1
// =================
// Заголовок уровня 2
// -----------------
// Заголовок уровня 3
// ~~~~~~~~~~~~~~~~~
```

Синтаксис заголовков варьируется в зависимости от используемого языка или системы разметки. В HTML и Markdown существуют чёткие уровни заголовков от 1 до 6, а в LaTeX и вики-движках используются соответствующие команды и символы. В языках программирования заголовки не являются частью синтаксиса, но комментарии могут использоваться для создания подобной структуры.

# **Что такое динамическая типизация ?**
<!-- basicblock-start oid="ObsRUi8qurkPBSNBKSDXIj1h"  deck='1_PD_php' -->
**Что такое динамическая типизация ?**::

*Спросят с вероятностью 20%*

<u>Динамическая типизация</u> означает, что типы данных переменных определяются во время выполнения программы, и одна и та же переменная может последовательно принимать значения разных типов. Это добавляет гибкости при разработке, но также требует внимательности, чтобы избежать типовых ошибок.

Вот пример, демонстрирующий, как переменная может менять свой тип в зависимости от контекста использования:
```
<?php
$x = 42;        // Сначала $x — целое число
echo gettype($x);  // выводит: integer

$x = "Hello, world!";  // Теперь $x — строка
echo gettype($x);  // выводит: string

$x = 42.5;       // Теперь $x — число с плавающей точкой
echo gettype($x);  // выводит: double

$x = true;       // Теперь $x — булев тип
echo gettype($x);  // выводит: boolean
?>
```

В этом коде переменная `$x` последовательно принимает значения различных типов: целое число, строка, число с плавающей точкой и булев тип. Функция `gettype()` используется для вывода текущего типа переменной `$x`.

Динамическая типизация также позволяет производить различные операции с переменными разных типов без явного преобразования типов:
```
<?php
$x = "10";           // $x — строка
$y = 20;             // $y — целое число

$sum = $x + $y;      // Прибавление строки к числу
echo $sum;           // Выводит: 30

$concatenation = $x . $y;  // Конкатенация строки и числа
echo $concatenation;  // Выводит: 1020
?>
```

В этом примере переменная `$x` является строкой, а `$y` — целым числом. При сложении `$x + $y` PHP автоматически приводит строку к числу, и результатом является числовая сумма. При конкатенации же (`$x . $y`) числовое значение `$y` преобразуется в строку, и результатом является строковая конкатенация.

Динамическая типизация упрощает многие аспекты разработки за счет автоматического приведения типов и возможности использовать переменные в различных контекстах. Однако это также может привести к ошибкам, если не обращать внимание на текущий тип переменной и не предусматривать проверки типов там, где это необходимо.

# **Имеет ли значение регистр заголовка ?**
<!-- basicblock-start oid="ObsveMTIL2ktXxacnH7h68Jk"  deck='1_PD_php' -->
**Имеет ли значение регистр заголовка ?**::

*Спросят с вероятностью 7%*

<u>Значение регистра</u> заголовков может варьироваться в зависимости от конкретного контекста или системы разметки, в которой используются заголовки. Рассмотрим несколько примеров, чтобы понять, как различные системы относятся к регистру заголовков.

**HTML**

Регистр заголовков не имеет значения. Теги HTML не чувствительны к регистру, поэтому `<H1>Заголовок</H1>` и `<h1>Заголовок</h1>` будут интерпретироваться одинаково.
```
<h1>Заголовок</h1>
<H1>Заголовок</H1>
```

Оба варианта будут отображены одинаково.

**Markdown**

Регистр заголовков также не имеет значения для самой разметки, но обычно принято использовать заглавные буквы для первых букв слов в заголовках, чтобы улучшить читаемость.
```
# Заголовок
# заголовок
```

Оба варианта будут интерпретированы как заголовки первого уровня.

**LaTeX**

Регистр заголовков тоже не имеет значения с точки зрения разметки, но стандартной практикой является использование заглавных букв в начале каждого важного слова для улучшения читаемости.
```
\section{Заголовок}
\section{заголовок}
```

Оба варианта создадут заголовок первого уровня, хотя стандартный стиль предпочтёт использование заглавных букв.

**Wiki-разметка (например, MediaWiki)**

Регистр заголовков не влияет на разметку, но для консистентности и лучшей читаемости заголовки часто оформляют с заглавными буквами.
```
= Заголовок =
= заголовок =
```

Оба варианта будут интерпретированы как заголовки первого уровня.

**Языки программирования**

Как таковые не используются, но комментарии-заголовки могут быть оформлены по-разному. Регистр здесь также не имеет значения для компилятора или интерпретатора, но для людей, читающих код, использование заглавных букв может сделать заголовки более заметными.
```
# ЗАГОЛОВОК УРОВНЯ 1
# заголовок уровня 1
```

Оба варианта являются допустимыми комментариями.
```
// ЗАГОЛОВОК УРОВНЯ 1
// заголовок уровня 1
```

Оба варианта работают как комментарии.

В большинстве систем разметки и языков регистр заголовков не влияет на их интерпретацию. Однако, для улучшения читаемости и консистентности, часто используется определённый стиль написания заголовков, обычно с заглавными буквами для первых букв важных слов. Это соглашение делает заголовки более заметными и понятными для людей, читающих текст или код.

# **Как браузер понимает, что заголовки закончились ?**
<!-- basicblock-start oid="ObseTbC2A9V9A4MuopdBeyQT"  deck='1_PD_php' -->
**Как браузер понимает, что заголовки закончились ?**::

*Спросят с вероятностью 7%*

<u>Заголовки (headers)</u> передаются в запросах и ответах для передачи метаданных о самом запросе или ответе. Браузер, как и другие HTTP-клиенты и серверы, понимает, что заголовки закончились, благодаря определённым правилам протокола HTTP.

**Как браузер понимает, что заголовки закончились**

1️⃣**Разделение заголовков и тела сообщения**:
✅Заголовки HTTP отделяются от тела сообщения пустой строкой. В HTTP-протоколе пустая строка (двойной перенос строки, или CRLF CRLF) сигнализирует о завершении заголовков.
   
2️⃣**Формат заголовков**:
✅Каждый заголовок начинается с имени заголовка, за которым следует двоеточие и значение заголовка. Например:
```

     Content-Type: text/html
     Content-Length: 1234
     
```
✅Заголовки передаются в виде строки, где каждый заголовок заканчивается CRLF (`\r\n`).
```
GET /index.html HTTP/1.1
Host: www.example.com
Connection: keep-alive
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/91.0.4472.124 Safari/537.36
Accept: text/html,application/xhtml+xml,application/xml;q=0.9,image/webp,*/*;q=0.8

<тело сообщения при необходимости>
```

В этом примере пустая строка после заголовков говорит браузеру, что заголовки закончились и начинается тело сообщения (если оно есть).
```
HTTP/1.1 200 OK
Date: Mon, 27 May 2024 12:28:53 GMT
Server: Apache/2.4.1 (Unix)
Last-Modified: Tue, 15 Nov 2022 12:45:26 GMT
Content-Length: 88
Content-Type: text/html
Connection: Closed

<тело сообщения>
```

Опять же, пустая строка (CRLF CRLF) отделяет заголовки от тела ответа.

Браузер понимает, что HTTP-заголовки закончились, благодаря присутствию пустой строки, которая отделяет заголовки от тела сообщения. Это ключевое правило протокола HTTP, позволяющее корректно интерпретировать данные запроса и ответа.

Опять же, пустая строка (CRLF CRLF) отделяет заголовки от тела ответа.

Браузер понимает, что HTTP-заголовки закончились, благодаря присутствию пустой строки, которая отделяет заголовки от тела сообщения. Это ключевое правило протокола HTTP, позволяющее корректно интерпретировать данные запроса и ответа.

# **В чем разница между merge и rebase ?**
<!-- basicblock-start oid="ObsIhuKAv5vhIT07mIOntP6d"  deck='1_PD_php' -->
**В чем разница между merge и rebase ?**::

*Спросят с вероятностью 20%*
<u>
merge и rebase</u> являются двумя различными способами интеграции изменений из одной ветки в другую. Оба метода используются для слияния изменений, но они делают это по-разному и имеют различные последствия для истории коммитов.

**merge**

Используется для объединения изменений из одной ветки в другую. `Merge` создаёт новый коммит, который автоматически имеет двух родителей: один указывает на последний коммит текущей ветки (на которую вы сейчас нацелены), а другой — на коммит из сливаемой ветки.

**Особенности:**
**✅Не изменяет историю.** История сохраняется такой, какая она есть, что может быть полезно для сохранения полной истории проекта и контекста изменений.
**✅Создаёт "merge commit".** Этот коммит объединяет истории двух веток, что иногда может привести к загромождению истории, особенно в больших проектах с множеством веток.
```
git merge feature-branch
```
Эта команда объединит изменения из `feature-branch` в текущую ветку.

**Rebase**

Это другой способ интеграции изменений, который фактически переносит ветку на новую базу. При его использовании коммиты из одной ветки переносятся и применяются поверх другой ветки.

**Особенности:**
**✅Изменяет историю.** Переписывает историю коммитов, что делает её более чистой и линейной.
**✅Избегает лишних merge commits.** История коммитов выглядит как последовательный поток, что может облегчить понимание истории изменений.
**✅Может быть рискованным.** Изменение истории веток, которые уже были опубликованы и используются другими разработчиками, может привести к конфликтам и потребует от всех участников проекта пересинхронизировать свои репозитории.
```
git rebase master
```
Эта команда перенесёт текущую ветку на вершину ветки `master`.
**
Когда их использовать**

**✅Используйте** `merge`**,** если вам важно сохранить точную историю изменений и когда работаете в команде, где изменения регулярно синхронизируются между множеством веток.
**✅Используйте** `rebase`**,** если вы хотите поддерживать чистую и линейную историю изменений, особенно перед вливанием локальной ветки в основную. Однако важно сначала получить последние изменения из основной ветки и только после этого выполнять rebase.

Выбор между merge и rebase может зависеть от конкретной ситуации и от того, какие приоритеты и политики установлены в вашем проекте относительно управления версиями.

# **Что такое протокол ?**
<!-- basicblock-start oid="ObscxPLO1Py8LraPIglUMG0Z"  deck='1_PD_php' -->
**Что такое протокол ?**::

*Спросят с вероятностью 7%*

<u>Протокол</u> — это набор правил и стандартов, которые определяют, как данные должны передаваться между различными устройствами в сети. Протоколы обеспечивают согласованность и упорядоченность в обмене данными, позволяя различным системам и устройствам взаимодействовать друг с другом.

**Типы** 

Можно классифицировать по различным уровням сетевой модели OSI (Open Systems Interconnection) и TCP/IP модели.

**Протоколы прикладного уровня (Application Layer)**

1️⃣**HTTP (Hypertext Transfer Protocol)**:
✅Протокол для передачи гипертекста, используемый в интернете для просмотра веб-страниц.
✅Работает по принципу запрос-ответ между клиентом (например, браузером) и сервером.

2️⃣**FTP (File Transfer Protocol)**:
✅Протокол для передачи файлов между клиентом и сервером.
✅Поддерживает функции загрузки и скачивания файлов.

3️⃣**SMTP (Simple Mail Transfer Protocol)**:
✅Протокол для передачи электронной почты.
✅Используется для отправки сообщений от клиента к серверу и между серверами.

**Протоколы транспортного уровня (Transport Layer)**

1️⃣**TCP (Transmission Control Protocol)**:
✅Обеспечивает надежную, управляемую передачу данных.
✅Гарантирует доставку данных в правильном порядке и без потерь.

2️⃣**UDP (User Datagram Protocol)**:
✅Обеспечивает быструю, но ненадежную передачу данных.
✅Не гарантирует доставку и порядок получения данных, но менее затратен по ресурсам.

**Протоколы сетевого уровня (Network Layer)**

1️⃣**IP (Internet Protocol)**:
✅Основной протокол для передачи данных по сети.
✅Использует IP-адреса для маршрутизации пакетов данных от отправителя к получателю.

2️⃣**ICMP (Internet Control Message Protocol)**:
✅Протокол для передачи сообщений об ошибках и диагностической информации.
✅Используется, например, для команды `ping`.

**Протоколы канального уровня (Data Link Layer)**

1️⃣**Ethernet**:
✅Протокол для локальных сетей (LAN), определяющий физические и канальные аспекты передачи данных.
✅Использует MAC-адреса для идентификации устройств в сети.

2️⃣**PPP (Point-to-Point Protocol)**:
✅Протокол для прямого соединения двух точек.
✅Часто используется для соединений через телефонные линии.

**Когда вы вводите URL в браузере, происходит следующий процесс:**

1️⃣**Запрос HTTP**: Браузер отправляет HTTP-запрос к серверу, запрашивая нужную веб-страницу.
2️⃣**Ответ HTTP**: Сервер отправляет обратно HTTP-ответ, содержащий код состояния (например, 200 OK) и содержимое страницы.
3️⃣**Отображение**: Браузер отображает полученную страницу на экране пользователя.

Протоколы являются критически важными для обеспечения связи и взаимодействия между различными устройствами и системами в сети. Они определяют правила и стандарты передачи данных, обеспечивая надежность, согласованность и безопасность обмена информацией.

# **Что такое статическое связывание ?**
<!-- basicblock-start oid="ObsLMdhNephkxh48i0FtizdH"  deck='1_PD_php' -->
**Что такое статическое связывание ?**::

*Спросят с вероятностью 20%*
<u>
Статическое связывание</u> также играет важную роль, особенно когда дело доходит до разрешения вызовов методов в контексте наследования классов. Использует позднее статическое связывание для предоставления контекста вызова в статических методах, что позволяет переопределять статические методы в дочерних классах. Рассмотрим это на примере.
```
class BaseClass {
    public static function who() {
        echo "Я BaseClass\n";
    }

    public static function test() {
        self::who(); // Здесь используется статическое связывание
    }
}

class ChildClass extends BaseClass {
    public static function who() {
        echo "Я ChildClass\n";
    }
}

BaseClass::test(); // Вывод: Я BaseClass
ChildClass::test(); // Вывод: Я BaseClass
```

В этом примере, вызов `ChildClass::test()` приводит к выводу "Я BaseClass", поскольку метод `test()` в базовом классе привязан статически к методу `who()` базового класса через `self::`, который не учитывает контекст вызывающего класса.

Предоставляет ключевое слово `static::`, которое позволяет переопределять статические методы в контексте наследования, используя так называемое "позднее статическое связывание".
```
class BaseClass {
    public static function who() {
        echo "Я BaseClass\n";
    }

    public static function test() {
        static::who(); // Используется позднее статическое связывание
    }
}

class ChildClass extends BaseClass {
    public static function who() {
        echo "Я ChildClass\n";
    }
}

BaseClass::test(); // Вывод: Я BaseClass
ChildClass::test(); // Вывод: Я ChildClass
```

Здесь, когда вызывается `ChildClass::test()`, `static::who()` корректно определяет, что должен быть вызван переопределённый метод `who()` в `ChildClass`, и поэтому выводится "Я ChildClass". Это поведение особенно полезно в шаблонах проектирования, где поведение базового класса должно быть расширено или модифицировано в производных классах.

Gозднее статическое связывание позволяет обеспечить более гибкое поведение статических методов в иерархии классов, что делает его мощным инструментом для ООП.

# **Какую проблему решают фабрика и фабричный метод ?**
<!-- basicblock-start oid="ObsEiBc1cjGMzeK48XMpuuKp"  deck='1_PD_php' -->
**Какую проблему решают фабрика и фабричный метод ?**::

*Спросят с вероятностью 20%*

Паттерны проектирования<u> "Фабрика" (Factory) и "Фабричный метод" (Factory Method)</u> помогают решать общую проблему в программировании — создание объектов без указания конкретных классов продуктов. Оба паттерна предлагают способ делегирования процесса инстанциации объектов в специальные классы или методы, что упрощает управление зависимостями и делает систему более модульной и легко расширяемой.

**Фабричный метод (Factory Method)**

Этот паттерн определяет интерфейс для создания объекта, но позволяет подклассам изменять тип создаваемых объектов. Таким образом, классы могут делегировать создание экземпляров другим классам.

**Проблемы, которые он решает:**
**1️⃣Гибкость**: Позволяет классам оставаться независимыми от конкретных классов продуктов, которые они должны создавать.
**2️⃣Расширяемость**: Упрощает добавление новых продуктов или изменение существующих без изменения существующего кода, который их создает.
**3️⃣Декаплинг**: Изолирует конкретные классы, упрощая замену, расширение и управление зависимостями.
```
interface Product {
    public function operation(): string;
}

class ConcreteProductA implements Product {
    public function operation(): string {
        return "Результат работы продукта A";
    }
}

class ConcreteProductB implements Product {
    public function operation(): string {
        return "Результат работы продукта B";
    }
}

abstract class Creator {
    abstract public function factoryMethod(): Product;

    public function someOperation(): string {
        $product = $this->factoryMethod();
        return "Creator: тот же самый код работает с " . $product->operation();
    }
}

class ConcreteCreatorA extends Creator {
    public function factoryMethod(): Product {
        return new ConcreteProductA();
    }
}

class ConcreteCreatorB extends Creator {
    public function factoryMethod(): Product {
        return new ConcreteProductB();
    }
}

function clientCode(Creator $creator) {
    echo $creator->someOperation();
}

clientCode(new ConcreteCreatorA());
clientCode(new ConcreteCreatorB());
```
**
Фабрика (Factory)**

Представляет собой другой способ создания объектов — специальный класс или метод, который создает и возвращает экземпляры объектов. Этот паттерн обычно используется, когда нужно создать несколько различных, но похожих типов объектов.

**Проблемы, которые она решает:**
**1️⃣Централизация логики создания**: Хранение всей логики создания объектов в одном месте упрощает обслуживание и изменения.
**2️⃣Отделение кода**: Изоляция кода создания объектов от их использования.
**3️⃣Управление комплексными процессами создания**: Фабрика может обрабатывать сложные процессы создания, включая инициализацию различных членов объекта.
```
class CarFactory {
    public static function createCar($type) {
        if ($type === 'sedan') {
            return new Sedan();
        } elseif ($type === 'suv') {
            return new SUV();
        } else {
            throw new Exception("Тип автомобиля не поддерживается.");
        }
    }
}

class Sedan {
    public function describe() {
        return "Я седан";
    }
}

class SUV {
    public function describe() {
        return "Я внедорожник";
    }
}

$car = CarFactory::createCar('sedan');
echo $car->describe();
```

Оба паттерна — Фабрика и Фабричный метод — помогают упростить создание объектов, делая систему более гибкой и поддерживаемой. Они позволяют изменять и добавлять новые типы объектов без внесения изменений в код, который эти объекты использует, обеспечивая тем самым лучшую организацию кода и его масштабируемость.

**Для чего нужен middleware ?**::

<u>
Middleware</u> — это ПО, которое располагается между веб-сервером и приложением. Оно обрабатывает входящие запросы до того, как они достигнут вашего приложения, или обрабатывает исходящие ответы после того, как приложение их сгенерировало.

**Зачем он нужен**
**1️⃣Управление запросами**: Может изменять или проверять запросы перед передачей их в приложение. Например, оно может проверять наличие валидных токенов доступа для аутентификации или осуществлять проверку прав доступа.

**2️⃣Перехват ответов**: Также может изменять ответы перед тем, как они будут отправлены пользователю, например, добавлять нужные заголовки HTTP или сжимать данные.

**3️⃣Логирование и мониторинг**: Оно может записывать информацию о запросах и ответах для анализа трафика или обнаружения ошибок.

**4️⃣Обработка ошибок**: Часто используется для централизованной обработки ошибок, позволяя разработчикам управлять ошибками элегантно и единообразно.

В PHP-фреймворке, таком как Laravel, middleware часто используется для аутентификации, логирования, обработки сессий и т.д. Ниже пример middleware, который проверяет, залогинен ли пользователь в Laravel:
```
namespace App\Http\Middleware;

use Closure;
use Illuminate\Support\Facades\Auth;

class CheckAuthenticated
{
    /**
     * Handle an incoming request.
     *
     * @param  \Illuminate\Http\Request  $request
     * @param  \Closure  $next
     * @return mixed
     */
    public function handle($request, Closure $next)
    {
        if (!Auth::check()) {
            return redirect('/login');
        }

        return $next($request);
    }
}
```

В этом примере, `CheckAuthenticated` проверяет, аутентифицирован ли пользователь. Если нет, перенаправляет его на страницу входа.

Middleware — это слой между сервером и приложением, который помогает управлять запросами и ответами, обеспечивает безопасность, и поддерживает чистоту и модульность кода. Это посредник, который позволяет вам централизованно управлять общими задачами, связанными с запросами и ответами.

Middleware</u> — это ПО, которое располагается между веб-сервером и приложением. Оно обрабатывает входящие запросы до того, как они достигнут вашего приложения, или обрабатывает исходящие ответы после того, как приложение их сгенерировало.

**Зачем он нужен**
**1️⃣Управление запросами**: Может изменять или проверять запросы перед передачей их в приложение. Например, оно может проверять наличие валидных токенов доступа для аутентификации или осуществлять проверку прав доступа.

**2️⃣Перехват ответов**: Также может изменять ответы перед тем, как они будут отправлены пользователю, например, добавлять нужные заголовки HTTP или сжимать данные.

**3️⃣Логирование и мониторинг**: Оно может записывать информацию о запросах и ответах для анализа трафика или обнаружения ошибок.

**4️⃣Обработка ошибок**: Часто используется для централизованной обработки ошибок, позволяя разработчикам управлять ошибками элегантно и единообразно.

В PHP-фреймворке, таком как Laravel, middleware часто используется для аутентификации, логирования, обработки сессий и т.д. Ниже пример middleware, который проверяет, залогинен ли пользователь в Laravel:
```
namespace App\Http\Middleware;

use Closure;
use Illuminate\Support\Facades\Auth;

class CheckAuthenticated
{
    /**
     * Handle an incoming request.
     *
     * @param  \Illuminate\Http\Request  $request
     * @param  \Closure  $next
     * @return mixed
     */
    public function handle($request, Closure $next)
    {
        if (!Auth::check()) {
            return redirect('/login');
        }

        return $next($request);
    }
}
```

В этом примере, `CheckAuthenticated` проверяет, аутентифицирован ли пользователь. Если нет, перенаправляет его на страницу входа.

Middleware — это слой между сервером и приложением, который помогает управлять запросами и ответами, обеспечивает безопасность, и поддерживает чистоту и модульность кода. Это посредник, который позволяет вам централизованно управлять общими задачами, связанными с запросами и ответами.

# **Какая разница между self и this ?**
<!-- basicblock-start oid="ObsdtkHivcQ0iFPGZtkWPjjA"  deck='1_PD_php' -->
**Какая разница между self и this ?**::

*Спросят с вероятностью 27%*

<u>self и this</u> используются для ссылки на текущий класс и его экземпляр соответственно, но каждый из них имеет свои особенности и область применения.

**this**

Используется для обращения к текущему объекту класса. Он позволяет получить доступ к нестатическим свойствам и методам объекта. Является ссылкой на вызываемый объект и используется внутри методов объекта для обращения к его свойствам и методам.
```
class Car {
    public $color = 'red';

    public function getColor() {
        return $this->color; // Используется $this для доступа к свойству текущего объекта
    }
}

$myCar = new Car();
echo $myCar->getColor(); // Выведет 'red'
```
Здесь `$this->color` обращается к свойству `color` текущего экземпляра класса `Car`.

**self**

Используется для обращения к текущему классу и применяется в основном для доступа к статическим свойствам и методам класса. Ссылается на класс, в котором она была вызвана, и не требует создания экземпляра объекта для доступа к содержимому.
```
class Car {
    public static $count = 0;

    public function __construct() {
        self::$count++; // Используется self для доступа к статическому свойству
    }

    public static function getTotalCars() {
        return self::$count; // Обращение к статическому методу или свойству
    }
}

$newCar1 = new Car();
$newCar2 = new Car();
echo Car::getTotalCars(); // Выведет '2'
```
В этом примере `self::$count` используется для управления статическим свойством, которое отслеживает количество созданных автомобилей.

**Основные различия**

**✅Контекст использования**: `$this` используется для доступа к свойствам и методам текущего объекта экземпляра, тогда как `self` используется для доступа к статическим свойствам и методам класса.
**✅Статический vs Нестатический**: `$this` нельзя использовать в статических методах, потому что статические методы могут быть вызваны без создания объекта класса. `self`, напротив, предназначена для использования в статическом контексте.
**✅Привязка**: `self` привязана к классу, в котором она написана, а `$this` — к объекту, через который вызывается метод.

Эти различия определяют, когда и как использовать каждый из этих ключевых слов в коде для правильного управления доступом к данным и функционалу класса и его экземпляров.

# **В чем различие между where и having ?**
<!-- basicblock-start oid="ObsbrJiRjFFxR1cbDHgzBLit"  deck='1_PD_php' -->
**В чем различие между where и having ?**::

*Спросят с вероятностью 27%*

<u>WHERE и HAVING</u> являются двумя различными предложениями, которые используются для фильтрации записей, но они применяются в разных контекстах и имеют разные цели.
**
1️⃣WHERE**
Используется для фильтрации строк перед тем, как они будут обработаны в любых группировках оператором `GROUP BY` или перед тем, как будут отображены в итоговом результате. `WHERE` эффективно ограничивает, какие строки будут включены в следующий этап обработки запроса.
```
SELECT * FROM employees
WHERE department = 'Sales';
```
Здесь `WHERE` фильтрует записи так, чтобы в результат вошли только те, где значение столбца `department` равно 'Sales'.
**
2️⃣HAVING**
Применяется после группировки данных с помощью `GROUP BY`, когда необходимо фильтровать группы по определённым критериям, основанным на агрегатных функциях, таких как `COUNT()`, `SUM()`, `AVG()` и т.д. `HAVING` можно считать аналогом `WHERE`, который специально предназначен для работы с группами, а не с отдельными записями.
```
SELECT department, COUNT(*) as num_employees
FROM employees
GROUP BY department
HAVING num_employees > 10;
```
Здесь `HAVING` фильтрует результаты запроса, оставляя только те группы, в которых количество сотрудников (`num_employees`) превышает 10. Предварительно данные группируются по департаменту.

Основные различия
**✅Этап применения**: `WHERE` фильтрует строки до группировки (перед `GROUP BY`), а `HAVING` — после группировки.
**✅Типы условий**: `WHERE` не может использовать агрегатные функции, потому что эти функции ещё не применены на этапе фильтрации `WHERE`. `HAVING` предназначен для фильтрации, используя агрегатные функции.
**✅Использование без** `GROUP BY`**:** `WHERE` может использоваться без `GROUP BY`, в то время как `HAVING` обычно используется с `GROUP BY` (хотя и может быть использован и без него в некоторых СУБД для фильтрации агрегатов по значениям).

Эти два предложения служат разным целям и используются в различных сценариях запросов для обеспечения точности и эффективности выборки данных в SQL.

**Что из себя представляет http-запрос ?**::

*Спросят с вероятностью 27%*

<u>HTTP-запрос</u> — это основа данных, которую клиент (обычно веб-браузер) отправляет на сервер для выполнения определенных действий на веб-странице или веб-сервисе. Является протоколом передачи данных в интернете, и запросы по этому протоколу задают параметры и содержимое обмена информацией между клиентом и сервером.

**Структура HTTP-запроса:**

**1️⃣Стартовая строка (Start Line)**: Включает в себя метод запроса, URI (Uniform Resource Identifier) ресурса и версию HTTP. Примеры методов запроса:
`✅GET` — запрос на получение данных.
`✅POST` — запрос на отправку данных для обработки.
`✅PUT` — запрос на обновление данных.
`✅DELETE` — запрос на удаление данных.
✅и другие.

**2️⃣Заголовки (Headers)**: Служат для передачи дополнительной информации между клиентом и сервером. Заголовки могут содержать данные о типе контента, методах аутентификации, кэшировании и многом другом.

**3️⃣Пустая строка**: Разделяет заголовки и тело запроса. Это просто перевод строки.

**4️⃣Тело запроса (Body)** (необязательно): Непосредственные данные, отправляемые серверу. Например, при отправке формы методом `POST` данные формы будут находиться в теле запроса. Тело запроса может отсутствовать, например, в методах `GET` или `HEAD`.

Допустим, клиент отправляет HTTP-запрос на сервер с целью получения информации о пользователе. Запрос может выглядеть так:

```
GET /users/12345 HTTP/1.1
Host: example.com
Accept: application/json
Authorization: Bearer your_access_token
```

Здесь:
`✅GET` — метод запроса.
`✅/users/12345` — URI запрашиваемого ресурса.
`✅HTTP/1.1` — версия HTTP.
`✅Host`, `Accept`, `Authorization` — заголовки запроса, описывающие сервер, формат ответа, который клиент ожидает получить, и метод аутентификации соответственно.

HTTP-запросы являются фундаментальной частью веб-коммуникаций, позволяя пользователям взаимодействовать с веб-ресурсами. Они используются для загрузки веб-страниц, отправки форм, взаимодействия с API и многое другое, обеспечивая динамичное взаимодействие на платформе всемирной паутины.

# **Что такое индекс ?**
<!-- basicblock-start oid="ObsgI2YuBBaW8B6ybo00iQzi"  deck='1_PD_php' -->
**Что такое индекс ?**::

*Спросят с вероятностью 20%*

<u>индекс</u> — это структура данных, которая улучшает скорость операций выборки данных из таблицы базы данных. Они строятся на основе одного или нескольких столбцов таблицы и позволяют быстро находить строки без необходимости сканировать всю таблицу.

**Зачем они нужны?**

1️⃣**Ускорение поиска**: Позволяют базе данных быстрее находить и извлекать данные. Без индексов СУБД приходится выполнять полный поиск по всей таблице (full table scan), что может быть очень неэффективно для больших объемов данных.
2️⃣**Эффективность запросов**: Особенно важны для улучшения производительности запросов, содержащих условия `WHERE`, `ORDER BY`, `GROUP BY` и `JOIN`.
3️⃣**Уникальность**: Можно использовать для обеспечения уникальности данных в столбце, предотвращая дублирование записей.

**Как они работают?**

Обычно реализуются с использованием структур данных, таких как B-деревья или хеш-таблицы. Каждый индекс содержит указатели на строки основной таблицы, что позволяет СУБД быстро переходить к нужным данным без полного перебора таблицы.

✅**B-дерево**: Наиболее часто используемая структура для индексов, которая поддерживает порядок и быстрый поиск, вставку, удаление и обход элементов. Она эффективно работает с операциями поиска на основе диапазонов.
✅**Хеш-таблица**: Лучше подходит для операций с точечным поиском, где используются условия эквивалентности.

**Типы:**

1️⃣**Основной индекс (Primary index)**: созданный на первичном ключе таблицы.
2️⃣**Вторичный индекс (Secondary index)**: на одном или нескольких столбцах, которые не являются первичным ключом.
3️⃣**Уникальный индекс**: Гарантирует, что все значения в индексе уникальны.
4️⃣**Составной индекс**: Включает несколько столбцов.

Создание индекса для столбца `email` в таблице `users` для ускорения поиска по электронной почте:
`CREATE INDEX idx_email ON users(email);`

Этот индекс позволит СУБД быстрее находить записи, осуществляя поиск по столбцу `email`, благодаря предварительно построенной структуре индекса.

Хотя индексы значительно ускоряют чтение данных, они также добавляют накладные расходы на операции записи, такие как вставка, обновление и удаление записей, так как при каждой такой операции необходимо также обновлять индекс. Кроме того, индексы занимают дополнительное место в памяти или на диске. Поэтому важно тщательно планировать, какие индексы создавать и как их поддерживать.

# **Зачем нужен абстрактный класс ?**
<!-- basicblock-start oid="ObsaWxFVu752Mh1n0KoUUNuf"  deck='1_PD_php' -->
**Зачем нужен абстрактный класс ?**::

*Спросят с вероятностью 27%*
<u>
Абстрактный класс</u> в ООП служит шаблоном для других классов, определяя общий интерфейс и поведение, которые могут быть унаследованы дочерними классами. Он не предназначен для создания экземпляров напрямую, но предоставляет базовую структуру, на которой могут строиться другие классы.

**Основные цели использования:**

**1️⃣Определение общего интерфейса**: Позволяет определить методы, которые должны быть реализованы во всех дочерних классах, обеспечивая тем самым согласованность интерфейса.

**2️⃣Избежание дублирования кода**: Позволяют разработчикам поместить общий код для нескольких классов в одном месте, уменьшая тем самым дублирование и упрощая поддержку кода.

**3️⃣Контроль реализации**: Они предоставляют стандартизированный способ заставить разработчиков следовать определенной архитектуре или методологии при создании новых классов.

**4️⃣Поддержка множественного наследования через интерфейсы**: В языках, где классы могут реализовывать несколько интерфейсов, абстрактные классы могут служить для реализации методов этих интерфейсов, предоставляя при этом возможность наследования реализации кода, что не поддерживается интерфейсами напрямую.

Рассмотрим пример с абстрактным классом `Vehicle` и несколькими его наследниками:
```
abstract class Vehicle {
    protected $speed = 0;

    abstract public function increaseSpeed($increment);

    public function setSpeed($speed) {
        $this->speed = $speed;
    }

    public function getSpeed() {
        return $this->speed;
    }
}

class Car extends Vehicle {
    public function increaseSpeed($increment) {
        $this->speed += $increment;
        echo "Скорость автомобиля увеличена до " . $this->speed . " км/ч.\n";
    }
}

class Bicycle extends Vehicle {
    public function increaseSpeed($increment) {
        $this->speed += $increment;
        echo "Скорость велосипеда увеличена до " . $this->speed . " км/ч.\n";
    }
}

$car = new Car();
$car->setSpeed(50);
$car->increaseSpeed(20);

$bicycle = new Bicycle();
$bicycle->setSpeed(15);
$bicycle->increaseSpeed(5);
```

В этом примере `Vehicle` является абстрактным классом, который определяет базовые методы и свойства для `Car` и `Bicycle`. Метод `increaseSpeed` является абстрактным, и его реализация должна быть предоставлена каждым конкретным классом, наследующим `Vehicle`.

Использование абстрактных классов упрощает разработку программного обеспечения, гарантируя, что все производные классы следуют определенному контракту, а также способствует повторному использованию кода. Они играют важную роль в проектировании архитектуры приложений, обеспечивая структурированное и легко расширяемое решение.

**Какие бывают индексы ?**::

Чтобы продемонстрировать, как можно использовать индексы, прежде всего нужно рассмотреть процесс создания индексов в базе данных и последующее выполнение SQL запросов с использованием PHP. Возьмем MySQL в качестве примера базы данных и использование PDO (PHP Data Objects) для взаимодействия с базой данных из PHP.
**
Шаг 1: Создание индексов в MySQL**

Допустим, у вас есть таблица `users` с полями `id`, `email`, `name`, и `age`. Вы хотите оптимизировать поиск по `email`, который часто используется для входа в систему или других операций. Вы можете создать уникальный индекс для столбца `email`:
```
CREATE UNIQUE INDEX idx_email ON users (email);
```

Если вы также часто выполняете запросы, которые фильтруют пользователей по возрасту, вы можете создать простой индекс для столбца `age`:
```
CREATE INDEX idx_age ON users (age);
```

**Шаг 2: Использование индексов**

Теперь, когда у вас есть индексы, давайте посмотрим, как вы можете использовать PHP для выполнения запросов, которые могут извлекать выгоду из этих индексов. Мы будем использовать PDO для создания безопасных запросов с использованием подготовленных выражений.
```
<?php
$dsn = 'mysql:host=localhost;dbname=testdb';
$username = 'root';
$password = '';

try {
    $pdo = new PDO($dsn, $username, $password);
    $pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);

    // Запрос с использованием индекса по email
    $email = 'user@example.com';
    $stmt = $pdo->prepare("SELECT * FROM users WHERE email = :email");
    $stmt->execute(['email' => $email]);

    while ($row = $stmt->fetch(PDO::FETCH_ASSOC)) {
        echo "Имя: " . $row['name'] . ", Email: " . $row['email'] . ", Возраст: " . $row['age'] . "<br/>";
    }

    // Запрос с использованием индекса по возрасту
    $age = 25;
    $stmt = $pdo->prepare("SELECT * FROM users WHERE age >= :age");
    $stmt->execute(['age' => $age]);

    while ($row = $stmt->fetch(PDO::FETCH_ASSOC)) {
        echo "Имя: " . $row['name'] . ", Email: " . $row['email'] . ", Возраст: " . $row['age'] . "<br/>";
    }
} catch (PDOException $e) {
    die("Ошибка подключения: " . $e->getMessage());
}
?>
```
**
Пояснения к коду**
**1️⃣PDO Connection**: Создание соединения с базой данных через PDO.
**2️⃣Подготовленные Запросы**: Использование подготовленных запросов для избежания SQL-инъекций.
**3️⃣Использование Индексов**: Запросы автоматически извлекают выгоду из созданных индексов, что ускоряет их выполнение.

Этот пример демонстрирует, как создание и использование индексов может улучшить производительность запросов. Создание индексов снижает время, необходимое для поиска данных, особенно в больших таблицах, и является важной частью оптимизации баз данных.

**Что знаешь про выборку, джойны ?**::

*Спросят с вероятностью 27%*

Для работы с базами данных и выполнения операций выборки и джойнов можно использовать различные расширения, такие как PDO (PHP Data Objects) или mysqli. Ниже я приведу примеры использования PDO, так как это расширение предоставляет более гибкий и безопасный интерфейс для работы с базой данных, включая подготовленные запросы, которые помогают избежать SQL-инъекций.

Допустим, у нас есть таблица `users`, и мы хотим выбрать имена и возраст пользователей старше 18 лет. Вот как это можно сделать с помощью PDO:
```
<?php
$dsn = 'mysql:host=your_host;dbname=your_dbname';
$username = 'your_username';
$password = 'your_password';

try {
    $pdo = new PDO($dsn, $username, $password);
    $pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);

    $query = "SELECT name, age FROM users WHERE age >= 18";
    $stmt = $pdo->query($query);

    while ($row = $stmt->fetch(PDO::FETCH_ASSOC)) {
        echo "Имя: " . $row['name'] . ", Возраст: " . $row['age'] . "<br/>";
    }
} catch (PDOException $e) {
    die("Ошибка подключения: " . $e->getMessage());
}
?>
```

Теперь рассмотрим пример, где нам нужно получить имена пользователей и названия их заказов, объединив таблицы `users` и `orders`. Используем INNER JOIN для этого:
```
<?php
$dsn = 'mysql:host=your_host;dbname=your_dbname';
$username = 'your_username';
$password = 'your_password';

try {
    $pdo = new PDO($dsn, $username, $password);
    $pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);

    $query = "
    SELECT users.name, orders.order_name
    FROM users
    INNER JOIN orders ON users.id = orders.user_id
    ";
    $stmt = $pdo->query($query);

    while ($row = $stmt->fetch(PDO::FETCH_ASSOC)) {
        echo "Пользователь: " . $row['name'] . ", Заказ: " . $row['order_name'] . "<br/>";
    }
} catch (PDOException $e) {
    die("Ошибка подключения: " . $e->getMessage());
}
?>
```

**Общие советы**

**1️⃣Безопасность**: Используйте подготовленные запросы для защиты от SQL инъекций, особенно когда в запросах используются данные, вводимые пользователями.

2️⃣ **Отладка**: Устанавливайте режим ошибок PDO на `PDO::ERRMODE_EXCEPTION`, чтобы получать исключения при ошибках базы данных, что облегчит отладку.

**3️⃣Управление ресурсами**: Всегда закрывайте соединения с базой данных и освобождайте ресурсы, когда они вам больше не нужны, например, закрывая объекты PDOStatement после их использования.

Эти примеры демонстрируют, как можно эффективно использовать PHP и PDO для работы с базами данных, выполняя операции выборки и джойнов для извлечения и объединения данных.

# **Что такое агрегатные функции ?**
<!-- basicblock-start oid="ObsTFC21Zzm7cHKMW5RxbX7q"  deck='1_PD_php' -->
**Что такое агрегатные функции ?**::

*Спросят с вероятностью 20%*

<u>Агрегатные функции</u> в контексте управления базами данных и SQL — это специальные функции, которые выполняют вычисление над набором значений и возвращают единственный результат. Они часто используются для выполнения математических, статистических и других операций с данными в запросах для анализа и обобщения информации из множества записей.

**Основные агрегатные функции:**

1️⃣**COUNT()**: Подсчитывает количество элементов в наборе. Эта функция может использоваться для подсчета количества строк в таблице или количества строк, соответствующих определенным критериям.
✅Пример: `SELECT COUNT(*) FROM users;` — подсчитывает количество всех строк в таблице `users`.

2️⃣**SUM()**: Суммирует числовые значения столбца. Используется для получения общей суммы числовых данных.
✅Пример: `SELECT SUM(salary) FROM employees;` — считает общую сумму зарплат всех сотрудников.

3️⃣**AVG()**: Вычисляет среднее значение числовых данных. Эта функция полезна для нахождения среднего значения определенного столбца.
✅Пример: `SELECT AVG(price) FROM products;` — рассчитывает среднюю цену продукта.

4️⃣**MIN()** **и** **MAX()**: Возвращают минимальное и максимальное значения в столбце соответственно. Эти функции используются для нахождения наименьших и наибольших значений.
✅Пример: `SELECT MIN(age), MAX(age) FROM users;` — находит минимальный и максимальный возраст среди пользователей.
**
5️⃣GROUP_CONCAT() (в MySQL) / STRING_AGG() (в PostgreSQL**): Склеивают строки из столбца, объединяя их в одну строку с разделителем.
✅Пример (MySQL): `SELECT GROUP_CONCAT(username SEPARATOR ', ') FROM users WHERE city = 'New York';` — объединяет имена пользователей из Нью-Йорка через запятую.

Агрегатные функции часто используются в сочетании с оператором `GROUP BY`, который позволяет группировать строки по одному или нескольким столбцам и применять агрегатные функции к каждой группе отдельно. Это позволяет выполнить более детальный анализ данных.
`SELECT department, AVG(salary) AS average_salary
FROM employees
GROUP BY department;`
Этот запрос вычисляет среднюю зарплату по каждому отделу в компании.

Агрегатные функции — мощный инструмент для работы с большими объемами данных, позволяя быстро получать обобщенную информацию о данных, что особенно полезно для отчетов и аналитики.

<u>Интерфейсы</u> — это структуры, которые помогают определять шаблонные методы, которые должны быть реализованы в классах, их имплементирующих. Интерфейсы предоставляют способ формализовать определённые аспекты поведения объекта, гарантируя, что классы реализуют предписанные методы. Это полезно для создания унифицированного API и для обеспечения согласованности между различными частями приложения.

**Особенности:**

1️⃣**Методы интерфейса**: Все методы в нем должны быть публичными и не могут иметь реализацию. Тело каждого метода определяется только в классах, которые реализуют интерфейс.

2️⃣**Наследование интерфейсов**: Могут наследовать другие интерфейсы, и класс может реализовывать множество интерфейсов, что обеспечивает гибкость множественного наследования через интерфейсное программирование.

**Пример использования**

Допустим, у вас есть приложение с различными способами логирования информации (файл, облако, консоль). Вы можете определить интерфейс `LoggerInterface`, который будет иметь метод `log()`. Затем, разные классы, такие как `FileLogger`, `CloudLogger`, и `ConsoleLogger`, могут реализовать этот интерфейс, обеспечивая свою уникальную реализацию метода `log()`.
```
interface LoggerInterface {
    public function log($message);
}

class FileLogger implements LoggerInterface {
    public function log($message) {
        file_put_contents('log.txt', $message . PHP_EOL, FILE_APPEND);
    }
}

class CloudLogger implements LoggerInterface {
    public function log($message) {
        // отправка сообщения в облачное хранилище
    }
}

class ConsoleLogger implements LoggerInterface {
    public function log($message) {
        echo $message . PHP_EOL;
    }
}

// Пример использования
$logger = new FileLogger();
$logger->log("Hello, World!");
```

**Зачем они нужны?**

✅**Согласованность**: Обеспечивают стандартизацию, требуя от классов реализациопределённых методов.
✅**Гибкость**: Различные классы могут предоставлять свою собственную реализацию интерфейса, что позволяет программам динамически изменять поведение.
✅**Разделение и инкапсуляция**: Позволяют создавать код, который может работать с любым объектом, реализующим интерфейс, без знания конкретной реализации этого объекта.

<u>traits</u> являются механизмом для повторного использования кода в языках, поддерживающих только одиночное наследование, как PHP. **Зачем они нужны**

Трейты вводятся для решения проблемы множественного наследования и для облегчения повторного использования кода. Они позволяют разработчикам создавать компоненты, которые могут быть использованы в различных классах без необходимости наследования от базового класса. Это полезно в ситуациях, где класс должен интегрировать функциональность из нескольких источников.

Предположим, вы разрабатываете приложение, где несколько классов должны иметь возможность записывать логи. Вместо того чтобы писать или копировать одни и те же методы логирования в каждый класс, вы можете создать трейт и использовать его в каждом классе.
```
trait Logger {
    public function log($message) {
        echo "Log: $message\n";
    }
}

class FileProcessor {
    use Logger;

    public function process($file) {
        $this->log("Processing file: $file");
        // Обработка файла
    }
}

class Communication {
    use Logger;

    public function send($message) {
        $this->log("Sending message: $message");
        // Отправка сообщения
    }
}

$fileProcessor = new FileProcessor();
$fileProcessor->process("example.txt");

$communication = new Communication();
$communication->send("Hello World!");
```

✅**Конфликты имен**: Если два трейта вставляют метод с одинаковым именем в класс, PHP не знает, какой метод использовать, и потребует от разработчика разрешить конфликт явно.
✅**Приоритет трейтов**: Класс может переопределить методы трейта, тем самым предоставляя собственные реализации.

Трейты — это мощный инструмент для повторного использования кода, который позволяет разработчикам включать одну и ту же функциональность в различные классы без множественного наследования. Это помогает поддерживать код чистым, организованным и уменьшает дублирование кода.

# **Зачем нужно ключевое слово final ?**
<!-- basicblock-start oid="ObscInc1iK9FIgZxB29RPTkn"  deck='1_PD_php' -->
**Зачем нужно ключевое слово final ?**::

*Спросят с вероятностью 27%*

Ключевое слово <u>final</u> используется для управления наследованием классов и методов, ограничивая их дальнейшую модификацию в дочерних классах. Это ключевое слово может быть применено как к классам, так и к методам и служит важным инструментом для контроля архитектуры приложения.

**Использование с классами**

Когда он применяется к классу, это означает, что данный класс не может быть унаследован. Это полезно, когда класс был спроектирован с учетом того, что он является окончательным в своей иерархии и его функциональность не должна быть расширена. Использование его для класса гарантирует, что его поведение останется неизменным во всех использованиях, что может быть критически важно для безопасности или стабильности.
```
final class BaseClass {
    public function sayHello() {
        echo "Hello, I am a final class!";
    }
}

// Это вызовет ошибку, так как BaseClass не может быть унаследован
class ChildClass extends BaseClass {
}
```

Использование с методами
Применение `final` к методу класса предотвращает его переопределение в любом классе-наследнике. Это полезно в случаях, когда метод несет в себе ключевую логику, которую не следует изменять, чтобы сохранить предполагаемое поведение объекта. Таким образом, он помогает обеспечить, что определенные важные аспекты поведения класса сохранятся во всех его наследниках.
```
class BaseClass {
    final public function sayHello() {
        echo "Hello, I cannot be overridden!";
    }
}

class ChildClass extends BaseClass {
    // Это вызовет ошибку, так как метод sayHello() объявлен как final и не может быть переопределен
    public function sayHello() {
        echo "Hello from Child!";
    }
}
```

**Зачем это нужно?**

Использование `final` помогает:
✅**Обеспечить безопасность и надежность**: Ограничивая переопределение, вы можете избежать ошибок или изменений в ключевой функциональности, которые могли бы привести к неправильному поведению или уязвимостям.

       }

```

1️⃣**Resource (ресурс)** — представляет собой ссылку на внешние ресурсы, такие как файлы, соединения с базами данных и т.д.
2️⃣**NULL** — тип, имеющий одно значение `NULL`, используется для обозначения переменной без значения.

Есть четыре основных скалярных типа данных (целые числа, дробные числа, строки, булевы значения), два составных типа (массивы и объекты) и специальные типы (ресурс и NULL). Каждый из этих типов данных используется для различных задач в программировании, что делает PHP мощным и гибким языком для разработки веб-приложений.

# **Что такое в мире PHP PSR и RFC ?**

**Что такое в мире PHP PSR и RFC ?**::

*Спросят с вероятностью 33%*

<u>PSR (PHP Standard Recommendation) и RFC (Request for Comments)</u> играют важные роли в стандартизации и развитии PHP.

**PSR (PHP Standard Recommendation)**

Это стандарты, которые предлагаются PHP Framework Interop Group (PHP-FIG), группой, которая состоит из представителей ведущих PHP-проектов. Цель этих стандартов — улучшить совместимость между различными PHP-фреймворками и библиотеками. Его стандарты  охватывают различные аспекты программирования на PHP, такие как стиль кодирования, логирование, автозагрузка классов и многие другие. 

Пример стандарта PSR-4, который касается автозагрузки классов. В соответствии с PSR-4, каждый класс должен находиться в отдельном файле, и пространство имен класса должно соответствовать структуре каталогов файловой системы. Это упрощает автозагрузку классов без необходимости регистрации каждого класса вручную.
```
// Пример автозагрузки в соответствии с PSR-4
spl_autoload_register(function ($class) {
    include 'src/' . str_replace('\\', '/', $class) . '.php';
});
```

**RFC (Request for Comments)**

Это документы, которые предлагают нововведения или изменения в языке PHP. Любой участник сообщества может предложить RFC, который будет рассмотрен и, возможно, принят для реализации в будущих версиях PHP. RFC обсуждаются на официальном сайте PHP и в рассылках, где разработчики могут высказывать свои мнения и голосовать за или против предложений.

RFC часто включают подробные описания предлагаемых функций, примеры кода, обсуждение возможных проблем и другие технические детали. Например, введение типизации аргументов функций в PHP было одобрено через процесс RFC.

PSR и RFC являются важными элементами экосистемы PHP. PSR помогают разработчикам следовать общим стандартам и обеспечивают лучшую совместимость между различными проектами. RFC позволяют сообществу направлять развитие PHP, предлагая и обсуждая новые функции и изменения.

# **Что происходит, если в приложении выбрасывается исключение ?**
<!-- basicblock-start oid="Obs0DEs0ioWgIhfAZRdjKgKu"  deck='1_PD_php' -->
**Что происходит, если в приложении выбрасывается исключение ?**::

*Спросят с вероятностью 13%*

<u>Исключения</u> — это способ обработки ошибок в программе. Это тип ошибки, который возникает во время выполнения программы и может быть "пойман" и обработан кодом, что позволяет приложению продолжить свою работу или корректно завершиться.

Когда происходит ошибка, которая может быть обработана как исключение, вы можете использовать конструкцию `try-catch` для перехвата и обработки исключения. В блоке `try` размещается код, который может вызвать исключение, а в блоке `catch` — код, который выполнится, если в блоке `try` было выброшено исключение.

```
function divide($dividend, $divisor) {
    if ($divisor == 0) {
        throw new Exception("Деление на ноль.");
    }
    return $dividend / $divisor;
}

try {
    echo divide(5, 0);
} catch (Exception $e) {
    echo "Ошибка: " . $e->getMessage();
}
```

В этом примере, если делитель равен нулю, выбрасывается исключение с сообщением "Деление на ноль." Если во время выполнения функции `divide()` выбросится исключение, выполнение программы перейдет в блок `catch`, и будет выведено сообщение об ошибке.

Использование исключений важно по нескольким причинам:
1️⃣ **Контроль потока программы**: Исключения помогают управлять потоком программы в случаях, когда происходят нештатные ситуации.
2️⃣ **Безопасность**: Позволяют программе завершиться корректно, освободить ресурсы и предотвратить потенциальные утечки памяти или другие проблемы безопасности.
3️⃣ **Поддерживаемость и расширяемость**: Код с обработкой исключений легче читать, поддерживать и модифицировать.

Когда в приложении выбрасывается исключение, это значит, что произошла ошибка, которую можно обработать. Это позволяет программе реагировать адекватно на ошибки, избежать аварийного завершения и улучшить управляемость ошибками в программе.

Индексы в базах данных используются для ускорения процесса поиска и извлечения данных. Эти инструменты особенно важны в условиях больших объемов данных и сложных запросов. Основные случаи использования:

1️⃣ **Поиск по ключевым столбцам**: Если запросы часто включают поиск по определённому столбцу, индекс по этому столбцу может значительно ускорить эти операции. Например, если вы часто ищете пользователей по их email, стоит создать индекс по столбцу email.

3️⃣ **Сортировка данных (ORDER BY)**: Если запросы часто требуют сортировки по определённому полю, индекс по этому полю поможет ускорить процесс сортировки, так как данные в индексе уже будут частично или полностью упорядочены.

5️⃣ **Агрегация данных (GROUP BY)**: Индексы могут ускорить группировку данных, если группировка происходит по индексированным полям.

Использование индексов делает операции с базой данных быстрее и эффективнее, особенно при больших объёмах данных. Они как оглавление в книге, позволяющее быстро найти нужную информацию без необходимости "перелистывать" всю книгу.

# **Что такое middleware ?**
<!-- basicblock-start oid="ObsO4f990GssY8tdAazNNetd"  deck='1_PD_php' -->
**Что такое middleware ?**::

*Спросят с вероятностью 33%*

<u>Middleware</u> — это ПО, которое располагается между веб-сервером и приложением. Оно обрабатывает входящие запросы до того, как они достигнут вашего приложения, или обрабатывает исходящие ответы после того, как приложение их сгенерировало.

Зачем нужен Middleware

**1️⃣ Управление запросами**: Может изменять или проверять запросы перед передачей их в приложение. Например, оно может проверять наличие валидных токенов доступа для аутентификации или осуществлять проверку прав доступа.

**2️⃣ Перехват ответов**: Также может изменять ответы перед тем, как они будут отправлены пользователю, например, добавлять нужные заголовки HTTP или сжимать данные.

**3️⃣ Логирование и мониторинг**: Оно может записывать информацию о запросах и ответах для анализа трафика или обнаружения ошибок.

**4️⃣ Обработка ошибок**: Часто используется для централизованной обработки ошибок, позволяя управлять ошибками элегантно и единообразно.

В PHP-фреймворке, таком как Laravel, он часто используется для аутентификации, логирования, обработки сессий и т.д. Ниже пример middleware, который проверяет, залогинен ли пользователь в Laravel:

```
namespace App\Http\Middleware;

use Closure;
use Illuminate\Support\Facades\Auth;

class CheckAuthenticated
{
    /**
     * Handle an incoming request.
     *
     * @param  \Illuminate\Http\Request  $request
     * @param  \Closure  $next
     * @return mixed
     */
    public function handle($request, Closure $next)
    {
        if (!Auth::check()) {
            return redirect('/login');
        }

        return $next($request);
    }
}
```

В этом примере, `CheckAuthenticated` проверяет, аутентифицирован ли пользователь. Если нет, перенаправляет его на страницу входа.

<u>Middleware</u> — это слой между сервером и приложением, который помогает управлять запросами и ответами, обеспечивает безопасность, и поддерживает чистоту и модульность кода. Это посредник, который позволяет вам централизованно управлять общими задачами, связанными с запросами и ответами.

# **Что такое SOLID ?**
<!-- basicblock-start oid="Obsrzp8apad0R4DCAxfZpkb8"  deck='1_PD_php' -->
**Что такое SOLID ?**::

*Спросят с вероятностью 40%*

<u>SOLID</u> — это акроним, представляющий пять основных принципов ООП и проектирования, предложенных Робертом Мартином. Эти принципы направлены на повышение гибкости, читаемости, и поддерживаемости кода, а также упрощение его тестирования и рефакторинга. Вот они:

1️⃣**S: Принцип единственной ответственности (Single Responsibility Principle)** - Каждый класс должен иметь только одну причину для изменения. Этот принцип подчеркивает, что класс должен заниматься только одной задачей или иметь одну область ответственности.

2️⃣**O: Принцип открытости/закрытости (Open/Closed Principle)** - Сущности программы должны быть открыты для расширения, но закрыты для модификации. Это означает, что можно добавлять новые функциональности без изменения существующего кода.

3️⃣**L: Принцип подстановки Барбары Лисков (Liskov Substitution Principle)** - Объекты в программе можно заменять их наследниками без изменения свойств программы. Это предполагает, что объекты подклассов должны действовать так же, как объекты суперкласса, от которых они произошли.

4️⃣**I: Принцип разделения интерфейса (Interface Segregation Principle)** - Клиенты не должны зависеть от интерфейсов, которые они не используют. Этот принцип говорит о том, что лучше иметь много специализированных интерфейсов, чем один универсальный.

5️⃣**D: Принцип инверсии зависимостей (Dependency Inversion Principle)** - Модули высокого уровня не должны зависеть от модулей низкого уровня. Обе категории должны зависеть от абстракций. Кроме того, абстракции не должны зависеть от деталей; детали должны зависеть от абстракций. Это способствует ослаблению связности компонентов системы.

Применение принципов SOLID позволяет создавать более понятный, гибкий и поддерживаемый код, что упрощает дальнейшее развитие и сопровождение программного обеспечения. Эти принципы являются ключом к построению качественных и масштабируемых систем.

# **Как устроен декоратор ?**
<!-- basicblock-start oid="ObsvFdNyUYQzXsh9NtJsS5w4"  deck='1_PD_php' -->
**Как устроен декоратор ?**::

*Спросят с вероятностью 13%*

<u>Декоратор</u> — это структурный паттерн проектирования, который позволяет динамически добавлять новые функции объектам, оборачивая их в полезные «обёртки». Этот паттерн часто используется для расширения функциональности объектов на этапе выполнения без изменения кода декорируемых классов.

Как он работает

Декоратор предоставляет гибкую альтернативу наследованию для расширения функциональности. Вместо того чтобы наследовать функциональность от базового класса, вы создаёте набор классов с одинаковым интерфейсом, каждый из которых выполняет свою роль, добавляя или изменяя поведение.

Рассмотрим простой пример, где у нас есть базовый класс `Coffee` и несколько декораторов для добавления ингредиентов.

1. Определим интерфейс:```

interface Coffee {
    public function getCost();
    public function getDescription();
}

2. Создадим базовый класс `SimpleCoffee`, который реализует этот интерфейс:
class SimpleCoffee implements Coffee {
    public function getCost() {
        return 50; // стоимость простого кофе
    }

    public function getDescription() {
        return 'Simple coffee';
    }
}
```

3. Определим декораторы:```

class MilkCoffee implements Coffee {
    protected $coffee;

    public function __construct(Coffee $coffee) {
        $this->coffee = $coffee;
    }

    public function getCost() {
        return $this->coffee->getCost() + 10; // добавляем стоимость молока
    }

    public function getDescription() {
        return $this->coffee->getDescription() . ', milk';
    }
}

class VanillaCoffee implements Coffee {
    protected $coffee;

    public function __construct(Coffee $coffee) {
        $this->coffee = $coffee;
    }

    public function getCost() {
        return $this->coffee->getCost() + 15; // добавляем стоимость ванили
    }

    public function getDescription() {
        return $this->coffee->getDescription() . ', vanilla';
    }
}
```

4. Использование декораторов:```

$someCoffee = new SimpleCoffee();
echo $someCoffee->getDescription(); // Вывод: Simple coffee
echo $someCoffee->getCost(); // Вывод: 50

$someCoffee = new MilkCoffee($someCoffee);
echo $someCoffee->getDescription(); // Вывод: Simple coffee, milk
echo $someCoffee->getCost(); // Вывод: 60

$someCoffee = new VanillaCoffee($someCoffee);
echo $someCoffee->getDescription(); // Вывод: Simple coffee, milk, vanilla
echo $someCoffee->getCost(); // Вывод: 75
```

<u>Декоратор</u>  — это паттерн, позволяющий расширить функциональность объекта без изменения его структуры путём оборачивания его в дополнительные классы с тем же интерфейсом. Это позволяет добавлять функциональность динамически и гибко.

**Проще говоря**, декоратор - это когда вы добавляете новые "украшения" или функции к объекту, оборачивая его в новый класс, который делает его еще лучше или полезнее, не меняя основной класс.

# **Что такое динамические переменные ?**
<!-- basicblock-start oid="ObsOkL5mI8DNWCjtdpGFJxFW"  deck='1_PD_php' -->
**Что такое динамические переменные ?**::

*Спросят с вероятностью 13%*

<u>Динамические переменные</u> — это переменные, имена которых определяются во время выполнения программы. Это позволяет создавать, модифицировать или обращаться к переменным динамически, основываясь на входных данных или условиях выполнения программы. Такой подход может быть полезен в сценариях, где структура данных неизвестна на момент написания кода или когда нужно генерировать переменные на лету в зависимости от контекста выполнения.

**PHP**

Имена переменных могут быть динамически сформированы с использованием переменных переменных:
```
$name = "variable";
$$name = "Hello, World!";

echo $variable; // Выведет "Hello, World!"
```

Здесь `$$name` создаёт переменную с именем, хранящимся в `$name`, и присваивает ей значение `"Hello, World!"`.

**Преимущества**:
✅Гибкость: позволяет создавать более адаптивные и динамические программы, которые могут работать с данными, структура которых заранее неизвестна.
✅Удобство: упрощает работу с большим количеством похожих переменных или свойств объекта без необходимости явного объявления каждой переменной.

**Недостатки**:
✅Читаемость кода: использование динамических переменных может сделать код менее понятным и труднее для отладки, поскольку не всегда ясно, какие переменные создаются и используются.
✅Управление памятью: динамическое создание большого количества переменных может привести к неэффективному использованию памяти и снижению производительности.

Использование динамических переменных требует внимательного подхода к проектированию приложения, чтобы избежать ошибок во время выполнения и обеспечить поддерживаемость и производительность кода.

# **Что такое транзакция ?**
<!-- basicblock-start oid="ObsCh1IzJ4UzaehJrKX7K4s0"  deck='1_PD_php' -->
**Что такое транзакция ?**::

*Спросят с вероятностью 40%*

<u>Транзакция в контексте баз данных</u> — это последовательность операций с данными, которые рассматриваются как единое целое. Основная цель — обеспечить надежное выполнение группы операций, так чтобы база данных оставалась в согласованном состоянии даже в случае возникновения ошибок или сбоев. Подчиняются принципу ACID, который обеспечивает:

✅**Атомарность (Atomicity)**: Выполняется полностью или не выполняется вовсе. Если какая-либо часть транзакции не может быть завершена, то все её действия откатываются (отменяются), и система возвращается к состоянию, которое было до начала транзакции.
✅**Согласованность (Consistency)**: Переводит базу данных из одного согласованного состояния в другое. Это означает, что все правила целостности данных соблюдаются.
✅**Изолированность (Isolation)**: Не видит промежуточных состояний других транзакций. Это предотвращает возможные проблемы, такие как "грязное чтение" или "неповторяемое чтение".
✅**Долговечность (Durability)**: После ее завершения (commit) её результаты сохраняются в базе данных независимо от последующих сбоев системы.

Они используются для выполнения различных задач, таких как перевод средств между банковскими счетами, обновление инвентаря в системах управления товарами, изменения в системах управления пользователями и многие другие операции, требующие гарантий целостности данных.

**Пример:**
```
BEGIN TRANSACTION;

UPDATE БанковскиеСчета SET Баланс = Баланс - 100 WHERE НомерСчета = '123456';
UPDATE БанковскиеСчета SET Баланс = Баланс + 100 WHERE НомерСчета = '654321';

COMMIT;
```

В этом примере производится перевод средств между двумя банковскими счетами в рамках одной транзакции. Если обновление баланса на любом из счетов не может быть выполнено по любой причине (например, из-за сбоя в системе), транзакция будет отменена, и база данных вернется к исходному состоянию, тем самым гарантируя целостность данных.

<u>Транзакция</u> — это механизм, который позволяет группировать несколько операций с базой данных в одно целое для обеспечения ACID-гарантий, что критически важно для поддержания целостности и надежности данных.
