**В чем отличие self от static ?**::

*Спросят с вероятностью 13%*

<u>self и static</u> используются для доступа к статическим методам и свойствам класса, но между ними есть важные различия. Эти различия касаются поведения при наследовании классов.

**self**

✅**Прямое обращение к текущему классу**: Используется для обращения к статическим методам и свойствам текущего класса. Он не учитывает наследование, поэтому всегда ссылается на класс, в котором он был написан.
✅**Раннее связывание (early binding)**: Осуществляет раннее связывание, что означает, что он связывается с классом во время компиляции.
```
<?php
class Base {
    public static function who() {
        echo __CLASS__;
    }

    public static function test() {
        self::who(); // всегда вызывает метод who() класса Base
    }
}

class Child extends Base {
    public static function who() {
        echo CLASS;
    }
}

Child::test(); // Выведет: Base
?>
```

В этом примере, несмотря на то, что метод `test` вызывается у класса `Child`, использование `self::who()` приводит к вызову метода `who()` класса `Base`.

**static**

✅**Позднее статическое связывание**: Используется для обращения к статическим методам и свойствам класса и учитывает контекст вызова, что означает, что он ссылается на класс, в котором метод был вызван, а не в котором он был написан.
✅**Позднее связывание (late binding)**: Осуществляет позднее связывание, что означает, что он связывается с классом во время выполнения.

# **В чем заключается смысл полиморфизма ?**

<!-- basicblock-start oid="ObsWSgu37M96rtiJojoAp6Kz"  deck='P_PHP' -->
**В чем заключается смысл полиморфизма ?**::

*Спросят с вероятностью 13%*

<u>Полиморфизм</u> — это одна из основных концепций ООП, которая позволяет объектам разных классов быть обработанными через один и тот же интерфейс. Это достигается благодаря способности методов принимать объекты различных типов, что позволяет использовать один и тот же код для обработки разных типов объектов.

**Основные виды**

1️⃣**Полиморфизм подтипов (или включения)**: 
✅Это наиболее распространенный вид полиморфизма в ООП, который достигается через наследование и интерфейсы. Он позволяет объекту производного класса использоваться везде, где ожидается объект базового класса.
✅Использование базового класса или интерфейса для работы с объектами производных классов.

2️⃣**Ад-хок полиморфизм (или перегрузка)**:
✅Это способность функций обрабатывать объекты разного типа, используя перегрузку методов или операторов. Это достигается за счет объявления нескольких версий одной и той же функции с разными параметрами.
✅Перегрузка методов в одном классе, когда методы имеют одинаковое имя, но разные параметры.

Рассмотрим пример, где полиморфизм подтипов используется для обработки объектов различных классов через общий интерфейс.
```
<?php
// Определение интерфейса
interface Shape {
    public function draw();
}

// Реализация интерфейса в классе Circle
class Circle implements Shape {
    public function draw() {
        echo "Drawing a Circle\n";
    }
}

// Реализация интерфейса в классе Square
class Square implements Shape {
    public function draw() {
        echo "Drawing a Square\n";
    }
}

// Функция, принимающая объект любого класса, реализующего интерфейс Shape
function renderShape(Shape $shape) {
    $shape->draw();
}

// Создание объектов классов Circle и Square
$circle = new Circle();
$square = new Square();

// Вызов функции renderShape для каждого объекта
renderShape($circle); // Выведет "Drawing a Circle"
renderShape($square); // Выведет "Drawing a Square"
?>
```

В этом примере функция `renderShape` принимает аргумент типа `Shape`, что позволяет ей работать с любым объектом, реализующим этот интерфейс, будь то `Circle` или `Square`. Это и есть полиморфизм подтипов.

Хотя не поддерживает перегрузку методов непосредственно, вы можете использовать аргументы с заданными значениями по умолчанию и типизацию аргументов для достижения похожего результата.
```
<?php
class Printer {
    // Метод с необязательным аргументом
    public function printData($data = null) {
        if (is_null($data)) {
            echo "No data provided\n";
        } elseif (is_array($data)) {
            echo "Array: " . implode(", ", $data) . "\n";
        } elseif (is_string($data)) {
            echo "String: " . $data . "\n";
        } else {
            echo "Unknown type\n";
        }
    }
}

$printer = new Printer();
$printer->printData(); // Выведет "No data provided"
$printer->printData("Hello"); // Выведет "String: Hello"
$printer->printData([1, 2, 3]); // Выведет "Array: 1, 2, 3"
?>
```

**Смысл** 

✅**Универсальность кода**: Позволяет писать более универсальный и гибкий код, который может работать с объектами разных типов без необходимости изменять его.
✅**Расширяемость**: Легче добавлять новые классы и методы, которые интегрируются с существующей системой, не затрагивая её структуру.
✅**Упрощение дизайна**: Помогает создавать более чистую и понятную архитектуру, где объекты взаимодействуют через общие интерфейсы.

Полиморфизм позволяет объектам разных классов обрабатываться одинаково через общий интерфейс, улучшая универсальность, расширяемость и дизайн кода.

# **Чем отличается stop от мока ?**
<!-- basicblock-start oid="ObsJfwQdScXNCWxbru7A4IwH"  deck='P_PHP' -->
**Чем отличается stop от мока ?**::

*Спросят с вероятностью 13%*

В ООП и, в частности, в тестировании, существуют разные методы и инструменты для создания поддельных объектов, которые используются для замены реальных зависимостей в тестах. Два из таких методов — это **stubs** (стабы) и **mocks** (моки). Они имеют разные цели и используются по-разному.

**Stubs (Стабы)**

Это простые поддельные объекты, которые возвращают заранее заданные данные, когда их методы вызываются. Они не проверяют, как они были вызваны, а лишь предоставляют фиксированные ответы, необходимые для теста.

**Основные характеристики:**
✅**Цель**: Возврат фиксированных значений.
✅**Использование**: Подставляют зависимости, чтобы изолировать тестируемый код от внешних влияний.
✅**Проверка**: Не проверяют взаимодействия с тестируемым кодом.
```
class User {
    private $database;

    public function __construct(Database $database) {
        $this->database = $database;
    }

    public function getUserName($userId) {
        return $this->database->fetchUserName($userId);
    }
}

class DatabaseStub {
    public function fetchUserName($userId) {
        return 'John Doe';
    }
}

$databaseStub = new DatabaseStub();
$user = new User($databaseStub);
echo $user->getUserName(1); // Выведет "John Doe"
```
В этом примере `DatabaseStub` возвращает фиксированное значение `'John Doe'`, когда вызывается метод `fetchUserName`.

**Mocks (Моки)**

Это поддельные объекты, которые не только возвращают фиксированные данные, но и проверяют, как они были вызваны. Моки позволяют задавать ожидания относительно вызовов их методов и проверяют, что эти ожидания выполнены во время выполнения теста.

**Основные характеристики:**
✅**Цель**: Проверка взаимодействий и поведения.
✅**Использование**: Подменяют зависимости и проверяют, как тестируемый код взаимодействует с ними.
✅**Проверка**: Проверяют вызовы методов, аргументы вызовов и количество вызовов.
```
use PHPUnit\Framework\TestCase;

class UserTest extends TestCase {
    public function testGetUserName() {
        // Создаем мок объекта Database
        $databaseMock = $this->createMock(Database::class);

        // Задаем ожидания: метод fetchUserName должен быть вызван с аргументом 1 и вернуть 'John Doe'
        $databaseMock->expects($this->once())
                     ->method('fetchUserName')
                     ->with($this->equalTo(1))
                     ->willReturn('John Doe');

        $user = new User($databaseMock);
        $this->assertEquals('John Doe', $user->getUserName(1));
    }
}
```
В этом примере мы используем PHPUnit для создания мока `Database`. Мы задаем ожидание, что метод `fetchUserName` будет вызван один раз с аргументом 1 и вернет `'John Doe'`.

**Основные отличия:**

1️⃣**Назначение**:
✅**Стабы**: Возвращают заранее заданные данные, изолируя тестируемый код от реальных зависимостей.
✅**Моки**: Проверяют взаимодействия и поведение тестируемого кода с его зависимостями.

2️⃣**Фокус**:
✅**Стабы**: Сфокусированы на данных, которые возвращаются.
✅**Моки**: Сфокусированы на том, как методы были вызваны, с какими аргументами и сколько раз.

3️⃣**Простота**:
✅**Стабы**: Просты в реализации и не проверяют взаимодействия.
✅**Моки**: Более сложные, так как включают проверки взаимодействий и поведения.

Если объяснить совсем просто: стабы возвращают заранее заданные ответы, а моки проверяют, как именно и сколько раз их методы были вызваны.

**Как сделать так, чтобы сессии не хранились в файле ?**::

*Спросят с вероятностью 13%*

По умолчанию сессии хранятся в файлах на сервере. Однако, для улучшения производительности, масштабируемости или безопасности, вы можете изменить способ хранения сессий, например, использовать базы данных, Redis, Memcached или другие хранилища. Давайте рассмотрим, как можно изменить хранение сессий с использованием различных методов.

**Хранение сессий в базе данных**

1️⃣**Создание таблицы для сессий**:
```
CREATE TABLE sessions (
    id VARCHAR(255) NOT NULL PRIMARY KEY,
    data TEXT NOT NULL,
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

2️⃣**Настройка пользовательских обработчиков сессий**:

Создайте класс для обработки сессий в базе данных.
```
<?php
class MySQLSessionHandler implements SessionHandlerInterface {
    private $pdo;

    public function __construct(PDO $pdo) {
        $this->pdo = $pdo;
    }

    public function open($savePath, $sessionName) {
        return true;
    }

    public function close() {
        return true;
    }

    public function read($id) {
        $stmt = $this->pdo->prepare("SELECT data FROM sessions WHERE id = :id");
        $stmt->bindParam(':id', $id, PDO::PARAM_STR);
        $stmt->execute();

        if ($row = $stmt->fetch(PDO::FETCH_ASSOC)) {
            return $row['data'];
        }

        return '';
    }

    public function write($id, $data) {
        $stmt = $this->pdo->prepare("REPLACE INTO sessions (id, data, timestamp) VALUES (:id, :data, NOW())");
        $stmt->bindParam(':id', $id, PDO::PARAM_STR);
        $stmt->bindParam(':data', $data, PDO::PARAM_STR);
        return $stmt->execute();
    }

    public function destroy($id) {
        $stmt = $this->pdo->prepare("DELETE FROM sessions WHERE id = :id");
        $stmt->bindParam(':id', $id, PDO::PARAM_STR);
        return $stmt->execute();
    }

    public function gc($maxlifetime) {
        $stmt = $this->pdo->prepare("DELETE FROM sessions WHERE timestamp < NOW() - INTERVAL :maxlifetime SECOND");
        $stmt->bindParam(':maxlifetime', $maxlifetime, PDO::PARAM_INT);
        return $stmt->execute();
    }
}

// Использование пользовательского обработчика сессий
$pdo = new PDO('mysql:host=localhost;dbname=test', 'username', 'password');
$handler = new MySQLSessionHandler($pdo);
session_set_save_handler($handler, true);
session_start();
?>
```

**Хранение сессий в Redis**

1️⃣**Установка и настройка Redis**:

# **Какие существуют типы данных в PHP?**
<!-- basicblock-start oid="ObstEnI8SvLUfigHhCbv7GM4"  deck='P_PHP' -->
**Какие существуют типы данных в PHP?**::


PHP, как и многие другие языки программирования, поддерживает различные типы данных. Эти типы данных можно разделить на скалярные, составные и специальные типы. Вот основные типы данных в PHP:

**1. Скалярные типы**

✔️Integer (Целое число): Представляет целые числа без десятичной точки. Примеры: 42, -7.
✔️Float (Число с плавающей точкой, также Double): Представляет числа с десятичной точкой. Примеры: 3.14, -0.99.
✔️String (Строка): Представляет последовательность символов. Примеры: «Hello, World!», 'PHP'.
✔️Boolean (Булево значение): Представляет два возможных значения: true или false.

**2. Составные типы**
✅Array (Массив): Представляет собой коллекцию значений. Массивы могут быть индексированными (числовыми) или ассоциативными (пары ключ-значение).

✅Object (Объект): Представляет собой экземпляры классов. Объекты позволяют хранить данные и функции вместе в одном элементе.

**3. Специальные типы**
🔸NULL: Представляет переменную без значения. Это единственное значение типа NULL.

🔸Resource (Ресурс): Представляет ссылку на внешний ресурс, например, соединение с базой данных, файловый дескриптор и т.д. Ресурсы — это специальные переменные, которые содержат ссылки на внешние ресурсы, а не данные.

**4. Псевдотипы (Не настоящие типы данных, но используются в документации PHP)**
🔸Mixed (Смешанный): Указывает, что параметр или возвращаемое значение могут быть нескольких типов.

🔸Number (Число): Указывает на значение, которое может быть либо целым числом, либо числом с плавающей точкой.

🔸Callable (Вызываемый): Представляет собой функцию или метод, которые можно вызвать. Это может быть строка, массив или анонимная функция.

🔸Iterable (Итерируемый): Представляет любое значение, которое можно перебрать с помощью foreach, включая массивы и объекты, реализующие интерфейс Traversable.

**Какие процессы происходят, когда пользователь вводит в браузере URL?**::


Когда пользователь вводит URL в браузере, происходит следующая последовательность процессов:

1. Парсинг URL: Браузер анализирует введенный URL, чтобы выделить протокол, доменное имя и путь к ресурсу.

2. DNS-поиск: Браузер отправляет запрос к DNS-серверу для получения IP-адреса, связанного с доменным именем. DNS-сервер возвращает IP-адрес браузеру.

3. Установка TCP-соединения: Браузер устанавливает TCP-соединение с веб-сервером, используя полученный IP-адрес и порт (обычно порт 80 для HTTP или порт 443 для HTTPS).

4. Отправка HTTP-запроса: Браузер отправляет HTTP-запрос на сервер, включая метод запроса (GET, POST и т.д.), заголовки и URI (Uniform Resource Identifier), который содержит запрошенный ресурс.

5. Обработка и выполнение запроса на сервере: Веб-сервер получает HTTP-запрос, выполняет обработку и обращается к соответствующему приложению или файлу. На этом этапе сервер может также взаимодействовать с базой данных или другими серверами для получения данных, необходимых для формирования ответа.

6. Подготовка HTTP-ответа: Сервер формирует HTTP-ответ, включающий статус запроса, заголовки и содержимое. Код состояния (например, 200 для успешного запроса) указывает на результат обработки запроса.

7. Передача HTTP-ответа: Сформированный HTTP-ответ передается обратно по TCP-соединению на браузер клиента.

8. Обработка HTTP-ответа: Браузер получает HTTP-ответ, анализирует статус запроса и заголовки. Если запрос был успешным, браузер начинает загружать и отображать содержимое ответа (HTML, CSS, JavaScript, изображения и т.д.).

9. Рендеринг и отображение: Браузер обрабатывает полученное содержимое, выполняет интерпретацию HTML, применяет стили CSS, обрабатывает скрипты JavaScript и, в конечном итоге, отображает запрошенную веб-страницу на экране пользователя.

# **Какие методы авторизации используют для построения API?**
<!-- basicblock-start oid="Obs7yK92tEz4NtF4jOx0G1xj"  deck='P_PHP' -->
**Какие методы авторизации используют для построения API?**::


При построении API в PHP разработчики обычно используют различные методы аутентификации и авторизации, чтобы обеспечить безопасность и контроль доступа к ресурсам:

1. Токены доступа (Access Tokens): Это один из наиболее распространенных методов для аутентификации в API. После успешной аутентификации пользователь получает токен, который затем отправляется с каждым запросом API. Сервер API проверяет токен для разрешения доступа к ресурсам.

2. HTTP Basic Authentication: Пользовательские учетные данные (имя пользователя и пароль) отправляются в заголовке запроса. Однако, этот метод не является безопасным, так как учетные данные могут быть перехвачены.

3. Bearer Token Authentication: Это расширение для токенов доступа, где токен отправляется в заголовке Authorization как Bearer [access_token].

4. JWT (JSON Web Tokens): JWT — это компактный и самосодержащийся способ представления информации между двумя сторонами. Он может быть подписан (для обеспечения целостности данных) и зашифрован (для обеспечения конфиденциальности). JWT часто используются вместе с токенами доступа.

5. OAuth 2.0: Это открытый стандарт протокола аутентификации и авторизации, позволяющий приложениям получать доступ к ресурсам от имени пользователя. OAuth 2.0 поддерживает различные методы авторизации, включая авторизацию по паролю, авторизацию по коду подтверждения, и т.д.

6. API Keys: Каждый запрос к API содержит уникальный ключ (токен) для аутентификации. Обычно, этот ключ передается в заголовке запроса.

**Расскажите о утечки памяти в PHP. Приведите примеры.**::


Утечка памяти в PHP происходит, когда память, выделенная для выполнения программы, не освобождается после завершения ее работы, что может привести к исчерпанию ресурсов и падению производительности. Это может происходить, когда объекты или переменные не удаляются из памяти после завершения их использования.

Вот несколько примеров утечек памяти в PHP:

**1. Неявное копирование больших данных:**
В этом примере функция `str_replace` неявно выполняет копию большого файла в память, что приводит к утечке памяти. Рекомендуется использовать работу с файлами по частям или потоками (stream) для избежания этой проблемы.

**2. Открытые ресурсы без явного закрытия:**
В этом примере ресурс файла остается открытым после завершения программы, что приводит к утечке памяти. Рекомендуется всегда явно закрывать открытые ресурсы с помощью `fclose($handle);`.

**3. Циклические ссылки:**
В этом примере создаются два объекта `MyClass`, которые ссылаются друг на друга. Если эти объекты не освобождаются из памяти явным образом, то они продолжат существовать и приведут к утечке памяти. Рекомендуется обнулять ссылки перед выходом из области видимости или использовать сборку мусора (garbage collection) для автоматического удаления недоступных объектов.

Чтобы предотвратить утечки памяти в PHP, рекомендуется проводить регулярный аудит кода, закрывать открытые ресурсы, освобождать объекты из памяти после завершения их использования и избегать формирования циклических ссылок. Использование инструментов анализа кода и профилирования также может помочь в обнаружении и исправлении утечек памяти.

# **Какая разница между MyISAM и InnoDB? В каких случаях и что лучше применять?**
<!-- basicblock-start oid="ObsmXko0vaLew4zWyrNST4M9"  deck='P_PHP' -->
**Какая разница между MyISAM и InnoDB? В каких случаях и что лучше применять?**::


MyISAM и InnoDB — это два самых распространенных типа таблиц в MySQL. Отличия между ними заключаются в следующем:

**1. Система хранения данных:** MyISAM использует таблицы с фиксированной длиной строк, в то время как InnoDB использует таблицы с переменной длиной строк. Это означает, что MyISAM обычно быстрее при выполнении операций чтения, а InnoDB более эффективен при выполнении операций записи.

**2. Транзакции и целостность данных:** InnoDB поддерживает ACID-транзакции (Atomicity, Consistency, Isolation, Durability — Атомарность, Согласованность, Изолированность, Устойчивость). Это означает, что в случае сбоя данных, InnoDB может откатить все изменения, сохраняя целостность данных. MyISAM не поддерживает транзакции и не обеспечивает такую же уровень целостности данных.

**3. Блокировка таблиц:** MyISAM блокирует всю таблицу во время выполнения операции записи, в то время как InnoDB блокирует только строки, с которыми происходит операция. Это означает, что InnoDB обычно более подходит для многопользовательских приложений, где множество операций происходит одновременно.

**4. Внешние ключи:** InnoDB поддерживает внешние ключи (foreign keys), что облегчает поддержку связей между таблицами и обеспечивает целостность данных. MyISAM не поддерживает внешние ключи.

Итак, в каких случаях что лучше использовать:

🔸 Если нагрузка на базу данных состоит главным образом из операций чтения, то MyISAM может быть предпочтительнее из-за его более высокой производительности.
🔸 Если приложение требует поддержку транзакций (например, при обработке платежей или других критически важных операций), или имеется необходимость в внешних ключах для поддержания целостности данных, то InnoDB является более подходящим выбором.

В отличие от MyISAM, InnoDB также более рекомендуется при работе с многопользовательскими приложениями, где одновременно выполняется много операций записи и требуется высокий уровень целостности данных.

# Проблема здесь в том, что ваше регулярное выражение `/[(\*|\+|\/|\-)]*/` не соответствует ожидаемому поведению из-за нескольких факторов:
<!-- basicblock-start oid="ObswQhxROEX9d9XqHd8kJ2We"  deck='P_PHP' -->
Проблема здесь в том, что ваше регулярное выражение `/[(\*|\+|\/|\-)]*/` не соответствует ожидаемому поведению из-за нескольких факторов:::


1. **Квадратные скобки `[...]`**: В регулярных выражениях квадратные скобки используются для создания классов символов, что означает "любой из перечисленных символов". В вашем случае `[(*|+\/\-)]*` будет искать любое количество символов, соответствующих `(`, `*`, `+`, `/`, или `-`.

2. **Квантификатор `*`**: Символ `*` означает "ноль или более повторений предыдущего символа или группы символов". В вашем случае `[(\*|\+|\/|\-)]*` означает любое количество символов из перечисленных в квадратных скобках.

Для вашей строки "1 +     2   * 2 / 3", вы хотите извлечь операторы (`+`, `*`, `/`). Лучше всего использовать следующее регулярное выражение:

```
[\+\*\/\-]
```

Это выражение будет искать любой из операторов `+`, `*`, `/`, `-` в строке. Если вы хотите найти все вхождения операторов, вы можете использовать метод соответствия в Python или PHP:

```
import re

text = "1 +     2   * 2 / 3"
operators = re.findall(r'[\+\*\/\-]', text)

### Пример реализации польской нотации в PHP:
Рассмотрим функцию, которая вычисляет выражение, записанное в польской нотации, и поясним, как происходит заполнение стека:

```
function evaluatePolishNotation($expression) {
    $stack = []; // Инициализация пустого стека
    $tokens = explode(' ', $expression); // Разбиваем выражение на отдельные токены

    // Проходим по каждому токену (операнд или оператор)
    foreach (array_reverse($tokens) as $token) {
        // Если токен — оператор (+, -, *, /)
        if (in_array($token, ['+', '-', '*', '/'])) {
            // Извлекаем два верхних значения из стека
            $operand1 = array_pop($stack); // Первый операнд
            $operand2 = array_pop($stack); // Второй операнд

            // Выполняем операцию и результат кладем обратно в стек
            switch ($token) {
                case '+':
                    $result = $operand1 + $operand2;
                    break;
                case '-':
                    $result = $operand1 - $operand2;
                    break;
                case '*':
                    $result = $operand1 * $operand2;
                    break;
                case '/':
                    $result = $operand1 / $operand2;
                    break;
            }
            array_push($stack, $result); // Помещаем результат операции обратно в стек
        } else {
            // Если токен — операнд, просто помещаем его в стек
            array_push($stack, (float)$token);
        }
    }

    // В итоге в стеке останется одно значение — результат выражения
    return array_pop($stack);
}

// Пример использования:
$expression = '+ 3 * 4 2';
$result = evaluatePolishNotation($expression);
echo "Результат: " . $result; // Вывод: Результат: 11
```

### Как заполняется стек:
1. **Начало:** Изначально стек пустой.

2. **Чтение токенов:**
   - Выражение разбивается на токены: `['+', '3', '*', '4', '2']`.
   - Токены обрабатываются в обратном порядке, начиная с `'2'` и заканчивая `'+'`.

3. **Заполнение стека:**
   - **Токен `'2'`:** Это операнд, поэтому он помещается в стек.  
     Состояние стека: `[2]`
   - **Токен `'4'`:** Это тоже операнд, и он также помещается в стек.  
     Состояние стека: `[2, 4]`
   - **Токен `'*'`:** Это оператор. Для его выполнения из стека извлекаются два верхних операнда: `4` и `2`. Выполняется операция `4 * 2`, результат `8` помещается обратно в стек.  
     Состояние стека: `[8]`
   - **Токен `'3'`:** Это операнд, и он помещается в стек.  
     Состояние стека: `[8, 3]`
   - **Токен `'+'`:** Это оператор. Из стека извлекаются два верхних операнда: `3` и `8`. Выполняется операция `3 + 8`, результат `11` помещается обратно в стек.  
     Состояние стека: `[11]`

4. **Результат:** В конце в стеке остается одно значение — результат выражения, которое и возвращается.

Этот процесс иллюстрирует, как стек используется для хранения операндов и промежуточных результатов, что позволяет корректно вычислить выражение в польской нотации.

### Особенности польской нотации:
1. **Отсутствие скобок:** В польской нотации нет необходимости использовать скобки для указания порядка операций, так как этот порядок однозначно определяется самим порядком следования операторов и операндов.
2. **Чтение слева направо:** Выражение в польской нотации вычисляется слева направо, причем операторы применяются сразу к следующим за ними операндам.
3. **Удобство для вычислительных машин:** Такая форма записи удобна для обработки компьютерами, так как она не требует запоминания приоритета операций и позволяет обходиться без скобок.

### Пример польской нотации:
Рассмотрим простое арифметическое выражение:
- Инфиксная нотация (стандартная форма): `3 + 4 * 2`
- Польская нотация (префиксная форма): `+ 3 * 4 2`

Для примера, выражение `+ 3 * 4 2` в польской нотации интерпретируется следующим образом:
1. Оператор `+` применяется к `3` и результату выражения `* 4 2`.
2. Оператор `*` применяется к `4` и `2`, результат равен `8`.
3. Оператор `+` теперь применяется к `3` и `8`, что дает результат `11`.

<u>PSR (PHP Standard Recommendation) и RFC (Request for Comments)</u> играют важные роли в стандартизации и развитии PHP.

🤔 **PSR (PHP Standard Recommendation)**

Это стандарты, которые предлагаются PHP Framework Interop Group (PHP-FIG), группой, которая состоит из представителей ведущих PHP-проектов. Цель этих стандартов — улучшить совместимость между различными PHP-фреймворками и библиотеками. Его стандарты  охватывают различные аспекты программирования на PHP, такие как стиль кодирования, логирование, автозагрузка классов и многие другие. 

Пример стандарта PSR-4, который касается автозагрузки классов. В соответствии с PSR-4, каждый класс должен находиться в отдельном файле, и пространство имен класса должно соответствовать структуре каталогов файловой системы. Это упрощает автозагрузку классов без необходимости регистрации каждого класса вручную.
```
// Пример автозагрузки в соответствии с PSR-4
spl_autoload_register(function ($class) {
    include 'src/' . str_replace('\\', '/', $class) . '.php';
});
```

🤔 **RFC (Request for Comments)**

Это документы, которые предлагают нововведения или изменения в языке PHP. Любой участник сообщества может предложить RFC, который будет рассмотрен и, возможно, принят для реализации в будущих версиях PHP. RFC обсуждаются на официальном сайте PHP и в рассылках, где разработчики могут высказывать свои мнения и голосовать за или против предложений.

RFC часто включают подробные описания предлагаемых функций, примеры кода, обсуждение возможных проблем и другие технические детали. Например, введение типизации аргументов функций в PHP было одобрено через процесс RFC.

🤔 **Итог:**

PSR и RFC являются важными элементами экосистемы PHP. PSR помогают разработчикам следовать общим стандартам и обеспечивают лучшую совместимость между различными проектами. RFC позволяют сообществу направлять развитие PHP, предлагая и обсуждая новые функции и изменения.

<?php phpinfo(); ?>

Как установить и использовать дополнительные верссии php? mac::


На macOS установка и использование нескольких версий PHP можно осуществить с помощью пакетного менеджера **Homebrew**. Вот пошаговое руководство, как это сделать:

### 1. Установите Homebrew (если ещё не установлен):

Если у вас еще нет Homebrew, установите его с помощью следующей команды:

```
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

### 2. Обновите Homebrew:

Убедитесь, что Homebrew обновлен:

```
brew update
```

### 3. Установите нужные версии PHP:

Homebrew позволяет устанавливать несколько версий PHP. Например, чтобы установить PHP 7.4 и PHP 8.1, выполните следующие команды:

```
brew install php@7.4
brew install php@8.1
```

### 4. Переключение между версиями PHP:

Вы можете переключаться между разными версиями PHP, используя команду `brew unlink` и `brew link`. Например:

```
# Отключаем текущую версию PHP
brew unlink php

# Подключаем PHP 7.4
brew link --force --overwrite php@7.4

# Проверяем текущую версию PHP
php -v

# Подключаем PHP 8.1
brew unlink php@7.4
brew link --force --overwrite php@8.1

# Проверяем текущую версию PHP
php -v
```

### 5. Использование нескольких версий PHP с Valet (опционально):

Если вы используете Laravel Valet или другой инструмент для локального хостинга, вы можете переключать версии PHP для разных проектов.

Убедитесь, что Valet настроен для использования нужной версии PHP:

```
valet use php@7.4
```

### 6. Настройка веб-сервера (если требуется):

Если вы настраиваете локальный веб-сервер, такой как Apache или Nginx, вам нужно будет настроить конфигурацию для использования нужной версии PHP. 

Например, для Apache вам нужно будет указать путь к соответствующему модулю PHP в файле конфигурации:

```
# Отключаем модуль текущей версии PHP
sudo apachectl stop
sudo brew unlink php

# Подключаем модуль нужной версии PHP
sudo brew link php@7.4
sudo apachectl start
```

### 7. Проверка:

После переключения версии PHP в командной строке убедитесь, что нужная версия активна:

```
php -v
```

### Заключение

Теперь вы можете устанавливать и использовать несколько версий PHP на macOS. Это позволит вам гибко управлять версиями PHP для разных проектов, переключаясь между ними в зависимости от требований приложений.

📌 **<u>В каких случаях используют индексы?</u>** ::


💬 [Спрашивают в 33% собеседований](https://easyoffer.ru/rating/php_developer)

Индексы в базах данных используются для ускорения процесса поиска и извлечения данных. Эти инструменты особенно важны в условиях больших объемов данных и сложных запросов. Могут быть сравнены с оглавлением книги: вместо того, чтобы просматривать всю книгу (или всю таблицу данных), система может обратиться к индексу, чтобы быстро найти нужную информацию.

🤔 **Основные случаи использования:**

1️⃣ **Поиск по ключевым столбцам**: 

Если запросы часто включают поиск по определённому столбцу, индекс по этому столбцу может значительно ускорить эти операции. Например, если вы часто ищете пользователей по их email, стоит создать индекс по столбцу email.

2️⃣ **Условия в запросах (WHERE)**:

 Индексы очень полезны для условий фильтрации в запросах, особенно когда они включают большие объёмы данных.

3️⃣ **Сортировка данных (ORDER BY)**: 

Если запросы часто требуют сортировки по определённому полю, индекс по этому полю поможет ускорить процесс сортировки, так как данные в индексе уже будут частично или полностью упорядочены.

4️⃣ **Операции объединения (JOIN)**: 

Индексы на полях, используемых для соединения таблиц, могут значительно ускорить эти операции, особенно при работе с большими таблицами.

5️⃣ **Агрегация данных (GROUP BY)**: 

Индексы могут ускорить группировку данных, если группировка происходит по индексированным полям.

**🤔**** Итог:**

Использование индексов делает операции с базой данных быстрее и эффективнее, особенно при больших объёмах данных. Они как оглавление в книге, позволяющее быстро найти нужную информацию без необходимости "перелистывать" всю книгу.

**Расскажите про функции defined и get_defined_constants**::


**defined():**
Функция defined() используется для проверки существования константы с заданным именем. Она возвращает true, если константа существует, и false, если нет.

**get_defined_constants():**
Функция get_defined_constants() возвращает ассоциативный массив, содержащий все определенные константы в текущем скрипте. Этот массив имеет два уровня: глобальные константы и локальные (если они определены внутри функции).
