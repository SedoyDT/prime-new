# Чем композиция отличается от наследования?
<!-- basicblock-start oid="ObsBbsNkYgpMYpzcEHFLwGWT"  deck='O_oop' -->
Чем композиция отличается от наследования?::


Композиция и наследование — два основных подхода к организации кода и моделированию отношений между классами в объектно-ориентированном программировании (ООП). Они решают задачу повторного использования кода и упрощения дизайна, но имеют принципиальные различия.

---

### Наследование
**Наследование** — это создание нового класса на основе существующего. Новый класс (потомок) **расширяет** или **переопределяет** функциональность базового класса (родителя).

#### Преимущества наследования:
1. **Повторное использование кода**: Подкласс автоматически наследует методы и свойства родительского класса.
2. **Простота связи**: Подкласс можно рассматривать как "расширенную" версию родителя.

#### Пример:
```
class Animal {
    public function makeSound() {
        return "Some sound";
    }
}

class Dog extends Animal {
    public function makeSound() {
        return "Bark";
    }
}

$dog = new Dog();
echo $dog->makeSound(); // Вывод: Bark
```

#### Недостатки наследования:
1. **Жёсткая связь (tight coupling)**: Подклассы сильно зависят от базового класса. Изменения в родителе могут привести к ошибкам в наследниках.
2. **Ограниченность**: У класса может быть только один родитель (в языках с одиночным наследованием, как PHP).
3. **Сложность масштабирования**: Глубокая иерархия классов усложняет поддержку и понимание кода.

---

### Композиция
**Композиция** — это объединение объектов, где один объект **включает** другой как свой компонент, вместо того чтобы наследовать его. Композиция основана на принципе "имеет" (has-a).

#### Преимущества композиции:
1. **Гибкость**: Легко заменять или изменять компоненты объекта без изменения его основной структуры.
2. **Слабая связь (loose coupling)**: Изменения в одном классе минимально влияют на другие.
3. **Поддержка множественных компонентов**: Объект может содержать несколько независимых компонентов.

#### Пример:
```
class Engine {
    public function start() {
        return "Engine started";
    }
}

class Car {
    private $engine;

    public function __construct(Engine $engine) {
        $this->engine = $engine;
    }

    public function startCar() {
        return $this->engine->start();
    }
}

$engine = new Engine();
$car = new Car($engine);
echo $car->startCar(); // Вывод: Engine started
```

#### Недостатки композиции:
1. **Чуть больше кода**: Нужно вручную описывать связи между объектами.
2. **Менее интуитивно**: Новичкам иногда сложнее понять, как организована композиция, по сравнению с наследованием.

---

### Ключевые отличия

| **Характеристика**      | **Наследование**                             | **Композиция**                                 |
|--------------------------|----------------------------------------------|-----------------------------------------------|
| **Отношение**           | "Является" (is-a)                           | "Имеет" (has-a)                               |
| **Связь**               | Жёсткая                                     | Слабая                                        |
| **Повторное использование** | Через наследование методов/свойств         | Через включение компонентов                   |
| **Множественность**      | Один родитель (в языках с одиночным наследованием) | Может включать множество компонентов          |
| **Гибкость**            | Меньшая: зависимость от родительского класса | Больше: можно менять или заменять компоненты  |
| **Сложность**           | Простая структура для небольших задач       | Более сложная, но масштабируемая              |

---

### Когда использовать?

1. **Используйте наследование**, если:
   - Существует строгая иерархическая связь.
   - Подкласс действительно является разновидностью родительского класса.

2. **Используйте композицию**, если:
   - Требуется гибкость.
   - Нужно менять или добавлять компоненты без изменения существующего кода.
   - Объект включает функциональность, а не является её разновидностью.

---

### Резюме
- Наследование подходит для моделирования иерархических отношений, но увеличивает связанность кода.
- Композиция лучше для гибких систем, которые должны легко изменяться или расширяться.
