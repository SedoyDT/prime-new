# Чем отличается require от require-dev composer?
<!-- basicblock-start oid="ObsTuQ09ImbZqS199zyk5MXL"  deck='0_Pd_php_composer' -->
Чем отличается require от require-dev composer?::


В Composer, инструменте для управления зависимостями в PHP, существуют два основных типа зависимостей, которые вы можете указать в вашем `composer.json` файле: `require` и `require-dev`. Вот в чём их различия:

### `require`

- **Цель**: Зависимости, указанные в разделе `require`, являются обязательными для работы вашего проекта. Это те библиотеки и пакеты, которые необходимы вашему приложению в любом окружении, будь то продакшен, тестирование или разработка.

- **Использование**: Эти зависимости устанавливаются при выполнении команды `composer install`, и они включены в ваше приложение на всех стадиях его жизненного цикла.

- **Пример**:
  ```

  {
    "require": {
      "monolog/monolog": "^2.0",
      "guzzlehttp/guzzle": "^7.0"
    }
  }
  
```
  В этом примере `monolog/monolog` и `guzzlehttp/guzzle` являются обязательными для работы вашего приложения.

### `require-dev`

- **Цель**: Зависимости, указанные в разделе `require-dev`, предназначены только для разработки и тестирования. Эти пакеты необходимы для разработки вашего проекта, но не для его запуска в продакшен-окружении.

- **Использование**: Эти зависимости устанавливаются при выполнении команды `composer install --dev` или `composer install` в среде разработки. Они не устанавливаются при развертывании на продакшен-сервере или в других средах, где не требуется разработка и тестирование.

- **Пример**:
  ```

  {
    "require-dev": {
      "phpunit/phpunit": "^9.0",
      "phpspec/phpspec": "^5.0"
    }
  }
  
```
  В этом примере `phpunit/phpunit` и `phpspec/phpspec` используются только для тестирования и разработки, и не требуются в продакшен-окружении.

### Основные различия

- **Окружение**:
  - `require`: Необходимы во всех окружениях (продакшен, разработка, тестирование).
  - `require-dev`: Необходимы только в окружении разработки и тестирования.

- **Установка**:
  - `require`: Устанавливаются по умолчанию при запуске `composer install`.
  - `require-dev`: Устанавливаются только при явном указании или в среде разработки. Не устанавливаются при запуске `composer install --no-dev`.

- **Производительность**:
  - `require-dev`: Не загружаются в продакшен, что может помочь уменьшить размер развертывания и повысить производительность за счёт исключения ненужных зависимостей.

### Примеры использования

1. **Добавление зависимости для продакшен и разработки**:
   ```

   composer require monolog/monolog
   
```

2. **Добавление зависимости только для разработки**:
   ```

   composer require --dev phpunit/phpunit
   
```

Таким образом, использование `require` и `require-dev` помогает управлять зависимостями вашего проекта, гарантируя, что в продакшен-среде присутствуют только необходимые компоненты, а инструменты разработки и тестирования остаются только в среде разработки.

# Как запустить php из консоли?
<!-- basicblock-start oid="ObszC2s43cVHn2Q5ab6MadYN"  deck='0_Pd_php_composer' -->
Как запустить php из консоли?::


Запуск PHP из консоли может быть выполнен несколькими способами, в зависимости от того, что именно вам нужно сделать. Вот основные способы:

### 1. Запуск PHP-скрипта

Если у вас есть PHP-скрипт, который вы хотите выполнить, используйте следующую команду:

```

php /path/to/your/script.php

```

**Пример:**

Если ваш скрипт называется `test.php` и находится в текущей директории, команда будет:

```

php test.php

```

### 2. Запуск интерактивного режима PHP

Вы можете запустить интерактивный режим PHP для выполнения команд в интерактивной сессии:

```

php -a

```

В этом режиме вы можете вводить и исполнять PHP-код напрямую. Например:

```

php -a

```

После запуска вы увидите командную строку PHP:

```

php > echo "Hello, world!";
Hello, world!

```

### 3. Проверка версии PHP

Чтобы проверить установленную версию PHP, используйте:

```

php -v

```

Это выведет информацию о версии PHP и установленном расширении.

**Пример вывода:**

```

PHP 8.0.3 (cli) (built: Mar  2 2021 16:47:23) ( NTS )
Copyright (c) The PHP Group
Zend Engine v4.0.3, Copyright (c) Zend Technologies

```

### 4. Запуск встроенного веб-сервера PHP

PHP имеет встроенный веб-сервер, который можно использовать для тестирования веб-приложений без необходимости настройки полноценного веб-сервера. Для запуска встроенного веб-сервера выполните:

```

php -S localhost:8000

```

Эта команда запустит веб-сервер на `localhost` и порту `8000`. Если у вас есть файл `index.php` в текущей директории, он будет доступен по адресу `http://localhost:8000`.

### 5. Запуск PHP с указанием конфигурационного файла

Если вы хотите запустить PHP с определённым конфигурационным файлом (php.ini), используйте:

```

php -c /path/to/php.ini /path/to/your/script.php

```

**Пример:**

```

php -c /etc/php/7.4/cli/php.ini test.php

```

### 6. Запуск PHP с указанным режимом (CLI или FPM)

PHP может быть настроен как CLI (Command Line Interface) или FPM (FastCGI Process Manager). Убедитесь, что вы используете команду для нужного режима. CLI используется для выполнения командных скриптов, в то время как FPM работает с веб-сервером.

### Дополнительные советы

- Убедитесь, что PHP установлен и добавлен в переменную окружения PATH, чтобы можно было вызывать команду `php` из любой директории.
- Вы можете проверить пути установки и конфигурационные файлы PHP, используя команды `which php` или `whereis php` для получения информации о пути к исполняемому файлу PHP.

# Add PSR-4 autoload mapping? Maps namespace "Frolov\Test" to the entered relative path. [src/, n to skip]: **что это значит?**
<!-- basicblock-start oid="ObspdcEg52fG5cEdlvu50TQg"  deck='0_Pd_php_composer' -->
Add PSR-4 autoload mapping? Maps namespace "Frolov\Test" to the entered relative path. [src/, n to skip]: **что это значит?**::


При запуске команды `composer init` для создания нового проекта с Composer, вам может быть предложено настроить автозагрузку для вашего проекта. Одна из таких опций — это настройка автозагрузки по стандарту **PSR-4**.

### Значение запроса

Когда вам задают вопрос **"Add PSR-4 autoload mapping? Maps namespace 'Frolov\Test' to the entered relative path. [src/, n to skip]:"**, это означает следующее:

- **PSR-4 автозагрузка**: Вам предлагается настроить автозагрузку классов с использованием стандарта PSR-4. PSR-4 позволяет вам сопоставить пространства имен PHP с каталогами в файловой системе, упрощая автоматическую загрузку классов.

- **Namespace 'Frolov\Test'**: Вопрос указывает, что для автозагрузки будет использоваться пространство имен `Frolov\Test`. Это пространство имен будет сопоставляться с указанным путем в файловой системе.

- **Relative path**: Вам нужно указать относительный путь от корня вашего проекта до каталога, где будут находиться файлы классов, соответствующие этому пространству имен.

### Примеры

1. **Стандартная настройка**:
   - Если вы введете `src/`, это означает, что классы с пространством имен `Frolov\Test` будут размещены в каталоге `src/`. Например, класс `Frolov\Test\SomeClass` будет находиться в файле `src/SomeClass.php`.

     ```

     "autoload": {
         "psr-4": {
             "Frolov\\Test\\": "src/"
         }
     }
     
```

2. **Пропуск настройки**:
   - Если вы введете `n` (или просто нажмете Enter), настройка автозагрузки для этого пространства имен не будет добавлена. В этом случае вам придется настроить автозагрузку вручную в `composer.json`, если вам это понадобится в будущем.

### Как это выглядит в `composer.json`

После ввода относительного пути, в вашем `composer.json` будет добавлена секция `autoload` для PSR-4. Например, если вы указали `src/`, файл `composer.json` будет содержать:

```

{
    "autoload": {
        "psr-4": {
            "Frolov\\Test\\": "src/"
        }
    }
}

```

### Подробности

- **Файлы классов**: При такой настройке все классы, объявленные в пространстве имен `Frolov\Test`, должны находиться в каталоге `src/`. Например, класс `Frolov\Test\Example` будет находиться в `src/Example.php`.

- **Автозагрузка**: Composer будет автоматически загружать файлы классов из указанного каталога, когда вы будете использовать эти классы в вашем коде.

- **Обновление автозагрузчика**: После внесения изменений в `composer.json`, не забудьте запустить `composer dump-autoload`, чтобы обновить автозагрузчик.

Эта настройка помогает поддерживать структуру вашего кода организованной и облегчает работу с большими проектами, обеспечивая соответствие стандартам PHP и упрощая загрузку классов.

# Что такое psr-0
<!-- basicblock-start oid="ObstePpInttQeCWvwSABcfih"  deck='0_Pd_php_composer' -->
Что такое psr-0::


**PSR-0** (PHP Standard Recommendation 0) — это стандарт автозагрузки для PHP, разработанный PHP Framework Interop Group (PHP-FIG). Этот стандарт был принят в 2009 году и описывает, как должно быть организовано пространство имен и автозагрузка классов в PHP-проектах. 

### Основные принципы PSR-0

1. **Структура каталогов и именование классов**:
   - **Имя класса** должно совпадать с именем файла, в котором он находится.
   - Пространства имен (namespaces) и имена классов используются для определения структуры каталогов.
   - Пространства имен и имена классов преобразуются в путь к файлу по следующему принципу:
     - Пробелы или специальные символы в именах классов заменяются на символ `/` в пути к файлу.
     - Имя пространства имен и имя класса используются для создания структуры каталогов.
     - Например, класс `Vendor\Package\ClassName` должен быть расположен в `Vendor/Package/ClassName.php`.

2. **Формат файлов**:
   - Каждое имя пространства имен и имя класса должно быть представлено в виде файла и папок, где каждый элемент имени пространства имен и класса преобразуется в часть пути.
   - Корневой каталог или пространство имен указывает на корневой каталог проекта.

3. **Автозагрузка классов**:
   - PSR-0 требует, чтобы автозагрузчик преобразовывал пространство имен и имена классов в пути файлов и автоматически загружал их.

### Пример PSR-0

Предположим, у вас есть класс с именем `Vendor\Package\ClassName`. По стандарту PSR-0, структура файлов и каталогов должна выглядеть следующим образом:

```

/path/to/project/
├── Vendor/
│   └── Package/
│       └── ClassName.php

```

Файл `ClassName.php` должен содержать класс:

```

namespace Vendor\Package;

class ClassName {
    // Class implementation
}

```

### PSR-0 vs PSR-4

**PSR-0** был заменен **PSR-4** (PHP Standard Recommendation 4) в 2014 году. PSR-4 — это более гибкий стандарт автозагрузки, который упрощает организацию и загружает классы, основываясь на пространствах имен, не требуя строгого соответствия структуре каталогов и файлов, как это было в PSR-0.

**Основные отличия PSR-4 от PSR-0**:

1. **Формат пространства имен**:
   - В PSR-4 нет строгого требования, чтобы пространство имен и структура каталогов совпадали. Это позволяет иметь более свободную структуру каталогов.

2. **Множественные базовые каталоги**:
   - PSR-4 позволяет использовать несколько базовых каталогов, что упрощает организацию больших проектов.

3. **Нет необходимости в подкаталогах**:
   - В PSR-4 структура каталогов может быть более гибкой, и нет необходимости создавать подкаталоги для каждого пространства имен.

### Заключение

PSR-0 был важным шагом в стандартизации автозагрузки классов в PHP и способствовал лучшему взаимодействию между библиотеками и фреймворками. Несмотря на его устаревание, принципы PSR-0 все еще могут быть полезны для понимания базовых концепций автозагрузки и структуры кода в PHP.
