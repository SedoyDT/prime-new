### Zend_Controller_Router_Route_Regex::


**Описание**

`Zend_Controller_Router_Route_Regex` — это тип маршрута, который использует регулярные выражения для сопоставления URL. Этот маршрут предоставляет больше мощности и гибкости по сравнению с другими типами маршрутов, но это происходит за счет небольшой сложности. В то же время этот тип маршрута должен быть быстрее, чем стандартный маршрут, так как он позволяет обрабатывать URL-адреса с большей точностью и меньшими ограничениями.

**Пример использования**

Для создания маршрута с регулярным выражением необходимо определить маршрут и задать значения по умолчанию. Рассмотрим создание маршрута для архива, аналогичного предыдущему примеру, но с использованием регулярных выражений:

```

$route = new Zend_Controller_Router_Route_Regex(
    'archive/(\d+)',
    array(
        'controller' => 'archive',
        'action'     => 'show'
    )
);
$router->addRoute('archive', $route);

```

В этом примере маршрут будет сопоставлен с URL, который соответствует шаблону `archive/(\d+)`, где `\d+` — это любое количество цифр. После успешного сопоставления URL `http://domain.com/archive/2006` значения параметров будут выглядеть так:

```

$values = array(
    1            => '2006',  // Подвыражение регулярки захватывает 2006
    'controller' => 'archive',
    'action'     => 'show'
);

```

**Замечания:**

1. Перед сопоставлением из URL удаляются начальные и конечные слэши.
2. Анкоры начала и конца строки (`^` и `$`) автоматически добавляются к выражениям, поэтому их не нужно использовать в регулярных выражениях.
3. Этот класс маршрута использует символ `#` в качестве разделителя, поэтому при определении маршрутов нужно экранировать `#`, но не `/`.

**Извлечение параметров из регулярных выражений**

Вы можете получить параметры из подвыражений, используя метод `getParam()`:

```

public function showAction()
{
    $request = $this->getRequest();
    $year    = $request->getParam(1); // $year = '2006';
}

```

Здесь используется целочисленный ключ `1`, чтобы получить значение года из параметров запроса.

**Работа с необязательными подвыражениями**

Чтобы сделать часть маршрута необязательной, можно использовать дополнительное регулярное выражение:

```

$route = new Zend_Controller_Router_Route_Regex(
    'archive(?:/(\d+))?',
    array(
        1            => '2006',
        'controller' => 'archive',
        'action'     => 'show'
    )
);
$router->addRoute('archive', $route);

```

Теперь, если в URL отсутствует год, он будет установлен в значение по умолчанию `'2006'`.

**Преобразование имен параметров**

Использование целочисленных ключей для параметров может быть не очень удобным. Третий параметр конструктора — это ассоциативный массив, который представляет собой сопоставление подвыражений регулярного выражения с именованными ключами параметров. Пример:

```

$route = new Zend_Controller_Router_Route_Regex(
    'archive/(\d+)',
    array(
        'controller' => 'archive',
        'action'     => 'show'
    ),
    array(
        1 => 'year'
    )
);
$router->addRoute('archive', $route);

```

Это приведет к следующему набору значений, внедренных в запрос:

```

$values = array(
    'year'       => '2006',
    'controller' => 'archive',
    'action'     => 'show'
);

```

Можно задавать сопоставления как в направлении `подвыражение -> имя параметра`, так и в обратном:

```

$route = new Zend_Controller_Router_Route_Regex(
    'archive/(\d+)',
    array( ... ),
    array(1 => 'year')  // Или array('year' => 1)
);

```

**Заключение**

Использование маршрутов на основе регулярных выражений в `Zend Framework` предоставляет значительную гибкость и возможность создания сложных и уникальных URL. Это позволяет разработчикам более точно определять структуру URL и более эффективно управлять маршрутами, которые не могут быть описаны с помощью стандартных или статических маршрутов.
