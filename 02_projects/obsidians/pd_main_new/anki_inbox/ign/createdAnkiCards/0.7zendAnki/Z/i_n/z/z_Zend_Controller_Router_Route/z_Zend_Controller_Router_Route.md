### Значения по умолчанию для переменных

Каждая переменная в маршруте может иметь значение по умолчанию, и именно для этого используется второй параметр конструктора `Zend_Controller_Router_Route`. Этот параметр представляет собой массив, где ключи являются именами переменных, а значения — желаемыми значениями по умолчанию:

```

$route = new Zend_Controller_Router_Route(
    'archive/:year',
    array('year' => 2006)
);
$router->addRoute('archive', $route);

```

Вышеуказанный маршрут будет соответствовать таким URL, как `http://domain.com/archive/2005` и `http://example.com/archive`. В последнем случае переменная `year` будет иметь начальное значение по умолчанию 2006.

Этот пример приведет к добавлению переменной `year` в объект запроса. Поскольку информации о маршрутизации нет (параметры `controller` и `action` не определены), приложение будет направлено на контроллер и метод действия по умолчанию (которые оба определены в `Zend_Controller_Dispatcher_Abstract`). Чтобы сделать маршрут более удобным, нужно указать действительный контроллер и действительное действие в качестве значений по умолчанию для маршрута:

```

$route = new Zend_Controller_Router_Route(
    'archive/:year',
    array(
        'year' => 2006,
        'controller' => 'archive',
        'action' => 'show'
    )
);
$router->addRoute('archive', $route);

```

Этот маршрут приведет к вызову метода `showAction()` класса `ArchiveController`.

### Пояснения:

1. **Значения по умолчанию для переменных**: В маршрутах Zend Framework можно указывать значения по умолчанию для переменных. Если URL не содержит переменной, указанной в маршруте, будет использоваться значение по умолчанию, заданное в массиве.

2. **Сопоставление URL с маршрутом**: В примере `http://example.com/archive` переменная `year` не указана в URL, поэтому используется значение по умолчанию 2006.

3. **Определение контроллера и действия по умолчанию**: Если в маршруте не указаны контроллер и действие, Zend Framework использует контроллер и действие по умолчанию, определенные в `Zend_Controller_Dispatcher_Abstract`. Однако, чтобы сделать маршрут более конкретным и полезным, рекомендуется явно указывать контроллер и действие в настройках маршрута.

4. **Использование значений по умолчанию для маршрутизации**: Указание контроллера и действия по умолчанию, как в последнем примере, обеспечивает корректное направление на нужный контроллер и действие (`ArchiveController` и метод `showAction()`). Это позволяет маршруту работать предсказуемо и удобно. 

Такой подход к маршрутизации делает приложения на базе Zend Framework гибкими и позволяет легко обрабатывать различные URL с минимальными усилиями, задавая при этом логичные значения по умолчанию.

**Zend_Controller_Router_Route** — это стандартный маршрут (route) фреймворка Zend Framework. Он сочетает в себе простоту использования с гибкостью определения маршрутов. Каждый маршрут состоит в основном из сопоставления URL (как статических, так и динамических частей (переменных)) и может быть инициализирован значениями по умолчанию, а также с требованиями к переменным.

Представим, что наше вымышленное приложение будет нуждаться в информационной странице об авторах контента. Мы хотим иметь возможность направить наш веб-браузер на URL `http://domain.com/author/martel`, чтобы увидеть информацию об этом "martel". Маршрут для такой функциональности мог бы выглядеть следующим образом:

```

$route = new Zend_Controller_Router_Route(
    'author/:username',
    array(
        'controller' => 'profile',
        'action' => 'userinfo'
    )
);
 
$router->addRoute('user', $route);

```

Первый параметр в конструкторе `Zend_Controller_Router_Route` — это определение маршрута, которое будет сопоставлено с URL. Определение маршрута состоит из статических и динамических частей, разделенных символом слэша ('/'). Статические части — это просто текст: `author`. Динамические части, называемые переменными, отмечены добавлением двоеточия перед именем переменной: `:username`.

**Примечание: использование символов**
Текущая реализация позволяет использовать любой символ (кроме слэша) в качестве идентификатора переменной, но настоятельно рекомендуется использовать только символы, допустимые для идентификаторов переменных в PHP. В будущих версиях поведение может измениться, что может привести к скрытым ошибкам в вашем коде.

Этот пример маршрута должен быть сопоставлен, когда вы указываете в браузере URL `http://domain.com/author/martel`, в таком случае все его переменные будут переданы в объект `Zend_Controller_Request` и будут доступны в вашем контроллере `ProfileController`. Переменные, возвращаемые этим примером, могут быть представлены в виде массива с следующими ключами и значениями:

```

$values = array(
    'username' => 'martel',
    'controller' => 'profile',
    'action' => 'userinfo'
);

```

Позже `Zend_Controller_Dispatcher_Standard` должен вызвать метод `userinfoAction()` вашего класса `ProfileController` (в модуле по умолчанию) на основе этих значений. В этом методе вы сможете получить доступ ко всем переменным с помощью методов `Zend_Controller_Action::_getParam()` или `Zend_Controller_Request::getParam()`:

```

public function userinfoAction()
{
    $request = $this->getRequest();
    $username = $request->getParam('username');
 
    $username = $this->_getParam('username');
}

```

Определение маршрута может содержать еще один специальный символ — *подстановочный знак* (`*`). Он используется для сбора параметров, аналогично поведению маршрута модуля по умолчанию (пары `ключ => значение`, определенные в URI). Следующий маршрут в большей степени имитирует поведение маршрута модуля:

```

$route = new Zend_Controller_Router_Route(
    ':module/:controller/:action/*',
    array('module' => 'default')
);
$router->addRoute('default', $route);

```

### Пояснения:

1. **Маршрут (Route)** — это правило сопоставления URL с действиями (actions) контроллера. В данном случае маршрут определяет, как URL вида `http://domain.com/author/:username` будет ассоциироваться с определенным контроллером и действием.

2. **Динамические и статические части** — в URL могут быть как фиксированные части (например, `author`), так и переменные (например,` :username`), которые меняются в зависимости от запроса.

3. **Инициализация маршрута** — при создании маршрута можно указать, какой контроллер и какое действие будет выполняться при сопоставлении URL.

4. **Подстановочный знак `*`** — используется для сбора дополнительных параметров, которые не определены явно в маршруте, но присутствуют в URL.
