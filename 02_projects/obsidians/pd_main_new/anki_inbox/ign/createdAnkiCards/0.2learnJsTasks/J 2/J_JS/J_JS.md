# **<u>🤔</u>****<u> Как добавить слушатель события?</u>**
<!-- basicblock-start oid="ObskVMz6CsQtcTNtxzu4iGXf"  deck='J_JS' -->
**<u>🤔</u>****<u> Как добавить слушатель события?</u>**::


Это важный аспект работы с веб-приложениями, так как позволяет реагировать на действия пользователя, такие как клики, ввод текста, прокрутка и другие. В современных фреймворках и библиотеке JavaScript есть несколько способов добавить слушатели событий.

🚩**Почему это нужно?**

Слушатели событий позволяют интерактивно реагировать на действия пользователей, делая приложения динамичными и отзывчивыми. Например, при клике на кнопку можно вызвать определенную функцию, при вводе текста в поле — обновить состояние и так далее.

🚩**Как это используется?**

Рассмотрим три основных подхода к добавлению слушателей событий: в чистом JavaScript, в React и с использованием jQuery.

🟠**Чистый JavaScript**
Для добавления слушателя события используется метод `addEventListener`.
```
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Event Listener Example</title>
</head>
<body>
  <button id="myButton">Click me</button>

  <script>
    const button = document.getElementById('myButton');
    
    button.addEventListener('click', () => {
      alert('Button was clicked!');
    });
  </script>
</body>
</html>
```

🟠**React**
Обработчики событий добавляются непосредственно к JSX-элементам с использованием специальных атрибутов, таких как `onClick`, `onChange` и т.д.
```
import React from 'react';

function App() {
  const handleClick = () => {
    alert('Button was clicked!');
  };

  return (
    <div>
      <button onClick={handleClick}>Click me</button>
    </div>
  );
}

export default App;
```

🟠**jQuery**
Если вы используете его, добавление слушателей событий также очень просто и удобно.
```
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Event Listener Example</title>
  <script src="https://code.jquery.com/jquery-3.6.0.min.js"></script>
</head>
<body>
  <button id="myButton">Click me</button>

  <script>
    $(document).ready(function() {
      $('#myButton').on('click', function() {
        alert('Button was clicked!');
      });
    });
  </script>
</body>
</html>
```

🚩**Почему это удобно и важно**

🟠**Интерактивность**
Позволяет создавать динамичные и отзывчивые интерфейсы.
🟠**Гибкость**
Возможность реагировать на различные действия пользователей.
🟠**Удобство**
В каждом подходе (чистый JavaScript, React, jQuery) есть свои удобства и особенности, которые помогают решать задачи более эффективно.

# 🤔 **Что такое макро и микро задачи?**
<!-- basicblock-start oid="Obse0evpqiikHwHLVcwdfkyZ"  deck='J_JS' -->
🤔 **Что такое макро и микро задачи?**::


Макро-задачи (macro-tasks) — это крупные задачи, такие как события ввода-вывода, таймеры или сетевые запросы, которые планируются в основной очереди событий. Микро-задачи (micro-tasks) — это задачи меньшего приоритета, которые выполняются сразу после завершения текущего блока кода, но до выполнения следующих макро-задач (например, Promise или MutationObserver). Микро-задачи всегда выполняются перед макро-задачами, что позволяет им завершаться быстрее. Это важное отличие в управлении асинхронным кодом и приоритизацией событий.

# **<u>🤔</u>****<u> Как бы добавлял статический метод в prototype?</u>**
<!-- basicblock-start oid="Obs0KXG3wK9bmE8Rzx5wZSk7"  deck='J_JS' -->
**<u>🤔</u>****<u> Как бы добавлял статический метод в prototype?</u>**::


На самом деле, статические методы не добавляются в `prototype`, потому что они принадлежат самому классу, а не его экземплярам.  
Но если ты хочешь имитировать статический метод в `prototype`, можно использовать функцию-конструктор и добавить метод вручную.  

🚩**Как работают статические методы? (`static`)**  

В классе статические методы объявляются с помощью `static`. Они не находятся в `prototype`, а принадлежат самому классу.  
```
class User {
  static sayHello() {
    return "Привет!";
  }
}

console.log(User.sayHello()); // ✅ "Привет!"
console.log(User.prototype.sayHello); // ❌ undefined (нет в prototype)
```

🚩**Добавление "статического" метода в `prototype` (не совсем статический)**  

Если нужно, чтобы каждый объект имел доступ к "статическому" методу через `prototype`, можно сделать так
```
function User(name) {
  this.name = name;
}

// Добавляем метод в prototype
User.prototype.sayHello = function () {
  return "Привет!";
};

const user1 = new User("Иван");
console.log(user1.sayHello()); // ✅ "Привет!"
```

🚩**Добавление метода напрямую в сам класс (имитация `static`)**  

Если хочется добавить метод на сам класс, а не в `prototype`, можно сделать так
```
function User(name) {
  this.name = name;
}

// Добавляем метод прямо в функцию-конструктор
User.sayHello = function () {
  return "Привет!";
};

console.log(User.sayHello()); // ✅ "Привет!"
```

# Как сравнить два массива объектов в js?
<!-- basicblock-start oid="ObsgIXr0NHa1aKMaz7GhPhwA"  deck='J_JS' -->
Как сравнить два массива объектов в js?::


В JavaScript для сравнения двух массивов объектов важно учитывать несколько факторов, таких как порядок элементов в массивах и глубокое сравнение значений объектов.

Есть несколько способов, как это можно сделать:

1. **Сравнение с использованием метода `JSON.stringify()`**:
   Простой способ сравнить два массива объектов — преобразовать их в строки с помощью `JSON.stringify()` и сравнить эти строки. Однако, этот метод подходит только в случае, если порядок элементов в массивах важен и объекты не содержат циклических ссылок.

2. **Глубокое сравнение без учета порядка элементов**:
   Если вам нужно сравнить два массива объектов без учета порядка элементов, можно использовать дополнительные проверки, например, сравнив объекты в каждом массиве.

### Способ 1: Использование `JSON.stringify()` (если порядок элементов важен)

Этот метод работает, если порядок объектов в массивах важен:

```
function compareArrays(arr1, arr2) {
    return JSON.stringify(arr1) === JSON.stringify(arr2);
}

let arr1 = [{ id: 1, name: 'John' }, { id: 2, name: 'Alice' }];
let arr2 = [{ id: 1, name: 'John' }, { id: 2, name: 'Alice' }];
let arr3 = [{ id: 2, name: 'Alice' }, { id: 1, name: 'John' }];

console.log(compareArrays(arr1, arr2));  // true
console.log(compareArrays(arr1, arr3));  // false
```

**Преимущество**: Очень простой способ сравнения, не требующий дополнительных библиотек.
**Недостаток**: Сравниваются только строки JSON, что означает, что порядок элементов важен. Также это не работает для объектов с циклическими ссылками.

### Способ 2: Сравнение с использованием сортировки (если порядок не важен)

Если порядок объектов в массивах не имеет значения, можно отсортировать массивы и затем сравнить их. Например, с помощью функции, которая сортирует объекты по какому-то ключу:

```
function compareArrays(arr1, arr2) {
    // Сортируем оба массива по ключу (например, по "id")
    arr1 = arr1.sort((a, b) => a.id - b.id);
    arr2 = arr2.sort((a, b) => a.id - b.id);

    // Сравниваем массивы после сортировки
    return JSON.stringify(arr1) === JSON.stringify(arr2);
}

let arr1 = [{ id: 1, name: 'John' }, { id: 2, name: 'Alice' }];
let arr2 = [{ id: 2, name: 'Alice' }, { id: 1, name: 'John' }];
let arr3 = [{ id: 3, name: 'Bob' }, { id: 1, name: 'John' }];

console.log(compareArrays(arr1, arr2));  // true
console.log(compareArrays(arr1, arr3));  // false
```

**Преимущество**: Можно игнорировать порядок элементов в массивах.
**Недостаток**: Для каждого массива потребуется сортировка, что может быть неэффективно для больших данных.

### Способ 3: Глубокое сравнение объектов с использованием `every()` и `some()`

Для более гибкого сравнения можно написать функцию, которая будет проверять каждый элемент массива и сравнивать объекты по ключам:

```
function deepCompareArrays(arr1, arr2) {
    if (arr1.length !== arr2.length) return false;

    return arr1.every((obj1) => 
        arr2.some((obj2) => 
            Object.keys(obj1).every(key => obj1[key] === obj2[key])
        )
    );
}

let arr1 = [{ id: 1, name: 'John' }, { id: 2, name: 'Alice' }];
let arr2 = [{ id: 2, name: 'Alice' }, { id: 1, name: 'John' }];
let arr3 = [{ id: 3, name: 'Bob' }, { id: 1, name: 'John' }];

console.log(deepCompareArrays(arr1, arr2));  // true
console.log(deepCompareArrays(arr1, arr3));  // false
```

**Преимущество**: Гибкость, можно контролировать, как объекты сравниваются (например, по ключам).
**Недостаток**: В случае с большими массивами, такой способ может быть не самым эффективным.

### Способ 4: Использование библиотеки Lodash

Если вам нужно часто сравнивать сложные структуры данных, вы можете воспользоваться библиотекой [Lodash](https://lodash.com/), которая предоставляет метод `_.isEqual()` для глубокого сравнения объектов и массивов.

```
// Подключите библиотеку Lodash
const _ = require('lodash');

let arr1 = [{ id: 1, name: 'John' }, { id: 2, name: 'Alice' }];
let arr2 = [{ id: 2, name: 'Alice' }, { id: 1, name: 'John' }];
let arr3 = [{ id: 3, name: 'Bob' }, { id: 1, name: 'John' }];

console.log(_.isEqual(arr1, arr2));  // true
console.log(_.isEqual(arr1, arr3));  // false
```

# Как angular интегрируется с циклом событий браузера?
<!-- basicblock-start oid="ObsSEF7ZeDDzHvBSVHfuDURx"  deck='J_JS' -->
Как angular интегрируется с циклом событий браузера?::


**Интеграция с циклом событий браузера**

Диаграмма и пример ниже описывают, как AngularJS взаимодействует с циклом событий браузера.

1. Цикл событий браузера ожидает появления события. Событие — это взаимодействие пользователя, событие таймера или событие сети (например, ответ от сервера).
2. Выполняется обратный вызов события. Это переводит выполнение в контекст JavaScript. Обратный вызов может изменять структуру DOM.
3. После выполнения обратного вызова браузер покидает контекст JavaScript и перерисовывает представление с учётом изменений в DOM.

AngularJS изменяет стандартный поток выполнения JavaScript, предоставляя собственный цикл обработки событий. Это разделяет JavaScript на классический и AngularJS контексты выполнения. Только операции, выполняющиеся в контексте выполнения AngularJS, будут использовать такие возможности, как двусторонняя привязка данных, обработка исключений, наблюдение за свойствами и т. д. Также можно использовать `$apply()`, чтобы войти в контекст выполнения AngularJS из обычного JavaScript. Имейте в виду, что в большинстве случаев (контроллеры, сервисы) `$apply` уже был вызван для вас директивой, которая обрабатывает событие. Явный вызов `$apply` необходим только при реализации пользовательских обратных вызовов событий или при работе с обратными вызовами сторонних библиотек.

1. Войдите в контекст выполнения AngularJS, вызвав `scope.$apply(stimulusFn)`, где `stimulusFn` — это код, который вы хотите выполнить в контексте AngularJS.
2. AngularJS выполняет `stimulusFn()`, который обычно изменяет состояние приложения.
3. AngularJS входит в цикл `$digest`. Этот цикл состоит из двух меньших циклов, которые обрабатывают очередь `$evalAsync` и список `$watch`. Цикл `$digest` продолжает итерации до тех пор, пока модель не стабилизируется, что означает, что очередь `$evalAsync` пуста, а список `$watch` не обнаруживает изменений.
4. Очередь `$evalAsync` используется для планирования работы, которая должна быть выполнена вне текущего стека вызовов, но до рендеринга представления браузером. Обычно это делается с помощью `setTimeout(0)`, однако такой подход может быть медленным и вызывать мерцание представления, поскольку браузер перерисовывает представление после каждого события.
5. Список `$watch` — это набор выражений, которые могли измениться с последней итерации. Если изменения обнаружены, вызывается функция `$watch`, которая обычно обновляет DOM с новым значением.
6. После завершения цикла `$digest` выполнение покидает контекст AngularJS и JavaScript. Это сопровождается перерисовкой представления браузером с учётом всех изменений.

Вот объяснение того, как в примере "Hello World" достигается эффект привязки данных, когда пользователь вводит текст в поле.

1. **На этапе компиляции:**
    - Директивы `ng-model` и `input` устанавливают слушатель события `keydown` для элемента `<input>`.
    - Интерполяция устанавливает `$watch`, чтобы получать уведомления об изменениях имени.
   
2. **На этапе выполнения:**
    - При нажатии клавиши "X" браузер генерирует событие `keydown` для элемента input.
    - Директива input захватывает изменение значения поля ввода и вызывает `$apply("name = 'X';")`, чтобы обновить модель приложения в контексте AngularJS.
    - AngularJS применяет `name = 'X';` к модели.
    - Начинается цикл `$digest`.
    - Список `$watch` обнаруживает изменение свойства `name` и уведомляет интерполяцию, которая в свою очередь обновляет DOM.
    - AngularJS выходит из контекста выполнения, а затем завершает выполнение события `keydown` и сам контекст JavaScript.
    - Браузер перерисовывает представление с обновлённым текстом.

# Как работает call stack?
<!-- basicblock-start oid="ObsZhfLDta4bGVfScCsPyZ8u"  deck='J_JS' -->
Как работает call stack?::


**Стек вызовов (Call Stack)** — это структура данных, которая используется для отслеживания выполнения функций в JavaScript. Стек работает по принципу **LIFO** (Last In, First Out) — последний вызов функции становится первым, который завершится.

Каждый раз, когда в программе вызывается функция, она помещается в стек вызовов. Когда функция завершает выполнение, она извлекается из стека, и выполнение продолжается с места, где эта функция была вызвана.

Давайте подробнее разберём, как работает стек вызовов в JavaScript.

### Основные моменты:
1. **Когда вызывается функция, она помещается в стек**: При каждом вызове функции информация о её исполнении (включая параметры, контекст и адрес возврата) добавляется в стек.
   
2. **Когда функция завершает выполнение, она удаляется из стека**: Как только функция завершает выполнение (например, возвращает значение или достигает конца кода), её запись удаляется из стека, и выполнение возвращается к предыдущей функции, которая была в стеке.

3. **Когда стек пуст, выполнение программы завершено**: Когда стек вызовов пуст, это означает, что весь синхронный код был выполнен.

### Пример работы стека вызовов:
Предположим, у нас есть следующий код:

```
function a() {
    console.log('a');
    b();   // Вызов функции b
    console.log('a again');
}

function b() {
    console.log('b');
    c();   // Вызов функции c
}

function c() {
    console.log('c');
}

a();  // Вызов функции a
```

### Шаги выполнения:

1. **Запуск программы**:
   - Функция `a()` вызывается первым.
   - Стек вызовов: `a()`

2. **Вызов функции `b()` внутри `a()`**:
   - Когда интерпретатор доходит до `b()`, функция `b()` помещается в стек.
   - Стек вызовов: `a()`, `b()`

3. **Вызов функции `c()` внутри `b()`**:
   - Когда интерпретатор доходит до `c()`, функция `c()` помещается в стек.
   - Стек вызовов: `a()`, `b()`, `c()`

4. **Выполнение кода в `c()`**:
   - Функция `c()` выполняет свой код (выводит 'c') и завершает выполнение.
   - Стек вызовов: `a()`, `b()`

5. **Возврат в `b()`**:
   - После завершения `c()` функция `b()` продолжает выполнение.
   - Стек вызовов: `a()`

6. **Возврат в `a()`**:
   - После завершения `b()` функция `a()` продолжает выполнение.
   - Стек вызовов: (пустой)

### Порядок вывода:
```
c
b
a
a again
```

- Сначала вызывается `a()`, затем из неё вызывается `b()`, а затем из `b()` вызывается `c()`.
- После завершения `c()`, управление возвращается в `b()`, затем в `a()`, и выполнение продолжается.

### Важные моменты:
- **Синхронный код** всегда выполняется поочередно. Как только одна функция завершает выполнение, следующая функция из стека вызовов продолжает выполнение.
- **Рекурсия** (когда функция вызывает сама себя) может привести к переполнению стека, если рекурсия не имеет условия завершения.

### Пример с рекурсией:

```
function factorial(n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}

console.log(factorial(3));  // Вызов factorial(3)
```

В этом примере происходит несколько рекурсивных вызовов:
1. `factorial(3)`
2. `factorial(2)`
3. `factorial(1)` (основное условие завершения)

Каждый из этих вызовов будет помещаться в стек и извлекаться по мере завершения выполнения.

### Стек вызовов и асинхронные операции:
Асинхронные операции, такие как промисы, обработчики событий или таймеры, не блокируют стек вызовов. Когда происходит асинхронный вызов, например, с использованием `setTimeout`, код передаётся в очередь событий (message queue), а не в стек. Стек вызовов продолжает выполнять синхронные операции, а асинхронные задачи будут обработаны только тогда, когда стек станет пустым.

### Пример асинхронной операции:
```
console.log('Start');

setTimeout(function() {
    console.log('Inside setTimeout');
}, 0);

console.log('End');
```

**Вывод:**
```
Start
End
Inside setTimeout
```

- Сначала выполняется синхронный код (`'Start'`, затем `'End'`).
- `setTimeout` добавляется в очередь сообщений (поскольку это асинхронная операция), и её выполнение будет ожидать, пока стек вызовов не станет пустым.

# Как работает событийный цикл в js
<!-- basicblock-start oid="ObsY9jzxg5GLjQiW4XTOlFCm"  deck='J_JS' -->
Как работает событийный цикл в js::


Событийный цикл (event loop) в JavaScript — это механизм, который позволяет асинхронному коду (например, обработчикам событий, таймерам, запросам) выполняться после завершения текущего выполнения синхронного кода. Он является основой для неблокирующего ввода/вывода и асинхронного программирования в JavaScript.

Чтобы понять, как работает событийный цикл, важно разобраться в нескольких ключевых концепциях:

### 1. **Стек вызовов (Call Stack)**
   Это структура данных, в которой хранится информация о текущих выполняемых функциях. Когда функция вызывается, она помещается в стек, а когда выполнение функции завершено, она извлекается из стека.

   Пример:
   ```
   function foo() {
       console.log('Hello');
   }

   foo(); // 'Hello' будет выведено
   
```
   В данном примере функция `foo` помещается в стек, а затем из него извлекается, когда она завершает выполнение.

### 2. **Очередь сообщений (Message Queue) или Очередь событий (Event Queue)**
   Это очередь, в которую помещаются асинхронные задачи, такие как обработчики событий, таймеры (`setTimeout`, `setInterval`), промисы и другие операции ввода-вывода. Задачи из этой очереди выполняются по очереди, когда стек вызовов пуст.

   Пример:
   ```
   setTimeout(function() {
       console.log('Goodbye');
   }, 0);
   
```

   Здесь `setTimeout` добавляет функцию в очередь сообщений, и она будет выполнена после того, как стек вызовов станет пустым, даже если таймер установлен на 0 миллисекунд.

### 3. **Макротаски и микротаски**
   - **Макротаски**: Это большие задачи, такие как обработчики событий, таймеры, запросы и другие операции, которые добавляются в очередь сообщений. Пример: `setTimeout`, обработчики событий, `setInterval`.
   - **Микротаски**: Это более мелкие задачи, которые выполняются сразу после текущего потока выполнения, но до выполнения макротасков. Пример: промисы (`then`, `catch`, `finally`).

   **Важно**: Микротаски выполняются **все** перед следующим циклом событий, а макротаски — по очереди, после того как стек вызовов пуст.

### 4. **Работа событийного цикла**

1. **Начало работы**: Когда запускается программа, стек вызовов пуст.
2. **Выполнение синхронного кода**: Сначала выполняется весь синхронный код, который находится в стеке.
3. **Обработка микротасков**: После того как стек пуст, перед переходом к следующей макротаске, событийный цикл проверяет и выполняет все задачи из очереди микротасков.
4. **Обработка макротасков**: После выполнения микротасков, если стек вызовов пуст, цикл переходит к выполнению первой задачи из очереди макротасков (например, обработчики событий или таймеры).
5. **Повторение**: Цикл повторяется снова и снова.

### Пример работы событийного цикла:
```
console.log('Start'); // 1. Синхронный код

setTimeout(function() {
    console.log('Timeout'); // 4. Макротаска (позже)
}, 0);

Promise.resolve().then(function() {
    console.log('Promise'); // 3. Микротаска (сразу после синхронного кода)
});

console.log('End'); // 2. Синхронный код
```

**Ожидаемый вывод**:
```
Start
End
Promise
Timeout
```

- **Step 1**: Сначала выполняется синхронный код: `console.log('Start')` и `console.log('End')`.
- **Step 2**: Затем микротаски (промисы) выполняются сразу после синхронного кода, то есть выводится `Promise`.
- **Step 3**: После этого события из очереди макротасков выполняются (в данном случае `setTimeout`), и выводится `Timeout`.

### Заключение
Событийный цикл в JavaScript гарантирует, что асинхронные операции не блокируют выполнение синхронного кода. Он разделяет задачи на макротаски и микротаски, где микротаски всегда выполняются перед макротасками, что позволяет управлять порядком выполнения задач и предотвращать блокировки.
