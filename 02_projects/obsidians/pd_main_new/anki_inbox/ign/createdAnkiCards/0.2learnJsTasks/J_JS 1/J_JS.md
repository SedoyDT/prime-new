# 🤔 **Что такое макро и микро задачи?**
<!-- basicblock-start oid="Obss0kV4jmmPJ0Or9RbAv7Ge"  deck='J_JS' -->
🤔 **Что такое макро и микро задачи?**::


Макро-задачи (macro-tasks) — это крупные задачи, такие как события ввода-вывода, таймеры или сетевые запросы, которые планируются в основной очереди событий. Микро-задачи (micro-tasks) — это задачи меньшего приоритета, которые выполняются сразу после завершения текущего блока кода, но до выполнения следующих макро-задач (например, `Promise` или `MutationObserver`). Микро-задачи всегда выполняются перед макро-задачами, что позволяет им завершаться быстрее. Это важное отличие в управлении асинхронным кодом и приоритизацией событий.

# **🤔**** Для чего нужен eventloop в js?**
<!-- basicblock-start oid="ObsqAchrZzkF32NEnwWFOs2o"  deck='J_JS' -->
**🤔**** Для чего нужен eventloop в js?**::


Event Loop (цикл событий) в JavaScript управляет выполнением асинхронного кода, следя за очередями задач и выполняя их последовательно. Когда в основной поток попадает асинхронная задача, такая как таймер или сетевой запрос, она добавляется в очередь событий. После завершения текущего блока кода Event Loop проверяет, есть ли готовые задачи в очереди, и запускает их. Это позволяет JavaScript быть однопоточным языком с поддержкой асинхронных операций без блокировки основного потока.

# **🤔**** В чём отличие хранения данных в local storage от куки?**
<!-- basicblock-start oid="ObsSU1dnHuuS1RpqAm6qUXpo"  deck='J_JS' -->
**🤔**** В чём отличие хранения данных в local storage от куки?**::


`localStorage` хранит данные на стороне клиента и позволяет сохранять информацию в виде ключ-значение без ограничения по времени, пока пользователь явно не удалит данные. Куки же могут передаваться на сервер при каждом запросе, имеют ограниченный объём (до 4KB) и срок действия. `localStorage` более удобен для долгосрочного хранения данных, которые не должны передаваться на сервер, тогда как куки полезны для передачи информации, такой как аутентификационные токены. `localStorage` работает только на клиентской стороне, куки же могут быть доступны и на стороне сервера.

# Что нужно сделать, чтобы при перезагрузке страницы состояние не менялось?
<!-- basicblock-start oid="ObsBG1i7LlLYjfOYiomUxBBn"  deck='J_JS' -->
Что нужно сделать, чтобы при перезагрузке страницы состояние не менялось?::


Чтобы сохранить состояние при перезагрузке страницы, нужно использовать механизмы, позволяющие хранить данные между сеансами. Вот несколько подходов:

### 1. **Использование `localStorage`**
   - `localStorage` позволяет хранить данные на стороне клиента между перезагрузками страницы и даже после закрытия браузера. Данные хранятся без ограничения по времени (до явного удаления).
   - При загрузке страницы можно проверять наличие данных в `localStorage` и восстанавливать состояние приложения.

   Пример:
   ```
   // Сохранение состояния при изменении
   function saveState(state) {
     localStorage.setItem("appState", JSON.stringify(state));
   }

   // Восстановление состояния при перезагрузке
   function loadState() {
     const savedState = localStorage.getItem("appState");
     return savedState ? JSON.parse(savedState) : null;
   }

   // Использование при загрузке страницы
   window.onload = function() {
     const state = loadState();
     if (state) {
       console.log("Восстановлено состояние:", state);
       // Восстановить состояние приложения
     }
   };

   // Пример сохранения
   const currentState = { page: 1, data: "example" };
   saveState(currentState);
   
```

### 2. **Использование `sessionStorage`**
   - `sessionStorage` похож на `localStorage`, но сохраняет данные только в пределах одной сессии браузера. Если вкладка или окно браузера закрываются, данные удаляются.
   
   Пример:
   ```
   sessionStorage.setItem("appState", JSON.stringify(state));
   const state = JSON.parse(sessionStorage.getItem("appState"));
   
```

### 3. **Использование `history.state`**
   - Объект `state`, который передается в методы `pushState` и `replaceState`, сохраняется в истории браузера и доступен даже после перезагрузки страницы.
   - Однако это работает только в том случае, если не происходит полная перезагрузка (например, с переадресацией на другой URL).

   Пример:
   ```
   // Сохранение состояния
   window.history.pushState({ page: 1, data: "example" }, "Title", "/page1");

   // Восстановление состояния при перезагрузке
   window.onload = function() {
     const state = window.history.state;
     if (state) {
       console.log("Восстановлено состояние из history.state:", state);
     }
   };
   
```

### 4. **Использование URL-параметров**
   - Состояние можно передавать через параметры URL. Это может быть полезно, если требуется сделать ссылку, ведущую на конкретное состояние.
   - Например, добавлять параметры состояния в URL и при перезагрузке страницы парсить их для восстановления состояния.

   Пример:
   ```
   // Добавление параметров состояния в URL
   window.history.pushState({}, "Title", "/page?state=1");

   // Парсинг URL при загрузке страницы
   const params = new URLSearchParams(window.location.search);
   const state = params.get("state");

   if (state) {
     console.log("Состояние из URL:", state);
     // Восстановить состояние на основе параметров URL
   }
   
```

### 5. **Куки (Cookies)**
   - Куки могут использоваться для хранения небольших объемов данных, но они ограничены по размеру (~4KB) и часто используются для хранения данных с целью идентификации пользователя.

### Что выбрать?
- **`localStorage`** — лучший вариант для долгосрочного хранения состояния между сеансами.
- **`sessionStorage`** — если состояние нужно сохранять только на время текущей сессии.
- **`history.state`** — удобно для сохранения состояния в истории браузера, но не подходит для полной перезагрузки.
- **URL-параметры** — полезны, если состояние нужно передавать через ссылку.

Какой подход использовать, зависит от того, как долго вы хотите сохранять состояние и насколько оно критично для работы вашего приложения.
