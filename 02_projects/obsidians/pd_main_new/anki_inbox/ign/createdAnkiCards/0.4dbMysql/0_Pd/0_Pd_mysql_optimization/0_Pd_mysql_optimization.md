# Объясни принцип работы команды explain mysql?
<!-- basicblock-start oid="Obsq07A8uK6toDI3ByGXzWeF"  deck='0_Pd_mysql_optimization' -->
Объясни принцип работы команды explain mysql?::


Команда `EXPLAIN` в MySQL используется для анализа и оптимизации запросов, отображая информацию о том, как MySQL будет выполнять запрос. Это полезно для диагностики производительности и для того, чтобы понять, как индексируется и обрабатывается запрос.

Вот основные моменты, которые нужно знать о команде `EXPLAIN`:

### Основной синтаксис

```

EXPLAIN <SQL-запрос>;

```

### Вывод команды `EXPLAIN`

Когда вы используете `EXPLAIN`, MySQL возвращает информацию в виде таблицы, которая содержит несколько колонок. Основные из них:

- **id**: Идентификатор запроса или подзапроса. Если запрос включает подзапросы, каждая часть будет иметь уникальный идентификатор.

- **select_type**: Тип запроса. Например, `SIMPLE` (простое), `PRIMARY` (основной запрос), `UNION` (объединение), `SUBQUERY` (подзапрос), и т.д.

- **table**: Имя таблицы, к которой применяется текущий шаг запроса.

- **type**: Тип соединения или способ доступа к таблице. Это может быть `ALL` (полный скан таблицы), `index` (сканирование индекса), `range` (поиск по диапазону), `ref` (поиск по индексу), `eq_ref` (точное соответствие), и др. Более предпочтительны типы, указывающие на использование индексов (`index`, `range`, `ref`, `eq_ref`).

- **possible_keys**: Список индексов, которые MySQL может использовать для выполнения запроса.

- **key**: Индекс, который фактически используется для выполнения запроса.

- **key_len**: Длина индекса, используемого для запроса. Это может помочь определить, насколько эффективно используется индекс.

- **ref**: Колонки или константы, используемые для поиска в индексе.

- **rows**: Оценка количества строк, которые MySQL предполагает, что нужно проверить для выполнения запроса.

- **Extra**: Дополнительная информация о том, как выполняется запрос. Может включать такие сообщения, как `Using where` (используется условие WHERE), `Using index` (используется индекс), `Using filesort` (используется внешняя сортировка), и т.д.

### Пример использования

Допустим, у вас есть таблица `users` и вы хотите узнать, как MySQL выполнит запрос на выборку данных:

```

EXPLAIN SELECT * FROM users WHERE age > 30;

```

Вы увидите вывод, который может выглядеть примерно так:

```

+----+-------------+-------+--------+---------------+---------+---------+-------+------+----------+-------------+
| id | select_type | table | type   | possible_keys | key     | key_len | ref   | rows | Extra    |             |
+----+-------------+-------+--------+---------------+---------+---------+-------+------+----------+-------------+
| 1  | SIMPLE      | users | range  | age_index     | age_index | 5       | NULL  | 100  | Using where |             |
+----+-------------+-------+--------+---------------+---------+---------+-------+------+----------+-------------+

```

- **id**: `1` — это основной запрос.
- **select_type**: `SIMPLE` — это простой запрос без подзапросов.
- **table**: `users` — таблица, к которой применяется запрос.
- **type**: `range` — поиск по диапазону.
- **possible_keys**: `age_index` — индекс, который может быть использован.
- **key**: `age_index` — фактически используемый индекс.
- **key_len**: `5` — длина индекса.
- **ref**: `NULL` — нет конкретных колонок или значений для поиска.
- **rows**: `100` — оценочное количество строк, которые нужно проверить.
- **Extra**: `Using where` — используется условие WHERE.

Использование `EXPLAIN` позволяет вам понять, как запрос будет выполняться, и определить потенциальные проблемы с производительностью, такие как полные сканы таблиц или неэффективное использование индексов.

# Что можно сказать про analize table?
<!-- basicblock-start oid="ObsVe41uSSKb3a2UktWLuGnr"  deck='0_Pd_mysql_optimization' -->
Что можно сказать про analize table?::


Вот упрощённая версия текста:

Команда `ANALYZE TABLE` анализирует распределение ключей в таблице и сохраняет эту информацию. Для таблиц MyISAM это то же самое, что и использование `myisamchk --analyze`.

Для выполнения этой команды нужны привилегии `SELECT` и `INSERT` на таблицу.

`ANALYZE TABLE` работает с таблицами InnoDB, NDB и MyISAM, но не с представлениями. Она также поддерживает разделенные таблицы. Вы можете проанализировать одну или несколько секций, используя команду `ALTER TABLE ... ANALYZE PARTITION`.

Во время анализа таблица блокируется на чтение для InnoDB и MyISAM.

Команда `ANALYZE TABLE` также удаляет таблицу из кеша, что может вызвать задержки, если другие транзакции или операции используют эту таблицу. Поэтому, несмотря на то что сама команда работает быстро, могут возникнуть задержки из-за блокировки кеша.

По умолчанию команда записывается в бинарный лог для репликации на другие серверы. Чтобы отключить логирование, используйте ключевое слово `NO_WRITE_TO_BINLOG` или `LOCAL`.

**Результаты выполнения `ANALYZE TABLE`:**

- **Распределение ключей:** Если таблица не изменилась с последнего анализа, она не будет проанализирована снова. MySQL использует информацию о распределении ключей для оптимизации порядка объединения таблиц и выбора индексов. 

- **Проверка информации:** Чтобы увидеть распределение ключей, используйте команду `SHOW INDEX` или таблицу `INFORMATION_SCHEMA STATISTICS`.

- **Кардинальность индексов:** Для таблиц InnoDB команда `ANALYZE TABLE` делает случайные выборки для оценки кардинальности индексов. Это быстрый способ, но не всегда на 100% точный. Чтобы улучшить точность статистики, можно включить `innodb_stats_persistent` и запустить `ANALYZE TABLE` после крупных изменений в данных. 

- **Другие моменты:** `ANALYZE TABLE` очищает статистику таблицы в системных таблицах и обновляет её при следующем доступе к таблице.

Если таблицы не оптимизированы должным образом, попробуйте выполнить `ANALYZE TABLE`. Если это не помогает, можно использовать `FORCE INDEX` в запросах или настроить системную переменную `max_seeks_for_key` для улучшения производительности поиска по индексам.

Команда `EXPLAIN` предоставляет информацию о том, как MySQL выполняет запросы:

`EXPLAIN` работает с запросами SELECT, DELETE, INSERT, REPLACE и UPDATE.

Когда `EXPLAIN` используется с объяснимым запросом, MySQL отображает информацию от оптимизатора о плане выполнения запроса. То есть MySQL объясняет, как он будет обрабатывать запрос, включая информацию о том, как объединяются таблицы и в каком порядке. Для получения информации о том, как использовать `EXPLAIN` для получения информации о плане выполнения, см. Раздел 8.8.2, "Формат вывода EXPLAIN".

Когда `EXPLAIN` используется с `FOR CONNECTION connection_id` вместо объяснимого запроса, он отображает план выполнения запроса, выполняющегося в указанном соединении. См. Раздел 8.8.4, "Получение информации о плане выполнения для указанного соединения".

Для запросов SELECT команда `EXPLAIN` выводит дополнительную информацию о плане выполнения, которую можно отобразить с помощью `SHOW WARNINGS`. См. Раздел 8.8.3, "Расширенный формат вывода EXPLAIN".

`EXPLAIN` полезен для анализа запросов, связанных с разделенными таблицами. См. Раздел 22.3.5, "Получение информации о разделах".

Опция `FORMAT` может использоваться для выбора формата вывода. `TRADITIONAL` представляет вывод в табличном формате. Это значение по умолчанию, если опция `FORMAT` не указана. Формат `JSON` отображает информацию в формате JSON.
