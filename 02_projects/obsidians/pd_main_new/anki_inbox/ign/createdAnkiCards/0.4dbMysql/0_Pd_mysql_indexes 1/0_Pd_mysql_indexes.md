# Покажи примеры создания UNIQUE KEY?
<!-- basicblock-start oid="Obs4wWsFnGDiZ937ylhn2gRH"  deck='0_Pd_mysql_indexes' -->
Покажи примеры создания UNIQUE KEY?::


Конечно! Уникальные индексы (`UNIQUE KEY`) в MySQL обеспечивают уникальность значений в одном или нескольких столбцах таблицы. Вот несколько примеров создания уникальных индексов в различных ситуациях.

### Пример 1: Уникальный индекс для одного столбца

Предположим, у нас есть таблица `users` с столбцом `email`, и мы хотим гарантировать, что каждое значение в этом столбце будет уникальным.

```

CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(255) UNIQUE
);

```

В этом примере уникальный индекс создается на столбце `email` таблицы `users`. Это гарантирует, что никакие два пользователя не могут иметь одинаковый адрес электронной почты.

### Пример 2: Уникальный индекс для нескольких столбцов

Если мы хотим создать уникальный индекс на комбинации нескольких столбцов, это также возможно. Например, пусть у нас есть таблица `orders`, и мы хотим гарантировать, что сочетание `order_number` и `customer_id` уникально.

```

CREATE TABLE orders (
    order_id INT AUTO_INCREMENT PRIMARY KEY,
    order_number VARCHAR(50),
    customer_id INT,
    order_date DATETIME,
    UNIQUE KEY unique_order (order_number, customer_id)
);

```

В этом примере уникальный индекс `unique_order` создан для комбинации столбцов `order_number` и `customer_id`. Это значит, что в таблице `orders` не может быть двух строк с одинаковым сочетанием `order_number` и `customer_id`.

### Пример 3: Добавление уникального индекса после создания таблицы

Если таблица уже существует и вы хотите добавить уникальный индекс, это можно сделать с помощью команды `ALTER TABLE`. Например, добавим уникальный индекс на столбец `username` в таблице `users`.

```

ALTER TABLE users
ADD UNIQUE KEY unique_username (username);

```

Этот запрос добавляет уникальный индекс `unique_username` на столбец `username` в таблице `users`.

### Пример 4: Уникальный индекс с условием (с MySQL 8.0.16 и выше)

С MySQL 8.0.16 можно создавать уникальные индексы с использованием условий (частично уникальные индексы). Например, мы можем создать уникальный индекс на столбец `email`, но только для пользователей, у которых статус `active`.

```

CREATE UNIQUE INDEX unique_active_email
ON users (email)
WHERE status = 'active';

```

В этом примере уникальный индекс `unique_active_email` будет применяться только к строкам, где статус равен `active`. Это значит, что для активных пользователей адреса электронной почты должны быть уникальными, но это условие не будет применяться к неактивным пользователям.

### Пример 5: Уникальный индекс на уже существующем столбце

Предположим, у нас есть таблица `products` и мы хотим добавить уникальный индекс на столбец `product_code`.

```

CREATE TABLE products (
    product_id INT AUTO_INCREMENT PRIMARY KEY,
    product_code VARCHAR(50),
    product_name VARCHAR(100),
    price DECIMAL(10, 2)
);

-- Добавляем уникальный индекс после создания таблицы
ALTER TABLE products
ADD UNIQUE KEY unique_product_code (product_code);

```

В этом примере сначала создается таблица `products`, а затем добавляется уникальный индекс `unique_product_code` на столбец `product_code`.

### Заключение

Уникальные индексы помогают поддерживать целостность данных, предотвращая дублирование значений в столбцах или комбинациях столбцов. Правильное использование уникальных индексов может улучшить производительность запросов и обеспечить соблюдение бизнес-правил в вашей базе данных.

# Что нужно знать о индексах в mysql?
<!-- basicblock-start oid="Obs6UbXqd2LekFVpHeKWaNLh"  deck='0_Pd_mysql_indexes' -->
Что нужно знать о индексах в mysql?::


Индексы в MySQL — это ключевая часть управления базами данных, которая значительно влияет на производительность запросов. Вот основные моменты, которые стоит знать о индексах в MySQL:

### 1. **Что такое индекс?**
Индекс в базе данных — это структура данных, которая улучшает скорость операций поиска, сортировки и фильтрации данных. Он создаётся для одного или нескольких столбцов таблицы.

### 2. **Типы индексов**

- **PRIMARY KEY**: 
  - Это уникальный индекс, который автоматически создаётся для столбца (или комбинации столбцов), определяемого как первичный ключ таблицы.
  - Значения в этом столбце уникальны и не могут быть NULL.

- **UNIQUE KEY**: 
  - Уникальный индекс, который обеспечивает уникальность значений в одном или нескольких столбцах. 
  - В отличие от первичного ключа, уникальные индексы могут содержать NULL, если столбец допускает NULL-значения.

- **INDEX (или KEY)**: 
  - Обычный индекс, который ускоряет поиск и сортировку, но не требует уникальности значений в столбцах. 
  - Это общий тип индекса, часто используемый для ускорения выполнения запросов.

- **FULLTEXT INDEX**: 
  - Индекс для поиска по тексту, который улучшает производительность полнотекстового поиска. 
  - Поддерживает поиск по словам и фразам в текстовых полях.

- **SPATIAL INDEX**: 
  - Индекс, предназначенный для работы с пространственными данными, такими как географические координаты.

### 3. **Как работают индексы?**

- **Структура данных**: 
  - Индексы в MySQL обычно реализуются с помощью структуры данных B-дерево (или B+-дерево), что позволяет эффективно выполнять операции поиска, вставки и удаления.

- **Упрощение поиска**:
  - Индексы позволяют ускорить поиск, так как они уменьшают количество строк, которые нужно просмотреть при выполнении запроса. Вместо полного сканирования таблицы, база данных может использовать индекс для быстрого нахождения нужных строк.

### 4. **Создание индексов**

- **Синтаксис создания индекса**:
  ```

  CREATE INDEX index_name ON table_name (column_name);
  
```

- **Создание уникального индекса**:
  ```

  CREATE UNIQUE INDEX index_name ON table_name (column_name);
  
```

- **Создание первичного ключа**:
  ```

  ALTER TABLE table_name ADD PRIMARY KEY (column_name);
  
```

- **Создание индекса FULLTEXT**:
  ```

  CREATE FULLTEXT INDEX index_name ON table_name (column_name);
  
```

- **Создание составного индекса** (индекс на несколько столбцов):
  ```

  CREATE INDEX index_name ON table_name (column1, column2);
  
```

### 5. **Использование индексов**

- **Ускорение запросов**:
  - Индексы особенно полезны для ускорения запросов с условиями WHERE, JOIN, ORDER BY и GROUP BY.
  
- **Анализ запросов**:
  - Используй команду `EXPLAIN` для анализа того, как MySQL использует индексы в запросах.
    ```

    EXPLAIN SELECT * FROM table_name WHERE column_name = 'value';
    
```

### 6. **Управление индексами**

- **Удаление индексов**:
  ```

  DROP INDEX index_name ON table_name;
  
```

- **Просмотр существующих индексов**:
  ```

  SHOW INDEX FROM table_name;
  
```

### 7. **Оптимизация индексов**

- **Избегай избыточных индексов**:
  - Меньше индексов означает меньше времени на вставку, обновление и удаление данных. Нужно находить баланс между количеством индексов и их пользой.

- **Выбор столбцов для индексации**:
  - Индексируй столбцы, которые часто используются в условиях WHERE, JOIN, ORDER BY и GROUP BY.

- **Поддержка индексов**:
  - Индексы могут потребовать реорганизации и восстановления с течением времени для поддержания их эффективности. Используй `OPTIMIZE TABLE` для этой цели:
    ```

    OPTIMIZE TABLE table_name;
    
```

### 8. **Примеры использования индексов**

- **Запрос с WHERE**:
  ```

  SELECT * FROM users WHERE email = 'example@example.com';
  
```
  Если на столбец `email` есть индекс, запрос будет выполнен быстрее.

# В чем заключается обратная сторона использования индеков?
<!-- basicblock-start oid="Obs2djjO40Rca7rSNim7AY7N"  deck='0_Pd_mysql_indexes' -->
В чем заключается обратная сторона использования индеков?::


Индексы ускоряют операции чтения, но могут замедлить операции записи, так как каждый индекс нужно обновить при изменении данных.

Если индексы столь эффективны, возникает вопрос: почему бы просто не индексировать всё подряд? 🧐

Ответ кроется в том, что каждый индекс представляет собой таблицу (пусть и особый тип таблицы, но все же это таблица). Следовательно, каждый раз, когда строка добавляется в таблицу или удаляется из неё, должны быть изменены все индексы в этой таблице. При обновлении строки любые индексы для столбца (или столбцов), которые были затронуты, также должны быть изменены. Следовательно, чем больше у вас индексов, тем больше должен работать СУБД, чтобы поддерживать все объекты схемы в актуальном состоянии — что приводит к замедлению работы.

Более того, индексы занимают дополнительное место на диске и требуют внимательного управления со стороны администраторов баз данных. Поэтому оптимальным решением является создание индексов только тогда, когда это действительно необходимо. Если индекс нужен временно, например, для выполнения месячного отчёта, его можно добавить перед началом процедуры и удалить после её завершения.

В итоге, идеальный подход заключается в нахождении баланса: необходимо иметь достаточно индексов для эффективной работы, но не столько, чтобы это сказывалось на производительности. Если вы не уверены в нужном количестве индексов, начните с минимального их числа и добавляйте по мере необходимости.

# Что можно сказать про индексы в целом?
<!-- basicblock-start oid="ObswzchoR7hMaq5yPJILydTY"  deck='0_Pd_mysql_indexes' -->
Что можно сказать про индексы в целом?::


Когда вы добавляете в таблицу новую строку, СУБД размещает эти данные не оптимально. Например, если вы добавляете строку в таблицу Users, СУБД не размещает строки в числовом порядке значений столбца id или в алфавитном порядке значений столбца last_name. Вместо этого он просто помещает данные в следующее доступное место в файле (СУБД поддерживает список свободных мест для каждой таблицы).

Это приводит к тому, что для выполнения запроса типа:

MySQL

```

SELECT email FROM Users WHERE email LIKE 'l%';

```

Серверу базы данных приходится проверять каждую строку таблицы, чтобы найти соответствия. Это подходит для маленьких таблиц, но становится чрезмерно времязатратным по мере роста объёма данных.

Для сравнения как запрос на поиск по email отработает в зависимости от наличия индекса на поле.

Влияние наличия индекса на скорость работы: 
Кол-во записей в таблице: 1000
Без индекса: 36 мс
С индексом: 21 мс

Кол-во записей в таблице: 1 000 000
Без индекса: 2950 мс
С индексом: 668 мс

Индексы функционируют как предметные указатели в книге 📖, позволяя быстро находить информацию без прочтения всего текста. Они представляют собой специальные таблицы, строки которых, в отличие от обычных таблиц данных, расположены в строго определённом порядке. Но вместо того, чтобы содержать все данные о некоторой записи, индекс содержит только столбец (или столбцы), используемый, чтобы найти строки в таблице данных, вместе с информацией, описывающей, где физически расположена эта строка. Таким образом, роль индексов состоит в том, чтобы облегчить поиск подмножества строк и столбцов таблицы без необходимости сканировать каждую строку в таблице.
