# Расскажи про временные таблицы mysql
<!-- basicblock-start oid="ObsR0BkF4Co4Sn71bkamgzIQ"  deck='M_mysql' -->
Расскажи про временные таблицы mysql::


Временные таблицы в MySQL — это таблицы, которые создаются временно и существуют только в пределах текущей сессии. Они используются для хранения промежуточных данных или результатов сложных запросов, которые можно повторно использовать в той же сессии. После закрытия сессии или подключения временная таблица автоматически удаляется.

### Основные характеристики временных таблиц:
1. **Временная таблица существует только в рамках текущей сессии**.
   - Как только сессия (или соединение) с базой данных завершится, таблица будет автоматически удалена.
   - Временные таблицы с одинаковыми именами могут существовать в разных сессиях, не конфликтуя друг с другом.

2. **Автоматическое удаление**:
   - Временная таблица удаляется при завершении сессии или может быть удалена вручную с помощью команды `DROP TEMPORARY TABLE`.

3. **Можно использовать временные таблицы для сложных вычислений**:
   - Временные таблицы часто используются для временного хранения результатов промежуточных выборок или вычислений.

4. **Ограничения**:
   - Временные таблицы нельзя индексировать так же, как постоянные таблицы (например, они могут не поддерживать внешние ключи).
   - Одной сессии нельзя использовать временную таблицу из другой сессии.
   - Имя временной таблицы может совпадать с именем постоянной таблицы, но во время работы с временной таблицей приоритет будет у временной версии.

### Создание временной таблицы

Для создания временной таблицы используется ключевое слово `TEMPORARY` перед `TABLE`. Пример:

```
CREATE TEMPORARY TABLE temp_users (
  id INT PRIMARY KEY,
  name VARCHAR(100),
  email VARCHAR(100)
);
```

- Эта таблица будет существовать только в рамках текущей сессии.
  
### Использование временной таблицы

```
-- Вставим несколько записей
INSERT INTO temp_users (id, name, email) VALUES
(1, 'John Doe', 'john@example.com'),
(2, 'Jane Smith', 'jane@example.com');

-- Выберем данные из временной таблицы
SELECT * FROM temp_users;
```

### Пример с использованием временной таблицы для промежуточных данных

Предположим, что у нас есть таблица заказов, и мы хотим выбрать заказы с конкретным статусом, обработать данные и использовать их в нескольких частях программы.

```
-- Создадим временную таблицу для хранения промежуточных данных
CREATE TEMPORARY TABLE temp_orders AS
SELECT order_id, customer_id, order_total
FROM orders
WHERE order_status = 'pending';

-- Теперь мы можем работать с этой таблицей, как с обычной
SELECT * FROM temp_orders WHERE order_total > 100;

-- По завершении работы временная таблица удаляется автоматически
```

### Удаление временной таблицы

Чтобы вручную удалить временную таблицу до завершения сессии, можно использовать команду `DROP TEMPORARY TABLE`:

```
DROP TEMPORARY TABLE temp_users;
```

### Пример использования в сложных запросах

Иногда временные таблицы используются для оптимизации сложных запросов с подзапросами или объединениями:

```
-- Создадим временную таблицу для хранения промежуточных данных
CREATE TEMPORARY TABLE temp_order_totals AS
SELECT customer_id, SUM(order_total) AS total_spent
FROM orders
GROUP BY customer_id;

-- Используем данные из временной таблицы для дальнейшего анализа
SELECT c.customer_id, c.name, t.total_spent
FROM customers c
JOIN temp_order_totals t ON c.customer_id = t.customer_id
WHERE t.total_spent > 500;
```

### Основные преимущества временных таблиц:
- **Повышение производительности**: Временные таблицы могут помочь в оптимизации сложных запросов, позволяя разбивать их на более простые части и временно сохранять результаты.
- **Упрощение логики**: В сложных аналитических запросах можно разбивать задачи на подзадачи, используя временные таблицы для хранения промежуточных результатов.
- **Автоматическое удаление**: Временные таблицы не требуют ручного управления их удалением после использования.

# Как извлчь из md5 mysql
<!-- basicblock-start oid="ObsjBv9FTQpxTBygKMu7Xllw"  deck='M_mysql' -->
Как извлчь из md5 mysql::


В MySQL нет встроенной функции для обратного извлечения исходного текста из MD5-хеша, поскольку MD5 (как и другие хеш-функции) является **односторонним алгоритмом**. Это значит, что MD5 преобразует данные в хеш фиксированной длины, но не существует способа напрямую восстановить исходные данные из полученного хеша.

Тем не менее, если нужно проверить, соответствует ли текст определенному MD5-хешу (например, для проверки пароля), это делается путём хеширования исходного текста и сравнения результата с имеющимся хешем. Вот как это можно сделать:

### Пример 1: Проверка соответствия текста MD5-хешу

1. Предположим, у вас есть таблица пользователей с паролями, хешированными с помощью MD5:

```
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    username VARCHAR(50),
    password_md5 CHAR(32)
);
```

2. Допустим, в базе данных у вас сохранён хеш пароля пользователя:

```
INSERT INTO users (username, password_md5)
VALUES ('anatoliy', MD5('mysecretpassword'));
```

3. Чтобы проверить, совпадает ли введённый пользователем пароль с сохранённым MD5-хешем, выполните следующий запрос:

```
SELECT * FROM users
WHERE username = 'anatoliy' AND password_md5 = MD5('mysecretpassword');
```

Этот запрос хеширует введённый пароль с помощью функции `MD5()` и сравнивает его с хешем, который хранится в базе данных.

### Пример 2: Извлечение MD5-хеша для конкретных данных

Чтобы получить MD5-хеш строки в MySQL, можно использовать встроенную функцию `MD5()`:

```
SELECT MD5('your_string_here');
```

Это вернёт MD5-хеш для строки `"your_string_here"`.

### Примечание о безопасности
Использование MD5 для хеширования паролей считается небезопасным, так как существуют методы (например, атаки по радужным таблицам), которые позволяют восстановить исходные данные для распространённых паролей. Для хеширования паролей рекомендуется использовать более современные и безопасные алгоритмы, такие как `bcrypt` или `SHA-256` с солью (salt).
