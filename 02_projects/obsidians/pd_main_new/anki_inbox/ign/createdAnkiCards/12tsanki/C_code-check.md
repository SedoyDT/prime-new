# Работа с Обобщенными Типовыми Переменными
<!-- basicblock-start oid="Obshk1yGeEYgHNQtro2U1adL"  deck='C_code-check' -->
Работа с Обобщенными Типовыми Переменными::


---


Когда вы начинаете использовать обобщения, вы заметите, что при создании обобщенных функций, таких как функция идентичности, компилятор проверяет, чтобы вы правильно использовали обобщенные параметры в теле функции. То есть, чтобы вы действительно обрабатывали эти параметры так, как если бы они могли быть любыми типами.

Возьмем нашу функцию идентичности из предыдущего примера:

```
function identity<Type>(arg: Type): Type {
  return arg;
}
```

Что если мы хотим также выводить длину аргумента `arg` в консоль при каждом вызове? Мы могли бы быть искушены написать это:

```
function loggingIdentity<Type>(arg: Type): Type {
  console.log(arg.length);
  return arg;
}
```

Когда мы это делаем, компилятор выдаст ошибку, что мы используем свойство `.length` у `arg`, но нигде не сказано, что у `arg` есть это свойство. Помните, мы говорили ранее, что эти типовые переменные представляют собой любые и все типы, поэтому кто-то, использующий эту функцию, мог передать число вместо массива, у числа нет свойства `.length`.

Предположим, что мы на самом деле намеревались, чтобы эта функция работала с массивами типа `Type`, а не с типом `Type` напрямую. Поскольку мы работаем с массивами, свойство `.length` должно быть доступно. Мы можем описать это так же, как мы создаем массивы других типов:

```
function loggingIdentity<Type>(arg: Type[]): Type[] {
  console.log(arg.length);
  return arg;
}
```

Вы можете прочитать тип функции `loggingIdentity` как “обобщенная функция `loggingIdentity` принимает параметр типа `Type` и аргумент `arg`, который является массивом типа `Type`, и возвращает массив типа `Type`.” Если мы передадим массив чисел, мы получим массив чисел обратно, поскольку `Type` будет связан с `number`. Это позволяет нам использовать нашу обобщенную типовую переменную `Type` как часть типов, с которыми мы работаем, а не как целый тип, что дает нам большую гибкость.

Вместо этого можно записать пример следующим образом:

```
function loggingIdentity<Type>(arg: Array<Type>): Array<Type> {
  console.log(arg.length); // Массив имеет свойство .length, так что ошибки нет
  return arg;
}
```

Вам уже может быть знаком этот стиль типизации из других языков. В следующем разделе мы рассмотрим, как можно создавать свои собственные обобщенные типы, такие как `Array<Type>`.

# Что можно сказать про hello world дженериков функцию identity?
<!-- basicblock-start oid="ObsQDrBdKeNOv3Co7jyD8yqB"  deck='C_code-check' -->
Что можно сказать про hello world дженериков функцию identity?::


Вот перевод текста на русский:

---

Привет, мир обобщений!

Давайте начнем с "Hello, world!" в мире обобщений: функции идентичности. Функция идентичности возвращает то же значение, которое было передано в нее. Можно представить это как команду echo.

Без обобщений мы должны были бы задать конкретный тип для функции идентичности:

```
function identity(arg: number): number {
  return arg;
}
```

Или же использовать тип any:

```
function identity(arg: any): any {
  return arg;
}
```

Хотя использование any позволяет функции принимать значения любого типа, мы теряем информацию о типе возвращаемого значения. Если мы передаем число, то мы теряем информацию о его типе в возвращаемом значении.

Вместо этого нам нужен способ захвата типа аргумента таким образом, чтобы мы могли использовать его и для указания типа возвращаемого значения. Для этого мы используем типовую переменную, специальный вид переменной, который работает с типами, а не со значениями.

```
function identity<Type>(arg: Type): Type {
  return arg;
}
```

Мы добавили типовую переменную Type к функции идентичности. Этот Type позволяет нам захватить тип, который пользователь передает (например, number), чтобы мы могли использовать эту информацию позже. Здесь мы снова используем Type в качестве типа возвращаемого значения. Теперь тип аргумента и тип возвращаемого значения совпадают. Это позволяет сохранить информацию о типе от одной стороны функции до другой.

Мы говорим, что эта версия функции идентичности является обобщенной, поскольку она работает с различными типами. В отличие от использования any, она также точно передает тип (т.е., не теряет информацию), как это делает первая функция идентичности с числовыми типами для аргумента и возвращаемого значения.

После написания обобщенной функции идентичности, мы можем вызвать ее двумя способами. Первый способ - передать все аргументы, включая типовый аргумент, функции:

```
let output = identity<string>("myString");
```

Здесь мы явно устанавливаем Type как string в аргументах функции, обозначая это с помощью <> вокруг аргументов, а не ().

Второй способ, возможно, более распространен. Здесь мы используем вывод типовых аргументов - то есть, мы хотим, чтобы компилятор автоматически установил значение Type на основе типа аргумента, который мы передаем:

```
let output = identity("myString");
```

Обратите внимание, что нам не нужно явно указывать тип в угловых скобках (<>); компилятор просто смотрит на значение "myString" и устанавливает Type в его тип. В то же время вывод типовых аргументов может быть полезным инструментом, чтобы сделать код короче и более читаемым, иногда вам придется явно указать типовые аргументы, как мы сделали в предыдущем примере, когда компилятор не может вывести тип, что может произойти в более сложных примерах.

# Ваш код в TypeScript имеет несколько проблем с типами, особенно в функции `debounce` и `filterGridElements`. Давайте исправим их и объясним, как правильно указать типы.
<!-- basicblock-start oid="ObsFLJ6LDZ9KRCGw7L1TGsq8"  deck='C_code-check' -->
Ваш код в TypeScript имеет несколько проблем с типами, особенно в функции `debounce` и `filterGridElements`. Давайте исправим их и объясним, как правильно указать типы.::


### Исправленный код

```
const utils = (() => {
    function debounce<T extends (...args: any[]) => void>(func: T, ms: number): (...args: Parameters<T>) => void {
        let timerId: NodeJS.Timeout | null = null;
        return function (this: any, ...args: Parameters<T>) {
            if (timerId) {
                clearTimeout(timerId);
            }
            timerId = setTimeout(() => func.apply(this, args), ms);
        };
    }

    // Функция фильтрации элементов по введенному тексту
    function filterGridElements(searchText: string, cellsArray: HTMLElement[]): HTMLElement[] {
        const searchLetters = searchText.toLowerCase();

        return cellsArray.filter(elem => {
            const dataSetValue = elem.dataset.value?.toLowerCase() || "";
            return dataSetValue.includes(searchLetters) ||
                dataSetValue.split("").reverse().join("").includes(searchLetters);
        });
    }

    return {
        debounce,
        filterGridElements,
    }
})();
```

### Объяснение исправлений

1. **Функция `debounce`**:
   - **Типизация функции**: Ваша функция `debounce` должна принимать функцию как параметр. Я использовал обобщение `T` для того, чтобы типизировать эту функцию корректно. `T` — это функция, принимающая любые аргументы и возвращающая `void`. Мы также указываем тип для параметров этой функции через `Parameters<T>`.
   - **Тип `timerId`**: Мы указываем тип `NodeJS.Timeout` (или `null`), так как `setTimeout` возвращает объект таймера, который мы очищаем при следующем вызове.
   - **`this` в функции**: Мы добавляем тип `this: any` для корректной работы с контекстом `this`.

2. **Функция `filterGridElements`**:
   - **Тип `cellsArray`**: Мы указываем тип `HTMLElement[]`, так как предполагается, что `cellsArray` содержит элементы DOM.
   - **Тип возвращаемого значения**: Мы также указываем тип возвращаемого значения как `HTMLElement[]`.
   - **Обработка `dataset`**: Мы используем оператор опциональной цепочки (`?.`) и устанавливаем пустую строку по умолчанию, чтобы избежать возможных ошибок при доступе к `elem.dataset.value`.

Эти изменения помогут вам избежать типовых ошибок и сделать ваш код более надежным и понятным.
