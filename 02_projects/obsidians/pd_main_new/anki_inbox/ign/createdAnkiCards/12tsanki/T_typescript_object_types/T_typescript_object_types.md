# Расскажи как создать словарь в TypeScript и сценарий применения
<!-- basicblock-start oid="ObsuBzfMw9jGGFOymKe915iJ"  deck='T_typescript_object_types' -->
Расскажи как создать словарь в TypeScript и сценарий применения::


Создание словаря в TypeScript можно реализовать с помощью объектов или Map. Словарь представляет собой коллекцию пар «ключ-значение», где каждый ключ уникален. Вот несколько способов, как это можно сделать:

### 1. Использование Объекта

Самый простой способ создать словарь в TypeScript — использовать объект. Вы можете определить тип для ключей и значений с помощью индексных подписей.

```
// Определяем интерфейс для словаря
interface StringDictionary {
  [key: string]: string; // ключи - строки, значения - строки
}

// Создаем словарь
const dictionary: StringDictionary = {
  hello: "привет",
  goodbye: "до свидания",
};

// Используем словарь
console.log(dictionary["hello"]); // вывод: "привет"
```

### 2. Использование Map

TypeScript также поддерживает объект `Map`, который позволяет использовать любые типы данных в качестве ключей и значений.

```
// Создаем словарь с помощью Map
const dictionary = new Map<string, string>();

// Добавляем значения
dictionary.set("hello", "привет");
dictionary.set("goodbye", "до свидания");

// Используем словарь
console.log(dictionary.get("hello")); // вывод: "привет"
```

### Сценарий применения

Рассмотрим сценарий, где мы создаем словарь для хранения перевода слов с английского на русский. Мы можем использовать либо объект, либо Map в зависимости от требований.

#### Пример 1: Словарь как объект

```
interface Dictionary {
  [key: string]: string;
}

const translations: Dictionary = {
  apple: "яблоко",
  orange: "апельсин",
};

function translate(word: string): string {
  return translations[word] || "перевод не найден";
}

console.log(translate("apple"));  // вывод: "яблоко"
console.log(translate("banana")); // вывод: "перевод не найден"
```

#### Пример 2: Словарь как Map

```
const translations = new Map<string, string>([
  ["apple", "яблоко"],
  ["orange", "апельсин"],
]);

function translate(word: string): string {
  return translations.get(word) || "перевод не найден";
}

console.log(translate("orange")); // вывод: "апельсин"
console.log(translate("banana")); // вывод: "перевод не найден"
```

### Почему выбирать Map или объект?

- **Объект**:
  - Более прост в использовании.
  - Использует строки в качестве ключей.
  - Хорошо подходит для небольших и простых словарей.

- **Map**:
  - Позволяет использовать любые типы данных в качестве ключей (включая объекты).
  - Предоставляет методы для работы с коллекцией (например, `set`, `get`, `delete`).
  - Более производителен при частых операциях добавления/удаления пар ключ-значение.

### Заключение

В зависимости от ваших нужд, вы можете выбрать либо объект, либо Map для создания словаря в TypeScript. Оба подхода позволяют эффективно хранить и получать данные по ключу, но Map предоставляет большую гибкость и функциональность.

### Чтение и Запись в Кортежи с Модификатором `readonly`

Кортежи в TypeScript могут иметь вариант `readonly`, что делает их элементы неизменяемыми. Это позволяет защитить данные от случайного изменения, что особенно полезно в функциональном программировании или в случаях, когда данные должны оставаться неизменными после их создания.

### Определение `readonly` кортежей

Чтобы объявить кортеж как `readonly`, просто добавьте модификатор `readonly` перед его определением:

```
function doSomething(pair: readonly [string, number]) {
  // ...
}
```

### Запрет записи в `readonly` кортежи

Попытка изменить значение элемента `readonly` кортежа приведёт к ошибке. TypeScript не позволит это сделать, так как свойства кортежа являются только для чтения:

```
function doSomething(pair: readonly [string, number]) {
  pair[0] = "hello!"; // Ошибка: нельзя присвоить значение свойству '0', так как оно является только для чтения.
}
```

### Применение `readonly` кортежей

1. **Защита данных**:
   Использование `readonly` кортежей позволяет защитить данные от изменений, что делает код более предсказуемым и безопасным.

2. **Константные массивы**:
   Если кортеж создается с использованием ассерций `const`, TypeScript будет автоматически определять его как `readonly`. Например:

   ```
   let point = [3, 4] as const;
   
```

   В этом случае тип переменной `point` будет выведен как `readonly [3, 4]`.

3. **Совместимость типов**:
   Когда функция принимает `readonly` кортежи, она может не принимать изменяемые кортежи, что может вызывать проблемы совместимости типов:

   ```
   function distanceFromOrigin([x, y]: [number, number]) {
     return Math.sqrt(x ** 2 + y ** 2);
   }
   
   distanceFromOrigin(point); // Ошибка: тип 'readonly [3, 4]' не совместим с '[number, number]'
   
```

   В этом случае `distanceFromOrigin` ожидает изменяемый кортеж, но `point` является `readonly`, что приводит к ошибке типизации.

### Рекомендации по использованию

- Используйте `readonly` кортежи, когда данные не должны изменяться после их создания. Это повышает безопасность кода и уменьшает количество потенциальных ошибок.
- Если у вас есть функции, которые не изменяют элементы кортежа, но принимают их в качестве параметров, помечайте эти кортежи как `readonly`, чтобы подчеркнуть их неизменяемость.

### Заключение

Использование `readonly` кортежей в TypeScript является хорошей практикой, которая помогает защитить данные и делает код более предсказуемым. Это полезно в ситуациях, когда важно, чтобы данные оставались неизменными после их создания, и позволяет избежать неожиданных ошибок при работе с массивами и кортежами.

### Типы Кортежей (Tuple Types)

Кортежи (или Tuple Types) в TypeScript — это особый тип массива, который определяет фиксированное количество элементов, каждый из которых имеет строго определённый тип. Кортежи обеспечивают большую строгость по сравнению с обычными массивами, позволяя указывать типы элементов на конкретных позициях.

### Основные особенности

1. **Определение кортежа**:
   Кортеж может быть определён с использованием квадратных скобок, где каждый элемент имеет свой тип. Например:

   ```
   type StringNumberPair = [string, number];
   
```

   Здесь `StringNumberPair` описывает кортеж, который на первой позиции содержит строку, а на второй — число.

2. **Использование кортежа в функциях**:
   Вы можете использовать кортежи в качестве параметров функции. Это позволяет чётко указать, какие типы данных ожидаются.

   ```
   function doSomething(pair: [string, number]) {
     const a = pair[0]; // a будет строкой
     const b = pair[1]; // b будет числом
   }
   
   doSomething(["hello", 42]);
   
```

3. **Проверка индексов**:
   Если вы попытаетесь обратиться к элементу по индексу, превышающему длину кортежа, TypeScript выдаст ошибку:

   ```
   function doSomething(pair: [string, number]) {
     const c = pair[2]; // Ошибка: кортеж '[string, number]' длиной '2' не имеет элемента с индексом '2'.
   }
   
```

4. **Деструктуризация кортежей**:
   Кортежи могут быть деструктурированы, как и обычные массивы, что позволяет удобнее работать с их элементами.

   ```
   function doSomething(stringHash: [string, number]) {
     const [inputString, hash] = stringHash;
     console.log(inputString); // inputString будет строкой
     console.log(hash); // hash будет числом
   }
   
```

5. **Неопциональные элементы**:
   Кортежи могут иметь необязательные элементы, используя знак вопроса (`?`). Неопциональные элементы могут находиться только в конце кортежа и влияют на тип длины кортежа.

   ```
   type Either2dOr3d = [number, number, number?];
   
   function setCoordinate(coord: Either2dOr3d) {
     const [x, y, z] = coord;
     console.log(`Предоставленные координаты имеют ${coord.length} измерений`);
   }
   
```

6. **Элементы с остальными значениями (Rest elements)**:
   Кортежи могут содержать элементы с остальными значениями, которые представляют собой массив (или кортеж).

   ```
   type StringNumberBooleans = [string, number, ...boolean[]];
   
```

   Например, `StringNumberBooleans` описывает кортеж, состоящий из строки и числа, за которыми могут следовать любое количество логических значений.

### Применение кортежей

1. **Обеспечение типизации**:
   Кортежи позволяют создать более строгую типизацию для функций и структур данных, где важно, чтобы определённые значения находились на определённых позициях.

2. **Параметры функции**:
   Кортежи могут использоваться в качестве параметров для функций, что позволяет передавать переменное количество аргументов с фиксированным набором типов.

   ```
   function readButtonInput(...args: [string, number, ...boolean[]]) {
     const [name, version, ...input] = args;
     // ...
   }
   
```

   Это эквивалентно следующей записи:

   ```
   function readButtonInput(name: string, version: number, ...input: boolean[]) {
     // ...
   }
   
```

### Заключение

Кортежи в TypeScript — мощный инструмент для обеспечения строгой типизации и структурирования данных. Они позволяют легко работать с фиксированными наборами значений и поддерживают удобные методы, такие как деструктуризация и использование остальных значений. Это делает их полезными в ситуациях, где необходимо передавать несколько связанных значений с различными типами.

### Тип `ReadonlyArray`

Тип `ReadonlyArray` в TypeScript используется для создания массивов, элементы которых нельзя изменять. Это позволяет обеспечить безопасность данных, гарантируя, что массивы не будут случайно модифицированы.

### Основные особенности

1. **Чтение, но не изменение**:
   С массивами типа `ReadonlyArray` вы можете читать их элементы, но не можете изменять их. Это полезно для передачи данных, когда вы хотите гарантировать, что вызывающая сторона не изменит массив.

   **Пример использования `ReadonlyArray`:**
   ```
   function doStuff(values: ReadonlyArray<string>) {
     // Мы можем читать значения из 'values'...
     const copy = values.slice();
     console.log(`Первое значение: ${values[0]}`);
     
     // ...но мы не можем модифицировать 'values'.
     values.push("hello!"); // Ошибка: Property 'push' does not exist on type 'readonly string[]'.
   }
   
```

2. **Присваивание обычных массивов**:
   Вы можете присваивать обычные массивы переменным типа `ReadonlyArray`. Это означает, что любой обычный массив можно использовать как `ReadonlyArray`, но обратное не верно.

   **Пример присваивания**:
   ```
   const roArray: ReadonlyArray<string> = ["red", "green", "blue"];
   
```

3. **Сокращение для `ReadonlyArray`**:
   TypeScript предоставляет сокращение для `ReadonlyArray<Type>` в виде `readonly Type[]`. Это позволяет вам использовать более лаконичную запись, сохраняя при этом все преимущества.

   **Пример с использованием сокращения**:
   ```
   function doStuff(values: readonly string[]) {
     // Мы можем читать значения из 'values'...
     const copy = values.slice();
     console.log(`Первое значение: ${values[0]}`);
     
     // ...но мы не можем модифицировать 'values'.
     values.push("hello!"); // Ошибка: Property 'push' does not exist on type 'readonly string[]'.
   }
   
```

### Ограничения

1. **Неизменяемость**:
   `ReadonlyArray` не поддерживает методы, изменяющие массив, такие как `push`, `pop`, `shift`, `unshift`, `splice` и т.д. Если вы попытаетесь использовать их, TypeScript выдаст ошибку.

2. **Одностороннее присваивание**:
   Хотя вы можете присваивать обычные массивы переменным типа `ReadonlyArray`, это не работает в обратном направлении. Попытка присвоить `ReadonlyArray` переменной типа обычного массива приведет к ошибке.

   **Пример ошибки**:
   ```
   let x: readonly string[] = [];
   let y: string[] = [];
   
   x = y; // Это работает, y присваивается x
   y = x; // Ошибка: Тип 'readonly string[]' является 'readonly' и не может быть присвоен изменяемому типу 'string[]'.
   
```

### Заключение

Тип `ReadonlyArray` является мощным инструментом для работы с массивами, которые не должны изменяться. Это помогает предотвратить случайные изменения данных и обеспечивает большую безопасность типов в вашем коде. Использование `ReadonlyArray` или `readonly Type[]` позволяет вам четко выразить намерения в вашем коде, делая его более понятным и надежным.

### Генерический тип `Array`

Тип `Array` в TypeScript — это один из примеров генерических типов, которые позволяют создавать контейнеры для различных типов данных. В этом случае `Array<Type>` позволяет определять массивы, элементы которых могут быть любого типа.

### Как работает тип `Array`

Когда мы используем нотацию `string[]` или `number[]`, на самом деле это просто сокращение для `Array<string>` и `Array<number>`. Таким образом, обе формы являются эквивалентными, и вы можете использовать любую из них в зависимости от ваших предпочтений.

**Пример функции с использованием типа `Array`:**

```
function doSomething(value: Array<string>) {
  console.log(value.join(", "));
}

let myArray: string[] = ["hello", "world"];

// Оба варианта работают!
doSomething(myArray);
doSomething(new Array("hello", "world"));
```

В этом примере функция `doSomething` принимает аргумент типа `Array<string>`, и мы можем передавать как массив `myArray`, так и новый массив, созданный с помощью конструктора `Array`.

### Определение типа `Array`

Тип `Array` определяется следующим образом:

```
interface Array<Type> {
  length: number; // Длина массива
  pop(): Type | undefined; // Удаляет последний элемент и возвращает его
  push(...items: Type[]): number; // Добавляет элементы и возвращает новую длину массива
  // Другие методы ...
}
```

Это означает, что массив может содержать элементы одного типа (например, `string`, `number` и т.д.), и методы массива, такие как `pop` и `push`, будут работать с этим типом.

### Пример работы с `Array`

Давайте посмотрим на пример использования различных методов, доступных в массиве:

```
let numbers: Array<number> = [1, 2, 3];

// Добавляем элемент
numbers.push(4); // numbers теперь [1, 2, 3, 4]

// Удаляем последний элемент
let last = numbers.pop(); // last будет 4, numbers теперь [1, 2, 3]

// Проверяем длину массива
console.log(numbers.length); // 3
```

### Другие генерические структуры данных

Помимо массива, в современном JavaScript и TypeScript есть и другие генерические структуры данных:

1. **Map<K, V>**: Позволяет хранить пары ключ-значение, где `K` — это тип ключа, а `V` — тип значения.
   ```
   let myMap: Map<string, number> = new Map();
   myMap.set("one", 1);
   myMap.set("two", 2);
   
```

2. **Set<T>**: Позволяет хранить уникальные значения.
   ```
   let mySet: Set<number> = new Set([1, 2, 3]);
   mySet.add(4);
   
```

3. **Promise<T>**: Позволяет работать с асинхронными операциями, возвращая значение типа `T` после завершения.
   ```
   let myPromise: Promise<string> = new Promise((resolve) => {
     setTimeout(() => resolve("Hello!"), 1000);
   });
   
```

### Заключение

Генерические типы, такие как `Array`, позволяют создавать структуры данных, которые могут работать с различными типами. Это делает ваш код более гибким и переиспользуемым. Используя такие типы, как `Map`, `Set` и `Promise`, вы можете создать мощные абстракции для работы с данными, обеспечивая при этом безопасность типов в вашем коде.

# Объясни дженерики по доке typescript Generic object types?
<!-- basicblock-start oid="Obs9JTFKJ4cJjd7Y2d5lJGbd"  deck='T_typescript_object_types' -->
Объясни дженерики по доке typescript Generic object types?::


Давайте разберем концепцию **генерических типов объектов** на примере типа `Box`, который может содержать значения различных типов, таких как строки, числа и другие объекты. Основная идея заключается в создании гибкой структуры данных, которая позволяет избежать проблем, связанных с использованием типа `any` и избыточного кода.

### Проблема с типами `any` и `unknown`

1. **Тип `any`**:
   - При использовании типа `any` для свойства `contents` в `Box`, вы теряете преимущества статической типизации TypeScript. Это может привести к ошибкам, которые будут трудно отследить.

   ```
   interface Box {
     contents: any; // Использование any
   }

   let x: Box = {
     contents: "hello world",
   };

   // Можно вызвать ошибку
   console.log(x.contents.toLowerCase()); // Это будет работать, но без проверки типа
   
```

2. **Тип `unknown`**:
   - Тип `unknown` более безопасен, чем `any`, так как требует проверки типа перед использованием. Однако это может привести к необходимости дополнительных проверок и явных утверждений типов.

   ```
   interface Box {
     contents: unknown; // Использование unknown
   }

   let x: Box = {
     contents: "hello world",
   };

   // Проверка типа
   if (typeof x.contents === "string") {
     console.log(x.contents.toLowerCase()); // Безопасно
   }
   
```

### Проблема с созданием множества интерфейсов

Чтобы избежать использования `any` и `unknown`, можно создать разные интерфейсы для различных типов содержимого:

```
interface NumberBox {
  contents: number;
}

interface StringBox {
  contents: string;
}

interface BooleanBox {
  contents: boolean;
}
```

Однако это приводит к созданию множества функций и перегрузок, что делает код избыточным:

```
function setContents(box: StringBox, newContents: string): void;
function setContents(box: NumberBox, newContents: number): void;
function setContents(box: BooleanBox, newContents: boolean): void;
function setContents(box: { contents: any }, newContents: any) {
  box.contents = newContents; // Избыточность
}
```

### Решение с использованием генериков

Чтобы сделать код более элегантным и избежать избыточного написания кода, можно создать генерический тип `Box`:

```
interface Box<Type> {
  contents: Type; // Используем параметр типа
}
```

Теперь, когда мы используем `Box`, мы можем указать конкретный тип:

```
let box: Box<string>; // Генерический тип Box с типом string
```

**Пример использования:**

```
let boxA: Box<string> = { contents: "hello" };
let boxB: Box<number> = { contents: 42 };
```

### Переиспользование

Генерические типы позволяют переиспользовать типы, не создавая новые интерфейсы:

```
interface Apple {
  variety: string;
}

// Создание типа AppleBox
type AppleBox = Box<Apple>;
```

### Генерические функции

С генерическими типами мы можем избежать перегрузок, создавая генерические функции:

```
function setContents<Type>(box: Box<Type>, newContents: Type) {
  box.contents = newContents; // Безопасно, так как тип соответствует
}
```

### Генерические типовые алиасы

Типовые алиасы также могут быть генерическими:

```
type Box<Type> = {
  contents: Type; // Генерический тип
};
```

### Создание утилитных типов

Кроме определения объектов, генерики могут быть использованы для создания утилитных типов:

```
type OrNull<Type> = Type | null;
type OneOrMany<Type> = Type | Type[];
type OneOrManyOrNull<Type> = OrNull<OneOrMany<Type>>;
```

### Заключение

Генерические типы объектов в TypeScript позволяют создавать гибкие и переиспользуемые структуры, обеспечивая при этом безопасность типов. Использование генериков позволяет избежать проблем с `any` и `unknown`, а также значительно уменьшает объем повторяющегося кода. Генерики открывают новые возможности для создания абстрактных типов и функций, что делает код более чистым и поддерживаемым.

# Что можешь сказть по теме Generic Object Types?
<!-- basicblock-start oid="ObsV4vGG4sgTSr1pjxLFO8Ls"  deck='T_typescript_object_types' -->
Что можешь сказть по теме Generic Object Types?::


**Генерические типы объектов** (Generic Object Types) в TypeScript представляют собой мощный инструмент, позволяющий создавать более абстрактные и гибкие типы, которые могут работать с различными данными без необходимости заранее определять конкретные типы. Генерики помогают сделать ваш код более повторно используемым и безопасным в отношении типов.

### Основные понятия и особенности

1. **Что такое генерики?**
   Генерики позволяют определять типы, которые могут быть указаны позже, при использовании типа или функции. Это позволяет создавать более гибкие структуры данных и функции, которые могут работать с любыми типами.

2. **Общая структура**
   Генерические типы обычно обозначаются с помощью угловых скобок `<T>`, где `T` — это параметр типа. Вы можете использовать один или несколько параметров типа.

   ```
   interface GenericBox<T> {
     content: T;
   }
   
```

3. **Использование с функциями**
   Генерики особенно полезны в функциях, где типы входных и выходных данных могут варьироваться.

   ```
   function identity<T>(arg: T): T {
     return arg;
   }

   const result1 = identity<string>("Hello"); // результат будет типа string
   const result2 = identity<number>(42);       // результат будет типа number
   
```

4. **Комбинирование с другими типами**
   Генерики могут комбинироваться с другими типами, включая интерфейсы, классы и пересечения типов.

   ```
   interface Response<T> {
     data: T;
     error?: string;
   }

   const response: Response<string> = {
     data: "Hello",
   };

   const responseWithNumber: Response<number> = {
     data: 42,
     error: "No error",
   };
   
```

5. **Параметры по умолчанию**
   Генерическим типам можно задавать значения по умолчанию, если они не указаны.

   ```
   interface Pair<T, U = string> {
     first: T;
     second: U;
   }

   const pair1: Pair<number> = { first: 1, second: "default" }; // second - строка по умолчанию
   const pair2: Pair<number, boolean> = { first: 1, second: true }; // second - boolean
   
```

6. **Ограничения (Constraints)**
   Вы можете ограничить параметры типа, указывая, что они должны соответствовать определенному типу или интерфейсу.

   ```
   interface Person {
     name: string;
   }

   function greet<T extends Person>(person: T): string {
     return `Hello, ${person.name}!`;
   }

   const user = { name: "Alice", age: 30 };
   console.log(greet(user)); // Hello, Alice!
   
```

### Примеры использования

#### Пример 1: Генерический класс

Генерические классы позволяют создавать структуры, которые могут работать с любыми типами.

```
class GenericStack<T> {
  private items: T[] = [];

  push(item: T): void {
    this.items.push(item);
  }

  pop(): T | undefined {
    return this.items.pop();
  }
}

const numberStack = new GenericStack<number>();
numberStack.push(1);
numberStack.push(2);
console.log(numberStack.pop()); // 2

const stringStack = new GenericStack<string>();
stringStack.push("Hello");
console.log(stringStack.pop()); // Hello
```

#### Пример 2: Генерическая функция с несколькими типами

Иногда функции могут принимать несколько параметров с разными типами.

```
function merge<T, U>(obj1: T, obj2: U): T & U {
  return { ...obj1, ...obj2 };
}

const merged = merge({ name: "Alice" }, { age: 30 });
console.log(merged); // { name: 'Alice', age: 30 }
```

### Преимущества использования генерических типов

1. **Гибкость**: Генерические типы позволяют создавать функции и структуры, которые могут работать с любыми типами, что уменьшает дублирование кода.
2. **Типизация**: Улучшение безопасности типов, так как TypeScript может проверять типы во время компиляции.
3. **Читаемость**: Код становится более понятным и читаемым, так как типы ясно указывают, какие данные ожидаются.

### Заключение

Генерические типы объектов в TypeScript — это мощный инструмент для создания гибкого и повторно используемого кода. Они позволяют разрабатывать функции и структуры, которые могут работать с различными типами данных, сохраняя при этом типовую безопасность. Используя генерики, вы можете создать более чистый и эффективный код, улучшая при этом его читаемость и удобство использования.

# Что можешь сказать по теме Interfaces vs. Intersections?
<!-- basicblock-start oid="Obs4ERJ6I6d7Yc3whTF0uHBr"  deck='T_typescript_object_types' -->
Что можешь сказать по теме Interfaces vs. Intersections?::


**Интерфейсы** и **пересечения типов** в TypeScript — это два разных подхода к созданию сложных типов, каждый из которых имеет свои особенности и применения. Давайте рассмотрим их различия, преимущества и случаи использования.

### 1. **Интерфейсы**

#### Определение
Интерфейсы в TypeScript используются для определения структуры объектов. Они описывают, какие свойства и методы должен иметь объект.

#### Основные особенности:
- **Расширяемость**: Интерфейсы можно расширять, создавая новые интерфейсы на основе существующих. Это позволяет использовать множественное наследование.
  
  ```
  interface Animal {
    name: string;
  }

  interface Dog extends Animal {
    breed: string;
  }
  
```

- **Объединение интерфейсов**: Если два интерфейса имеют одинаковые свойства, TypeScript автоматически объединит их. Это называется "объединением интерфейсов".

  ```
  interface Person {
    name: string;
  }

  interface Person {
    age: number;
  }

  const john: Person = {
    name: "John",
    age: 30,
  };
  
```

- **Поддержка методов**: Интерфейсы могут включать как свойства, так и методы.

  ```
  interface Vehicle {
    drive(): void;
  }
  
```

#### Когда использовать интерфейсы?
- Когда нужно описать структуру объекта или класс.
- Когда требуется использовать расширяемость и объединение.
- Когда нужно работать с объектами, которые будут использоваться в классовых структурах.

### 2. **Пересечения типов (Intersection Types)**

#### Определение
Пересечения типов позволяют объединять несколько типов в один, создавая новый тип, который включает все свойства всех исходных типов.

#### Основные особенности:
- **Комбинирование свойств**: Пересечения позволяют комбинировать несколько типов, чтобы создать более сложные структуры данных.

  ```
  type Person = {
    name: string;
  };

  type Employee = {
    employeeId: number;
  };

  type Manager = Person & Employee;

  const manager: Manager = {
    name: "Alice",
    employeeId: 1234,
  };
  
```

- **Типы и интерфейсы**: Пересечения могут быть использованы с типами (`type`) и интерфейсами (`interface`).

- **Отсутствие объединения**: В отличие от интерфейсов, пересечения не поддерживают объединение свойств. Если два типа имеют одинаковые свойства, но с разными типами, возникает ошибка.

  ```
  type A = { prop: string };
  type B = { prop: number };

  type C = A & B; // Ошибка: типы несовместимы
  
```

#### Когда использовать пересечения типов?
- Когда нужно создать новый тип, который должен содержать свойства нескольких типов без необходимости создавать новый интерфейс.
- Когда необходимо комбинировать существующие типы, не используя расширение.
- Когда нужно использовать утилитные типы, такие как `Partial`, `Required`, и комбинировать их с другими типами.

### 3. **Сравнение интерфейсов и пересечений типов**

| **Характеристика**             | **Интерфейсы**                             | **Пересечения типов**                  |
|----------------------------------|--------------------------------------------|-----------------------------------------|
| **Расширяемость**               | Поддерживают наследование                   | Не поддерживают расширение              |
| **Объединение**                 | Поддерживают объединение                    | Не поддерживают объединение              |
| **Применение**                  | Подходят для описания структуры объектов    | Подходят для комбинирования типов       |
| **Поддержка методов**           | Да                                         | Нет (только свойства)                   |
| **Сложность**                   | Простой и интуитивно понятный синтаксис    | Могут быть более сложными               |

### 4. **Примеры использования**

#### Пример интерфейса:
```
interface User {
  id: number;
  name: string;
}

const user: User = {
  id: 1,
  name: "John",
};
```

#### Пример пересечения типов:
```
type Admin = {
  role: string;
};

type User = {
  id: number;
  name: string;
};

type AdminUser = User & Admin;

const adminUser: AdminUser = {
  id: 1,
  name: "Alice",
  role: "Administrator",
};
```

# Что ты можешь рассказать про Intersection Types?
<!-- basicblock-start oid="ObsGczcOotCfkcT3SxE8YFro"  deck='T_typescript_object_types' -->
Что ты можешь рассказать про Intersection Types?::


**Пересечение типов** (Intersection Types) в TypeScript — это мощный механизм, который позволяет комбинировать несколько типов в один. Это позволяет создавать более сложные структуры, которые могут содержать свойства и методы нескольких типов. Пересечение типов обозначается с помощью оператора `&`.

### Основные моменты пересечения типов:

1. **Объединение свойств**: Когда два или более типа пересекаются, результатом является новый тип, который включает все свойства всех участвующих типов.

2. **Совместимость**: Пересечённый тип должен соответствовать всем типам, участвующим в пересечении. Это означает, что объект, который соответствует пересечённому типу, должен содержать все необходимые свойства из всех объединяемых типов.

3. **Использование с интерфейсами и типами**: Пересечение типов можно использовать как с интерфейсами, так и с типами.

### Пример 1: Основы пересечения типов

Предположим, у нас есть два типа: `Person` и `Employee`.

```
type Person = {
  name: string;
  age: number;
};

type Employee = {
  employeeId: number;
  department: string;
};

// Создаём новый тип, который является пересечением Person и Employee
type EmployeeDetails = Person & Employee;

const employee: EmployeeDetails = {
  name: "Alice",
  age: 30,
  employeeId: 1234,
  department: "HR",
};
```

В этом примере:
- Тип `EmployeeDetails` объединяет свойства `Person` и `Employee`.
- Объект `employee` должен содержать все свойства из обоих типов.

### Пример 2: Использование пересечений с функциями

Пересечения типов могут быть полезны, когда функции принимают аргументы с несколькими типами.

```
type Bird = {
  canFly: boolean;
};

type Fish = {
  canSwim: boolean;
};

type FlyingFish = Bird & Fish;

function describeCreature(creature: FlyingFish) {
  console.log(`Can fly: ${creature.canFly}, Can swim: ${creature.canSwim}`);
}

const myCreature: FlyingFish = {
  canFly: true,
  canSwim: true,
};

describeCreature(myCreature); // Can fly: true, Can swim: true
```

Здесь:
- Мы определяем новый тип `FlyingFish`, который включает в себя свойства как `Bird`, так и `Fish`.
- Функция `describeCreature` принимает аргумент типа `FlyingFish`, который должен содержать свойства обеих сущностей.

### Пример 3: Пересечение типов и объединение с `Partial`

Пересечение типов также может быть полезно вместе с утилитными типами, такими как `Partial`.

```
type User = {
  username: string;
  password: string;
};

type UpdateUser = Partial<User> & {
  id: number;
};

const userUpdate: UpdateUser = {
  id: 1,
  username: "newUsername", // password может отсутствовать
};
```

В этом примере:
- Мы создаём тип `UpdateUser`, который требует `id` и делает остальные свойства `User` необязательными.
- Таким образом, объект `userUpdate` может содержать только некоторые свойства `User`.

### Пример 4: Пересечение с классами

Пересечение типов можно использовать и с классами.

```
class Vehicle {
  make: string;
  model: string;

  constructor(make: string, model: string) {
    this.make = make;
    this.model = model;
  }
}

class Electric {
  batteryCapacity: number;

  constructor(batteryCapacity: number) {
    this.batteryCapacity = batteryCapacity;
  }
}

// Пересечение классов (практически для использования в типах)
type ElectricCar = Vehicle & Electric;

const myElectricCar: ElectricCar = {
  make: "Tesla",
  model: "Model 3",
  batteryCapacity: 75,
};
```

Здесь:
- Мы создаём тип `ElectricCar`, который объединяет свойства `Vehicle` и `Electric`.
- Объект `myElectricCar` должен содержать все свойства обеих сущностей.

### Ключевые моменты

- **Объединение свойств**: Пересечение типов позволяет комбинировать несколько типов, создавая новый, который включает в себя свойства всех участвующих типов.
- **Типы и интерфейсы**: Пересечение типов можно использовать как с интерфейсами, так и с типами.
- **Совместимость**: Объект, соответствующий пересечённому типу, должен содержать все свойства из всех объединяемых типов.

# ### 5. **Ключевые моменты расширения типов**
<!-- basicblock-start oid="ObsCx8LxcLd6Q3HTK9HyVrdp"  deck='T_typescript_object_types' -->
### 5. **Ключевые моменты расширения типов**::


- **Интерфейсы** удобно использовать, если тебе нужно расширять типы, добавляя новые свойства, или если нужно множественное наследование.
- **Типы (`type`)** позволяют делать пересечение нескольких типов и дают больше гибкости, например, для объединения типов.
- **Классы** могут наследовать другие классы и расширять их функциональность.
- **Utility Types** позволяют модифицировать существующие типы, делая свойства необязательными, обязательными, доступными только для чтения и так далее.

### Итог:

# Расскажи про extending types
<!-- basicblock-start oid="ObsiRc2nzucakPdk2BABg0Q3"  deck='T_typescript_object_types' -->
Расскажи про extending types::


Расширение типов (**extending types**) в TypeScript — это механизм, который позволяет создавать новые типы на основе существующих. Это делается с помощью ключевого слова `extends`. Благодаря расширению типов можно добавлять новые свойства, методы и модифицировать типы без необходимости переписывать весь исходный тип.

TypeScript поддерживает расширение как интерфейсов, так и типов (`type`). Рассмотрим различные способы расширения типов.

### 1. **Расширение интерфейсов**

Интерфейсы могут быть расширены другими интерфейсами. Это позволяет наследовать все свойства одного интерфейса в другом.

#### Пример:
```
interface Animal {
  name: string;
  age: number;
}

interface Dog extends Animal {
  breed: string;
}

const myDog: Dog = {
  name: "Rex",
  age: 5,
  breed: "Labrador",
};
```

Здесь:
- Интерфейс `Animal` определяет свойства `name` и `age`.
- Интерфейс `Dog` расширяет `Animal`, добавляя новое свойство `breed`.
- Объект `myDog` должен содержать все свойства как из интерфейса `Animal`, так и из `Dog`.

#### Множественное расширение интерфейсов:
TypeScript также позволяет расширять несколько интерфейсов сразу:

```
interface Pet {
  petName: string;
}

interface Animal {
  age: number;
}

interface Dog extends Pet, Animal {
  breed: string;
}

const myDog: Dog = {
  petName: "Rex",
  age: 5,
  breed: "Labrador",
};
```

Здесь интерфейс `Dog` расширяет сразу два интерфейса: `Pet` и `Animal`, и объект `myDog` должен соответствовать обоим.

### 2. **Расширение типов (`type`)**

Типы (`type`) также можно расширять. Это делается с использованием **пересечения типов** (`intersection types`), при котором создаётся новый тип, который объединяет свойства нескольких типов.

#### Пример:
```
type Animal = {
  name: string;
  age: number;
};

type Dog = Animal & {
  breed: string;
};

const myDog: Dog = {
  name: "Rex",
  age: 5,
  breed: "Labrador",
};
```

Здесь тип `Dog` — это пересечение (`&`) типов `Animal` и объекта с новым свойством `breed`. Это работает аналогично интерфейсам, где все свойства наследуются.

#### Множественное пересечение:
Типы можно пересекать с несколькими другими типами:

```
type Pet = {
  petName: string;
};

type Animal = {
  age: number;
};

type Dog = Pet & Animal & {
  breed: string;
};

const myDog: Dog = {
  petName: "Rex",
  age: 5,
  breed: "Labrador",
};
```

Здесь тип `Dog` создаётся путём пересечения трёх типов: `Pet`, `Animal` и объекта с `breed`.

### 3. **Расширение классов**

TypeScript поддерживает классическое наследование классов с использованием ключевого слова `extends`. Это позволяет классам наследовать свойства и методы от других классов.

#### Пример:
```
class Animal {
  name: string;
  age: number;

  constructor(name: string, age: number) {
    this.name = name;
    this.age = age;
  }

  makeSound(): void {
    console.log(`${this.name} is making a sound.`);
  }
}

class Dog extends Animal {
  breed: string;

  constructor(name: string, age: number, breed: string) {
    super(name, age);  // Вызов конструктора родительского класса
    this.breed = breed;
  }

  bark(): void {
    console.log(`${this.name} is barking.`);
  }
}

const myDog = new Dog("Rex", 5, "Labrador");
myDog.makeSound();  // Rex is making a sound.
myDog.bark();       // Rex is barking.
```

Здесь:
- Класс `Dog` расширяет класс `Animal`.
- Конструктор класса `Dog` вызывает конструктор родительского класса `Animal` с помощью `super()`.
- Метод `bark` является уникальным для класса `Dog`, тогда как метод `makeSound` наследуется от `Animal`.

### 4. **Расширение с помощью Utility Types**

TypeScript также предлагает утилитные типы для изменения или расширения существующих типов. Например:

#### `Partial`
Создаёт тип, где все свойства исходного типа становятся необязательными.

```
interface Person {
  name: string;
  age: number;
}

type PartialPerson = Partial<Person>;

const person: PartialPerson = {
  name: "John", // age не обязательный
};
```

#### `Required`
Превращает все свойства типа в обязательные.

```
interface Person {
  name?: string;
  age?: number;
}

type RequiredPerson = Required<Person>;

const person: RequiredPerson = {
  name: "John",
  age: 30, // теперь это обязательное свойство
};
```

# Что такое "проверка избыточных свойств"?
<!-- basicblock-start oid="ObsvPuDNjNlF9lpIP1JJzcot"  deck='T_typescript_object_types' -->
Что такое "проверка избыточных свойств"?::


Давай я объясню этот пример о **"проверке избыточных свойств"** и как TypeScript ведёт себя с объектными литералами.

### Что такое "проверка избыточных свойств"?

Когда ты передаёшь объект в функцию, TypeScript проверяет, чтобы объект соответствовал ожидаемому типу (или интерфейсу). Если в объекте есть **лишние свойства**, которые не описаны в типе или интерфейсе, TypeScript выдаёт ошибку.

### Пример:

У тебя есть интерфейс `SquareConfig`:

```
interface SquareConfig {
  color?: string;
  width?: number;
}
```

Он описывает объект, у которого может быть два свойства:
- `color` (строка, необязательное),
- `width` (число, необязательное).

Теперь у тебя есть функция `createSquare`, которая принимает объект типа `SquareConfig`:

```
function createSquare(config: SquareConfig): { color: string; area: number } {
  return {
    color: config.color || "red",  // если color нет, используем "red"
    area: config.width ? config.width * config.width : 20,  // если width нет, площадь = 20
  };
}
```

Всё хорошо, пока ты не пытаешься передать объект с ошибкой:

```
let mySquare = createSquare({ colour: "red", width: 100 });
```

Здесь ты используешь свойство `colour` вместо `color`, и TypeScript выдаёт ошибку:

```
Object literal may only specify known properties, but 'colour' does not exist in type 'SquareConfig'. Did you mean to write 'color'?
```

### Почему возникает ошибка?

TypeScript проверяет объектные литералы очень строго и видит, что свойство `colour` не существует в интерфейсе `SquareConfig`. В отличие от JavaScript, который бы просто проигнорировал это лишнее свойство, TypeScript сообщает, что тут, скорее всего, ошибка, ведь ты, вероятно, просто опечатался (хотел написать `color`).

### Как обойти эту проверку?

Есть несколько способов:

#### 1. **Использовать "type assertion" (принудительное приведение типа)**

Ты можешь явно сказать TypeScript, что этот объект должен рассматриваться как `SquareConfig`, даже если там есть лишние свойства:

```
let mySquare = createSquare({ width: 100, opacity: 0.5 } as SquareConfig);
```

Здесь ты добавил свойство `opacity`, которое не описано в `SquareConfig`. Однако, используя `as SquareConfig`, ты говоришь TypeScript не проверять избыточные свойства.

#### 2. **Добавить индексную сигнатуру в интерфейс**

Если ты знаешь, что у объекта могут быть **другие дополнительные свойства**, которые не описаны в интерфейсе, можно добавить индексную сигнатуру:

```
interface SquareConfig {
  color?: string;
  width?: number;
  [propName: string]: any;  // позволяет использовать любые дополнительные свойства
}
```

Теперь интерфейс говорит TypeScript, что объект может иметь любые другие свойства, не только `color` и `width`. Их тип будет `any`, что позволяет хранить данные любого типа.

```
let mySquare = createSquare({ colour: "red", width: 100 });
```

Здесь TypeScript больше не выдаст ошибку, так как он позволяет наличие других свойств, таких как `colour`.

#### 3. **Присвоить объект промежуточной переменной**

Если ты сначала присвоишь объект переменной, а потом передашь её в функцию, TypeScript не будет так строго проверять свойства. Это происходит, потому что проверка избыточных свойств выполняется только на **объектных литералах**, а не на переменных:

```
let squareOptions = { colour: "red", width: 100 };
let mySquare = createSquare(squareOptions);
```

TypeScript не выдаст ошибку, так как при передаче переменной (`squareOptions`) избыточные свойства не проверяются так строго, как в случае с объектным литералом.

Однако, если в объекте не будет **никаких общих свойств** с интерфейсом `SquareConfig`, TypeScript снова выдаст ошибку:

```
let squareOptions = { colour: "red" };  // Нет общих свойств с SquareConfig
let mySquare = createSquare(squareOptions);  // Ошибка!
```

Ошибка:
```
Type '{ colour: string; }' has no properties in common with type 'SquareConfig'.
```

Здесь ошибка возникает, потому что объект `squareOptions` вообще не содержит свойства `width`, которое описано в `SquareConfig`.

### Когда следует обходить эти проверки?

# Что можно сказать о индексных подписях в TypeScript?
<!-- basicblock-start oid="Obs6WNLoMe3JQHQqsp1k0Nes"  deck='T_typescript_object_types' -->
Что можно сказать о индексных подписях в TypeScript?::


В TypeScript **индексные подписи (index signatures)** используются для описания объектов, где заранее неизвестны имена всех свойств, но известен тип значений этих свойств. Это полезно, когда нужно работать с объектами, структура которых напоминает словарь или массив с динамическими ключами.

### Основные моменты:

1. **Описание индексной подписи**: С помощью индексной подписи можно указать, какие типы допустимы для ключей и какие типы будут у значений по этим ключам.
   
2. **Ограничения на типы ключей**: Индексная подпись может использовать только ключи типов `string`, `number`, `symbol`, шаблонные строковые литералы или их комбинации.

3. **Согласованность типов для разных ключей**: Если в интерфейсе используются как числовые, так и строковые ключи, тип для числовых ключей должен быть подтипом типа для строковых. Это связано с тем, что в JavaScript ключи для числовых индексов автоматически преобразуются в строки при доступе к объекту.

### Примеры и объяснение:

#### 1. **Простая индексная подпись**

```
interface StringArray {
  [index: number]: string;
}

const myArray: StringArray = ["apple", "banana"];
const secondItem = myArray[1]; // "banana"
```

В этом примере:
- `StringArray` — это интерфейс, который имеет числовую индексную подпись `[index: number]`. Это означает, что при обращении к массиву по индексу (числовому ключу) будет возвращаться значение типа `string`.

#### 2. **Несовместимость типов для разных индексных ключей**

```
interface Animal {
  name: string;
}

interface Dog extends Animal {
  breed: string;
}

// Ошибка! Тип для числового индекса Animal не является подтипом Dog для строкового индекса.
interface NotOkay {
  [x: number]: Animal;
  [x: string]: Dog;
}
```

Здесь возникает ошибка, потому что TypeScript требует, чтобы тип значений для числовых индексов (`Animal`) был подтипом значений для строковых индексов (`Dog`). Это связано с тем, что числовые индексы в JavaScript преобразуются в строки, и доступ к объекту через `myObject[100]` будет эквивалентен `myObject["100"]`.

#### 3. **Индексная подпись со свойствами разного типа**

```
interface NumberDictionary {
  [index: string]: number;
  
  length: number; // OK
  name: string; // Ошибка: 'name' не соответствует типу индексной подписи 'number'
}
```

Здесь ошибка возникает, потому что свойство `name` имеет тип `string`, а индексная подпись ожидает значения типа `number`.

#### 4. **Использование объединений для типов индексной подписи**

```
interface NumberOrStringDictionary {
  [index: string]: number | string;
  
  length: number; // OK
  name: string; // OK
}
```

В этом случае индексная подпись `[index: string]` допускает значения как типа `number`, так и `string`, поэтому свойствам `length` и `name` разрешено быть разных типов.

#### 5. **Readonly индексные подписи**

```
interface ReadonlyStringArray {
  readonly [index: number]: string;
}

let myArray: ReadonlyStringArray = ["apple", "banana"];
myArray[2] = "cherry"; // Ошибка! Нельзя изменять значения по индексам.
```

Индексная подпись `readonly` запрещает изменения значений по индексам, позволяя только чтение.

### Резюме:
- **Индексные подписи** позволяют описывать объекты с динамическими ключами и контролировать типы значений.
- Ключи могут быть типа `string`, `number`, `symbol`, и они должны быть согласованы в случае использования нескольких типов индексов.
- Можно использовать **`readonly`** для защиты значений от изменений.

# Расскажи максимум про readonly в объектах ts
<!-- basicblock-start oid="Obsa87CDdOsGMXTi0eDXLZ95"  deck='T_typescript_object_types' -->
Расскажи максимум про readonly в объектах ts::


В TypeScript ключевое слово `readonly` предоставляет возможность сделать свойства объектов неизменяемыми после их инициализации. Это важная часть системы типов, которая помогает повысить безопасность и устойчивость к ошибкам в коде, предотвращая непреднамеренные изменения данных. `readonly` может применяться к объектам, массивам, параметрам функций и типам, что позволяет создать более строгие и контролируемые структуры данных.

### 1. **Readonly для свойств объекта**

Свойства объекта, помеченные как `readonly`, могут быть присвоены только один раз — в момент создания объекта (например, в конструкторе или при объявлении объекта). После этого они становятся неизменяемыми.

#### Пример:

```
interface User {
  readonly id: number;
  name: string;
}

const user: User = {
  id: 1,
  name: 'John'
};

// Можно изменять `name`
user.name = 'Jane';

// Ошибка! Попытка изменить readonly-свойство
user.id = 2; // Error: Cannot assign to 'id' because it is a read-only property.
```

### 2. **Readonly для массивов**

В TypeScript можно создать неизменяемый массив с помощью `ReadonlyArray<T>`. Такой массив запрещает любые операции, которые изменяют его содержимое, например, методы `push`, `pop`, `splice` и т.д. Однако чтение данных по индексу по-прежнему возможно.

#### Пример:

```
let arr: ReadonlyArray<number> = [1, 2, 3];

// Ошибка! Нельзя модифицировать массив
arr.push(4); // Error: Property 'push' does not exist on type 'readonly number[]'.

// Однако можно читать данные
console.log(arr[0]); // 1
```

Чтобы изменить массив, необходимо создать его копию, например, с использованием метода `slice`:

```
let newArr = arr.slice();
newArr.push(4); // OK
```

### 3. **Readonly для параметров функций**

С помощью `readonly` можно объявить параметры функций, которые не должны изменяться внутри функции. Это повышает безопасность функций, гарантируя, что аргументы останутся неизменными.

#### Пример:

```
function printNames(names: readonly string[]): void {
  // names.push('John'); // Ошибка! Массив 'names' является readonly
  names.forEach((name) => console.log(name));
}
```

### 4. **Readonly для классов**

В классе `readonly` можно использовать для определения свойств, которые могут быть инициализированы только один раз (например, в конструкторе), после чего не могут быть изменены.

#### Пример:

```
class Car {
  readonly brand: string;

  constructor(brand: string) {
    this.brand = brand; // Присваивание допускается только в конструкторе
  }

  changeBrand(newBrand: string) {
    // Ошибка! Свойство brand - readonly
    // this.brand = newBrand;
  }
}

const myCar = new Car('Toyota');
console.log(myCar.brand); // Toyota

// Ошибка! Нельзя изменить readonly свойство
myCar.brand = 'Honda'; // Error: Cannot assign to 'brand' because it is a read-only property.
```

### 5. **Readonly и Массивы / Кортежи**

Тип `ReadonlyArray<T>` и `readonly [T1, T2, ..., Tn]` для кортежей обеспечивают аналогичную защиту для массивов и кортежей, предотвращая изменения структуры данных после их инициализации.

#### Пример с кортежем:

```
const point: readonly [number, number] = [10, 20];

// Ошибка! Нельзя изменять кортеж
point[0] = 30; // Error: Cannot assign to '0' because it is a read-only property.
```

### 6. **Readonly против const**

Важно понимать различие между `readonly` и `const`. `const` делает переменную неизменной — сама переменная не может указывать на другой объект или значение, но свойства объекта, на который указывает переменная, могут изменяться.

- `const` — это для переменных, которые не могут быть переназначены.
- `readonly` — это для свойств объектов, которые не могут быть изменены.

#### Пример:

```
const obj = { name: 'John' };
obj.name = 'Jane'; // OK, объект не является readonly
```

Однако, если свойство объекта объявлено с `readonly`, его изменить нельзя:

```
const obj: { readonly name: string } = { name: 'John' };
obj.name = 'Jane'; // Ошибка! Нельзя изменить readonly-свойство
```

### 7. **Readonly и деструктуризация**

При деструктуризации объектов или массивов TypeScript позволяет использовать `readonly` для того, чтобы сделать переменные, полученные из объектов или массивов, неизменяемыми.

# Можно ли создать экземпляр типа или интерфейса в ts
<!-- basicblock-start oid="Obsg3T6rt9jvxM66E4hFz5Vo"  deck='T_typescript_object_types' -->
Можно ли создать экземпляр типа или интерфейса в ts::


В TypeScript **нельзя напрямую создать экземпляр типа или интерфейса**, так как они существуют только на этапе компиляции и служат для проверки типов, а не для создания объектов в рантайме. Однако вы можете создать объект, который соответствует типу или интерфейсу, используя классы или литералы объектов.

### Пример с интерфейсом:

```
interface User {
  name: string;
  age: number;
}

// Нельзя создать экземпляр интерфейса напрямую
// const user = new User(); // Ошибка

// Но можно создать объект, соответствующий интерфейсу
const user: User = {
  name: "Alice",
  age: 25
};

console.log(user);
```

### Пример с типом:

```
type Point = {
  x: number;
  y: number;
};

// Нельзя создать экземпляр типа напрямую
// const point = new Point(); // Ошибка

// Но можно создать объект, соответствующий типу
const point: Point = { x: 10, y: 20 };

console.log(point);
```

### Использование класса для создания экземпляра:
Чтобы создать экземпляр, можно использовать классы, которые реализуют интерфейс:

```
interface User {
  name: string;
  age: number;
}

class Person implements User {
  constructor(public name: string, public age: number) {}
}

const person = new Person("Bob", 30);
console.log(person); // Person { name: 'Bob', age: 30 }
```

### Вывод:
- **Типы и интерфейсы** сами по себе не могут быть инстанцированы.
- **Создать объект** с типом или интерфейсом можно через объектные литералы или классы, которые реализуют интерфейсы.
