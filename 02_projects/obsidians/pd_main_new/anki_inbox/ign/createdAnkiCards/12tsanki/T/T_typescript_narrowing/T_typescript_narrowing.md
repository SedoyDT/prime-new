# Что можно сказать про Discriminated unions?
<!-- basicblock-start oid="ObsKUDWHP5XfoAne9txUF36a"  deck='T_typescript_narrowing' -->
Что можно сказать про Discriminated unions?::


**Discriminated unions** (также называемые **tagged unions** или **algebraic data types**) — это паттерн в TypeScript, который помогает безопасно и удобно работать с объединёнными типами (union types), содержащими несколько разных вариантов, каждый из которых имеет уникальное дискриминирующее поле. Этот паттерн позволяет TypeScript автоматически сужать типы в зависимости от значения этого поля, что делает код проще, безопаснее и легче для анализа.

### Основные элементы discriminated unions:

1. **Дискриминирующее поле (discriminant)**:  
   Это специальное поле с фиксированным значением, которое служит для различения вариантов в объединении. Чаще всего это строковый или числовой литерал.

2. **Уникальные типы для каждого варианта**:  
   Каждый вариант объединённого типа (union type) должен иметь дискриминирующее поле с уникальным значением.

3. **TypeScript автоматически сужает типы** на основе проверки значения дискриминирующего поля. Благодаря этому TypeScript понимает, какой конкретный тип используется в определённом участке кода.

### Пример discriminated unions:

```
type Square = {
  kind: "square"; // дискриминирующее поле
  size: number;
};

type Rectangle = {
  kind: "rectangle"; // дискриминирующее поле
  width: number;
  height: number;
};

type Circle = {
  kind: "circle"; // дискриминирующее поле
  radius: number;
};

// Объединённый тип (discriminated union)
type Shape = Square | Rectangle | Circle;

function area(shape: Shape): number {
  switch (shape.kind) {
    case "square":
      return shape.size * shape.size;
    case "rectangle":
      return shape.width * shape.height;
    case "circle":
      return Math.PI * shape.radius * shape.radius;
    default:
      // Мы можем быть уверены, что рассмотрели все варианты
      return assertNever(shape);
  }
}

// Помощник для проверки полноты рассмотрения случаев
function assertNever(x: never): never {
  throw new Error("Unexpected object: " + x);
}
```

### Разбор кода:

1. **Типы `Square`, `Rectangle` и `Circle`**:  
   Каждый из этих типов имеет поле `kind`, которое уникально для каждого типа (`"square"`, `"rectangle"`, `"circle"`). Это поле и является дискриминирующим.

2. **Объединённый тип `Shape`**:  
   Тип `Shape` — это объединение трёх вариантов: `Square | Rectangle | Circle`. Каждый из этих типов имеет уникальное дискриминирующее поле `kind`, которое позволяет TypeScript различать их.

3. **Функция `area()`**:  
   В функции `area()` мы используем `switch` по полю `shape.kind`. TypeScript автоматически сужает тип переменной `shape` в каждой ветке `case`. Например:
   - В ветке `case "square"`, TypeScript знает, что тип `shape` — это `Square`, и мы можем безопасно использовать его свойство `size`.
   - В ветке `case "rectangle"`, TypeScript знает, что `shape` — это `Rectangle`.

4. **Полнота рассмотрения случаев**:  
   Используя функцию `assertNever`, мы можем проверить, что все возможные варианты дискриминируемых типов были рассмотрены. Если мы забыли рассмотреть один из вариантов в `switch`, TypeScript выдаст ошибку компиляции, что делает код более надёжным и предотвращает ошибки.

### Преимущества discriminated unions:

1. **Безопасное сужение типов**:  
   TypeScript автоматически сужает тип переменной, основываясь на значении дискриминирующего поля, что уменьшает вероятность ошибок и делает код более выразительным.

2. **Полнота рассмотрения вариантов**:  
   Используя такие конструкции, как `switch`, TypeScript может гарантировать, что все возможные варианты объединённого типа рассмотрены, или выдать ошибку, если что-то упущено. Это помогает избежать багов и делает код более надёжным.

3. **Легкость расширения**:  
   Добавление новых вариантов (например, нового типа формы) просто: нужно добавить новый тип с уникальным дискриминирующим полем и обновить места, где происходит сужение типов.

# Что можно сказать про using type predicates?
<!-- basicblock-start oid="ObshhvkgvkyJR5SQXYxWp2s4"  deck='T_typescript_narrowing' -->
Что можно сказать про using type predicates?::


**Type predicates** (типовые предикаты) в TypeScript — это механизм, который позволяет разработчикам явно указывать, что функция или метод проверяет и сужает тип переданного значения. Этот механизм используется для создания **кастомных гвардов типов** (type guards), которые помогают TypeScript точно понимать, как тип переменной изменяется в зависимости от результата проверки.

### Как работают типовые предикаты?

Типовой предикат используется в возвращаемом значении функции и имеет следующий формат:

```
function isFish(pet: Fish | Bird): pet is Fish {
  return (pet as Fish).swim !== undefined;
}
```

- **`pet is Fish`** — это и есть **типовой предикат**. Он указывает TypeScript, что если функция `isFish()` возвращает `true`, то переменная `pet` должна быть типа `Fish`.
- TypeScript автоматически сужает тип переменной в том месте, где была вызвана функция, основываясь на результатах этой проверки.

### Пример использования типового предиката:

```
type Fish = { swim: () => void };
type Bird = { fly: () => void };

function isFish(animal: Fish | Bird): animal is Fish {
  return (animal as Fish).swim !== undefined;
}

function move(animal: Fish | Bird) {
  if (isFish(animal)) {
    // Теперь TypeScript знает, что это Fish
    animal.swim();
  } else {
    // А здесь TypeScript понимает, что это Bird
    animal.fly();
  }
}
```

#### Разбор:
1. **Функция `isFish`**:
   - Функция принимает переменную типа `Fish | Bird`, что означает, что переменная может быть либо рыбой, либо птицей.
   - Мы проверяем, есть ли у объекта `swim`. Если это так, то возвращаем `true`, и функция говорит TypeScript, что переданный объект — это рыба.
   - Типовой предикат `animal is Fish` сообщает TypeScript, что если результат `true`, то переменная имеет тип `Fish`.

2. **Использование `isFish` в функции `move`**:
   - Если условие `if (isFish(animal))` истинно, TypeScript сужает тип переменной `animal` до `Fish`, и можно безопасно вызывать метод `swim()`.
   - Если условие ложно, TypeScript сужает тип переменной до `Bird`, и в блоке `else` можно безопасно вызывать метод `fly()`.

### Зачем использовать типовые предикаты?

1. **Создание кастомных гвардов типов**: TypeScript предоставляет встроенные механизмы, такие как `typeof`, `instanceof` и проверка на наличие свойств для сужения типов. Однако в реальных сценариях часто требуется более сложная проверка типов. Типовые предикаты позволяют разработчикам создавать свои собственные правила для проверки типов.

2. **Сужение сложных объединённых типов**: При работе с объединёнными типами (union types) или пересекающимися типами (intersection types), можно использовать типовые предикаты для явного указания TypeScript, какой тип нужно сузить в зависимости от результата проверки.

3. **Улучшение безопасности типов**: TypeScript становится ещё более строгим и безопасным, если вы явно указываете типы с помощью предикатов, что помогает избежать ошибок в коде.

### Пример: проверка сложных типов

```
type Car = { drive: () => void };
type Boat = { sail: () => void };
type Plane = { fly: () => void };

function isCar(vehicle: Car | Boat | Plane): vehicle is Car {
  return (vehicle as Car).drive !== undefined;
}

function isBoat(vehicle: Car | Boat | Plane): vehicle is Boat {
  return (vehicle as Boat).sail !== undefined;
}

function moveVehicle(vehicle: Car | Boat | Plane) {
  if (isCar(vehicle)) {
    vehicle.drive(); // TypeScript теперь знает, что это Car
  } else if (isBoat(vehicle)) {
    vehicle.sail(); // TypeScript понимает, что это Boat
  } else {
    vehicle.fly(); // TypeScript понимает, что это Plane
  }
}
```

#### Разбор:
1. **Типы `Car`, `Boat` и `Plane`**:  
   - У каждого из типов есть своё уникальное поведение: `drive` для машины, `sail` для лодки и `fly` для самолёта.
   
2. **Типовые предикаты `isCar()` и `isBoat()`**:  
   - Каждый типовой предикат проверяет, присутствует ли уникальный метод, присущий конкретному типу (`drive` для машины, `sail` для лодки). Если метод найден, предикат возвращает `true`, и TypeScript сужает тип переменной до соответствующего типа.

# Что можно сказать про control flow analysis?
<!-- basicblock-start oid="ObsbHyVfrW4sEYdLZiwg0nIi"  deck='T_typescript_narrowing' -->
Что можно сказать про control flow analysis?::


**Анализ потока управления (control flow analysis)** — это механизм в TypeScript, который отслеживает, как переменные изменяют свои типы в зависимости от выполнения программы. Это ключевая функция TypeScript для точного анализа типов, которая позволяет автоматически сужать типы переменных на основе условий, циклов, ветвлений, проверок и присваиваний.

TypeScript использует **анализ потока управления** для того, чтобы понять, как тип переменной изменяется в зависимости от различных веток выполнения программы. Он автоматически "узнаёт" о типе переменной в контексте, исходя из того, что происходило до и после выполнения блоков кода, таких как `if`, `else`, `switch`, циклы и другие конструкции.

### Как это работает:

#### Пример 1: Условные проверки (if)

```
function example(x: number | string) {
  if (typeof x === "string") {
    // В этом блоке TypeScript знает, что x — строка
    console.log(x.toUpperCase());
  } else {
    // Здесь TypeScript знает, что x — число
    console.log(x * 2);
  }
}
```

#### Что происходит:

1. Изначально переменная `x` имеет тип `number | string`. Это **объединённый тип** (union type), который может быть либо числом, либо строкой.
2. Когда TypeScript встречает условие `typeof x === "string"`, он **сузит тип** переменной `x` внутри этого блока до `string`. Внутри этого блока можно безопасно вызывать методы строки, такие как `toUpperCase()`.
3. В блоке `else` TypeScript понимает, что раз `x` не является строкой, значит, это точно число (`number`), и разрешает выполнение операций с числами, таких как умножение.

#### Пример 2: Проверка на null/undefined

```
function printValue(value: string | null | undefined) {
  if (value != null) {
    // Здесь TypeScript понимает, что value не может быть null или undefined
    console.log(value.toLowerCase());
  } else {
    console.log("No value provided");
  }
}
```

1. Сначала переменная `value` имеет тип `string | null | undefined`.
2. Когда выполняется проверка `value != null`, TypeScript сужает тип переменной `value` внутри блока до `string`, так как проверка исключает `null` и `undefined`.
3. В блоке `else` TypeScript понимает, что переменная может быть только `null` или `undefined`.

### Ключевые принципы анализа потока управления:

1. **Типовые гварды (type guards)**:  
   Когда TypeScript видит проверку типа, например, через `typeof`, `instanceof`, или проверку на наличие свойства (`in`), он сужает тип переменной внутри этой ветки.

2. **Проверки на null/undefined**:  
   TypeScript автоматически сужает тип переменной после проверок на `null` или `undefined`, например, используя операторы `!= null`, `!==`, или `==`.

3. **Циклы и return**:  
   Анализ потока управления также работает в циклах и при возвратах из функций. Например, если внутри цикла `while` переменная меняет свой тип, TypeScript может это учесть и сузить тип переменной после выхода из цикла.

4. **Unreachable code (недостижимый код)**:  
   TypeScript способен обнаруживать участки кода, до которых никогда не будет выполнен переход, например, после вызова `return`, `throw` или при условии, что предыдущие проверки уже полностью покрыли все возможные варианты.

#### Пример 3: Анализ типов в циклах

```
function checkArray(arr: (string | number)[]) {
  for (const item of arr) {
    if (typeof item === "string") {
      console.log(item.toUpperCase());
    } else {
      console.log(item * 2);
    }
  }
}
```

1. В цикле переменная `item` может быть либо строкой, либо числом (`string | number`).
2. При проверке `typeof item === "string"`, TypeScript автоматически сужает тип переменной внутри этого блока до `string`.
3. В блоке `else`, если `item` не строка, TypeScript понимает, что это число, и разрешает операции над числами.

# Что можно сказать про сужение через присвоение?
<!-- basicblock-start oid="ObsM4xVCLm2IYBiDdfFSNrvA"  deck='T_typescript_narrowing' -->
Что можно сказать про сужение через присвоение?::


Этот пример объясняет, как TypeScript обрабатывает типы переменных при присваивании значений, и демонстрирует концепцию **сужения типов** (narrowing) при присвоении. Давайте разберём это по шагам.

### Пример:

```
let x = Math.random() < 0.5 ? 10 : "hello world!";
```

#### Что происходит здесь:

1. **Инициализация `x`**:  
   Переменная `x` инициализируется условным выражением, которое случайно присваивает ей либо значение `10`, либо строку `"hello world!"`. TypeScript автоматически определяет тип переменной `x` как **`string | number`**, потому что переменная может быть либо числом (`10`), либо строкой (`"hello world!"`).

   ```
   let x: string | number
   
```

2. **Сужение типов при присвоении**:  
   Теперь мы можем присваивать переменной `x` значения типов `number` или `string`, поскольку её изначально объявленный тип — `string | number`. Каждый раз, когда присваивается новое значение, TypeScript автоматически сужает наблюдаемый тип переменной до типа этого значения.

   Например:
   ```
   x = 1; // x становится типа number
   console.log(x); // Выводит 1
   
```

   После присвоения числа `1`, TypeScript сужает **наблюдаемый** тип переменной до `number`, потому что текущее значение переменной — это число. Тем не менее, переменной всё ещё можно присвоить строку, так как её **объявленный тип** — `string | number`.

3. **Присвоение строки**:
   ```
   x = "goodbye!"; // x теперь типа string
   console.log(x); // Выводит "goodbye!"
   
```

   Даже после присвоения числа мы можем снова присвоить переменной строку, потому что объявленный тип `x` позволяет это. TypeScript отслеживает **объявленный тип** переменной, а не только её текущее значение.

4. **Ошибка при присвоении неподходящего типа**:

   Однако если мы попытаемся присвоить переменной `x` значение типа, который не соответствует объявленному типу, TypeScript покажет ошибку:
   
   ```
   x = true; // Ошибка: Type 'boolean' is not assignable to type 'string | number'.
   
```

   TypeScript выдаёт ошибку, потому что тип `boolean` не входит в состав объявленного типа `string | number`.

### Вывод:

1. **Объявленный тип переменной** определяет, какие значения могут быть присвоены переменной в будущем. В примере `x` был объявлен как `string | number`, поэтому ему можно присваивать значения типа `string` или `number`, но не другие типы.

2. **Сужение типов** происходит при каждом присвоении. Когда вы присваиваете переменной значение, TypeScript сужает её тип до типа этого значения. Например, после присвоения числа переменная временно рассматривается как `number`.

3. **Проверка присваиваемых типов** всегда происходит на основе **объявленного типа**, а не на основе текущего наблюдаемого значения.

### Заключение:
TypeScript сужает типы переменных при каждом присвоении, но всегда проверяет совместимость с **объявленным типом** переменной. Это позволяет точно отслеживать типы и избегать ошибок при присвоении значений неподходящего типа.

Что можно сказать про insanceof narrowing?::


**`instanceof` narrowing** — это механизм сужения типов в TypeScript, который используется для определения типа объекта на основе его конструктора. Оператор `instanceof` проверяет, является ли объект экземпляром определённого класса или его подкласса. TypeScript использует эту информацию для автоматического сужения типов.

### Как работает `instanceof narrowing`:

Когда вы используете оператор `instanceof`, TypeScript автоматически сужает тип переменной внутри соответствующего блока к указанному типу (классу), если проверка проходит успешно. Это полезно при работе с типами, которые могут быть экземплярами нескольких классов или наследовать друг от друга.

### Пример:

```
class Dog {
  bark() {
    console.log("Woof!");
  }
}

class Cat {
  meow() {
    console.log("Meow!");
  }
}

function makeSound(animal: Dog | Cat) {
  if (animal instanceof Dog) {
    animal.bark(); // TypeScript теперь знает, что это Dog
  } else {
    animal.meow(); // TypeScript понимает, что это Cat
  }
}
```

#### Разбор:

1. **Тип `animal`**:  
   В этой функции переменная `animal` может быть либо экземпляром класса `Dog`, либо класса `Cat`. На этапе компиляции TypeScript не может точно знать, с каким объектом мы имеем дело, поэтому указывается тип объединения (union) — `Dog | Cat`.

2. **Проверка `if (animal instanceof Dog)`**:
   - Оператор `instanceof` проверяет, является ли переменная `animal` экземпляром класса `Dog`.
   - Если условие истинно, TypeScript автоматически сужает тип переменной `animal` до класса `Dog`. Это означает, что внутри этого блока можно безопасно вызывать метод `bark()`, так как `animal` — объект типа `Dog`.

3. **Иначе (`else`)**:
   - Если проверка на `Dog` не проходит, TypeScript понимает, что переменная `animal` должна быть объектом типа `Cat`. Это позволяет безопасно вызвать метод `meow()` в ветке `else`.

### Пример с наследованием:

```
class Animal {
  move() {
    console.log("Animal is moving");
  }
}

class Fish extends Animal {
  swim() {
    console.log("Fish is swimming");
  }
}

function checkAnimal(animal: Animal) {
  if (animal instanceof Fish) {
    animal.swim(); // TypeScript знает, что это Fish
  } else {
    animal.move(); // Здесь animal точно будет Animal
  }
}
```

#### Разбор:

1. **Тип `animal`**:  
   В этом примере функция принимает переменную типа `Animal`, которая может быть как экземпляром базового класса `Animal`, так и производного класса `Fish`.

2. **Проверка `if (animal instanceof Fish)`**:
   - Оператор `instanceof` проверяет, является ли `animal` экземпляром класса `Fish`.
   - Если условие истинно, TypeScript сужает тип переменной до `Fish`, и вы можете безопасно вызвать метод `swim()`, который есть только у объектов типа `Fish`.

3. **Иначе (`else`)**:
   - Если `animal` не является объектом типа `Fish`, TypeScript сужает тип до базового класса `Animal`, и можно использовать методы, доступные в классе `Animal`, например, `move()`.

### Заключение:
- **`instanceof narrowing`** — это способ сузить тип объекта на основе его конструктора.
- Это особенно полезно при работе с типами, которые являются классами или наследуют друг от друга.
- TypeScript автоматически сужает типы в зависимости от успешности проверки `instanceof`, что позволяет безопасно работать с объектами, вызывая методы или свойства, которые специфичны для конкретных классов.

# Что можно сказать про in narrowing?
<!-- basicblock-start oid="ObseRUVqIuyI6k5loZfOSOlC"  deck='T_typescript_narrowing' -->
Что можно сказать про in narrowing?::


**`in` narrowing** (сужение с помощью оператора `in`) — это механизм в TypeScript, который позволяет сузить тип переменной, проверяя, существует ли конкретное свойство в объекте. Это полезно, когда переменная может иметь несколько разных типов, каждый из которых содержит уникальные свойства. TypeScript использует проверку `in` как типовой гвард (type guard), чтобы сузить переменные к тем типам, которые содержат это свойство.

### Как работает `in narrowing`:

#### Пример с функцией `move`:

```
type Fish = {swim: () => void};
type Bird = {fly: () => void};

function move(animal: Fish | Bird) {
    if ("swim" in animal) {
        return animal.swim();
    }

    return animal.fly();
}
```

#### Разбор:

1. **Тип `animal`**:  
   Функция `move` принимает параметр `animal`, который может быть либо `Fish` (содержит метод `swim`), либо `Bird` (содержит метод `fly`).

2. **Проверка `if ("swim" in animal)`**:
   - Оператор `in` проверяет наличие свойства `"swim"` в объекте `animal`.
   - Если условие истинно (`"swim"` есть в объекте), TypeScript автоматически сужает тип переменной `animal` до типа **`Fish`**. Ветвь с истинным условием может безопасно использовать метод `swim()`, так как TypeScript знает, что это объект типа `Fish`.
   
3. **Иначе (`else`)**:
   - Если условие ложно, TypeScript автоматически понимает, что в этой ветке `animal` должен быть объектом типа **`Bird`** (так как в нем нет свойства `"swim"`, но есть метод `fly()`), и соответственно можно безопасно вызывать метод `fly()`.

Таким образом, TypeScript сужает тип на основе присутствия или отсутствия свойства, делая код безопаснее.

#### Пример с функцией `move2`:

```
function move2(animal: Fish | Bird | Human) {
    if ("swim" in animal) {
        // animal;  // Здесь animal будет Fish или Human
    } else {
        // animal;  // Здесь animal будет Bird
    }
}
```

#### Разбор:

1. **Тип `animal`**:  
   В этой версии функция принимает тип, который может быть `Fish`, `Bird` или `Human`. Как видно, и `Fish`, и `Human` содержат метод `swim`, а `Bird` — нет.

2. **Проверка `if ("swim" in animal)`**:
   - Когда проверяется наличие метода `"swim"`, TypeScript автоматически сужает тип переменной `animal` к либо `Fish`, либо `Human` (поскольку оба типа содержат метод `swim`).
   
3. **Иначе (`else`)**:
   - Если метод `"swim"` отсутствует, TypeScript автоматически понимает, что переменная `animal` должна быть типа `Bird`, так как только этот тип не содержит метода `swim`.

Таким образом, в зависимости от проверки наличия свойства `"swim"`, TypeScript сужает типы до конкретных подмножеств типов, что позволяет писать код безопасно.

### Заключение:
- **`in narrowing`** — это способ сужать типы на основе проверки наличия свойства в объекте.
- Это особенно полезно, когда работаешь с типами объединения (union types), которые могут представлять объекты с разными наборами свойств.
- TypeScript автоматически сужает типы в зависимости от того, существует ли указанное свойство, что упрощает работу с переменными и повышает безопасность кода.

# Что можно сказать про equality nattowing ?
<!-- basicblock-start oid="ObsKwyH8GhTqpJ022QFMV3PX"  deck='T_typescript_narrowing' -->
Что можно сказать про equality nattowing ?::


**Equality narrowing** (сужение с помощью проверки на равенство) — это процесс, при котором TypeScript сужает тип переменной, основываясь на проверке значений через операторы сравнения. Это позволяет исключать нежелательные значения, такие как `null` или `undefined`, и работать с более конкретными типами.

### Пример и разбор функции `multiplyValue`:

```
interface Container {
  value: number | null | undefined;
}

function multiplyValue(container: Container, factor: number) {
  // Remove both 'null' and 'undefined' from the type.
  if (container.value != null) {
    console.log(container.value);

    // Now we can safely multiply 'container.value'.
    container.value *= factor;
  }
}
```

#### Что происходит:

1. **Тип `container.value` до проверки**:  
   Изначально, у `container.value` тип `number | null | undefined`, так как он может принимать одно из этих значений.

2. **Проверка `container.value != null`**:
   - Проверка `!= null` — это особая форма равенства, которая одновременно исключает **`null`** и **`undefined`**. В JavaScript (и TypeScript), `null == undefined` возвращает `true`, что делает это удобной проверкой для исключения обоих этих значений.
   - После этой проверки TypeScript понимает, что внутри блока `if` тип `container.value` **не может быть** ни `null`, ни `undefined`. Это значит, что в этом месте тип `container.value` сужается до **`number`**.

3. **Безопасная работа с типом `number`**:
   - После проверки, внутри блока `if`, мы можем безопасно работать с `container.value` как с числом. Это означает, что можно выполнять операции с ним, такие как умножение (`container.value *= factor`).

4. **Вывод**:
   - TypeScript автоматически сузил тип переменной на основании проверки `!= null`, и теперь он знает, что `container.value` внутри блока `if` может быть только числом.
   - С помощью такой проверки на равенство вы устраняете `null` и `undefined`, и TypeScript "понимает", что оставшийся тип — это только число, что позволяет безопасно выполнять математические операции.

### Ключевые моменты:
- **Equality narrowing** через `!= null` — это один из способов исключить `null` и `undefined`, оставляя только значения, которые можно безопасно использовать (например, числа).
- В TypeScript такие проверки позволяют работать с типами более эффективно, так как язык автоматически "сужает" тип переменной после проверки, исключая ненужные варианты.

#### Преимущества использования проверки `!= null`:
- Одновременно исключает и `null`, и `undefined`.
- Позволяет TypeScript корректно сужать тип переменной.
- Упрощает написание кода, когда нужно гарантировать, что значение существует и готово для дальнейших операций.

# Что такое сужение в typescript?
<!-- basicblock-start oid="ObsaOu4Wfc2ZCgrp0YsEBt1c"  deck='T_typescript_narrowing' -->
Что такое сужение в typescript?::


В TypeScript **сужение типов** (*type narrowing*) — это процесс, при котором TypeScript "сужает" широкий тип переменной (например, `string | number`) до более конкретного типа (например, только `string` или только `number`), основываясь на условиях, операциях или других проверках, выполняемых в коде. Это позволяет работать с более точным и безопасным набором типов, уменьшив вероятность ошибок.

Когда TypeScript "понимает", что переменная может быть только определенного типа в определенной части программы, это называется **сужением типа**.

### Пример 1: Сужение через `typeof`
```
function printId(id: string | number) {
    if (typeof id === 'string') {
        console.log(id.toUpperCase());  // Здесь TypeScript знает, что id — строка
    } else {
        console.log(id);  // Здесь TypeScript знает, что id — число
    }
}
```
В этом примере `id` изначально имеет тип `string | number`. Когда используется проверка `typeof id === 'string'`, TypeScript "сужает" тип переменной `id` до `string` внутри блока `if`. В блоке `else` TypeScript понимает, что тип переменной теперь только `number`.

### Пример 2: Сужение через проверки на равенство (`==`, `===`, `!=`, `!==`)
```
function printTruthy(value: string | null | undefined) {
    if (value) {
        console.log(value);  // Здесь TypeScript знает, что value не null и не undefined
    } else {
        console.log("Value is null or undefined");
    }
}
```
Когда проверяется истинность значения (`if (value)`), TypeScript исключает `null` и `undefined` из возможных типов переменной `value` и сужает его до типа `string`.

### Пример 3: Сужение через проверки с помощью оператора `instanceof`
```
function printDate(date: string | Date) {
    if (date instanceof Date) {
        console.log(date.toISOString());  // Здесь TypeScript знает, что date — это объект Date
    } else {
        console.log(date);  // Здесь TypeScript знает, что date — это строка
    }
}
```
Используя оператор `instanceof`, TypeScript может сужать тип объекта до более конкретного типа, если проверка проходит успешно.

### Пример 4: Сужение через пользовательские типовые гварды (type guards)
Можно написать собственные функции для сужения типов. Это называется **пользовательские типовые гварды**.
```
function isString(value: any): value is string {
    return typeof value === 'string';
}

function printValue(value: string | number) {
    if (isString(value)) {
        console.log("String value:", value);  // Здесь TypeScript знает, что value — это строка
    } else {
        console.log("Number value:", value);  // Здесь TypeScript знает, что value — это число
    }
}
```
Здесь функция `isString` возвращает результат проверки, который помогает TypeScript сужать тип.

### Когда используется сужение типов
1. **Для безопасного доступа к свойствам или методам**: После сужения типов можно безопасно вызывать методы, которые принадлежат только одному конкретному типу.
2. **Для предотвращения ошибок во время выполнения**: TypeScript на основе сужения может предупредить разработчика, если он пытается выполнить операцию с неправильным типом.
3. **Для повышения удобочитаемости и поддерживаемости кода**: Явное сужение типов делает код понятнее и легче для сопровождения.

### Заключение
Сужение типов в TypeScript — это мощная функция, которая позволяет работать с переменными, типизированными более общими типами, и безопасно приводить их к конкретным типам, исходя из логики программы. Это делает код безопаснее и предотвращает возможные ошибки, связанные с несовместимостью типов.
