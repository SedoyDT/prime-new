# ### 7. **Аннотации Вариации**
<!-- basicblock-start oid="Obs3IwFu5bXMp1fz7ZLkDu0f"  deck='T_typescipt' -->
### 7. **Аннотации Вариации**::


Вариация — это более сложная тема в теории типов, которая описывает, как подтипы соотносятся с родительскими типами. В TypeScript это обычно выводится автоматически, но может быть аннотировано при необходимости.

- **Ковариантность**: Позволяет заменить тип подтипом (например, `Producer<Cat>` где ожидается `Producer<Animal>`).
- **Контравариантность**: Позволяет заменить тип суперклассом (например, `Consumer<Animal>` где ожидается `Consumer<Cat>`).

#### Пример Ковариантности и Контравариантности:

```
interface Producer<out T> {
  make(): T;
}

interface Consumer<in T> {
  consume(arg: T): void;
}
```

Аннотации вариации используются для более сложных сценариев и редко необходимы в повседневной разработке на TypeScript.

# ### 5. **Использование Параметров Типа в Ограничениях Обобщений**
<!-- basicblock-start oid="Obs0h1YS8nXLTDMoCMOpkXhs"  deck='T_typescipt' -->
### 5. **Использование Параметров Типа в Ограничениях Обобщений**::


Вы можете использовать параметры типа в ограничениях, чтобы обеспечить правильные отношения между типами.

#### Пример:

```
function getProperty<Type, Key extends keyof Type>(obj: Type, key: Key) {
  return obj[key];
}

let x = { a: 1, b: 2, c: 3, d: 4 };

getProperty(x, "a"); // Работает
getProperty(x, "m"); // Ошибка: Аргумент типа '"m"' не совместим с параметром типа '"a" | "b" | "c" | "d"'
```

Здесь `Key` ограничен ключами объекта `Type`.

# ### 4. **Ограничения Обобщений**
<!-- basicblock-start oid="Obs0I6oFdaIz5BkzEUgG1WvU"  deck='T_typescipt' -->
### 4. **Ограничения Обобщений**::


Ограничения позволяют ограничить типы, которые могут использоваться с обобщением. Это полезно, когда вам нужно убедиться, что тип обладает определенными свойствами или методами.

#### Пример:

```
interface Lengthwise {
  length: number;
}

function loggingIdentity<Type extends Lengthwise>(arg: Type): Type {
  console.log(arg.length);
  return arg;
}

loggingIdentity({ length: 10, value: 3 }); // Работает
loggingIdentity(3); // Ошибка: Свойство 'length' не существует
```

В этом примере `Type` ограничен типами, которые имеют свойство `length`.

# ### 3. **Обобщенные Классы**
<!-- basicblock-start oid="Obsjszfcb0lhsZ8OX8DOtZfe"  deck='T_typescipt' -->
### 3. **Обобщенные Классы**::


Обобщенные классы позволяют создавать классы, которые работают с различными типами, сохраняя при этом типобезопасность.

#### Пример:

```
class GenericNumber<NumType> {
  zeroValue: NumType;
  add: (x: NumType, y: NumType) => NumType;
}

let myGenericNumber = new GenericNumber<number>();
myGenericNumber.zeroValue = 0;
myGenericNumber.add = function (x, y) {
  return x + y;
};

let stringNumeric = new GenericNumber<string>();
stringNumeric.zeroValue = "";
stringNumeric.add = function (x, y) {
  return x + y;
};
```

В этом примере `GenericNumber` — это класс, который работает с обобщенным типом `NumType`.

# ### 2. **Обобщенные Интерфейсы**
<!-- basicblock-start oid="ObsryDnKOHGpE4WX8UV8KvE6"  deck='T_typescipt' -->
### 2. **Обобщенные Интерфейсы**::


Вы можете использовать обобщения в интерфейсах для определения функций или методов, которые работают с различными типами.

#### Пример:

**Обобщенная Функция в Интерфейсе:**

```
interface GenericIdentityFn {
  <Type>(arg: Type): Type;
}

let myIdentity: GenericIdentityFn = identity;
```

**Обобщенный Интерфейс с Параметром Типа:**

```
interface GenericIdentityFn<Type> {
  (arg: Type): Type;
}

let myIdentity: GenericIdentityFn<number> = identity;
```

В этом примере `GenericIdentityFn` — это интерфейс, который описывает функцию, принимающую один аргумент типа `Type` и возвращающую значение того же типа.

# ### 1. **Обобщенные Функции**

### 1. **Обобщенные Функции**::


Обобщенная функция позволяет написать функцию, которая может работать с любым типом данных. Тип функции параметризован с помощью переменных типа.

#### Пример:

```
function identity<Type>(arg: Type): Type {
  return arg;
}

let myIdentity: <Type>(arg: Type) => Type = identity;
```

Здесь `Type` является заполнительным типом, который представляет тип `arg` и возвращаемого значения.

# Что можно сказать о дженериках в ts?
<!-- basicblock-start oid="ObsbqNetjzuwcUTbze2aZGgQ"  deck='T_typescipt' -->
Что можно сказать о дженериках в ts?::


Основная часть разработки программного обеспечения — это создание компонентов, которые не только имеют четко определенные и согласованные API, но и допускают повторное использование. Компоненты, способные работать как с данными сегодняшнего дня, так и с данными завтрашнего дня, предоставят вам наиболее гибкие возможности для создания больших программных систем.

В таких языках, как C# и Java, одним из основных инструментов для создания повторно используемых компонентов являются дженерики, то есть возможность создавать компонент, который может работать с различными типами, а не с одним. Это позволяет пользователям использовать эти компоненты и использовать свои собственные типы.

# Что можно сказать про hello world дженериков функцию identity?
<!-- basicblock-start oid="ObsUGWDpft1bwh0StN5VgvxV"  deck='T_typescipt' -->
Что можно сказать про hello world дженериков функцию identity?::


Вот перевод текста на русский:

---

Привет, мир обобщений!

Давайте начнем с "Hello, world!" в мире обобщений: функции идентичности. Функция идентичности возвращает то же значение, которое было передано в нее. Можно представить это как команду echo.

Без обобщений мы должны были бы задать конкретный тип для функции идентичности:

```
function identity(arg: number): number {
  return arg;
}
```

Или же использовать тип any:

```
function identity(arg: any): any {
  return arg;
}
```

Хотя использование any позволяет функции принимать значения любого типа, мы теряем информацию о типе возвращаемого значения. Если мы передаем число, то мы теряем информацию о его типе в возвращаемом значении.

Вместо этого нам нужен способ захвата типа аргумента таким образом, чтобы мы могли использовать его и для указания типа возвращаемого значения. Для этого мы используем типовую переменную, специальный вид переменной, который работает с типами, а не со значениями.

```
function identity<Type>(arg: Type): Type {
  return arg;
}
```

Мы добавили типовую переменную Type к функции идентичности. Этот Type позволяет нам захватить тип, который пользователь передает (например, number), чтобы мы могли использовать эту информацию позже. Здесь мы снова используем Type в качестве типа возвращаемого значения. Теперь тип аргумента и тип возвращаемого значения совпадают. Это позволяет сохранить информацию о типе от одной стороны функции до другой.

Мы говорим, что эта версия функции идентичности является обобщенной, поскольку она работает с различными типами. В отличие от использования any, она также точно передает тип (т.е., не теряет информацию), как это делает первая функция идентичности с числовыми типами для аргумента и возвращаемого значения.

После написания обобщенной функции идентичности, мы можем вызвать ее двумя способами. Первый способ - передать все аргументы, включая типовый аргумент, функции:

```
let output = identity<string>("myString");
```

Здесь мы явно устанавливаем Type как string в аргументах функции, обозначая это с помощью <> вокруг аргументов, а не ().

Второй способ, возможно, более распространен. Здесь мы используем вывод типовых аргументов - то есть, мы хотим, чтобы компилятор автоматически установил значение Type на основе типа аргумента, который мы передаем:

```
let output = identity("myString");
```

Обратите внимание, что нам не нужно явно указывать тип в угловых скобках (<>); компилятор просто смотрит на значение "myString" и устанавливает Type в его тип. В то же время вывод типовых аргументов может быть полезным инструментом, чтобы сделать код короче и более читаемым, иногда вам придется явно указать типовые аргументы, как мы сделали в предыдущем примере, когда компилятор не может вывести тип, что может произойти в более сложных примерах.
