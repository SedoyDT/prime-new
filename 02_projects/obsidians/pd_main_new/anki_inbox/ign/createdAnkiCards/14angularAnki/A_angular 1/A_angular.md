# Как работает angular.copy?
<!-- basicblock-start  deck='A_angular' -->
Как работает angular.copy?::


В AngularJS функция `angular.copy()` используется для создания **глубокой копии** объекта или массива, что означает, что копия будет полностью независимой от оригинала, включая вложенные объекты или массивы. Это полезно, когда нужно избежать проблем с изменением оригинальных данных при их изменении через ссылку. 

### Как работает `angular.copy()`?

1. **Глубокое копирование**:
   - Функция выполняет **глубокое копирование** (deep copy), что означает, что она копирует все вложенные объекты рекурсивно.
   - Для простых типов (строки, числа, булевы значения) создается новая копия значений.
   - Для объектов и массивов создаются новые объекты и массивы, и они копируются по аналогии с первичными объектами.

2. **Объекты и массивы**:
   - При копировании объектов или массивов `angular.copy()` создает новый объект или массив и копирует все свойства или элементы оригинала в новый объект.
   - Это значит, что если в оригинале есть вложенные объекты или массивы, они также будут скопированы (а не просто скопирована ссылка на них).

3. **Не изменяет оригинал**:
   - Функция создает независимую копию, и любые изменения, внесенные в копию, не затрагивают оригинал и наоборот.

### Пример использования

```
// Оригинальный объект
var originalObject = {
    name: 'Angular',
    version: 1.8,
    features: ['two-way data binding', 'dependency injection'],
    nested: {
        innerProperty: 'value'
    }
};

// Создание копии
var copiedObject = angular.copy(originalObject);

// Изменим значение в копии
copiedObject.name = 'AngularJS';
copiedObject.features.push('directives');
copiedObject.nested.innerProperty = 'new value';

// Проверим, что изменился только copiedObject, а originalObject остался неизменным
console.log(originalObject);
// { name: 'Angular', version: 1.8, features: [ 'two-way data binding', 'dependency injection' ], nested: { innerProperty: 'value' } }

console.log(copiedObject);
// { name: 'AngularJS', version: 1.8, features: [ 'two-way data binding', 'dependency injection', 'directives' ], nested: { innerProperty: 'new value' } }
```

### Как работает копирование:

- **Простые типы** (строки, числа, булевы значения) копируются по значению. Например, если вы копируете строку или число, то оригинальная строка или число и копия будут независимыми.
- **Массивы и объекты** копируются по ссылке на каждый элемент или свойство. Это означает, что если в объекте или массиве есть вложенные данные, то они будут полностью скопированы, а не просто ссылка на оригинальные данные.

### Что происходит при копировании:

- В оригинале `name` остается "Angular", а в копии изменяется на "AngularJS".
- Вложенный объект `nested` имеет разные значения в оригинале и копии, поскольку `angular.copy()` создает новый объект для вложенных объектов.
- Массив `features` также изменяется в копии (добавлен новый элемент), но оригинальный массив остается неизменным.

### Особенности и ограничения:
1. **Функции**: Если объект или массив содержит функции, `angular.copy()` скопирует их ссылку, а не создаст новую копию функции.
2. **Циклические ссылки**: В случае объектов с цикличными ссылками (когда объект ссылается на самого себя), `angular.copy()` вызовет ошибку. Это также может быть причиной проблем, если попытаться скопировать такие объекты.
3. **Сложности с Date и RegExp**: При копировании объектов типа `Date` или `RegExp` результат может быть не всегда ожидаемым, так как не все типы данных правильно обрабатываются при копировании. Чтобы избежать проблем, в таких случаях лучше использовать специализированные методы.

### Примечание:
С Angular 2 и выше `angular.copy()` больше не используется. Вместо этого используются нативные методы JavaScript, такие как `JSON.parse(JSON.stringify(object))` (для "глубокого" копирования, но без сохранения функций и цикличности) или библиотеки, например, `lodash` (с функцией `_.cloneDeep()`).

Тем не менее, в AngularJS `angular.copy()` был и остается полезным инструментом для работы с объектами, который легко решает задачу глубокого копирования в приложениях на AngularJS.

# Поскольку `$rootScope` является глобальным, вы можете использовать его для прослушивания событий, отправленных в любом месте приложения, даже если они не принадлежат определенному контроллеру или директиве.
<!-- basicblock-start  deck='A_angular' -->
Поскольку `$rootScope` является глобальным, вы можете использовать его для прослушивания событий, отправленных в любом месте приложения, даже если они не принадлежат определенному контроллеру или директиве.::


Пример:
```
app.run(['$rootScope', function($rootScope) {
    $rootScope.$on('globalEvent', function(event, data) {
        console.log('Global event received:', data);
    });
}]);
```

### Резюме:
Метод `$scope.$on` может использоваться для подписки на события в следующих сущностях:
- **Контроллеры** — для получения событий, переданных с помощью `$broadcast` или `$emit`.
- **Директивы** — для получения событий от других частей приложения.
- **Сервисы и фабрики** — через `$rootScope` для распространения событий по всему приложению.
- **Маршруты** — через `$routeChangeStart`, `$routeChangeSuccess` и другие события маршрутизации.
- **Глобальные события** — через `$rootScope.$on` для подписки на события, генерируемые в разных частях приложения.

Таким образом, `$scope.$on` можно использовать во всех компонентах AngularJS, где доступен `$scope` (например, контроллеры, директивы), а для глобальных событий, если нужно, можно подписаться через `$rootScope.$on`.

# В каких еще сущностях angular можно использовать $scope.$on ?
<!-- basicblock-start  deck='A_angular' -->
В каких еще сущностях angular можно использовать $scope.$on ?::


Метод `$scope.$on` в AngularJS используется для подписки на события, которые распространяются по дереву $scope. Этот метод не ограничивается только контроллерами, его можно использовать в нескольких других сущностях AngularJS. Вот основные сущности, в которых можно использовать `$scope.$on` для подписки на события:

### 1. **Контроллеры (`$scope`)**

Контроллеры — это одна из основных сущностей, где можно использовать `$scope.$on`. Внутри контроллера вы подписываетесь на события, отправленные через `$broadcast` или `$emit`, и обновляете данные на основе этих событий.

Пример:
```
app.controller('MyController', ['$scope', function($scope) {
    $scope.$on('customEvent', function(event, data) {
        console.log('Received customEvent:', data);
    });
}]);
```

### 2. **Директивы**

Директивы в AngularJS также могут использовать `$scope.$on` для прослушивания событий. Это полезно, когда вы хотите обработать события, приходящие от других директив или контроллеров.

Пример:
```
app.directive('myDirective', function() {
    return {
        restrict: 'E',
        link: function(scope, element, attrs) {
            scope.$on('customEvent', function(event, data) {
                console.log('Directive received customEvent:', data);
            });
        }
    };
});
```

### 3. **Сервисы (через `$rootScope`)**

Хотя сервисы не имеют `$scope`, они могут генерировать события с помощью `$rootScope.$on`, и если сервис нужен для распространения событий по всей апликации, другие компоненты могут подписаться на эти события.

Пример:
```
app.service('myService', ['$rootScope', function($rootScope) {
    this.triggerEvent = function() {
        $rootScope.$broadcast('customEvent', { data: 'Hello from service!' });
    };
}]);

// Другие компоненты могут подписаться на событие:
app.controller('MyController', ['$scope', function($scope) {
    $scope.$on('customEvent', function(event, data) {
        console.log('Controller received customEvent:', data);
    });
}]);
```

### 4. **Фильтры**

Хотя фильтры обычно не взаимодействуют с событиями напрямую (так как они не имеют собственного `$scope`), теоретически можно использовать их в связке с сервисами или контроллерами для прослушивания событий. Например, вы можете использовать фильтры для преобразования данных, передаваемых через события.

Однако использование `$scope.$on` в фильтрах не является распространенной практикой, так как фильтры обычно должны быть чистыми и только изменять данные, не имея побочных эффектов.

### 5. **Модули и сервисы, использующие `$rootScope`**

Так как `$rootScope` является глобальным контейнером для всех событий и данных, вы можете использовать его для передачи и прослушивания событий в любом месте приложения, включая сервисы и фабрики. Например, если вы хотите отправить событие по всему приложению, можно использовать `$rootScope.$broadcast` и подписаться на событие в любом компоненте через `$rootScope.$on`.

Пример:
```
// В одном сервисе
app.service('myService', ['$rootScope', function($rootScope) {
    this.triggerEvent = function() {
        $rootScope.$broadcast('customEvent', { message: 'Data from service!' });
    };
}]);

// В другом контроллере
app.controller('AnotherController', ['$scope', function($scope) {
    $scope.$on('customEvent', function(event, data) {
        console.log('AnotherController received customEvent:', data);
    });
}]);
```

### 6. **`$routeProvider` и маршруты (`$route` и `$location`)**

Если ваше приложение использует маршрутизацию, вы можете подписываться на события изменения маршрута с помощью `$scope.$on`. AngularJS предоставляет специальные события для маршрутов, такие как `$routeChangeStart`, `$routeChangeSuccess`, и `$routeChangeError`.

Пример:
```
app.controller('RouteChangeController', ['$scope', '$route', function($scope, $route) {
    $scope.$on('$routeChangeStart', function(event, next, current) {
        console.log('Route is changing...');
    });

    $scope.$on('$routeChangeSuccess', function(event, current, previous) {
        console.log('Route changed successfully!');
    });
}]);
```

# как контроллеры узнают о событии которое было сгенерировано $broadcast
<!-- basicblock-start  deck='A_angular' -->
как контроллеры узнают о событии которое было сгенерировано $broadcast::


В AngularJS контроллеры могут узнать о событии, сгенерированном с помощью `$broadcast`, используя механизм слушателей событий через `$scope.$on`. С помощью этого механизма компоненты могут подписаться на события и реагировать на их изменения.

### Важные моменты:
1. **`$broadcast`** — Это метод, который используется для отправки событий от контроллера или другого компонента вниз по иерархии (потомкам в DOM-дереве). Он отправляет событие всем дочерним контроллерам или директивам, которые подписались на это событие с помощью `$scope.$on`.

2. **`$scope.$on`** — Это метод, который позволяет подписаться на событие. Когда событие будет отправлено через `$broadcast`, слушатель, подписанный на это событие, получит его и сможет выполнить соответствующие действия.

### Пример в вашем коде:

В вашем случае, событие `yearChanged` генерируется в сервисе `yearExchange` при изменении года с помощью `$rootScope.$broadcast('yearChanged', year)`. Затем контроллеры подписываются на это событие с помощью `$scope.$on('yearChanged', ...)`.

### Где и как происходит подписка на событие?

В обоих контроллерах (родительском и дочернем) вы подписываетесь на событие `yearChanged` с помощью `$scope.$on`:

```
$scope.$on('yearChanged', function(event, newYear) {
    $scope.year = newYear;
});
```

Этот код слушает событие `yearChanged`, и когда оно будет сгенерировано, будет выполнена переданная функция. В этой функции вы получаете новое значение года (`newYear`), которое передается в качестве второго аргумента в обработчик события. Затем вы обновляете `$scope.year`, чтобы отобразить новый год.

### Важные моменты:
- **`$scope.$on`** — подписка на событие.
- **`$rootScope.$broadcast`** — отправка события.
- Когда родительский или дочерний контроллер подписывается на событие с помощью `$scope.$on`, он будет "слушать" события, сгенерированные в других компонентах (например, в сервисах или других контроллерах).

Таким образом, когда событие `yearChanged` генерируется, все контроллеры, подписанные на это событие через `$scope.$on`, получат это событие и смогут обновить свой `$scope` в соответствии с новыми данными.

### Пример работы события:
1. Пользователь увеличивает или уменьшает год в любом из контроллеров (например, в родительском).
2. Это вызывает вызов метода `setYear` сервиса `yearExchange`, который затем вызывает `$rootScope.$broadcast('yearChanged', newYear)`.
3. Все контроллеры, подписанные на событие `yearChanged`, получают это событие через `$scope.$on`, и обновляют своё состояние (например, `$scope.year`).

Таким образом, вся система компонентов обновляется синхронно при изменении года.

# Digest cycle может быть инициирован в следующих ситуациях:
<!-- basicblock-start  deck='A_angular' -->
Digest cycle может быть инициирован в следующих ситуациях:::


1. **Изменение данных в контроллере**: Когда значение в модели (например, `$scope.variable`) изменяется.
2. **События DOM**: Когда происходит событие, например, `click`, `input`, `keyup` и другие.
3. **Асинхронные операции**: Когда приходит ответ от HTTP-запроса или другого асинхронного действия, которое обновляет данные.
4. **`$apply()` и `$digest()`**: 
   - Вызывая `$apply()` (например, из сервиса или других сторонних библиотек), можно вручную запустить цикл digest. `$apply()` передает управление в Angular и заставляет его обработать изменения.
   - `$digest()` — более низкоуровневый метод, который позволяет вручную инициировать цикл.

### Пример использования `$apply()`:

```
$scope.$apply(function() {
    $scope.message = "New Message!";
});
```

Это приведет к запуску digest цикла и обновлению DOM с новым значением `message`.

### Проблемы с Digest Cycle:

1. **Бесконечные циклы**: Если в процессе digest цикла происходит изменение данных, которое снова инициирует цикл, это может привести к бесконечному циклу. Чтобы предотвратить это, Angular ограничивает количество итераций по умолчанию до 10.
   
2. **Производительность**: Если у вас большое количество данных, и Angular выполняет проверку изменений для каждого из них, это может снизить производительность приложения. Поэтому важно минимизировать количество выражений и наблюдаемых значений, которые проверяются на каждом цикле.

### Заключение:

**Digest cycle** — это ключевая часть механизма двухсторонней привязки данных в AngularJS, обеспечивающая автоматическое обновление DOM в ответ на изменения в данных. Он работает с использованием "dirty checking", чтобы сравнить старые и новые значения данных и обновить представление при необходимости. Это позволяет Angular эффективно синхронизировать модель и представление, но важно учитывать производительность и избегать бесконечных циклов.

# Что такое digest cicle в angular?
<!-- basicblock-start  deck='A_angular' -->
Что такое digest cicle в angular?::


**Digest cycle** (цикл обработки или цикл "digest") в **AngularJS** — это процесс, в рамках которого фреймворк отслеживает изменения в данных и обновляет представление (view) на основе этих изменений. Когда происходит изменение в данных или состоянии приложения, Angular выполняет "цикл проверки" (digest cycle), чтобы проверить, нужно ли обновить DOM. Этот процесс лежит в основе механизма двухсторонней привязки данных (two-way data binding), который является одной из ключевых особенностей AngularJS.

### Как работает Digest Cycle?

1. **Модели и представления**:
   AngularJS связывает модели (данные, которые находятся в контроллерах или сервисах) с представлениями (HTML-шаблоны). Когда данные в модели изменяются, представление должно быть обновлено, чтобы отразить эти изменения.

2. **Изменение модели**:
   Когда какое-то значение модели изменяется (например, пользователь вводит данные в форму, происходит событие или асинхронная операция, например, HTTP-запрос), это может повлиять на отображение (view), и Angular должен обновить DOM.

3. **Запуск Digest Cycle**:
   Когда Angular обнаруживает изменение в модели, он инициирует **digest cycle**, чтобы проверить все биндинги данных и обновить соответствующие части DOM.

4. **Процесс работы Digest Cycle**:
   - Angular проходит по всем наблюдаемым значениям в приложении (обычно это значения в `scope` и модели) и проверяет, изменились ли они с момента последней проверки.
   - Этот процесс включает в себя серию "итераций" (или "проверок"), где Angular сравнивает текущее состояние значений с предыдущим состоянием. Это называется **dirty checking** — проверка "грязных" (измененных) значений.
   - Если значение изменилось, Angular обновляет DOM, чтобы отразить новые данные.
   - Если в процессе цикла обнаружены изменения, процесс может быть повторен еще раз (до нескольких итераций), чтобы убедиться, что все изменения были обработаны.

5. **Завершение цикла**:
   Цикл продолжается до тех пор, пока все наблюдаемые значения не будут проверены и DOM не будет обновлен. После завершения цикла, Angular снова готов отслеживать изменения и снова инициировать цикл при необходимости.

### Как это работает на практике?

#### Пример: 

Допустим, у нас есть простой контроллер, который обновляет модель, а Angular отслеживает изменения.

```
myApp.controller('ExampleController', function($scope) {
    $scope.message = "Hello, World!";

    $scope.updateMessage = function() {
        $scope.message = "Hello, Angular!";
    };
});
```

HTML-шаблон:

```
<div ng-controller="ExampleController">
    <p>{{ message }}</p>
    <button ng-click="updateMessage()">Change Message</button>
</div>
```

- Когда пользователь нажимает кнопку, вызывается метод `updateMessage`, который изменяет значение `message`.
- Angular автоматически отслеживает изменения в `message` и запускает digest cycle, чтобы обновить DOM и отобразить новое значение.

### Детали работы Digest Cycle:

1. **Dirty Checking**:
   - AngularJS использует механизм "dirty checking" для проверки изменений. Это значит, что фреймворк периодически проверяет (в цикле) все выражения и наблюдаемые значения (например, переменные в `$scope`) на предмет изменений.
   - Angular хранит предыдущие значения этих переменных и сравнивает их с текущими значениями. Если они отличаются, значит, произошли изменения.

2. **Процесс завершения цикла**:
   - Если во время одного прохода digest cycle были обнаружены изменения, то цикл повторяется (до 10 итераций по умолчанию), чтобы убедиться, что все изменения были учтены. Это делается для предотвращения "бесконечных циклов", если какая-то логика неправильно обновляет данные в процессе цикла.

3. **Производительность**:
   - Каждый раз, когда Angular выполняет цикл "digest", он проверяет все выражения и наблюдаемые значения, что может стать дорогим процессом, если в приложении много данных и сложных выражений.
   - Для улучшения производительности Angular предлагает такие механизмы, как `ng-model`, `ng-repeat` и оптимизированные директивы, которые минимизируют количество наблюдаемых значений.
