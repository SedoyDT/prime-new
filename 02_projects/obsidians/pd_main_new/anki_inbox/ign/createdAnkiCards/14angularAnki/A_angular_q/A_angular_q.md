Цепочку промисов можно создавать любой длины, и поскольку промис может быть разрешен другим промисом, цепочку можно приостановить или отложить на любой точке.

### Различия между **Q** и `$q`

Основные различия:

1. **Интеграция с моделью `$rootScope.Scope` в AngularJS**: Это означает более быстрое распространение разрешения или отклонения в модели и избегание лишних перерасчетов браузера (фликеринг UI).
2. **Функциональные различия**: Q имеет гораздо больше функций, чем `$q`, но это увеличивает размер библиотеки. `$q` компактный, но содержит все необходимые функции для решения большинства стандартных асинхронных задач.

### Пример тестирования

```
it('should simulate promise', inject(function($q, $rootScope) {
  var deferred = $q.defer();
  var promise = deferred.promise;
  var resolvedValue;

  promise.then(function(value) { resolvedValue = value; });
  expect(resolvedValue).toBeUndefined();

  // Симулируем разрешение промиса
  deferred.resolve(123);
  expect(resolvedValue).toBeUndefined();

  // Применяем $apply(), чтобы разрешение промиса дошло до 'then' функций
  $rootScope.$apply();
  expect(resolvedValue).toEqual(123);
}));
```

### Методы API `$q`

- **`defer()`** — Создает объект Deferred, который представляет задачу, которая завершится в будущем.
- **`reject(reason)`** — Создает отклоненный промис с указанной причиной.
- **`when(value, [successCallback], [errorCallback], [progressCallback])`** — Оборачивает значение или промис в `$q` промис.
- **`all(promises)`** — Объединяет несколько промисов в один, который будет разрешен, когда все промисы разрешатся.
- **`race(promises)`** — Создает промис, который будет разрешен или отклонен, как только один из промисов будет завершен.

### Заключение

`$q` является мощным инструментом для работы с асинхронным кодом в AngularJS. Он предоставляет интерфейс для работы с промисами, как в стиле **ES6**, так и через традиционный механизм `deferred`, который упрощает создание и управление асинхронными операциями.

# ### Обзор
<!-- basicblock-start  deck='A_angular_q' -->
### Обзор::


Сервис `$q` помогает вам запускать функции асинхронно и использовать их возвращаемые значения (или исключения), когда они завершат обработку.

Это реализация **Promise/A+** совместимых объектов промисов и deferred-объектов, вдохновленная библиотекой **Q** Криса Ковала.

### Два способа использования `$q`

`$q` можно использовать двумя способами — один из которых более похож на реализацию промисов и deferred-объектов в библиотеке **Q** или в **jQuery Deferred**, а другой имеет сходство с промисами в стандарте **ES6 (ES2015)**.

### Конструктор `$q`

Упрощенный стиль промисов, похожий на ES6, фактически использует `$q` как конструктор, который принимает функцию-резолвер в качестве первого аргумента. Это аналогично нативной реализации `Promise` в **ES6** (см. MDN).

Хотя поддержка использования конструктора есть, не все методы из стандарта ES6 для промисов доступны в `$q`.

Пример использования:

```
// Предположим, что переменные `$q` и `okToGreet` доступны в текущей области видимости.
function asyncGreet(name) {
  return $q(function(resolve, reject) {
    setTimeout(function() {
      if (okToGreet(name)) {
        resolve('Hello, ' + name + '!');
      } else {
        reject('Greeting ' + name + ' is not allowed.');
      }
    }, 1000);
  });
}

var promise = asyncGreet('Robin Hood');
promise.then(function(greeting) {
  alert('Success: ' + greeting);
}, function(reason) {
  alert('Failed: ' + reason);
});
```

### Примечания:
- **Callbacks для прогресса и уведомлений** не поддерживаются через интерфейс в стиле ES6.
- В отличие от поведения ES6, исключение, брошенное внутри функции-конструктора, **не** отклонит промис автоматически.

### Традиционное использование в стиле CommonJS

Традиционное использование API **Promise** через **`$q.defer()`** все еще доступно. Это основано на концепции **deferred-объектов**, которые позволяют отслеживать и управлять состоянием промиса. Пример использования:

```
function asyncGreet(name) {
  var deferred = $q.defer();

  setTimeout(function() {
    deferred.notify('About to greet ' + name + '.');

    if (okToGreet(name)) {
      deferred.resolve('Hello, ' + name + '!');
    } else {
      deferred.reject('Greeting ' + name + ' is not allowed.');
    }
  }, 1000);

  return deferred.promise;
}

var promise = asyncGreet('Robin Hood');
promise.then(function(greeting) {
  alert('Success: ' + greeting);
}, function(reason) {
  alert('Failed: ' + reason);
}, function(update) {
  alert('Got notification: ' + update);
});
```

### API `Deferred`

Новый экземпляр deferred создается с помощью `$q.defer()`. 

Цель deferred-объекта — предоставить API для управления состоянием асинхронной операции и возможности отслеживания ее результата.

**Методы**:

- `resolve(value)` — разрешает промис с переданным значением. Если значение — отклонение, созданное через `$q.reject()`, промис будет отклонен.
- `reject(reason)` — отклоняет промис с переданной причиной.
- `notify(value)` — предоставляет обновления состояния выполнения промиса. Этот метод можно вызывать несколько раз до того, как промис будет разрешен или отклонен.

**Свойства**:
- `promise` — объект промиса, связанный с этим deferred.

### API `Promise`

Новый объект промиса создается при вызове `deferred.promise`.

**Методы**:
- `then(successCallback, [errorCallback], [notifyCallback])` — вызывает один из обратных вызовов (`successCallback` или `errorCallback`) асинхронно, как только результат будет доступен. Обратный вызов `notifyCallback` может быть вызван несколько раз для предоставления уведомлений о прогрессе.
- `catch(errorCallback)` — сокращенная версия `promise.then(null, errorCallback)`.
- `finally(callback, notifyCallback)` — позволяет наблюдать за результатом промиса, не изменяя его финальное значение. Полезно для освобождения ресурсов или очистки, которая должна быть выполнена, независимо от того, был ли промис разрешен или отклонен.

### Цепочка промисов

Так как вызов метода `then` промиса возвращает новый производный промис, легко создать цепочку промисов:

```
promiseB = promiseA.then(function(result) {
  return result + 1;
});
```

# Что делает $q.defer?
<!-- basicblock-start  deck='A_angular_q' -->
Что делает $q.defer?::


В AngularJS `$q.defer()` — это метод, используемый для создания и управления обещаниями (Promises). Он позволяет вам вручную управлять состоянием обещания (решение или отклонение) в асинхронных операциях.

Когда вы используете `$q.defer()`, вы получаете объект, состоящий из трех основных частей:

1. **`promise`** — объект, который представляет само обещание. Этот объект может быть передан в другие части кода, которые будут ожидать его разрешения или отклонения.
2. **`resolve(value)`** — метод, который используется для выполнения (разрешения) обещания. Когда обещание разрешается, оно переходит в состояние "выполнено" с переданным значением `value`.
3. **`reject(reason)`** — метод, который используется для отклонения обещания. Когда обещание отклоняется, оно переходит в состояние "не выполнено" с переданным значением `reason`.

### Пример использования `$q.defer()`:

```
var deferred = $q.defer();  // Создаем объект defer

// Функция, которая выполняет асинхронную операцию
function asyncOperation() {
    setTimeout(function() {
        var success = true;  // Это просто пример, у вас может быть любая логика
        if (success) {
            deferred.resolve('Операция завершена успешно!');  // Разрешаем обещание
        } else {
            deferred.reject('Произошла ошибка');  // Отклоняем обещание
        }
    }, 1000);
}

// Использование promise
asyncOperation();
deferred.promise.then(function(result) {
    console.log('Успех: ' + result);  // Если promise разрешено
}, function(error) {
    console.log('Ошибка: ' + error);  // Если promise отклонено
});
```

### Важные моменты:
- **`$q.defer()`** используется для ручного контроля за выполнением обещания, что может быть полезно в сложных асинхронных операциях, когда нужно решить или отклонить обещание в зависимости от результата.
- Когда вы вызываете `deferred.promise`, вы получаете обычный promise-объект, который можно использовать с методами `.then()`, `.catch()` и `.finally()` для обработки результатов или ошибок.

### Почему использовать `$q.defer()`?
- В AngularJS `$q.defer()` предоставляет гибкость в асинхронной логике, позволяя вам в любой момент разрешить или отклонить обещание, а не только в момент его создания, как это происходит с обычными Promise.
- Это особенно полезно, если вам нужно работать с внешними API или асинхронными операциями, результат которых может быть доступен не сразу.

Однако стоит отметить, что в более современных версиях JavaScript (например, в ES6 и выше) используются стандартные `Promise` и синтаксис async/await, который более удобен и рекомендуется для новых проектов.

# что такое $$state в $q.resolve()
<!-- basicblock-start  deck='A_angular_q' -->
что такое $$state в $q.resolve()::


В AngularJS, `$$state` — это внутренний объект, который используется для отслеживания состояния промиса в библиотеке `$q`. Он содержит информацию о текущем состоянии промиса, таком как его состояние (resolved, rejected) и причины этого состояния.

### Контекст `$$state` в `$q`

Каждый промис, создаваемый через `$q`, имеет скрытое (внутреннее) свойство `$$state`, которое позволяет AngularJS отслеживать, был ли промис разрешён или отклонён, и если отклонён, то с какой причиной.

**Важно:** `$$state` — это не то, что вам нужно использовать напрямую в коде. Это внутренний механизм, который используется библиотекой `$q` для управления состоянием промисов.

Однако, знание о нем может быть полезно для более глубокого понимания того, как работает система промисов в AngularJS.

### Структура `$$state`

Объект `$$state` имеет следующие основные свойства:

1. **`status`** — содержит информацию о том, разрешён ли промис (`status === 1`), отклонён ли (`status === 2`) или ещё не завершён (`status === 0`).

   - `0`: Промис в процессе выполнения, не завершён.
   - `1`: Промис был разрешён.
   - `2`: Промис был отклонён.

2. **`value`** — если промис был разрешён, это значение будет хранить результат выполнения промиса. Если промис был отклонён, здесь будет причина отклонения.

3. **`reason`** — если промис был отклонён, это поле будет содержать причину отклонения.

4. **`pending`** — это флаг, который указывает на то, ожидает ли промис выполнения (если равен `true` — он ещё не завершён, если `false` — промис завершён).

### Пример:

Чтобы показать, как работает `$$state`, давайте рассмотрим пример:

```
var app = angular.module('myApp', []);

app.controller('MainController', function($scope, $q) {
    // Создаём новый промис с использованием $q.resolve
    var promise = $q.resolve('Success!');

    // Делаем вывод на консоль состояния промиса
    promise.then(function(result) {
        console.log('Promise resolved with:', result);  // 'Success!'
        console.log('Promise $$state:', promise.$$state);  // Печать состояния
    });

    // Пример отклонённого промиса
    var rejectedPromise = $q.reject('Something went wrong!');

    rejectedPromise.catch(function(error) {
        console.log('Promise rejected with:', error);  // 'Something went wrong!'
        console.log('Rejected Promise $$state:', rejectedPromise.$$state);  // Печать состояния отклонённого промиса
    });
});
```

### Объяснение:

- В случае с `promise`, который был разрешён через `$q.resolve()`, состояние `$$state` будет отражать разрешённое состояние промиса и содержать результат `'Success!'`.
- В случае с `rejectedPromise`, который был отклонён через `$q.reject()`, состояние `$$state` будет отражать отклонённое состояние и содержать причину отклонения `'Something went wrong!'`.

### Когда вам нужно использовать `$$state`?

Для большинства случаев в обычных приложениях AngularJS вы не должны работать с `$$state` напрямую. Все необходимые операции по отслеживанию состояния промиса можно выполнить через методы `.then()`, `.catch()`, или `.finally()`.

Однако, если вам нужно получить внутреннюю информацию о промисе или дебажить его состояние, то доступ к `$$state` может быть полезен. Например, это может быть полезно при тестировании, отладке или если вам нужно наблюдать за состоянием промиса более детально.

### Заключение:

`$$state` — это внутренний объект, который используется в библиотеке `$q` для хранения состояния промиса в AngularJS. Он отслеживает, был ли промис разрешён, отклонён или всё ещё находится в ожидании. Обычно вам не нужно работать с `$$state` напрямую, так как все основные операции с промисами можно обрабатывать через стандартные методы `.then()`, `.catch()`, и `.finally()`.

# Что такое ресолвенный promise
<!-- basicblock-start  deck='A_angular_q' -->
Что такое ресолвенный promise::


**Ресолвенный (resolved) промис** — это промис, который был успешно выполнен и завершён с результатом. В терминах JavaScript, когда промис "ресолвится", это означает, что операция завершена с успехом, и промис переходит в состояние **fulfilled** (выполнен). В результате промис возвращает некоторое значение, которое может быть использовано в дальнейшем с помощью метода `.then()`.

### Статусы промиса:

1. **Pending (Ожидающий)**: Промис ещё не завершён, операция всё ещё выполняется.
2. **Resolved (Решённый или Выполненный)**: Промис успешно завершён и возвращает результат.
3. **Rejected (Отклонённый)**: Промис не смог выполнить операцию и был отклонён, вернув причину ошибки.

Когда промис "ресолвится", он переходит из состояния "pending" в состояние "resolved" (или "fulfilled") и передает значение в обработчик успеха, переданный в `.then()`.

### Пример работы с "ресолвенным" промисом:

```
// Создание промиса с успешным выполнением
let promise = new Promise(function(resolve, reject) {
    let success = true;
    if (success) {
        resolve('Операция завершена успешно');  // Ресолвим промис с результатом
    } else {
        reject('Что-то пошло не так');  // Если операция не успешна, отклоняем промис
    }
});

// Обработка успешного завершения промиса
promise.then(function(result) {
    console.log(result);  // Выведет: 'Операция завершена успешно'
}).catch(function(error) {
    console.error(error);  // Если промис отклонён, выведет ошибку
});
```

### Объяснение:

- В данном примере промис будет "ресолвиться", потому что условие `success` истинно.
- Как только промис разрешается, метод `.then()` получает результат (строку `'Операция завершена успешно'`) и выводит его в консоль.
  
### Как работает `$q.resolve()`:

В AngularJS `$q.resolve()` создаёт **ресолвенный** промис, который немедленно возвращает заданное значение. Этот метод полезен, когда вам нужно сразу получить готовое значение, обёрнутое в промис.

Пример использования `$q.resolve()`:

```
var app = angular.module('myApp', []);

app.controller('MainController', function($scope, $q) {
    // Создание промиса, который сразу же решается с результатом
    var resolvedPromise = $q.resolve('Решённый промис');

    resolvedPromise.then(function(result) {
        console.log(result);  // Выведет: 'Решённый промис'
    });
});
```

### Разница между "resolved" и "rejected" промисами:

- **Resolved промис** — это промис, который был успешно выполнен. Это означает, что операция завершилась без ошибок, и в промис передано значение.
- **Rejected промис** — это промис, который не смог выполнить операцию и был отклонён. В случае отклонения промис передает причину ошибки.

Пример отклонённого промиса:

```
let promise = new Promise(function(resolve, reject) {
    let success = false;
    if (success) {
        resolve('Операция выполнена');
    } else {
        reject('Ошибка при выполнении операции');
    }
});

promise.then(function(result) {
    console.log(result);
}).catch(function(error) {
    console.error(error);  // Выведет: 'Ошибка при выполнении операции'
});
```

### Заключение:

**Ресолвенный промис** — это промис, который был успешно выполнен и завершён с результатом, передаваемым через `resolve(value)`. Он переходит в состояние "fulfilled", и значение передается в обработчик `.then()`. Ресолвенные промисы широко используются для работы с асинхронными операциями, где результат успешной операции возвращается через промис.
