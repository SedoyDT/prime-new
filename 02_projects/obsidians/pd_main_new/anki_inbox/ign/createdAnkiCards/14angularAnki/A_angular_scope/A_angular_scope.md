# Что делает $scope.apply?
<!-- basicblock-start  deck='A_angular_scope' -->
Что делает $scope.apply?::


Метод `$scope.$apply()` в AngularJS используется для того, чтобы инициировать процесс **обновления привязанных данных** и **перерисовки интерфейса**.

Когда вы изменяете значение переменной в AngularJS, интерфейс не всегда сразу обновляется. AngularJS отслеживает изменения в моделях через механизм **диффа** (например, через **`ng-model`** или **двустороннюю привязку**), но он это делает только в определённые моменты времени — во время циклов обработки событий или асинхронных операций, таких как запросы к серверу, `setTimeout`, `setInterval` и так далее.

### Когда это нужно?

Если вы выполняете изменения, которые происходят **вне зоны отслеживания AngularJS**, например, в асинхронных функциях, таких как обработка событий браузера (например, через `window.onpopstate`), то AngularJS может не заметить эти изменения. В таких случаях, чтобы уведомить AngularJS о том, что данные изменились, необходимо вызвать `$scope.$apply()`. Это заставляет AngularJS выполнить цикл обнаружения изменений и обновить DOM.

### Пример использования `$scope.$apply()`:

Предположим, у нас есть обработчик событий, который изменяет модель за пределами AngularJS (например, при изменении состояния с помощью браузерного события).

```
window.onpopstate = function(event) {
    if (event.state) {
        $scope.state = event.state;
        $scope.$apply();  // Явно вызываем apply, чтобы обновить модель и перерисовать UI
    }
};
```

Здесь, поскольку событие `onpopstate` не является частью AngularJS, необходимо вручную вызвать `$scope.$apply()`, чтобы AngularJS заметил изменения и обновил UI.

### Как работает `$apply()`?

1. **Запускает цикл обнаружения изменений**: При вызове `$apply()` AngularJS запускает процесс **обнаружения изменений** (digest cycle). Этот цикл проверяет все привязанные модели и обновляет DOM, если необходимо.
   
2. **Инициализация функций и методов**: Внутри `$apply()` AngularJS вызывает функцию, переданную в качестве аргумента, а затем обрабатывает все связанные модели и их изменения. Например, можно передать функцию, которая будет изменять состояние модели:

    ```
    $scope.$apply(function() {
        $scope.state = newState;
    });
    
```

3. **Обновление DOM**: После выполнения циклов Angular обновит DOM, если данные были изменены.

### Стоит ли всегда использовать `$scope.$apply()`?

Нет, `$apply()` следует использовать только тогда, когда вы работаете с асинхронным кодом или событиями, которые происходят вне зоны AngularJS. В большинстве случаев, если вы используете AngularJS-директивы, такие как `ng-click`, `ng-model` и другие, Angular автоматически отслеживает изменения и обновляет интерфейс без необходимости вручную вызывать `$apply()`.

### Пример без `$apply()` (обычные события):

```
<button ng-click="incrementCounter()">Increment</button>
```

```
$scope.incrementCounter = function() {
    $scope.counter++;  // Angular отслеживает это изменение автоматически
};
```

В этом случае не требуется `$apply()`, потому что изменение происходит внутри AngularJS.

### Заключение:

- **`$scope.$apply()`** используется для принудительного запуска цикла обнаружения изменений и обновления интерфейса, когда изменения происходят вне зоны отслеживания AngularJS.
- В большинстве случаев, при работе с AngularJS, этого не требуется, так как Angular сам отслеживает изменения в данных и обновляет интерфейс, но для асинхронных операций или внешних событий нужно вызвать `$apply()`.

# Что можно сказать про глубину отслеживания $scope?
<!-- basicblock-start  deck='A_angular_scope' -->
Что можно сказать про глубину отслеживания $scope?::


**Глубина отслеживания $scope**

Проверка изменений может выполняться тремя стратегиями: по ссылке, по содержимому коллекции и по значению. Эти стратегии различаются по типам изменений, которые они могут обнаружить, и по характеристикам производительности.

- **Отслеживание по ссылке** (`scope.$watch(watchExpression, listener)`) обнаруживает изменения, когда всё значение, возвращаемое выражением для отслеживания, меняется на новое. Если значение — это массив или объект, изменения внутри них не отслеживаются. Это самая эффективная стратегия.
  
- **Отслеживание содержимого коллекции** (`scope.$watchCollection(watchExpression, listener)`) обнаруживает изменения, происходящие внутри массива или объекта: когда элементы добавляются, удаляются или переупорядочиваются. Это поверхностная проверка — она не проникает в вложенные коллекции. Отслеживание содержимого коллекции более затратное, чем отслеживание по ссылке, так как необходимо поддерживать копии содержимого коллекции. Однако эта стратегия старается минимизировать количество необходимых копий.

- **Отслеживание по значению** (`scope.$watch(watchExpression, listener, true)`) обнаруживает любое изменение в произвольно вложенной структуре данных. Это самая мощная стратегия обнаружения изменений, но и самая дорогая. Для каждой «дигест-сессии» необходимо полностью пройти по всей вложенной структуре данных, и она должна быть полностью скопирована в память.

# Что можно сказать про Директивы, создающие области видимости?
<!-- basicblock-start  deck='A_angular_scope' -->
Что можно сказать про Директивы, создающие области видимости?::


### **Директивы, создающие области видимости**

В большинстве случаев **директивы** и **области видимости** взаимодействуют, но не создают новые экземпляры области видимости. Однако некоторые директивы, такие как `ng-controller` и `ng-repeat`, **создают новые дочерние области видимости** и прикрепляют эту дочернюю область к соответствующему **DOM-элементу**.

#### **Особые типы областей видимости:**

1. **Дочерние области видимости:**
   - Некоторые директивы, например `ng-controller` и `ng-repeat`, создают **дочерние области видимости**. Дочерняя область видимости — это новая область, которая **наследуется** от родительской области, но при этом имеет свои собственные переменные и свойства.
   - Эти дочерние области видимости могут наследовать данные и методы от родительской области, но также могут определять свои собственные переменные, не влияя на родительскую область.

2. **Изолированная область видимости:**
   - **Изолированная область видимости** — это особый тип области видимости, которая не наследует свойства от родительской области видимости через прототип. Это полезно для **компонентных директив**, которые должны быть изолированы от своей родительской области.
   - Подробнее о изолированных областях видимости можно узнать в руководстве по директивам для пользовательских директив.

3. **Компонентные директивы:**
   - Также стоит отметить, что директивы, создаваемые с помощью помощника `.component()`, всегда создают **изолированную область видимости**.

# Что можно сказать про контроллеры области видимости?
<!-- basicblock-start  deck='A_angular_scope' -->
Что можно сказать про контроллеры области видимости?::


### **Контроллеры и области видимости (Scopes)**

Контроллеры и области видимости взаимодействуют друг с другом в следующих ситуациях:

1. **Контроллеры используют области видимости**, чтобы предоставлять методы контроллеров для шаблонов (например, через `ng-controller`).
2. **Контроллеры определяют методы (поведение)**, которые могут изменять модель (свойства на области видимости).
3. **Контроллеры могут регистрировать наблюдатели (watchers) на модели**. Эти наблюдатели выполняются сразу после того, как будет выполнено поведение контроллера.

Дополнительную информацию можно найти в документации по `ng-controller`.

---

### **Директивы, создающие области видимости**

В большинстве случаев директивы и области видимости взаимодействуют, но не создают новые экземпляры области видимости. Однако некоторые директивы, такие как `ng-controller` и `ng-repeat`, создают новые дочерние области видимости и прикрепляют эту область к соответствующему DOM-элементу.

Особым типом области видимости является **изолированная область видимости** (isolate scope), которая не наследует свойства от родительской области видимости прототипически. Этот тип области видимости полезен для компонентных директив, которые должны быть изолированы от родительской области видимости. Дополнительную информацию об изолированных областях видимости можно найти в руководстве по директивам.

Также стоит отметить, что компонентные директивы, создаваемые с помощью помощника `.component()`, всегда создают изолированную область видимости.

# Что можно сказать про жизненный цикл $scope в angular js?
<!-- basicblock-start  deck='A_angular_scope' -->
Что можно сказать про жизненный цикл $scope в angular js?::


### Жизненный цикл Scope в AngularJS

Нормальный процесс обработки события в браузере следующий: браузер получает событие и выполняет соответствующий JavaScript-обработчик. После завершения обработчика браузер заново рендерит DOM и снова ожидает новые события.

Когда браузер вызывает JavaScript, код выполняется вне контекста выполнения AngularJS, что означает, что AngularJS не знает об изменениях в модели. Чтобы правильно обработать изменения модели, выполнение должно попасть в контекст AngularJS с помощью метода `$apply`. Только изменения модели, выполняющиеся внутри метода `$apply`, будут правильно учтены AngularJS. Например, если директива слушает события DOM, такие как `ng-click`, она должна оценить выражение внутри метода `$apply`.

После того как выражение будет оценено, метод `$apply` выполняет цикл `$digest`. На фазе `$digest` scope проверяет все выражения `$watch` и сравнивает их с предыдущими значениями. Эта проверка изменений (dirty checking) выполняется асинхронно. Это означает, что присваивание, такое как `$scope.username = "angular"`, не вызовет немедленное уведомление `$watch`. Вместо этого уведомление `$watch` откладывается до фазы `$digest`. Такое задерживание уведомлений желательно, поскольку оно объединяет несколько обновлений модели в одно уведомление `$watch` и гарантирует, что во время уведомления `$watch` другие `$watch`-наблюдатели не будут работать. Если `$watch` изменяет значение модели, это вызовет дополнительный цикл `$digest`.

---

### Этапы жизненного цикла Scope

1. **Создание Scope**  
   Корневой scope создается во время инициализации приложения с помощью `$injector`. Во время связывания шаблона (template linking) некоторые директивы создают новые дочерние scopes.

2. **Регистрация Watcher**  
   Во время связывания шаблона директивы регистрируют наблюдатели (watches) на scope. Эти наблюдатели используются для распространения значений модели в DOM.

3. **Мутация модели**  
   Чтобы мутации модели правильно отслеживались, они должны выполняться только внутри `$scope.$apply()`. API AngularJS делает это неявно, поэтому дополнительный вызов `$apply` не требуется при синхронной работе в контроллерах или асинхронной работе с сервисами `$http`, `$timeout` или `$interval`.

4. **Наблюдение за мутациями**  
   В конце выполнения `$apply` AngularJS выполняет цикл `$digest` на корневом scope, который затем распространяется по всем дочерним scopes. Во время цикла `$digest` проверяются все выражения или функции, находящиеся под наблюдением `$watch`. Если обнаружена мутация, вызывается слушатель `$watch`.

5. **Уничтожение Scope**  
   Когда дочерние scopes больше не нужны, ответственность за их уничтожение лежит на создателе дочернего scope. Для этого используется метод API `scope.$destroy()`. Это остановит распространение вызовов `$digest` в дочерний scope и позволит сборщику мусора освободить память, используемую моделями дочернего scope.

--- 

Таким образом, жизненный цикл scope в AngularJS представляет собой комплексный процесс, включающий создание, регистрацию наблюдателей за изменениями данных, выполнение циклов проверки изменений, а также очистку памяти и уничтожение дочерних scopes. Все эти этапы играют важную роль в управлении состоянием приложения и обновлении DOM.

# 2. **Когда вы нажимаете на кнопку `$broadcast('MyEvent')` в любом дочернем элементе:**
<!-- basicblock-start  deck='A_angular_scope' -->
2. **Когда вы нажимаете на кнопку `$broadcast('MyEvent')` в любом дочернем элементе:**::

   - Событие отправляется **вниз** ко всем потомкам. Если у вас есть другие контроллеры в дочерних элементах, которые слушают это событие, их `count` увеличится.
   - Событие **не поднимется** вверх, и родительский элемент не получит это событие, если только он не подпишется на его обработку.

### Резюме:

- **`$emit`**: отправляет событие **вверх** по дереву DOM (от дочернего элемента к родительскому).
- **`$broadcast`**: отправляет событие **вниз** по дереву DOM (от родительского элемента к дочерним).

Таким образом, `$emit` и `$broadcast` позволяют организовать взаимодействие между контроллерами в AngularJS с помощью событий, передаваемых между ними, но в разных направлениях: вверх и вниз по дереву DOM.

# Как работает scope events propagation?
<!-- basicblock-start  deck='A_angular_scope' -->
Как работает scope events propagation?::


```
<div ng-controller="EventController">
  Root scope <tt>MyEvent</tt> count: {{count}}
  <ul>
    <li ng-repeat="i in [1]" ng-controller="EventController">
      <button ng-click="$emit('MyEvent')">$emit('MyEvent')</button>
      <button ng-click="$broadcast('MyEvent')">$broadcast('MyEvent')</button>
      <br>
      Middle scope <tt>MyEvent</tt> count: {{count}}
      <ul>
        <li ng-repeat="item in [1, 2]" ng-controller="EventController">
          Leaf scope <tt>MyEvent</tt> count: {{count}}
        </li>
      </ul>
    </li>
  </ul>
</div>
```

```


angular.module('eventExample', [])
.controller('EventController', ['$scope', function($scope) {
  $scope.count = 0;
  $scope.$on('MyEvent', function() {
    $scope.count++;
  });
}]);
```

Да, вы правильно понимаете принцип работы директив `$emit` и `$broadcast` в AngularJS. Давайте подробно разберём их поведение в контексте вашего примера.

### 1. **`$emit`** — событие распространяется **вверх** по дереву DOM

Метод `$emit` используется для того, чтобы **отправить событие от текущего элемента вверх** по дереву DOM, начиная с того элемента, на котором был вызван `$emit`, и до самого верхнего элемента, который может его перехватить (например, корневого элемента приложения или родительских контроллеров).

В вашем примере, если вы нажмете на кнопку с `$emit('MyEvent')` в любом из дочерних элементов, событие будет отправлено к родительскому элементу и обработано им (например, в корневом контроллере `EventController`).

### 2. **`$broadcast`** — событие распространяется **вниз** по дереву DOM

Метод `$broadcast` используется для того, чтобы **отправить событие ко всем потомкам** текущего элемента, т.е. события, вызванные `$broadcast`, "распространяются" вниз, в дочерние элементы.

В вашем примере, если вы нажмете на кнопку с `$broadcast('MyEvent')`, это событие будет передано всем потомкам элемента, в том числе вложенным контроллерам, и они смогут его обработать, если настроены на его перехват.

### Пример:

В вашем примере:
- **Корневой контроллер** (`ng-controller="EventController"`) будет слушать события, отправленные с помощью `$emit`.
- **Средний элемент** (например, первый элемент в `ng-repeat`) использует `$broadcast` для распространения событий в более низкие уровни DOM.

Когда происходит событие `$emit('MyEvent')`, оно поднимется от того элемента, где было вызвано, до самого верхнего уровня. Если это событие обрабатывается в корневом контроллере, то он может увеличивать счётчик `count`, а дочерние элементы не затронутся.

Когда происходит событие `$broadcast('MyEvent')`, оно будет отправлено вглубь DOM, ко всем потомкам текущего элемента. Если потомки настроены на обработку этого события, их счётчик `count` будет увеличен.

### Пример исправленного кода с пояснениями:

```
<div ng-controller="EventController">
  Root scope <tt>MyEvent</tt> count: {{count}}
  <ul>
    <li ng-repeat="i in [1]" ng-controller="EventController">
      <button ng-click="$emit('MyEvent')">Emit 'MyEvent'</button>
      <button ng-click="$broadcast('MyEvent')">Broadcast 'MyEvent'</button>
      <br>
      Middle scope <tt>MyEvent</tt> count: {{count}}
      <ul>
        <li ng-repeat="item in [1, 2]" ng-controller="EventController">
          Leaf scope <tt>MyEvent</tt> count: {{count}}
        </li>
      </ul>
    </li>
  </ul>
</div>
```

### Контроллер `EventController`:

```
angular.module('myApp', [])
  .controller('EventController', ['$scope', function($scope) {
    $scope.count = 0;

    // Слушаем событие "MyEvent" на уровне корневого контроллера
    $scope.$on('MyEvent', function() {
      $scope.count++;  // Увеличиваем счётчик при получении события
    });
  }]);
```

### Поведение:
1. **Когда вы нажимаете на кнопку `$emit('MyEvent')` в любом дочернем элементе:**
   - Событие отправляется **вверх**, и обработчик в родительском контроллере или на уровне корня получает событие и увеличивает `count`.
   - Событие **не влияет на потомков**, поскольку оно не будет распространяться вниз по дереву DOM.

# Что можно сказать про иерархию scope?
<!-- basicblock-start  deck='A_angular_scope' -->
Что можно сказать про иерархию scope?::


Каждое приложение AngularJS имеет ровно одну корневую область, но может иметь любое количество дочерних областей.

Приложение может иметь несколько областей действия, поскольку директивы могут создавать новые дочерние области. При создании новых областей они добавляются как дочерние элементы родительской области. Это создает древовидную структуру, параллельную DOM, к которому они прикреплены.

В разделе «Директивы, создающие области» содержится дополнительная информация о том, какие директивы создают области.

Когда AngularJS оценивает {{name}}, он сначала проверяет область действия, связанную с данным элементом для свойства name. Если такое свойство не найдено, выполняется поиск в родительской области и так далее, пока не будет достигнута корневая область. В JavaScript такое поведение известно как прототипическое наследование, и дочерние области прототипно наследуются от своих родителей.

Этот пример иллюстрирует области применения и прототипное наследование свойств. За примером следует диаграмма, изображающая границы области действия.

# Как работает двухсторонее связывание на примере $scope ?
<!-- basicblock-start  deck='A_angular_scope' -->
Как работает двухсторонее связывание на примере $scope ?::


```


angular.module('scopeExample', [])
.controller('MyController', ['$scope', function($scope) {
  $scope.username = 'World';

  $scope.sayHello = function() {
    $scope.greeting = 'Hello ' + $scope.username + '!';
  };
}]);
```

Давайте разберем этот отрывок и переведем его на русский, а также объясним его смысл.

### Перевод:
В приведенном примере обратите внимание, что контроллер **MyController** присваивает строку `"World"` свойству `username` на `$scope`. Это свойство затем уведомляет привязанный к нему элемент ввода, и результатом будет то, что поле ввода будет предварительно заполнено значением `username`. Это демонстрирует, как контроллер может записывать данные в `$scope`.

Точно так же, контроллер может назначить поведение на `$scope`, как показано в методе `sayHello`, который вызывается, когда пользователь нажимает на кнопку "greet". Метод `sayHello` может прочитать свойство `username` и создать новое свойство `greeting`. Это демонстрирует, что свойства на `$scope` автоматически обновляются, когда они привязаны к элементам ввода в HTML.

Логически рендеринг выражения `{{greeting}}` включает:

1. Получение `$scope`, связанного с DOM-узлом, где в шаблоне определено `{{greeting}}`. В данном примере это тот же самый `$scope`, который был передан в контроллер **MyController** (мы подробнее обсудим иерархию `$scope` позже).
2. Оценка выражения `greeting` относительно полученного `$scope` и присвоение результата тексту содержащего элемента DOM.

Можно считать `$scope` и его свойства данными, которые используются для рендеринга представления. `$scope` является единственным источником правды для всего, что связано с представлением.

С точки зрения тестируемости, разделение контроллера и представления желательно, потому что оно позволяет тестировать поведение без отвлечения на детали рендеринга.

### Объяснение:

Этот отрывок объясняет принцип работы **двусторонней привязки данных** в AngularJS, а также роль **`$scope`** в этом процессе. 

#### Основные моменты:
1. **`$scope` как источник данных:**
   В AngularJS контроллеры управляют данными, которые затем привязываются к элементам в представлении (HTML). Все данные, которые контроллер записывает в `$scope`, становятся доступными для представления через привязку данных (например, с помощью выражений `{{propertyName}}`).

2. **Двусторонняя привязка:**
   Когда контроллер присваивает значение свойству на `$scope` (например, `username = 'World'`), это значение автоматически отображается в связанный с ним элемент ввода в HTML. В обратную сторону — если пользователь изменит значение в поле ввода, то `$scope.username` также обновится.

3. **Рендеринг с использованием выражений:**
   Когда AngularJS отображает значение в представлении с помощью выражений, таких как `{{greeting}}`, AngularJS делает следующее:
   - Он находит правильный `$scope`, который привязан к данному участку DOM (например, элементу с `{{greeting}}`).
   - Затем вычисляется выражение (например, создание строки приветствия) и это значение выводится в элемент.

4. **Изоляция логики и представления:**
   Разделение логики (контроллер) и представления (HTML) полезно с точки зрения тестируемости. Логику можно тестировать независимо от того, как она отображается в представлении, что упрощает написание тестов.

5. **Роль `$scope`:**
   `$scope` в AngularJS — это объект, который используется для хранения данных, доступных как контроллеру, так и представлению. Можно рассматривать его как "единственный источник правды" для всех данных, которые будут использованы в представлении.

#### Тестируемость:
Когда вы разделяете логику и рендеринг, вам становится легче тестировать поведение вашего приложения. Вы можете написать тесты для контроллера, проверяя его логику (например, создание приветственного сообщения), без необходимости беспокоиться о том, как это сообщение отображается в HTML.

# Каковы характеристики scope?
<!-- basicblock-start  deck='A_angular_scope' -->
Каковы характеристики scope?::


Области предоставляют API ($watch) для наблюдения за изменениями модели.

Области предоставляют API ($apply) для распространения любых изменений модели через систему в представление за пределами «области AngularJS» (контроллеры, службы, обработчики событий AngularJS).

Области могут быть вложенными, чтобы ограничить доступ к свойствам компонентов приложения, одновременно обеспечивая доступ к общим свойствам модели. Вложенные области являются либо «дочерними областями», либо «изолированными областями». «Дочерняя область» (прототипически) наследует свойства родительской области. «Изолировать область» этого не делает. Дополнительные сведения см. в разделе изолированные области.

Области предоставляют контекст, в соответствии с которым оцениваются выражения. Например, выражение {{username}} не имеет смысла, если оно не оценивается по определенной области, которая определяет свойство имени пользователя.
