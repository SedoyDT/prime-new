**Чем отличается команда composer install от composer update ?**::

*Спросят с вероятностью 7%*

**composer install и composer update** — это две команды в системе управления зависимостями Composer, которые используются для управления пакетами. Они имеют разные цели и поведение.

**composer install**

1️⃣**Установка зависимостей**:
✅Команда `composer install` используется для установки всех зависимостей, указанных в файле `composer.json`, согласно точным версиям, зафиксированным в файле `composer.lock`.

2️⃣**Работа с `composer.lock`**:
✅Если файл `composer.lock` существует, `composer install` установит версии зависимостей именно из этого файла. Это гарантирует, что установка будет идентичной на всех машинах и в средах, где выполняется эта команда.
✅Если файла `composer.lock` нет, `composer install` сначала разрешит зависимости согласно правилам в `composer.json` и создаст `composer.lock` файл с фиксированными версиями для последующих установок.

3️⃣**Типичные сценарии использования**:
✅Первый запуск в новом окружении после клонирования репозитория.
✅Развертывание проекта в новой среде (например, на сервере).
✅Обеспечение консистентности версий зависимостей в команде разработчиков.
```
composer install
```

**composer update**

1️⃣**Обновление зависимостей**:
✅Команда `composer update` обновляет все зависимости до их последних версий, соответствующих правилам, заданным в `composer.json`.

2️⃣**Обновление**`mposer.lock` файл 
✅После выполнения команды `composer update`, файл `composer.lock` обновляется с новыми версиями пакетов. Эти изменения затем можно зафиксировать в системе контроля версий (например, git) для распространения среди других разработчиков или сред развертывания.

3️⃣**Управление обновлениями**:
✅Команду можно использовать для обновления всех зависимостей или только конкретных пакетов.

4️⃣**Типичные сценарии использования**:
✅Обновление зависимостей до последних версий для получения новых функций или исправлений.
✅Обновление отдельных пакетов по мере необходимости.

**Пример:**
```
composer update
# Или для конкретного пакета
composer update vendor/package
```

**Краткое резюме**

✅**`composer install`**: Устанавливает зависимости согласно зафиксированным версиям в `composer.lock`. Используется для обеспечения стабильности и консистентности версий зависимостей.
✅**`composer update`**: Обновляет зависимости до их последних версий, разрешённых `composer.json`, и обновляет `composer.lock`. Используется для получения новых версий пакетов.

Эти команды играют ключевую роль в управлении зависимостями, обеспечивая гибкость и стабильность разработки.
