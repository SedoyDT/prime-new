Что такое многоуровневая архитектура в корпоративных приложениях?::  
🧱 Это разделение кода на уровни:
1️⃣ **Presentation Layer** — HTML, JSON, CLI интерфейсы  
2️⃣ **Command & Controller Layer** — маршруты, команды, логика вызова  
3️⃣ **Application Logic Layer** — бизнес-логика, обработка данных  
4️⃣ **Data Layer** — работа с БД, файлами, внешними API  

🫶 Такое деление позволяет:
- упрощать тестирование  
- повышать гибкость  
- легко добавлять новые модули  
🎯 Главное преимущество: *изменение одного уровня не влияет на другой.*

Как работает шаблон Registry?::  
🟩 Это глобальное хранилище данных текущего процесса.  
🫶 Позволяет получать доступ к объектам типа: соединение с БД, конфигурация, логгер.  
🟨 Пример:
```php
class Registry {
    private static $instance;
    private $values = [];

    public static function instance(): Registry { ... }

    public function set(string $key, $value): void { ... }
    public function get(string $key) { ... }
}
```
🎯 Используется как контейнер зависимостей.  
⚠️ Недостаток: создаёт скрытые зависимости → сложности с тестированием.

<!-- basicblock-start oid="ObsYHPq5BJ3yNWsu0byYUiQq" deck='php-enterprise-patterns' -->
Как использовать Front Controller в PHP?::  
🟦 Единая точка входа для всех HTTP-запросов.  
🫶 Обрабатывает маршруты, вызывает контроллеры, выбирает представление.  
🟨 Пример:
```php
class FrontController {
    public function handleRequest(string $controllerName, string $actionName) {
        $controllerClass = ucfirst($controllerName) . 'Controller';
        if (!class_exists($controllerClass)) { throw new Exception("Controller not found"); }

        $controller = new $controllerClass();
        if (!method_exists($controller, $actionName)) { throw new Exception("Action not found"); }

        $controller->$actionName();
    }
}
```
🎯 Плюсы:
- Централизованная логика  
- Легче добавлять логгирование и авторизацию  
💡 Идеально для крупных проектов.  
<!-- basicblock-end -->

<!-- basicblock-start oid="ObsSbdqbNla6gqk2NLOqGgZc" deck='php-enterprise-patterns' -->
Как использовать Template View для отображения данных?::  
🟨 Шаблон, который отделяет данные от отображения.  
🫶 Позволяет рендерить HTML/JSON через переменные.  
🟨 Пример:
```php
class TemplateView {
    private $template;
    private $data = [];

    public function assign(string $key, $value): void {
        $this->data[$key] = $value;
    }

    public function render(): string {
        extract($this->data);
        ob_start();
        include $this->template;
        return ob_get_clean();
    }
}
```
🎯 Использование:
```php
$view = new TemplateView();
$view->setTemplate('event_list.php');
$view->assign('events', $eventModel->getAll());
echo $view->render();
```
💡 Это снижает связность между данными и выводом.

Почему важно разделять уровни приложения?::  
🧠 Потому что это:
1️⃣ Упрощает тестирование  
2️⃣ Повышает гибкость и повторное использование кода  
3️⃣ Облегчает добавление новых функциональностей  

🟨 Например: можно изменить способ хранения данных, не трогая логику отображения.  
🫶 Также:
- легче находить баги  
- проще масштабировать  
- удобнее писать юнит-тесты  

🎯 Это основа профессиональной архитектуры.

<!-- basicblock-start oid="ObsFF7UMWuwk16CaZjrZpXYG" deck='php-enterprise-patterns' -->
Какие уровни входят в архитектуру корпоративного приложения?::  
🟩 1. **Presentation Layer** — пользовательский интерфейс (HTML, JSON, CLI)  
🫶 2. **Command & Controller Layer** — маршруты, команды, выбор действия  
🟨 3. **Application Logic Layer** — бизнес-правила, расчёты, координация  
🟦 4. **Data Layer** — работа с БД, файлами, API  

🎯 Каждый уровень должен быть максимально независим от другого.  
💡 Чем меньше пересечений между уровнями — тем выше читаемость и тестируемость кода.
