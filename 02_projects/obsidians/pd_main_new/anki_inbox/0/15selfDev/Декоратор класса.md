Как выглядит простой пример декоратора для класса в ts?::


## 🧠 Цель кода

Добавить метод `toString()` к классу `Person`, который возвращает JSON-представление объекта (через `JSON.stringify(this)`), **не изменяя сам класс напрямую**. Это делается через **декоратор класса**.

---

## 🔍 Полный код с комментариями

```ts
// Определяем функцию-декоратор `toString`, которая принимает конструктор класса.
// T — это обобщённый тип, представляющий конструктор:
// - `new (...args: any[]): {}` означает, что это функция, создающая объект (конструктор).
function toString<T extends { new (...args: any[]): {} }>(constructor: T) {
  // Возвращаем новый класс, который расширяет исходный класс (constructor)
  return class extends constructor {
    // Переопределяем метод `toString`
    toString() {
      // Используем стандартный JSON.stringify для сериализации `this`
      return JSON.stringify(this);
    }
  };
}

// Применяем декоратор @toString к классу Person.
// Это значит, что Person будет передан как аргумент в функцию `toString`.
@toString
class Person {
  name = "Alice";
  age = 30;
}

// Создаём экземпляр класса Person (на самом деле это экземпляр изменённого класса после применения декоратора)
// Вызываем метод toString(), который теперь определён благодаря декоратору
console.log(new Person().toString());
// Вывод: {"name":"Alice","age":30}
```

---

## 📚 Подробное объяснение

### 1. **Декоратор класса**
```ts
@toString
class Person { ... }
```
Здесь используется **декоратор класса**. Синтаксис `@toString` говорит TypeScript, что нужно применить функцию `toString()` к классу `Person`.

Функция `toString` должна быть объявлена так, чтобы она принимала один параметр — **функцию-конструктор класса**, и возвращать **новый класс**, который расширяет исходный.

---

### 2. **Типизация `T` в `function toString<T extends { new (...args: any[]): {} }>`**

Это сложное ограничение типа:

```ts
T extends { new (...args: any[]): {} }
```

Оно означает, что `T` — это **тип конструктора**, то есть функция, которую можно вызвать с `new`, и которая возвращает какой-то объект (`{}`).

Примеры таких функций:
```ts
class Person {}
typeof Person // "function", но имеет сигнатуру `new () => Person`
```

Таким образом, мы гарантируем, что `constructor` — действительно конструктор класса.

---

### 3. **Возврат нового класса**
```ts
return class extends constructor {
  toString() {
    return JSON.stringify(this);
  }
};
```

Мы создаём **анонимный класс**, который наследуется от оригинального класса (`extends constructor`) и добавляет/переопределяет метод `toString()`.

То есть, при создании экземпляра `new Person()` на самом деле создаётся экземпляр этого нового анонимного класса, унаследованного от `Person`.

---

### 4. **Результат работы**
```ts
console.log(new Person().toString());
// {"name":"Alice","age":30}
```

Благодаря декоратору, у экземпляра есть метод `toString()`, который возвращает строковое представление объекта в формате JSON.

---

## 🛠️ Как это работает под капотом?

После применения декоратора `@toString`, класс `Person` фактически выглядит так:

```ts
class Person {
  name = "Alice";
  age = 30;
}

class ExtendedPerson extends Person {
  toString() {
    return JSON.stringify(this);
  }
}
```

И когда ты пишешь `new Person()`, ты на самом деле создаёшь экземпляр `ExtendedPerson`.

---

## 💡 Почему это метапрограммирование?

Потому что мы **динамически модифицируем поведение класса во время его определения**, не изменяя исходный код самого класса. Мы работаем с кодом на уровне абстракции выше — через декораторы.

---

## ✅ Плюсы подхода

- Не дублируется логика `toString()` в каждом классе.
- Можно повторно использовать декоратор для других классов.
- Чистый и декларативный синтаксис (`@toString`).

---

## ❗ Возможные проблемы / ограничения

- Не все среды поддерживают декораторы классов (нужны флаги компиляции в TypeScript).
- Может усложнить понимание кода новичкам.
- Если класс содержит приватные поля или методы, они могут не сериализоваться корректно.

---
