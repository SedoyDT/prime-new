## Отладка

Написание теста - это всегда процесс изучения кода и приложения. Ничего страшного, если тест нельзя написать с нуля или вы не понимаете, как работает код. Изучив следующие методы отладки, вы узнаете, как получить всю необходимую информацию внутри теста для его завершения.

## Повторный запуск неудачных тестов

Codeception сохраняет список неудачных тестов. Чтобы повторно запустить неудачный тест, запустите тесты из `failed` группы:

```
<span>php</span> <span>vendor</span><span>/</span><span>bin</span><span>/</span><span>codecept</span> <span>run</span> <span>-</span><span>g</span> <span>failed</span>
```

Если ни одно из тестов не завершилось неудачно, эта группа будет пустой.

## Вывод

Codeception предоставляет `codecept_debug` функцию для печати выходных данных отладки при запуске теста. Думайте об этом как о `var_dump` но для тестирования:

Отключите var\_dump, выходные данные будут выводиться на экран только в том случае, если тесты выполняются с флагом `--debug`.

```
php vendor/bin/codecept run --debug
```

Хранить `codecept_debug` внутри теста безопасно, это не повлияет на код, запущенный на сервере непрерывной интеграции.

`codecept_debug` может использоваться в любом месте ваших тестов, но запрещено использовать ее в коде приложения. Эта функция загружается только Codeception, поэтому приложение может быть сломано при попытке вызвать эту строку.

Внутри [помощника](https://codeception.com/docs/06-ModulesAndHelpers#Helpers) вы можете использовать аналоги этой функции для предоставления отладочного вывода для сложного действия.

```
<span>// print variable from helper</span>
<span>$this</span><span>-&gt;</span><span>debug</span><span>(</span><span>$response</span><span>);</span>

<span>// print variable with a short comment</span>
<span>$this</span><span>-&gt;</span><span>debugSection</span><span>(</span><span>'Response'</span><span>,</span> <span>$response</span><span>);</span>
```

Модули Codeception используют отладочный вывод, чтобы предоставить пользователю дополнительную информацию о данных, используемых тестом. Например, в режиме отладки вы можете видеть тело запроса и ответов при тестировании REST API.

## Пауза

При выполнении приемочного или функционального тестирования может потребоваться приостановить выполнение в какой-то момент, чтобы решить, что делать дальше. Например, при взаимодействии со страницей в веб-браузере может потребоваться приостановка выполнения, чтобы взаимодействовать с элементами на странице, найти подходящие локаторы и выполнить следующие шаги для сценария. Вот почему Codeception имеет интерактивный режим паузы (работает от [PsySH](https://psysh.org/)), который может быть запущен с помощью `codecept_pause` функции или `$I->pause()`.

Написание нового приемочного теста с нуля может быть удобнее, если вы держите окно браузера открытым. Рекомендуется начать написание нового приемочного теста с помощью этих двух команд:

```
<span>$I</span><span>-&gt;</span><span>amOnPage</span><span>(</span><span>'/'</span><span>);</span>
<span>$I</span><span>-&gt;</span><span>pause</span><span>();</span>
```

Интерактивная пауза запускается только тогда, когда `--debug` включена опция:

```
php vendor/bin/codecept run --debug
```

Чтобы запустить интерактивную паузу в контексте, когда `$I` объект недоступен, используйте `codecept_pause` вместо этого функцию. Чтобы проверить локальные переменные, передайте их в интерактивную оболочку, используя массив:

```
<span>$I</span><span>-&gt;</span><span>pause</span><span>([</span><span>'user'</span> <span>=&gt;</span> <span>$user</span><span>])</span>
<span>// or</span>
<span>codecept_pause</span><span>([</span><span>'user'</span> <span>=&gt;</span> <span>$user</span><span>]);</span>
```
