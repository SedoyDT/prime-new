## Модули и помощники

Codeception использует модульность для создания удобной среды тестирования для каждого написанного вами набора тестов.

Все действия и утверждения, которые могут выполняться объектом Tester в классе, определены в модулях. Вы можете расширить набор тестов своими собственными действиями и утверждениями, записав их в пользовательский модуль.

Давайте рассмотрим следующий тест:

```
<span>$I</span><span>-&gt;</span><span>amOnPage</span><span>(</span><span>'/'</span><span>);</span>
<span>$I</span><span>-&gt;</span><span>see</span><span>(</span><span>'Hello'</span><span>);</span>
<span>$I</span><span>-&gt;</span><span>seeInDatabase</span><span>(</span><span>'users'</span><span>,</span> <span>array</span><span>(</span><span>'id'</span> <span>=&gt;</span> <span>1</span><span>));</span>
<span>$I</span><span>-&gt;</span><span>seeFileFound</span><span>(</span><span>'running.lock'</span><span>);</span>
```

Он может работать с различными объектами: веб-страница может быть загружена с помощью модуля PhpBrowser, утверждение базы данных использует модуль Db, а состояние файла можно проверить с помощью модуля файловой системы.

Модули прикреплены к классам-исполнителям в конфигурации пакета. Например, в `tests/Functional.suite.yml` мы должны увидеть:

```
<span>actor</span><span>:</span> <span>FunctionalTester</span>
<span>modules</span><span>:</span>
    <span>enabled</span><span>:</span>
        <span>-</span> <span>PhpBrowser</span><span>:</span>
            <span>url</span><span>:</span> <span>http://localhost</span>
        <span>-</span> <span>Db</span><span>:</span>
            <span>dsn</span><span>:</span> <span>"</span><span>mysql:host=localhost;dbname=testdb"</span>
        <span>-</span> <span>Filesystem</span>
```

Класс FunctionalTester имеет свои методы, определенные в модулях. На самом деле, он не содержит ни одного из них, а скорее действует как прокси. Он знает, какой модуль выполняет это действие, и передает в него параметры. Чтобы ваша IDE могла видеть все методы FunctionalTester, вы должны выполнить команду `codecept build` . Она генерирует сигнатуры методов из включенных модулей и сохраняет их в чертеже, который включен в субъект. В текущем примере будет сгенерирован `tests/support/_generated/FunctionalTesterActions.php` файл. По умолчанию Codeception автоматически перестраивает свойство Actions при каждом изменении конфигурации пакета.

## Стандартные модули

Codeception имеет множество связанных модулей, которые помогут вам запускать тесты для различных целей и в разных средах. Идея модулей заключается в совместном выполнении общих действий, чтобы разработчики и инженеры по контролю качества могли сосредоточиться на тестировании, а не изобретать велосипед заново. Каждый модуль предоставляет методы тестирования своей части, и, комбинируя модули, вы можете получить мощную настройку для тестирования приложения на всех уровнях.

Существует `WebDriver` модуль для приемочного тестирования, модули для всех популярных фреймворков PHP, `PHPBrowser` для эмуляции работы браузера, `REST` для тестирования API и многое другое. Модули считаются наиболее ценной частью Codeception. Они постоянно совершенствуются, чтобы обеспечить наилучший опыт тестирования, и быть гибкими, чтобы удовлетворить потребности каждого.

### Конфликты модулей

Модули могут конфликтовать друг с другом. Если модуль реализует `Codeception\Lib\Interfaces\ConflictsWithModule`, он может объявить правило конфликта для использования с другими модулями. Например, WebDriver конфликтует со всеми модулями, реализующими `Codeception\Lib\Interfaces\Web` интерфейс.

```
<span>public</span> <span>function</span> <span>_conflicts</span><span>()</span>
<span>{</span>
    <span>return</span> <span>'Codeception\Lib\Interfaces\Web'</span><span>;</span>
<span>}</span>
```

Таким образом, если вы попытаетесь использовать два модуля, совместно использующих один и тот же конфликтующий интерфейс, вы получите исключение.

Во избежание путаницы, **модули Framework, PhpBrowser и WebDriver** нельзя использовать вместе. Например, метод `amOnPage` существует во всех этих модулях, и вам не следует пытаться угадать, какой модуль на самом деле выполнит его. Если вы проводите приемочное тестирование, настройте либо WebDriver, либо PhpBrowser, но не настраивайте оба одновременно. Если вы проводите функциональное тестирование, включите только один из модулей framework.

В случае, если вам нужно использовать модуль, который зависит от конфликтующего модуля, укажите его как зависимый модуль в конфигурации. Возможно, вы захотите использовать `WebDriver` с `REST` модулем, который взаимодействует с сервером через `PhpBrowser`. В этом случае ваша конфигурация должна выглядеть следующим образом:

```
<span>modules</span><span>:</span>
    <span>enabled</span><span>:</span>
        <span>-</span> <span>WebDriver</span><span>:</span>
            <span>browser</span><span>:</span> <span>firefox</span>
            <span>url</span><span>:</span> <span>http://localhost</span>
        <span>-</span> <span>REST</span><span>:</span>
            <span>url</span><span>:</span> <span>http://localhost/api/v1</span>
            <span>depends</span><span>:</span> <span>PhpBrowser</span>
```

Эта конфигурация позволит вам отправлять запросы GET / POST к API сервера при работе с сайтом через браузер.

Если вам нужно загрузить только некоторые части конфликтующего модуля, обратитесь к следующему разделу.

### Части модуля

Модули с разделом _Parts_ в их справочнике могут быть частично загружены. Таким образом, у `$I` объекта будут действия, относящиеся только к определенной части этого модуля. Частично загруженные модули также можно использовать, чтобы избежать конфликтов модулей.

Например, модуль Laravel имеет ORM-часть, которая содержит действия с базой данных. Вы можете включить модуль PhpBrowser для тестирования и ORM-часть Laravel для подключения к базе данных и проверки данных.

```
<span>modules</span><span>:</span>
    <span>enabled</span><span>:</span>
        <span>-</span> <span>PhpBrowser</span><span>:</span>
            <span>url</span><span>:</span> <span>http://localhost</span>
        <span>-</span> <span>Laravel</span><span>:</span>
            <span>part</span><span>:</span> <span>ORM</span>
```

Модули не будут конфликтовать, поскольку действия с одинаковыми именами загружаться не будут.

Модуль REST содержит части для `Xml` и `Json` таким же образом. Если вы тестируете службу REST только с ответами JSON, вы можете включить только JSON-часть этого модуля.:

```

<span>actor</span><span>:</span> <span>ApiTester</span>
<span>modules</span><span>:</span>
    <span>enabled</span><span>:</span>
        <span>-</span> <span>REST</span><span>:</span>
            <span>url</span><span>:</span> <span>http://serviceapp/api/v1/</span>
            <span>depends</span><span>:</span> <span>PhpBrowser</span>
            <span>part</span><span>:</span> <span>Json</span>
```

## Помощники

Codeception не ограничивает вас использованием только модулей из основного репозитория. Для вашего проекта может потребоваться добавление ваших собственных действий в набор тестов. Выполнив `codecept generate:helper Name` команду, вы можете сгенерировать пользовательский модуль под названием ‘Helper’ в `tests/Support/Helper` каталоге.

```


<span>namespace</span> <span>Tests\Support\Helper</span><span>;</span>
<span>// here you can define custom functions for FunctionalTester</span>

<span>class</span> <span>Functional</span> <span>extends</span> <span>\</span><span>Codeception\Module</span>
<span>{</span>
<span>}</span>
```

Действия также довольно просты. Каждое действие, которое вы определяете, является общедоступной функцией. Напишите общедоступный метод, затем выполните команду `build`, и вы увидите, что новая функция добавлена в класс FunctionalTester .

Общедоступные методы с префиксом \`\_\` рассматриваются как скрытые и не будут добавлены в ваш класс Actor.

Утверждения могут быть немного сложными. Прежде всего, рекомендуется ставить перед всеми вашими действиями с утверждением префикс `see` или `dontSee`.

Назовите свои утверждения следующим образом:

```
<span>$I</span><span>-&gt;</span><span>seePageReloaded</span><span>();</span>
<span>$I</span><span>-&gt;</span><span>seeClassIsLoaded</span><span>(</span><span>$classname</span><span>);</span>
<span>$I</span><span>-&gt;</span><span>dontSeeUserExist</span><span>(</span><span>$user</span><span>);</span>
```

А затем используйте их в своих тестах:

```
<span>$I</span><span>-&gt;</span><span>seePageReloaded</span><span>();</span>
<span>$I</span><span>-&gt;</span><span>seeClassIsLoaded</span><span>(</span><span>'FunctionalTester'</span><span>);</span>
<span>$I</span><span>-&gt;</span><span>dontSeeUserExist</span><span>(</span><span>$user</span><span>);</span>
```

Вы можете определять утверждения, используя методы assertXXX в своих модулях.

```
<span>function</span> <span>seeClassExist</span><span>(</span><span>$class</span><span>)</span>
<span>{</span>
    <span>$this</span><span>-&gt;</span><span>assertTrue</span><span>(</span><span>class_exists</span><span>(</span><span>$class</span><span>));</span>
<span>}</span>
```

В своих помощниках вы можете использовать эти утверждения:

```



<span>function</span> <span>seeCanCheckEverything</span><span>(</span><span>$thing</span><span>)</span>
<span>{</span>
    <span>$this</span><span>-&gt;</span><span>assertTrue</span><span>(</span><span>isset</span><span>(</span><span>$thing</span><span>),</span> <span>"this thing is set"</span><span>);</span>
    <span>$this</span><span>-&gt;</span><span>assertFalse</span><span>(</span><span>empty</span><span>(</span><span>$any</span><span>),</span> <span>"this thing is not empty"</span><span>);</span>
    <span>$this</span><span>-&gt;</span><span>assertNotNull</span><span>(</span><span>$thing</span><span>,</span> <span>"this thing is not null"</span><span>);</span>
    <span>$this</span><span>-&gt;</span><span>assertContains</span><span>(</span><span>"world"</span><span>,</span> <span>$thing</span><span>,</span> <span>"this thing contains 'world'"</span><span>);</span>
    <span>$this</span><span>-&gt;</span><span>assertNotContains</span><span>(</span><span>"bye"</span><span>,</span> <span>$thing</span><span>,</span> <span>"this thing doesn't contain 'bye'"</span><span>);</span>
    <span>$this</span><span>-&gt;</span><span>assertEquals</span><span>(</span><span>"hello world"</span><span>,</span> <span>$thing</span><span>,</span> <span>"this thing is 'Hello world'!"</span><span>);</span>
    <span>// ...</span>
<span>}</span>

```

### Доступ к другим модулям

Возможно, вам потребуется получить доступ к внутренним данным или функциям из других модулей. Например, для вашего модуля вам может потребоваться доступ к ответам или внутренним действиям других модулей.

Модули могут взаимодействовать друг с другом с помощью `getModule` метода. Пожалуйста, обратите внимание, что этот метод выдаст исключение, если требуемый модуль не был загружен.

Давайте представим, что мы пишем модуль, который повторно подключается к базе данных. Предполагается, что он использует значение подключения dbh из модуля Db.

```
<span>function</span> <span>reconnectToDatabase</span><span>()</span>
<span>{</span>
    <span>$dbh</span> <span>=</span> <span>$this</span><span>-&gt;</span><span>getModule</span><span>(</span><span>'Db'</span><span>)</span><span>-&gt;</span><span>dbh</span><span>;</span>
    <span>$dbh</span><span>-&gt;</span><span>close</span><span>();</span>
    <span>$dbh</span><span>-&gt;</span><span>open</span><span>();</span>
<span>}</span>
```

Используя функцию `getModule` , вы получаете доступ ко всем общедоступным методам и свойствам запрошенного модуля. `dbh`Свойство было определено как общедоступное специально для того, чтобы быть доступным для других модулей.

Модули также могут содержать методы, доступные для использования во вспомогательных классах. Эти методы начинаются с префикса `_` и недоступны в классах-исполнителях, поэтому доступны только из модулей и расширений.

Вы должны использовать их для написания своих собственных действий с использованием внутренних компонентов модуля.

```
<span>function</span> <span>seeNumResults</span><span>(</span><span>$num</span><span>)</span>
<span>{</span>
    <span>// retrieving webdriver session</span>
    <span>/**@var $table \Facebook\WebDriver\WebDriverElement */</span>
    <span>$elements</span> <span>=</span> <span>$this</span><span>-&gt;</span><span>getModule</span><span>(</span><span>'WebDriver'</span><span>)</span><span>-&gt;</span><span>_findElements</span><span>(</span><span>'#result'</span><span>);</span>
    <span>$this</span><span>-&gt;</span><span>assertNotEmpty</span><span>(</span><span>$elements</span><span>);</span>
    <span>$table</span> <span>=</span> <span>reset</span><span>(</span><span>$elements</span><span>);</span>
    <span>$this</span><span>-&gt;</span><span>assertEquals</span><span>(</span><span>'table'</span><span>,</span> <span>$table</span><span>-&gt;</span><span>getTagName</span><span>());</span>
    <span>$results</span> <span>=</span> <span>$table</span><span>-&gt;</span><span>findElements</span><span>(</span><span>'tr'</span><span>);</span>
    <span>// asserting that table contains exactly $num rows</span>
    <span>$this</span><span>-&gt;</span><span>assertEquals</span><span>(</span><span>$num</span><span>,</span> <span>count</span><span>(</span><span>$results</span><span>));</span>
<span>}</span>
```

В этом примере мы используем API библиотеки [facebook / php-webdriver](https://github.com/facebook/php-webdriver) , клиент Selenium WebDriver, на котором построен модуль. Вы также можете получить доступ к свойству `webDriver` модуля, чтобы получить доступ к `Facebook\WebDriver\RemoteWebDriver` пример для прямого взаимодействия с Selenium.

### Расширение модуля

Если доступ к модулям не обеспечивает достаточной гибкости, вы можете расширить модуль внутри вспомогательного класса:

```


<span>namespace</span> <span>Tests\Support\Helper</span><span>;</span>

<span>class</span> <span>MyExtendedSelenium</span> <span>extends</span> <span>\</span><span>Codeception\Module\WebDriver</span>
<span>{</span>
<span>}</span>
```

В этом помощнике вы можете заменить родительские методы своей собственной реализацией. Вы также можете заменить хуки `_before` и `_after` , что может быть дополнительным вариантом когда вам нужно настроить запуск и остановку сеанса тестирования.

### Хуки

Каждый модуль может обрабатывать события из запущенного теста. Модуль может быть запущен до начала теста или после его завершения. Это может быть полезно для действий начальной загрузки / очистки. Вы также можете определить специальное поведение при сбое теста. Это может помочь вам в устранении проблемы. Например, модуль PhpBrowser сохраняет текущую веб-страницу в каталог `tests/_output` при сбое теста.

Все перехваты определены в разделе [Codeception \\ Module](https://codeception.com/docs/reference/Module) и перечислены здесь. Вы можете переопределить их в своем модуле.

```

<span>// HOOK: used after configuration is loaded</span>
<span>public</span> <span>function</span> <span>_initialize</span><span>()</span>
<span>{</span>
<span>}</span>

<span>// HOOK: before each suite</span>
<span>public</span> <span>function</span> <span>_beforeSuite</span><span>(</span><span>$settings</span> <span>=</span> <span>array</span><span>())</span>
<span>{</span>
<span>}</span>

<span>// HOOK: after suite</span>
<span>public</span> <span>function</span> <span>_afterSuite</span><span>()</span>
<span>{</span>
<span>}</span>

<span>// HOOK: before each step</span>
<span>public</span> <span>function</span> <span>_beforeStep</span><span>(</span><span>\</span><span>Codeception\Step</span> <span>$step</span><span>)</span>
<span>{</span>
<span>}</span>

<span>// HOOK: after each step</span>
<span>public</span> <span>function</span> <span>_afterStep</span><span>(</span><span>\</span><span>Codeception\Step</span> <span>$step</span><span>)</span>
<span>{</span>
<span>}</span>

<span>// HOOK: before test</span>
<span>public</span> <span>function</span> <span>_before</span><span>(</span><span>\</span><span>Codeception\TestInterface</span> <span>$test</span><span>)</span>
<span>{</span>
<span>}</span>

<span>// HOOK: after test</span>
<span>public</span> <span>function</span> <span>_after</span><span>(</span><span>\</span><span>Codeception\TestInterface</span> <span>$test</span><span>)</span>
<span>{</span>
<span>}</span>

<span>// HOOK: on fail</span>
<span>public</span> <span>function</span> <span>_failed</span><span>(</span><span>\</span><span>Codeception\TestInterface</span> <span>$test</span><span>,</span> <span>$fail</span><span>)</span>
<span>{</span>
<span>}</span>

```

Пожалуйста, обратите внимание, что методы с `_` префиксы не добавляются в класс Actor. Это позволяет определять их как общедоступные, но использовать только для внутренних целей.

### Отладка

Как мы уже упоминали, `_failed` hook может помочь в отладке неудачного теста. У вас есть возможность сохранить состояние текущего теста и показать его пользователю, но вы не ограничены этим.

Каждый модуль может выводить внутренние значения, которые могут быть полезны во время отладки. Например, модуль PhpBrowser печатает код ответа и текущий URL-адрес каждый раз, когда переходит на новую страницу. Таким образом, модули не являются черными ящиками. Они пытаются показать вам, что происходит во время тестирования. Это делает отладку ваших тестов менее болезненной.

Для отображения дополнительной информации используйте методы модуля `debug` и `debugSection` . Вот пример того, как это работает в PhpBrowser.:

```
<span>$this</span><span>-&gt;</span><span>debugSection</span><span>(</span><span>'Request'</span><span>,</span> <span>$params</span><span>);</span>
<span>$this</span><span>-&gt;</span><span>client</span><span>-&gt;</span><span>request</span><span>(</span><span>$method</span><span>,</span> <span>$uri</span><span>,</span> <span>$params</span><span>);</span>
<span>$this</span><span>-&gt;</span><span>debug</span><span>(</span><span>'Response Code: '</span> <span>.</span> <span>$this</span><span>-&gt;</span><span>client</span><span>-&gt;</span><span>getStatusCode</span><span>());</span>

```

Этот тест, выполняемый с модулем PhpBrowser в режиме отладки, выведет что-то вроде этого:

```
I click "All pages"
* Request (GET) http://localhost/pages {}
* Response code: 200
```

## Настройка

Модули и помощники могут быть настроены из файла конфигурации пакета или глобально из `codeception.yml`.

Обязательные параметры должны быть определены в `$requiredFields` свойстве класса. Вот как это делается в модуле Db:

```
<span>class</span> <span>Db</span> <span>extends</span> <span>\</span><span>Codeception\Module</span>
<span>{</span>
    <span>protected</span> <span>$requiredFields</span> <span>=</span> <span>[</span><span>'dsn'</span><span>,</span> <span>'user'</span><span>,</span> <span>'password'</span><span>];</span>
    <span>// ...</span>
<span>}</span>
```

При следующем запуске пакета без установки одного из этих значений будет выдано исключение.

Для необязательных параметров следует установить значения по умолчанию. Свойство `$config` используется для определения необязательных параметров, а также их значений. В модуле WebDriver мы используем адрес и порт сервера Selenium по умолчанию.

```
<span>class</span> <span>WebDriver</span> <span>extends</span> <span>\</span><span>Codeception\Module</span>
<span>{</span>
    <span>protected</span> <span>$requiredFields</span> <span>=</span> <span>[</span><span>'browser'</span><span>,</span> <span>'url'</span><span>];</span>
    <span>protected</span> <span>$config</span> <span>=</span> <span>[</span><span>'host'</span> <span>=&gt;</span> <span>'127.0.0.1'</span><span>,</span> <span>'port'</span> <span>=&gt;</span> <span>'4444'</span><span>];</span>
    <span>// ...</span>
<span>}</span>

```

Параметры хоста и порта могут быть переопределены в конфигурации пакета. Значения устанавливаются в `modules:config` разделе файла конфигурации.

```
<span>modules</span><span>:</span>
    <span>enabled</span><span>:</span>
        <span>-</span> <span>WebDriver</span><span>:</span>
            <span>url</span><span>:</span> <span>'</span><span>http://mysite.com/'</span>
            <span>browser</span><span>:</span> <span>'</span><span>firefox'</span>
        <span>-</span> <span>Db</span><span>:</span>
            <span>cleanup</span><span>:</span> <span>false</span>
            <span>repopulate</span><span>:</span> <span>false</span>

```

Доступ к необязательным и обязательным параметрам можно получить через `$config` свойство. Используйте `$this->config['parameter']`, чтобы получить его значение.

### Динамическая настройка с параметрами

Модули могут быть динамически настроены с помощью переменных среды. Хранилище параметров должно быть указано в глобальной конфигурации `codeception.yml` внутри `params` Раздел. Параметры могут быть загружены из переменных среды, из yaml (формат Symfony), .env (формат Laravel), ini или php файлов.

Используйте раздел `params` глобального конфигурационного файла `codeception.yml` , чтобы указать, как их загружать. Вы можете указать несколько источников для параметров, из которых они будут загружаться.

Пример: загрузка параметров из среды:

```
<span>params</span><span>:</span>
    <span>-</span> <span>env</span> <span># load params from environment vars</span>
```

Пример: загрузка параметров из файла YAML (Symfony):

```
<span>params</span><span>:</span>
    <span>-</span> <span>app/config/parameters.yml</span>
```

Пример: загрузка параметров из php-файла (Yii)

```
<span>params</span><span>:</span>
    <span>-</span> <span>config/params.php</span>
```

Пример: загрузка параметров из .Env-файлов (Laravel):

```
<span>params</span><span>:</span>
    <span>-</span> <span>.env</span>
    <span>-</span> <span>.env.testing</span>

```

После загрузки переменные параметров могут использоваться в качестве значений конфигурации модуля. Используйте имя переменной, заключенное в `%` в качестве заполнителя, и оно будет заменено на ее значение.

Допустим, мы хотим указать учетные данные для службы облачного тестирования. Мы загрузили переменные `SAUCE_USER` и `SAUCE_KEY` из среды, и теперь мы передаем их значения в конфигурацию `WebDriver`:

```
<span>modules</span><span>:</span>
   <span>enabled</span><span>:</span>
      <span>-</span> <span>WebDriver</span><span>:</span>
         <span>url</span><span>:</span> <span>http://mysite.com</span>
         <span>host</span><span>:</span> <span>'</span><span>%SAUCE_USER%:%SAUCE_KEY%@ondemand.saucelabs.com'</span>

```

Параметры также полезны для предоставления учетных данных для подключения к `Db` модулю (взяты из файлов Laravel .env):

```
<span>modules</span><span>:</span>
    <span>enabled</span><span>:</span>
        <span>-</span> <span>Db</span><span>:</span>
            <span>dsn</span><span>:</span> <span>"</span><span>mysql:host=%DB_HOST%;dbname=%DB_DATABASE%"</span>
            <span>user</span><span>:</span> <span>"</span><span>%DB_USERNAME%"</span>
            <span>password</span><span>:</span> <span>"</span><span>%DB_PASSWORD%"</span>

```

Параметры могут задаваться в формате JSON. Таким образом, объекты, массивы, логические значения и строки также могут быть переданы в config.

```
<span>modules</span><span>:</span>
    <span>enabled</span><span>:</span>
        <span>-</span> <span>\Tests\Support\DataHelper</span><span>:</span>
            <span>users</span><span>:</span> <span>"</span><span>%USERS_ARRAY%"</span>
            <span>books</span><span>:</span> <span>"</span><span>%BOOKS_ARRAY%"</span>
```

В данном случае `USER_ARRAY` и `BOOKS_ARRAY` представляют собой массивы, построенные в формате JSON. Codeception превращает их в массив при разборе конфигурации.

### Конфигурация среды выполнения

Если вы хотите перенастроить модуль во время выполнения, вам нужно вызвать [helper](https://codeception.com/docs/ModulesAndHelpers#Helpers), который использует `_reconfigure` метод модуля.

В этом примере мы изменим корневой URL для PhpBrowser, чтобы он `amOnPage('/')` открылся `/admin/`.

```
<span>$this</span><span>-&gt;</span><span>getModule</span><span>(</span><span>'PhpBrowser'</span><span>)</span><span>-&gt;</span><span>_reconfigure</span><span>([</span><span>'url'</span> <span>=&gt;</span> <span>'http://localhost/admin'</span><span>]);</span>
```

Обычно эти изменения конфигурации вступают в силу немедленно. Однако в WebDriver изменения конфигурации не могут быть применены так просто. Например, если вы меняете браузер, вам нужно закрыть текущий сеанс браузера и начать новый. Для этого модуль WebDriver предоставляет `_restart` метод, который принимает конфигурационный массив и перезапускает браузер:

```
<span>// start chrome</span>
<span>$this</span><span>-&gt;</span><span>getModule</span><span>(</span><span>'WebDriver'</span><span>)</span><span>-&gt;</span><span>_restart</span><span>([</span><span>'browser'</span> <span>=&gt;</span> <span>'chrome'</span><span>]);</span>
<span>// or just restart browser</span>
<span>$this</span><span>-&gt;</span><span>getModule</span><span>(</span><span>'WebDriver'</span><span>)</span><span>-&gt;</span><span>_restart</span><span>();</span>
```

> Вы не можете изменять конфигурации статических тестов, например, `depends` во время выполнения.

В конце теста все изменения конфигурации будут возвращены к исходным значениям конфигурации.

### Конфигурация теста во время выполнения

Иногда требуется установить пользовательскую конфигурацию только для конкретного теста. Для форматов [Cest](https://codeception.com/docs/07-AdvancedUsage#Cest-Classes) и [Test\\Unit](https://codeception.com/docs/05-UnitTests) вы можете использовать `#[Prepare]` атрибут, который выполняет код перед выполнением других перехватчиков. Это позволяет `#[Prepare]` изменять конфигурацию модуля во время выполнения. `#[Prepare]` использует [внедрение зависимостей](https://codeception.com/docs/07-AdvancedUsage#Dependency-Injection) для автоматического внедрения необходимых модулей в метод.

Чтобы запустить определенный тест только в браузере Chrome, вы можете вызвать `_reconfigure` из модуля WebDriver сам тест с помощью `#[Prepare]`.

```
<span>use</span> <span>Codeception\Attribute\Prepare</span><span>;</span>

<span>#[Prepare('useChrome')]</span>
<span>public</span> <span>function</span> <span>chromeSpecificTest</span><span>()</span>
<span>{</span>
    <span>// ...</span>
<span>}</span>

<span>protected</span> <span>function</span> <span>useChrome</span><span>(</span><span>\</span><span>Codeception\Module\WebDriver</span> <span>$webdriver</span><span>)</span>
<span>{</span>
    <span>// WebDriver was injected by the class name</span>
    <span>$webdriver</span><span>-&gt;</span><span>_reconfigure</span><span>([</span><span>'browser'</span> <span>=&gt;</span> <span>'chrome'</span><span>]);</span>
<span>}</span>

```

Методы Prepare могут вызывать все методы модуля, а также скрытые методы API (начиная с `_`). Используйте их для настройки модуля для конкретного теста.

Чтобы изменить конфигурацию модуля для определенной группы тестов, используйте [GroupObjects](https://codeception.com/docs/08-Customization#Group-Objects).

## Заключение

Модули - это реальная мощь Codeception. Они используются для эмуляции множественного наследования для классов субъектов (UnitTester, FunctionalTester, AcceptanceTester и т.д.). Codeception предоставляет модули для эмуляции веб-запросов, доступа к данным, взаимодействия с популярными библиотеками PHP и т.д. Если вам недостаточно входящих в комплект модулей, ничего страшного, вы можете написать свои собственные! Используйте помощники (пользовательские модули) для всего, что Codeception не может сделать "из коробки". Помощники также можно использовать для расширения функциональности оригинальных модулей.

[**Улучшите** это руководство](https://github.com/Codeception/codeception.github.com/edit/master/docs/ModulesAndHelpers.md)
