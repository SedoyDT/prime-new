# 0. Общая архитектурная модель (фиксируем перед стартом)

## 0.1 Три слоя системы

```txt
L1 — Infrastructure (Docker + Data + Messaging)
L2 — Cognitive Apps (LLM/AI приложения)
L3 — Orchestration (event-driven нервная система)
```

---

## 0.2 Главный принцип

```txt
ВСЁ взаимодействие между сервисами = события
API — только входной слой
LLM — только внутри cognitive apps
Orchestration — не знает деталей LLM
```

---

# STEP 3 — Event System (P0)

## Цель

Сделать “нервную систему” системы.

---

## 3.1 Базовый event schema

```json
{
  "event_id": "uuid",
  "trace_id": "uuid",
  "type": "string",
  "source": "string",
  "timestamp": "iso8601",
  "payload": {}
}
```

---

## 3.2 Event naming rules

```txt
domain.action.status
```

Примеры:

```txt
calls.uploaded
calls.transcription.requested
calls.transcription.completed
calls.analysis.requested
calls.analysis.completed
```

---

## 3.3 SDK (ОБЯЗАТЕЛЬНО)

shared/sdk должен уметь:

- publish_event()
    
- subscribe()
    
- validate schema
    
- propagate trace_id
    

---

## 3.4 Результат STEP 3

```txt
любая часть системы может отправлять и получать события
```
