**ai**: Это — **детальный, пошаговый план построения event-driven AI-платформы**, ориентированной на локальную, надёжную и масштабируемую работу с аудио-звонками (например, анализ звонков в продажах).

---

### 📌 О чём этот документ?

Это **исполняемый технический план** для создания системы, где:

- Всё взаимодействие между компонентами происходит через **события (events)**.
- Каждый шаг — это **реализуемый, проверяемый этап**, с чёткими критериями успеха.
- Система строится по принципу:  
  **"Ничего не делается, пока не работает предыдущий шаг"** — это критическое правило.

---

### 🔧 Что включено?

| Часть | Что делает |
|------|-----------|
| **0. Архитектура** | Три слоя: инфраструктура → когнитивные приложения → оркестрация (нервная система) |
| **PHASE 1 — Фундамент** | От загрузки аудио до транскрипции (с Whisper) и хранения в MinIO/Postgres |
| **PHASE 2 — AI-аналитика** | Внедрение LLM для анализа эмоций, удовлетворённости клиента, возможностей продаж |
| **PHASE 3 — Распределённая система** | Многомашинная работа, агенты, внешние инструменты (файлы, браузер, API) |

---

### 🚀 Как я могу помочь?

Я могу:

- ✅ **Помочь реализовать конкретный шаг** (например, написать `docker-compose.yml` или `event schema + SDK`)
- ✅ **Проверить структуру папок и файлов** — например, построить `shared/sdk` с `publish_event()` и `subscribe()`
- ✅ **Продемонстрировать flow** — например, как выглядит полный цикл: `upload → transcription → analysis → summary`
- ✅ **Предложить оптимизации** — например, использование `Q4_K_M` quantization для локальных LLM, `flash attention`, `mmap` для эффективной работы
- ✅ **Помочь с настройкой локального LLM (GGUF, LM Studio, MLX)** — если нужно запустить AI-аналитику без внешних API
- ✅ **Сделать "супер-ядро" — краткое руководство по запуску системы по шагам**
